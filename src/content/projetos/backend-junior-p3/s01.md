A primeira etapa monta a base: o projeto com banco, as migrations que criam a tabela de usuários e a primeira rota, que consulta o saldo. Ainda não há dinheiro se mexendo, mas tudo o que vem depois apoia nesta estrutura.

## O projeto e o banco

Gere o projeto com Spring Web, Validation, Spring Data JPA, Flyway, o driver do PostgreSQL e o H2. O H2 é um banco em memória escrito em Java, e no **modo PostgreSQL** aceita quase todo o SQL que você vai escrever. A URL do banco vem de uma variável de ambiente, com o H2 como padrão:

```properties
spring.datasource.url=${DB_URL:jdbc:h2:mem:carteira;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE}
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.open-in-view=false
```

Com `ddl-auto=validate`, quem cria as tabelas é o Flyway, e o Hibernate só confere que as entidades batem com elas, como em [Migrations com Flyway](/assistir/backend-junior-t5-e05). O `open-in-view=false` fecha a sessão do JPA no fim do service: nada de consulta escondida durante a geração do JSON.

> [!PENSE]
> A tabela tem `check (saldo >= 0)`, e a entidade também vai recusar saldo negativo. Por que repetir a regra no banco, se o Java já a confere?

## O que construir

1. `V1__usuarios.sql`: a tabela `usuarios` com `id`, `nome`, `documento` e `email` únicos, `tipo` (`COMUM` ou `LOJISTA`), `saldo numeric(12,2)` com `check (saldo >= 0)` e `versao` para a trava otimista.
2. `V2__usuarios_de_exemplo.sql`: Ana Lima (comum, 500.00), Bruno Reis (comum, 50.00) e Loja Ipê (lojista, 0.00).
3. A entidade `Usuario`, com `@Enumerated(EnumType.STRING)` e `@Version`, e o `UsuarioRepository`.
4. `GET /usuarios/{id}` devolve um `UsuarioResposta` (sem documento nem e-mail) ou `404` como `ProblemDetail`.
5. Commit: `feat: usuários com migrations e consulta de saldo`.

```text
> curl -s localhost:8080/usuarios/1
{"id":1,"nome":"Ana Lima","tipo":"COMUM","saldo":500.00}
> curl -s localhost:8080/usuarios/99
{"detail":"usuário 99 não existe","instance":"/usuarios/99","status":404,"title":"Not Found"}
```

> [!BOAPRATICA]
> Os usuários de exemplo numa migration servem para desenvolver e para demonstrar. Num sistema de verdade, dados de exemplo ficam numa pasta de migrations carregada só no perfil de desenvolvimento (`spring.flyway.locations`), para nunca chegarem à produção.
