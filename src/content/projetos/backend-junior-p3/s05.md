O último passo é provar, com testes automáticos, que cada regra vale e que o "tudo ou nada" funciona. A suíte segue a pirâmide da [temporada de testes](/?t=backend-junior-t6): muitos testes rápidos sem Spring, alguns com o banco e poucos com a aplicação inteira.

## Quatro tamanhos

| Teste | Sobe | Prova |
|---|---|---|
| `UsuarioTest` | nada | as regras de `debitar`: lojista, saldo insuficiente, saldo zerado |
| `TransferenciaServiceTest` | nada; Mockito no lugar dos repositórios e do autorizador | a orquestração: o evento sai, a negada não grava, o mesmo usuário nem consulta o autorizador |
| `UsuarioRepositoryTest` | `@DataJpaTest`, com as migrations | as migrations rodam e o banco recusa um documento repetido |
| `TransferenciaIntegracaoTest` | `@SpringBootTest`, com o autorizador e o notificador em `@MockitoBean` | a transferência grava os saldos e notifica; a negada desfaz tudo e não notifica |

Para criar um `Usuario` nos testes sem banco, a entidade ganha um construtor público com os campos; o construtor sem argumentos continua `protected`, só para o JPA.

> [!PENSE]
> O teste de integração não pode usar `@Transactional` para limpar o banco no fim: com ele, o *commit* nunca aconteceria, e o `AFTER_COMMIT` da notificação nunca rodaria. Como ele restaura os saldos entre um teste e outro?

## O que construir

1. O construtor público de `Usuario`.
2. Os quatro testes da tabela, com os casos listados.
3. No teste de integração, um `@BeforeEach` que apaga as transferências e restaura os saldos com `JdbcTemplate`.
4. `./mvnw test` termina com `Tests run: 10, Failures: 0, Errors: 0`. Commit: `test: unidade, repositório e integração`.

```text
> ./mvnw test
[INFO] Tests run: 2, Failures: 0, Errors: 0, Skipped: 0 -- in br.com.ipe.carteira.TransferenciaIntegracaoTest
[INFO] Tests run: 3, Failures: 0, Errors: 0, Skipped: 0 -- in br.com.ipe.carteira.TransferenciaServiceTest
[INFO] Tests run: 2, Failures: 0, Errors: 0, Skipped: 0 -- in br.com.ipe.carteira.UsuarioRepositoryTest
[INFO] Tests run: 3, Failures: 0, Errors: 0, Skipped: 0 -- in br.com.ipe.carteira.UsuarioTest
[INFO] Tests run: 10, Failures: 0, Errors: 0, Skipped: 0
```

> [!IA]
> "Escreva um teste @SpringBootTest para TransferenciaService, Spring Boot 4.1, com @MockitoBean para Autorizador e Notificador. Prove que uma transferência negada não muda os saldos no banco e não chama o notificador. Não use @Transactional no teste, porque a notificação é AFTER_COMMIT; restaure os dados num @BeforeEach." Sem a última frase, o assistente quase sempre põe `@Transactional` no teste, e o teste da notificação passa a falhar sem motivo aparente.
