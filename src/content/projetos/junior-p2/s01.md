Um contrato é um punhado de dados que não muda: o nome, o valor, os dependentes. É o caso perfeito para um **record**, que numa linha declara os campos, o construtor, os métodos de acesso, `equals`, `hashCode` e `toString`.

## Records que se validam

Um record sem validação aceita salário negativo e estágio de 60 horas. O **construtor compacto**, da temporada [Java moderno](/?t=junior-t5), roda antes de os campos receberem os valores: ali você normaliza (tira os espaços do nome) e recusa o que for inválido com uma `IllegalArgumentException`.

```java
record Exemplo(String nome, long valor) {
    Exemplo {                              // sem parênteses: é o construtor compacto
        nome = nome.strip();               // reatribui o parâmetro, não o campo
        if (valor <= 0) throw new IllegalArgumentException("valor precisa ser positivo: " + nome);
    }
}
```

Os valores ficam em **centavos num `long`**, como no [caixa eletrônico](/projetos/estagiario-p1): R$ 4.500,00 é `4_500_00`. O `_` separa os centavos e deixa o número legível.

## Reajuste sem mudar nada

Um record não tem setters: os campos são `final`. Para reajustar um salário, crie um método que devolve um record **novo**, com o valor reajustado. O original continua igual, e isso é uma vantagem: quem estiver usando o objeto antigo não vê o valor mudar no meio de uma conta.

## O que construir

1. Os records `Clt(nome, salario, dependentes)`, `Pj(nome, valorMensal, notaEmitida)` e `Estagio(nome, bolsa, horasSemanais)`, com construtores compactos que validam as regras do pedido.
2. Em `Clt`, o método `comReajuste(int percentual)`.
3. Um `main` que imprime três contratos, compara dois records iguais, reajusta a Luiza em 10% e tenta criar um estágio de 40 horas, mostrando a mensagem da exceção.

```text
Clt[nome=Luiza Prado, salario=290000, dependentes=0]
...
Recusado: estágio vai de 1 a 30 horas por semana: Duda Alves
```

> [!ANTES]
> Antes do Java 16, cada um destes contratos era uma classe de umas 40 linhas: campos `private final`, construtor, getters, `equals`, `hashCode` e `toString`, escritos à mão ou gerados pela IDE. Muitos projetos usavam o `@Value` do **Lombok** para gerar tudo. Em código Java antigo, e em muito código Spring de hoje, você ainda vai encontrar as duas formas.

> [!BOAPRATICA]
> Valide no construtor, não em quem usa o objeto. Se um `Estagio` só existe com 1 a 30 horas, nenhuma outra parte do sistema precisa conferir isso de novo: um objeto inválido simplesmente não consegue nascer.
