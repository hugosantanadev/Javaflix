O primeiro passo é o projeto Spring Boot de pé e a rota que recebe transações, com as respostas certas para cada tipo de erro. Ainda não guardamos nada: esta etapa é só sobre a **porta de entrada** da API.

## O projeto

Gere o projeto no [Spring Initializr](https://start.spring.io/) com Java 25, Maven, Spring Boot 4.1 e duas dependências: **Spring Web** e **Validation**. O que cada uma faz, e o que a classe com `@SpringBootApplication` liga sozinha, está em [Seu primeiro projeto Spring Boot](/assistir/backend-junior-t4-e02).

## O DTO e a validação

O corpo da requisição vira um **record** com as anotações do Bean Validation: `@NotNull` para os campos obrigatórios e `@PositiveOrZero` para o valor. Use `BigDecimal` para o valor, nunca `double`, e `OffsetDateTime` para a data, que já traz o fuso do jeito que o pedido mostra (`-03:00`, `Z`).

O `@Valid` no parâmetro do controller faz o Spring validar antes de chamar o seu método. Quando a validação falha, ele lança `MethodArgumentNotValidException`; quando o JSON nem dá para ler, `HttpMessageNotReadableException`. Um `@RestControllerAdvice` traduz cada uma para o status do pedido, como em [Validação e tratamento de erros](/assistir/backend-junior-t4-e04).

> [!PENSE]
> `{"valor": -10}` e `{"valor": "dez"}` são erros diferentes. No primeiro, o JSON é válido e o **conteúdo** viola uma regra; no segundo, o JSON nem vira um objeto. Qual dos dois é `400`, e qual é `422`?

## O que construir

1. `TransacaoRequest`, um record com `valor` (`BigDecimal`, obrigatório, maior ou igual a zero) e `dataHora` (`OffsetDateTime`, obrigatória).
2. `POST /transacao` responde `201` sem corpo para uma transação válida e `422` se a `dataHora` estiver no futuro.
3. `TratadorDeErros`, com `@RestControllerAdvice`: validação que falha vira `422`; JSON ilegível vira `400`. Nenhum dos dois devolve corpo.
4. Teste com `curl` os sete casos da sessão abaixo. Commit: `feat: recebe transações com validação`.

```text
> curl -i -X POST localhost:8080/transacao -H "Content-Type: application/json" -d '{"valor": 123.45, "dataHora": "2026-10-31T12:34:56.789-03:00"}'
HTTP/1.1 201
> curl -i -X POST localhost:8080/transacao -H "Content-Type: application/json" -d '{"valor": -10.00, "dataHora": "2026-10-31T12:34:56.789-03:00"}'
HTTP/1.1 422
> curl -i -X POST localhost:8080/transacao -H "Content-Type: application/json" -d '{"valor": "cinquenta", "dataHora": "2026-10-31T12:34:56Z"}'
HTTP/1.1 400
```

> [!IA]
> Um bom pedido para esta etapa: "Spring Boot 4.1, Java 25. Escreva um @RestControllerAdvice que traduza MethodArgumentNotValidException para 422 e HttpMessageNotReadableException para 400, sem corpo na resposta e sem expor mensagens internas. Não use @ResponseStatus nas exceções do Spring e não acrescente dependências." Confira o pacote dos imports: as respostas antigas trazem classes que mudaram de nome no Spring 7.
