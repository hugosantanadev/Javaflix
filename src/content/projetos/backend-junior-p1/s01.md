Toda API começa igual: um processo escutando uma porta, que recebe texto em HTTP e devolve texto em HTTP. O JDK traz um servidor pronto para isso, o `HttpServer`, no pacote `com.sun.net.httpserver`, o mesmo do episódio [Uma conversa em texto](/assistir/backend-junior-t2-e01).

## O projeto

Crie um projeto Maven no IntelliJ (**New Project**, com **Maven** como sistema de build), sem nenhuma dependência, e um repositório Git na pasta com `git init`. Três classes:

- `ApiDeTarefas`, com um método `static HttpServer iniciar(int porta)` que monta e sobe o servidor;
- `Main`, que sobe a API de verdade, na porta 8080;
- `TesteDaApi`, que sobe a API numa porta livre, faz as requisições e confere as respostas.

```java
public class Main {
    public static void main(String[] args) throws Exception {
        ApiDeTarefas.iniciar(8080);
        System.out.println("API em http://127.0.0.1:8080, Ctrl + C para parar");
    }
}
```

## Contextos e respostas

`servidor.createContext("/saude", handler)` registra quem atende um caminho. O handler recebe um `HttpExchange`, a troca entre cliente e servidor, com a requisição e a resposta. Responder tem três passos, sempre nessa ordem: os cabeçalhos, o status com o tamanho do corpo em `sendResponseHeaders`, e o corpo em bytes. No fim, a troca precisa ser **fechada**; como `HttpExchange` é `AutoCloseable`, um `try (troca)` resolve.

Cuidado com o contexto: `/saude` atende também `/saude/extra`, porque o `HttpServer` escolhe o contexto pelo **prefixo** do caminho. Quem garante que `/saude/extra` dá 404 é o seu código.

## O que construir

1. `GET /saude` responde `200` com `{"status":"ok"}` e `Content-Type: application/json; charset=utf-8`.
2. Um contexto `/` responde `404` com `{"erro":"rota não encontrada"}` para todo o resto.
3. O servidor escuta em `InetAddress.getLoopbackAddress()`, o `127.0.0.1`.
4. `TesteDaApi` sobe a API na porta 0, faz `GET` em `/saude`, `/nada` e `/saude/extra`, imprime o status e o corpo de cada uma e para o servidor.
5. Rode o `Main` e teste no terminal com `curl -i http://127.0.0.1:8080/saude`. Depois, `git add .` e `git commit -m "feat: servidor e rota de saúde"`.

> [!ANTES]
> O `HttpServer` existe desde o Java 6, de 2006, e nasceu para testes e ferramentas internas. No Java 18 o JDK ganhou também o `jwebserver`, um comando que serve arquivos de uma pasta em uma linha, útil para testar páginas estáticas. Nenhum dos dois foi feito para produção pesada, e é por isso que o mercado usa Tomcat, Jetty ou Netty, normalmente por baixo do Spring.

> [!BOAPRATICA]
> Toda API de produção tem uma rota de saúde. Balanceadores de carga e orquestradores, como o Kubernetes da trilha Pleno, chamam essa rota a cada poucos segundos e tiram do ar a instância que parar de responder `200`.
