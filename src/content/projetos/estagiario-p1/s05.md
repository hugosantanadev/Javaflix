Última etapa: o extrato e a robustez. Teste o programa da etapa anterior digitando `cem` quando ele pede o valor do saque: ele para com uma `InputMismatchException`. O menu já se protegia, mas as outras perguntas não. E, no fim, você vai testar o caixa inteiro de uma vez, sem digitar nada.

## O extrato

Sem arrays, que chegam na temporada [Arrays e Math](/?t=estagiario-t6), dá para guardar o extrato numa `String` que cresce a cada movimentação. Cada linha termina com `"\n"`, a quebra de linha:

```java
String extrato = "";
extrato += "Depósito      +" + formatar(valor * 100L) + "\n";
```

Na opção 4, imprima o extrato com `print` (ele já termina em quebra de linha) e o saldo no fim. Se nada aconteceu ainda, mostre `Nenhuma movimentação.`; para saber, conte as movimentações numa variável `int`.

## Ler números sem quebrar

A proteção do menu, com `hasNextInt` e `next`, precisa valer para todas as perguntas. Em vez de copiar o mesmo bloco três vezes, crie um método que pergunta, insiste enquanto a resposta não for número e devolve o inteiro:

```java
static int lerInteiro(Scanner entrada, String pergunta) {
    // mostra a pergunta; enquanto não vier um número, avisa e pergunta de novo
}
```

Uma decisão de projeto: se a entrada acabar de vez (`hasNext()` responde `false`), o método devolve 0, e o caixa se despede como se a pessoa tivesse escolhido sair.

## Teste de aceitação

Digitar a mesma sequência toda vez que você muda o código cansa e erra. O terminal resolve: salve o que seria digitado num arquivo `entrada.txt`, uma resposta por linha, e mande para o programa:

```text
java Caixa.java < entrada.txt                    (cmd e terminais Linux e macOS)
Get-Content entrada.txt | java Caixa.java        (PowerShell)
```

Use esta sequência, que passa por todas as regras: `1`, `2`, `50`, `3`, `cem`, `180`, `3`, `35`, `3`, `100`, `3`, `100`, `3`, `100`, `3`, `600`, `4` e `0`, uma por linha. O extrato no fim precisa terminar com o saldo `R$ 801,55`.

> [!IA]
> Uma IA é boa para inventar casos de teste em que você não pensou. Um pedido que funciona: "Este é um caixa eletrônico de terminal em Java, com as regras abaixo. Liste 10 sequências de entrada para testar as bordas: limite diário exato, tarifa no quarto saque, letras, valores negativos e o maior depósito permitido. Para cada uma, diga a saída esperada. Não reescreva o código." Ela vai errar algumas saídas esperadas, e é aí que você confere rodando o programa. Peça também para não sugerir bibliotecas nem classes novas: o objetivo é testar o que existe.

> [!ANTES]
> Juntar texto com `+=` dentro de um laço cria uma String nova a cada volta, porque String não muda. Para um extrato de dez linhas não faz diferença; para milhares, faz. A temporada [Texto](/?t=estagiario-t5) mostra o `StringBuilder`, feito para isso.
