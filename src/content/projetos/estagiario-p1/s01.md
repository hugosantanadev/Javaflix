Toda aplicação de terminal começa igual: um laço que mostra as opções, lê a escolha e decide o que fazer. Nesta etapa as opções ainda não fazem nada; o que importa é o esqueleto aguentar qualquer coisa que a pessoa digitar.

## Lendo do teclado

O `System.out` escreve na tela; para ler do teclado, o JDK tem a classe `Scanner`, do pacote `java.util`. Por enquanto, trate as três linhas abaixo como uma receita. A palavra `new` cria um objeto, e a temporada [Classes e objetos](/?t=junior-t1) explica o que isso significa.

```java
import java.util.Scanner;   // no topo do arquivo, antes da classe

Scanner entrada = new Scanner(System.in);   // uma vez, no começo do main
int opcao = entrada.nextInt();              // espera a pessoa digitar um número e apertar Enter
```

Dois métodos do `Scanner` resolvem o problema das letras:

- `entrada.hasNextInt()` responde `true` se o próximo pedaço digitado é um número inteiro, **sem consumir** nada;
- `entrada.next()` consome o próximo pedaço, seja ele qual for. Serve para jogar fora o que não é número.

Se você chamar `nextInt()` e a pessoa tiver digitado `abc`, o programa para com uma `InputMismatchException`. Pergunte antes com `hasNextInt()`.

## O que construir

1. Crie o arquivo `Caixa.java` com a classe `Caixa` e o `main`.
2. Mostre o título `Caixa Javaflix` uma vez e, dentro de um laço, a linha do menu: `1 Saldo  2 Depositar  3 Sacar  4 Extrato  0 Sair`, seguida de `Opção:`.
3. Com um `switch` de seta (`->`), responda `Em construção.` para as opções de 1 a 4, `Até logo!` para o 0 e `Opção inválida.` para qualquer outro número.
4. Se a pessoa digitar algo que não é número, mostre `Digite só o número da opção.` e volte ao menu.
5. O laço termina quando a opção for 0.

Uma sessão com o programa pronto, com o que a pessoa digita marcado com `>`:

```text
Caixa Javaflix

1 Saldo  2 Depositar  3 Sacar  4 Extrato  0 Sair
Opção:
> abc
Digite só o número da opção.

1 Saldo  2 Depositar  3 Sacar  4 Extrato  0 Sair
Opção:
> 0
Até logo!
```

Repare que o `Opção:` usa `println`, com quebra de linha: assim a resposta fica na linha de baixo, tanto no terminal quanto na janela **Run** do IntelliJ, onde o que você digita aparece em outra cor.

> [!ANTES]
> O `Scanner` chegou no Java 5, em 2004. Antes dele, ler um número do teclado exigia `BufferedReader`, `InputStreamReader`, `Integer.parseInt` e um `try` para os erros, umas cinco linhas para cada leitura. No Java 25 existe ainda o `IO.readln("Opção: ")`, que lê uma linha inteira como texto; converter esse texto em número sem quebrar exige tratar exceções, assunto do Pleno, por isso este projeto fica com o `Scanner`.

> [!BOAPRATICA]
> Rode o programa a cada mudança pequena. Escrever as cinco partes de uma vez e rodar só no fim transforma um erro de digitação numa caça ao tesouro.
