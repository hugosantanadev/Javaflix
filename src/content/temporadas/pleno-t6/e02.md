A operação terminal é a que faz tudo acontecer: ela puxa os elementos pelo pipeline e produz o resultado final, que pode ser um valor, uma coleção, um `Optional` ou nada. Este episódio cobre todas elas, com atenção especial ao `reduce`, a operação que resume uma stream num único valor e que a prova cobra nas três formas.

## O mapa das terminais

| Operação | Devolve | Curto-circuito? |
|---|---|---|
| `forEach` / `forEachOrdered` | `void` | Não |
| `count()` | `long` | Não |
| `min(Comparator)` / `max(Comparator)` | `Optional<T>` | Não |
| `findFirst()` / `findAny()` | `Optional<T>` | Sim |
| `anyMatch` / `allMatch` / `noneMatch` | `boolean` | Sim |
| `reduce(...)` | Um valor ou `Optional<T>` | Não |
| `collect(...)` | O que o coletor montar | Não |
| `toList()` (Java 16) | `List<T>` imutável | Não |
| `toArray()` / `toArray(String[]::new)` | `Object[]` / array tipado | Não |

Repare nos tipos: `count` devolve `long`, não `int`; `min`, `max` e `findFirst` devolvem `Optional`, porque a stream pode estar vazia; e `min` e `max` de `Stream` exigem um `Comparator`, ao contrário das versões de `IntStream`.

```java executar
import java.util.Arrays;
import java.util.Comparator;
import java.util.stream.Stream;

public class Terminais {
    public static void main(String[] args) {
        System.out.println(Stream.of("b", "a", "c").max(Comparator.naturalOrder()).get() + " " + Stream.of("b", "a").min(String::compareTo));
        System.out.println(Stream.of(5, 3).count() + " " + Stream.of(1, 2, 3).findFirst() + " " + Stream.empty().findFirst());
        System.out.println(Stream.of(1, 2, 3).anyMatch(n -> n > 2) + " " + Stream.of(1, 2, 3).allMatch(n -> n > 0) + " " + Stream.of(1, 2, 3).noneMatch(n -> n > 5));
        System.out.println(Arrays.toString(Stream.of("p", "q").toArray(String[]::new)) + " " + Stream.of(1, 2).toArray().getClass().getSimpleName());
    }
}
```

```saida
c Optional[a]
2 Optional[1] Optional.empty
true true true
[p, q] Object[]
```

## Os testes e a stream vazia

Em uma stream **vazia**, `anyMatch` dá `false` (não existe ninguém que passe), mas `allMatch` e `noneMatch` dão `true` (não existe ninguém que reprove). É a lógica do "para todo" da matemática, chamada *verdade vácua*, e é uma das pegadinhas preferidas da prova.

Os três param assim que a resposta está decidida: `anyMatch` no primeiro que passa, `allMatch` no primeiro que falha. Com uma stream infinita, `anyMatch` pode terminar; `allMatch` só termina se encontrar um que falhe.

## reduce: resumindo a stream num valor

`reduce` combina os elementos dois a dois até sobrar um. Há três formas:

| Forma | Devolve | Uso |
|---|---|---|
| `reduce(identidade, acumulador)` | `T` | Soma, produto, concatenação |
| `reduce(acumulador)` | `Optional<T>` | Quando não há identidade natural, ou a stream pode estar vazia |
| `reduce(identidade, acumulador, combinador)` | `U` | Quando o resultado tem outro tipo |

```java executar
import java.util.stream.Stream;

public class Reducoes {
    public static void main(String[] args) {
        System.out.println(Stream.of(1, 2, 3).reduce(0, Integer::sum));
        System.out.println(Stream.of(1, 2, 3).reduce(10, Integer::sum));
        System.out.println(Stream.of(1, 2, 3).reduce(Integer::sum) + " " + Stream.<Integer>empty().reduce(Integer::sum));
        System.out.println(Stream.of("a", "b", "c").reduce("", String::concat));
        int letras = Stream.of("a", "bb", "ccc").reduce(0, (total, s) -> total + s.length(), Integer::sum);
        System.out.println(letras);
    }
}
```

```saida
6
16
Optional[6] Optional.empty
abc
6
```

A **identidade** é o valor que não muda o resultado: 0 para a soma, 1 para o produto, `""` para a concatenação. Ela também é o resultado de uma stream vazia. Usar 10 como "identidade" da soma funciona numa stream sequencial, dando 16, mas está errado: numa stream paralela, cada pedaço começa somando 10, e o resultado muda conforme a divisão.

A terceira forma resolve um problema de tipos. Para somar os tamanhos de uma `Stream<String>`, o acumulador recebe um `Integer` (o total) e uma `String` (o elemento), e devolve um `Integer`. O **combinador** junta dois totais parciais, e só é usado em streams paralelas, mas é obrigatório na assinatura.

> [!PROVA]
> `reduce` com identidade devolve `T`; sem identidade, devolve `Optional<T>`. A identidade precisa ser neutra para a operação, e o acumulador precisa ser **associativo**: `(a + b) + c == a + (b + c)`. Subtração e média não são, e dão resultados errados em paralelo.

## collect e toList

`collect` monta um resultado **mutável**. A forma com três argumentos mostra como ele funciona: um fornecedor do recipiente, um acumulador que põe um elemento nele e um combinador que junta dois recipientes. A forma com um `Collector`, como `Collectors.toList()`, empacota os três, e é o assunto do [episódio 5](/assistir/pleno-t6-e05).

```java executar
import java.util.List;
import java.util.stream.Collectors;
import java.util.stream.Stream;

public class Coletas {
    public static void main(String[] args) {
        StringBuilder sb = Stream.of("x", "y", "z").collect(StringBuilder::new, StringBuilder::append, StringBuilder::append);
        System.out.println(sb);

        List<Integer> mutavel = Stream.of(1, 2).collect(Collectors.toList());
        mutavel.add(3);
        List<Integer> imutavel = Stream.of(1, 2).toList();
        try {
            imutavel.add(3);
        } catch (UnsupportedOperationException e) {
            System.out.println(mutavel + " e toList() é imutável");
        }
    }
}
```

```saida
xyz
[1, 2, 3] e toList() é imutável
```

`Stream.toList()`, do Java 16, devolve uma lista **imutável**. `Collectors.toList()` não garante nada sobre a lista, mas na prática devolve um `ArrayList`. Prefira `toList()`, a menos que precise alterar o resultado.

## forEach e forEachOrdered

`forEach` executa uma ação para cada elemento. Numa stream sequencial, segue a ordem de encontro; numa paralela, não garante ordem nenhuma. `forEachOrdered` garante a ordem mesmo em paralelo, ao custo de desempenho. A documentação lembra também que a ação de um `forEach` não deve alterar a fonte da stream: remover ou acrescentar elementos à lista que está sendo percorrida lança `ConcurrentModificationException`.

## Por baixo dos panos

O `reduce` sequencial é um laço com um acumulador: `resultado = identidade; para cada x: resultado = f(resultado, x)`. O paralelo divide a fonte em pedaços, reduz cada um a partir da identidade, em threads diferentes, e junta os parciais com o combinador. É por isso que a identidade precisa ser neutra (ela entra uma vez por pedaço) e o acumulador, associativo (os parciais são combinados numa ordem que você não controla).

Essa estrutura vem da programação funcional, onde a operação se chama *fold*, e do modelo MapReduce, com que o Google processava a web inteira em milhares de máquinas: aplicar uma função a cada item, independentemente, e combinar os resultados por uma operação associativa. Uma stream paralela é um MapReduce em miniatura, dentro de uma única JVM.

## Resumo para a prova

- `count` devolve `long`; `min`, `max`, `findFirst` e `findAny` devolvem `Optional`
- Stream vazia: `anyMatch` dá `false`; `allMatch` e `noneMatch` dão `true`
- `reduce(identidade, acc)` devolve `T`; `reduce(acc)` devolve `Optional<T>`; a forma de três argumentos muda o tipo
- A identidade deve ser neutra e o acumulador, associativo
- `toList()` é imutável; `Collectors.toList()` costuma ser mutável
- `forEach` não garante ordem em paralelo; `forEachOrdered` garante
