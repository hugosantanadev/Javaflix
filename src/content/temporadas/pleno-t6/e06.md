O último episódio da temporada junta três assuntos que vão além do pipeline básico. O `flatMap` achata estruturas aninhadas. Os streams **paralelos** dividem o trabalho entre os núcleos do processador, com regras que, se ignoradas, produzem resultados errados. E os **gatherers**, do Java 24, permitem criar operações intermediárias novas, algo que a API não oferecia até então; eles são cobrados só na prova 1Z0-831.

## flatMap: de muitos para um

`map` transforma cada elemento em **um** elemento. Quando a transformação produz vários (uma lista, as palavras de uma frase), `map` gera uma stream de streams, ou de listas. `flatMap` recebe uma função que devolve uma `Stream` e **concatena** todas elas numa só:

```java executar
import java.util.Arrays;
import java.util.List;
import java.util.stream.Stream;

public class Achatando {
    public static void main(String[] args) {
        List<List<Integer>> listas = List.of(List.of(1, 2), List.of(), List.of(3));
        System.out.println(listas.stream().map(List::size).toList() + " " + listas.stream().flatMap(List::stream).toList());
        System.out.println(Stream.of("a b", "c").flatMap(s -> Arrays.stream(s.split(" "))).toList());
        System.out.println(Stream.of(1, 2, 3).flatMap(n -> Stream.of(n, n * 10)).toList());
        System.out.println(Stream.of("ab", "c").flatMapToInt(String::chars).count());
    }
}
```

```saida
[2, 0, 1] [1, 2, 3]
[a, b, c]
[1, 10, 2, 20, 3, 30]
3
```

A lista vazia simplesmente não contribui com nada. Existem também `flatMapToInt`, `flatMapToLong` e `flatMapToDouble`, que achatam em streams primitivas, e o `flatMap` do [Optional](/assistir/pleno-t6-e03) segue a mesma ideia. O `mapMulti` do [episódio 1](/assistir/pleno-t6-e01) é uma alternativa mais eficiente quando cada elemento gera poucos valores.

## Streams paralelos

`colecao.parallelStream()` ou `stream.parallel()` transformam o pipeline em paralelo: a fonte é dividida em pedaços, processados ao mesmo tempo por várias threads do `ForkJoinPool` comum, e os resultados são combinados. `sequential()` volta ao modo sequencial, e `isParallel()` informa o modo. O modo vale para o pipeline **inteiro**: o último `parallel()` ou `sequential()` chamado decide.

```java executar
import java.util.List;
import java.util.stream.Collectors;
import java.util.stream.IntStream;
import java.util.stream.Stream;

public class Paralelos {
    public static void main(String[] args) {
        System.out.println(IntStream.rangeClosed(1, 1000).parallel().sum());
        System.out.println(IntStream.rangeClosed(1, 5).parallel().boxed().toList() + " " + Stream.of("a", "b", "c").parallel().collect(Collectors.joining()));
        System.out.println(List.of(1, 2, 3, 4, 5).parallelStream().filter(n -> n > 2).findFirst().get());
        System.out.println(Stream.of(1, 2, 3).parallel().isParallel() + " " + Stream.of(1, 2, 3).parallel().sequential().isParallel());

        StringBuilder ordem = new StringBuilder();
        IntStream.range(0, 5).parallel().forEachOrdered(ordem::append);
        System.out.println(ordem);
    }
}
```

```saida
500500
[1, 2, 3, 4, 5] abc
3
true false
01234
```

O resultado é previsível quando a operação respeita a **ordem de encontro**: `toList`, `collect`, `findFirst`, `reduce` com operação associativa e `forEachOrdered` dão o mesmo resultado em paralelo e em sequência. Outras operações não garantem:

| Operação | Em paralelo |
|---|---|
| `forEach` | Ordem imprevisível |
| `findAny` | Pode devolver qualquer elemento |
| `reduce` com operação não associativa, como subtração | Resultado errado e variável |
| `reduce` com identidade não neutra | Resultado errado e variável |
| Lambda que altera uma variável ou coleção compartilhada | Condição de corrida |

> [!PROVA]
> `parallelStream()` e `parallel()` podem mudar a **ordem** de `forEach` e o resultado de `findAny`, mas não o de `findFirst`, `toList` ou `forEachOrdered`. `reduce` em paralelo exige identidade neutra e acumulador associativo e sem estado. Uma questão que imprime com `forEach` num stream paralelo não tem saída única.

Paralelizar nem sempre acelera. Dividir o trabalho, coordenar threads e combinar resultados custa caro, e só compensa com muitos elementos e muito trabalho por elemento. Fontes que se dividem bem, como `ArrayList` e arrays, ajudam; `LinkedList` e `Stream.iterate` se dividem mal. Operações que dependem da ordem, como `limit` e `sorted`, ficam mais caras em paralelo. Na dúvida, meça.

## Gatherers: operações intermediárias sob medida

Até o Java 23, só a terminal era extensível: qualquer um podia escrever um `Collector`, mas as intermediárias eram as que a API trazia. A JEP 485, final no Java 24, criou o `Gatherer`, a versão intermediária do coletor, usada com `stream.gather(...)`. A classe `Gatherers` traz cinco prontos:

| Gatherer | O que faz |
|---|---|
| `windowFixed(n)` | Agrupa em listas de `n` elementos (a última pode ser menor) |
| `windowSliding(n)` | Janelas de `n` elementos que andam de um em um |
| `fold(inicial, f)` | Reduz tudo a um único valor, emitido no fim |
| `scan(inicial, f)` | Emite cada resultado parcial de uma acumulação |
| `mapConcurrent(n, f)` | Aplica `f` em até `n` threads virtuais ao mesmo tempo, mantendo a ordem |

```java executar java25
import java.util.stream.Gatherer;
import java.util.stream.Gatherers;
import java.util.stream.Stream;

public class Coletas {
    public static void main(String[] args) {
        System.out.println(Stream.of(1, 2, 3, 4, 5).gather(Gatherers.windowFixed(2)).toList());
        System.out.println(Stream.of(1, 2, 3, 4).gather(Gatherers.windowSliding(3)).toList());
        System.out.println(Stream.of(1, 2, 3, 4).gather(Gatherers.scan(() -> 0, Integer::sum)).toList());
        System.out.println(Stream.of(1, 2, 3, 4).gather(Gatherers.fold(() -> "", (acc, n) -> acc + n)).toList());

        Gatherer<Integer, ?, Integer> soPares = Gatherer.of((estado, n, saida) -> {
            if (n % 2 == 0) {
                return saida.push(n);
            }
            return true;
        });
        System.out.println(Stream.of(1, 2, 3, 4).gather(soPares).toList());
    }
}
```

```saida
[[1, 2], [3, 4], [5]]
[[1, 2, 3], [2, 3, 4]]
[1, 3, 6, 10]
[1234]
[2, 4]
```

Um gatherer próprio recebe cada elemento e um `Downstream`, a saída, para a qual pode empurrar zero, um ou vários valores com `push`. Ele devolve `false` para encerrar a stream mais cedo, como faz o `limit`. Um gatherer também pode ter estado, criado por um inicializador, e uma etapa de finalização, que emite o que sobrou; é assim que `windowFixed` entrega a última janela incompleta.

> [!VERSAO]
> `Stream.gather` e a classe `Gatherers` existem a partir do Java 24 (prévia nos 22 e 23). No Java 17 e no 21, não compilam. Entre as provas, só a 1Z0-831 os cobra.

## Por baixo dos panos

O paralelismo se apoia em dois mecanismos. O `Spliterator` (de *split* e *iterator*) da fonte sabe se dividir em duas metades com `trySplit`, recursivamente, até os pedaços ficarem pequenos. Um `ArrayList` divide pelo índice do meio, em tempo constante; uma `LinkedList` precisa percorrer os nós para achar o meio. Os pedaços viram tarefas do **ForkJoinPool comum**, um conjunto de threads, em geral uma a menos que o número de núcleos, que usa *roubo de trabalho*: uma thread ociosa pega tarefas da fila de outra.

Como todas as streams paralelas do programa dividem o mesmo `ForkJoinPool`, uma operação lenta ou bloqueante, como uma chamada de rede dentro de um `map`, prende threads que outras streams esperavam usar. Para tarefas de entrada e saída, o caminho é outro: threads virtuais, da [temporada de threads](/assistir/senior-t1-e05), ou o próprio `mapConcurrent`, que as usa por baixo.

## Resumo para a prova

- `flatMap` recebe uma função que devolve `Stream` e concatena tudo; listas vazias somem
- `parallelStream()` / `parallel()`; o último `parallel`/`sequential` vale para o pipeline todo
- Em paralelo: `forEach` e `findAny` sem ordem garantida; `forEachOrdered`, `findFirst` e `toList` mantêm a ordem
- `reduce` paralelo exige identidade neutra e acumulador associativo e sem estado
- Gatherers (Java 24): `stream.gather(...)`, com `windowFixed`, `windowSliding`, `fold`, `scan` e `mapConcurrent`
- Um `Gatherer` empurra zero ou mais valores para o `Downstream` e pode encerrar a stream devolvendo `false`
