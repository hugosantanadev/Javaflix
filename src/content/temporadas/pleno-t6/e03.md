Tony Hoare, que inventou a referência nula em 1965, chamou-a depois de seu "erro de um bilhão de dólares". Em Java, um método que devolve `null` para dizer "não encontrei" deixa a quem chama a obrigação de lembrar de conferir, e o esquecimento vira `NullPointerException`. O `Optional`, do Java 8, torna a ausência explícita no **tipo**: um `Optional<Cliente>` avisa, já na assinatura, que talvez não haja cliente. Os streams o usam em `findFirst`, `min`, `max` e `reduce`.

## Criando e consultando

| Método | O que faz |
|---|---|
| `Optional.of(x)` | Embrulha `x`; com `null`, lança `NullPointerException` |
| `Optional.ofNullable(x)` | Embrulha `x`, ou devolve vazio se for `null` |
| `Optional.empty()` | Um `Optional` vazio |
| `isPresent()` / `isEmpty()` (Java 11) | Testam se há valor |
| `get()` / `orElseThrow()` (Java 10) | Devolvem o valor ou lançam `NoSuchElementException` |

```java executar
import java.util.NoSuchElementException;
import java.util.Optional;

public class Criando {
    public static void main(String[] args) {
        Optional<String> cheio = Optional.of("java");
        Optional<String> vazio = Optional.empty();
        Optional<String> talvez = Optional.ofNullable(null);
        System.out.println(cheio + " " + vazio + " " + talvez);
        System.out.println(cheio.isPresent() + " " + vazio.isEmpty() + " " + cheio.get());
        try {
            vazio.get();
        } catch (NoSuchElementException e) {
            System.out.println(e.getMessage());
        }
        try {
            Optional.of(null);
        } catch (NullPointerException e) {
            System.out.println("Optional.of(null) não é permitido");
        }
    }
}
```

```saida
Optional[java] Optional.empty Optional.empty
true true java
No value present
Optional.of(null) não é permitido
```

`get()` num `Optional` vazio é tão perigoso quanto a referência nula que ele substitui. O nome `orElseThrow()`, do Java 10, faz o mesmo e deixa claro que pode lançar. Os métodos das próximas seções evitam os dois.

## Valores alternativos: orElse e orElseGet

| Método | Se estiver vazio |
|---|---|
| `orElse(valor)` | Devolve `valor` |
| `orElseGet(Supplier)` | Chama o fornecedor e devolve o resultado |
| `orElseThrow(Supplier)` | Lança a exceção criada pelo fornecedor |
| `or(Supplier<Optional>)` (Java 9) | Devolve outro `Optional` |

A diferença entre `orElse` e `orElseGet` é a pegadinha mais famosa: o argumento de `orElse` é avaliado **sempre**, mesmo quando o `Optional` tem valor, porque é um argumento comum de método. O `Supplier` de `orElseGet` só é chamado se faltar valor.

```java executar
import java.util.Optional;

public class Alternativas {
    static String padraoCaro() {
        System.out.print("[calculando] ");
        return "padrão";
    }

    public static void main(String[] args) {
        Optional<String> cheio = Optional.of("java");
        Optional<String> vazio = Optional.empty();
        System.out.println(cheio.orElse(padraoCaro()));
        System.out.println(cheio.orElseGet(Alternativas::padraoCaro));
        System.out.println(vazio.orElseGet(Alternativas::padraoCaro));
        System.out.println(vazio.or(() -> Optional.of("plano B")).get());
        try {
            vazio.orElseThrow(() -> new IllegalStateException("configuração ausente"));
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

```saida
[calculando] java
java
[calculando] padrão
plano B
configuração ausente
```

## Transformando sem abrir

`map`, `filter` e `flatMap` trabalham **dentro** do `Optional`: se houver valor, aplicam a função; se não, devolvem vazio, sem nunca lançar exceção. Encadear essas operações substitui uma escada de `if (x != null)`.

```java executar
import java.util.Optional;

public class Transformando {
    record Endereco(String cidade) { }

    record Cliente(String nome, Endereco endereco) {
        Optional<Endereco> enderecoOpcional() {
            return Optional.ofNullable(endereco);
        }
    }

    public static void main(String[] args) {
        Optional<String> nome = Optional.of("java");
        System.out.println(nome.map(String::length) + " " + nome.filter(s -> s.startsWith("x")) + " " + nome.map(s -> null));

        Cliente ana = new Cliente("Ana", new Endereco("Recife"));
        Cliente bia = new Cliente("Bia", null);
        for (Cliente c : new Cliente[] {ana, bia}) {
            String cidade = Optional.of(c)
                .flatMap(Cliente::enderecoOpcional)
                .map(Endereco::cidade)
                .orElse("sem endereço");
            System.out.println(c.nome() + ": " + cidade);
        }
        System.out.println(Optional.of(ana).map(Cliente::enderecoOpcional));

        nome.ifPresent(s -> System.out.print("tem " + s + "; "));
        Optional.empty().ifPresentOrElse(s -> System.out.print("tem"), () -> System.out.print("não tem"));
        System.out.println();
    }
}
```

```saida
Optional[4] Optional.empty Optional.empty
Ana: Recife
Bia: sem endereço
Optional[Optional[Endereco[cidade=Recife]]]
tem java; não tem
```

`map` com uma função que devolve `null` produz um `Optional` vazio, sem exceção. E quando a função já devolve um `Optional`, `map` embrulha de novo, criando um `Optional<Optional<...>>`; `flatMap` evita a camada extra, como mostra a penúltima linha.

> [!PROVA]
> `Optional.of(null)` lança `NullPointerException`; `ofNullable(null)` dá vazio. `get()` e `orElseThrow()` num vazio lançam `NoSuchElementException`. O argumento de `orElse` sempre é avaliado; o de `orElseGet`, só se faltar valor. `map` com retorno `null` dá vazio, e `map` com retorno `Optional` aninha.

## Optional nos streams e versões primitivas

`Optional.stream()` (Java 9) transforma o `Optional` numa stream de zero ou um elemento, útil para descartar os vazios de uma stream de opcionais. Os streams primitivos usam `OptionalInt`, `OptionalLong` e `OptionalDouble`, com `getAsInt()` e afins:

```java executar
import java.util.Optional;
import java.util.OptionalDouble;
import java.util.OptionalInt;
import java.util.stream.IntStream;
import java.util.stream.Stream;

public class NosStreams {
    public static void main(String[] args) {
        System.out.println(Stream.of(Optional.of(1), Optional.<Integer>empty(), Optional.of(3)).flatMap(Optional::stream).toList());
        OptionalInt maior = IntStream.of(3, 9).max();
        OptionalDouble media = IntStream.empty().average();
        System.out.println(maior + " " + maior.getAsInt() + " " + media + " " + media.orElse(-1));
    }
}
```

```saida
[1, 3]
OptionalInt[9] 9 OptionalDouble.empty -1.0
```

## Por baixo dos panos

Um `Optional` é só um objeto com um campo `value`, que pode ser `null`. `Optional.empty()` devolve sempre o mesmo objeto, `EMPTY`. A classe é *value-based*, como as de `java.time`: não use `==` nem sincronize nela.

Brian Goetz, que a projetou, explica o uso pretendido: o `Optional` é para **tipos de retorno** que podem não ter resultado. Ele não é `Serializable` de propósito, e a recomendação é não usá-lo como campo, como parâmetro de método nem dentro de coleções, onde uma coleção vazia já expressa a ausência. Por isso o exemplo acima guarda o endereço como campo comum e oferece `enderecoOpcional()` para quem consulta. Stuart Marks resumiu a regra numa palestra famosa: o `Optional` existe para limitar o uso de `null` em retornos, não para eliminar todo `null` do programa.

## Resumo para a prova

- `of` exige valor; `ofNullable` aceita `null`; `empty` cria vazio
- `get`/`orElseThrow()` lançam `NoSuchElementException` no vazio
- `orElse` sempre avalia o argumento; `orElseGet` e `orElseThrow(Supplier)` só quando vazio
- `map`, `filter` e `flatMap` operam dentro do `Optional`; `flatMap` evita `Optional<Optional<T>>`
- `ifPresent`, `ifPresentOrElse` e `or` (Java 9); `isEmpty` (Java 11)
- Primitivos: `OptionalInt.getAsInt()`, `OptionalDouble.getAsDouble()`
