Uma `Stream<Integer>` guarda cada número num objeto `Integer`, e não tem `sum()`: a interface `Stream<T>` não sabe somar um `T` qualquer. Para números, o Java oferece três streams especializadas, `IntStream`, `LongStream` e `DoubleStream`, que trabalham com primitivos, sem autoboxing, e trazem as operações matemáticas prontas. Este episódio cobre as conversões entre os dois mundos e os tipos de retorno, que a prova adora trocar.

## As três streams primitivas

| Stream | Elementos | `sum()` | `average()` | `min()` / `max()` |
|---|---|---|---|---|
| `IntStream` | `int` (e `char`, `short`, `byte` promovidos) | `int` | `OptionalDouble` | `OptionalInt` |
| `LongStream` | `long` | `long` | `OptionalDouble` | `OptionalLong` |
| `DoubleStream` | `double` (e `float` promovido) | `double` | `OptionalDouble` | `OptionalDouble` |

Repare: `average()` devolve sempre `OptionalDouble`, mesmo num `IntStream`, porque a média de inteiros pode ser fracionária e a stream pode estar vazia. E `sum()` de uma stream vazia é 0, não um opcional, porque 0 é a identidade da soma.

```java executar
import java.util.stream.DoubleStream;
import java.util.stream.IntStream;
import java.util.stream.LongStream;

public class Primitivas {
    public static void main(String[] args) {
        System.out.println(IntStream.of(3, 1, 4, 1, 5).sum() + " " + IntStream.of(3, 1, 4, 1, 5).average() + " " + IntStream.of(3, 1, 4).max());
        System.out.println(IntStream.empty().sum() + " " + IntStream.empty().max() + " " + IntStream.of(1, 2).average().getAsDouble());
        System.out.println(DoubleStream.of(1.5, 2.5).sum() + " " + LongStream.rangeClosed(1, 20).reduce(1, (x, y) -> x * y));
        System.out.println(IntStream.iterate(1, i -> i * 2).limit(5).sum() + " " + IntStream.of(1, 2, 3).map(i -> i * i).sum());
    }
}
```

```saida
14 OptionalDouble[2.8] OptionalInt[4]
0 OptionalInt.empty 1.5
4.0 2432902008176640000
31 14
```

O fatorial de 20 cabe num `long`, mas não num `int`: com `IntStream`, o resultado estouraria em silêncio.

## Convertendo entre os mundos

| De | Para | Método |
|---|---|---|
| `Stream<T>` | `IntStream` | `mapToInt(ToIntFunction)` |
| `IntStream` | `Stream<Integer>` | `boxed()` |
| `IntStream` | `Stream<U>` | `mapToObj(IntFunction)` |
| `IntStream` | `LongStream` / `DoubleStream` | `asLongStream()` / `asDoubleStream()` ou `mapToLong` / `mapToDouble` |
| `IntStream` | `IntStream` | `map(IntUnaryOperator)` |

O detalhe que derruba: `map` numa stream primitiva continua no mesmo tipo. `IntStream.map` recebe um `IntUnaryOperator` e devolve outro `IntStream`; para sair para objetos, é `mapToObj` ou `boxed`. E `Stream<Integer>` não tem `sum()`: é preciso `mapToInt` primeiro.

```java executar
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;
import java.util.stream.IntStream;

public class Conversoes {
    public static void main(String[] args) {
        List<String> nomes = List.of("Ana", "Beatriz", "Caio");
        System.out.println(nomes.stream().mapToInt(String::length).sum() + " " + nomes.stream().mapToInt(String::length).max().getAsInt());
        System.out.println(IntStream.range(0, 3).mapToObj(i -> "#" + i).toList() + " " + IntStream.rangeClosed(1, 3).boxed().toList());
        System.out.println(IntStream.of(1, 2).asDoubleStream().sum() + " " + IntStream.of(1, 2).mapToLong(i -> i * 1_000_000_000L).sum());
        System.out.println("abc".chars().mapToObj(c -> (char) c).toList() + " " + "abc".chars().map(c -> c - 'a').boxed().toList());

        int[] ordenados = IntStream.of(3, 1, 2).sorted().toArray();
        System.out.println(Arrays.toString(ordenados) + " " + IntStream.of(1, 2, 3).mapToObj(Integer::toString).collect(Collectors.joining("+")) + "=" + IntStream.of(1, 2, 3).sum());
    }
}
```

```saida
14 7
[#0, #1, #2] [1, 2, 3]
3.0 3000000000
[a, b, c] [0, 1, 2]
[1, 2, 3] 1+2+3=6
```

`"abc".chars()` devolve um `IntStream` com os códigos dos caracteres; para tê-los como `Character`, é preciso o cast dentro do `mapToObj`.

## Estatísticas de uma vez

`summaryStatistics()` percorre a stream uma única vez e calcula contagem, soma, mínimo, máximo e média juntos, num `IntSummaryStatistics` (ou nas versões `Long` e `Double`):

```java executar
import java.util.IntSummaryStatistics;
import java.util.stream.IntStream;

public class Estatisticas {
    public static void main(String[] args) {
        IntSummaryStatistics s = IntStream.of(3, 1, 4, 1, 5).summaryStatistics();
        System.out.println(s.getCount() + " " + s.getSum() + " " + s.getMin() + " " + s.getMax() + " " + s.getAverage());

        IntSummaryStatistics vazio = IntStream.empty().summaryStatistics();
        System.out.println(vazio.getCount() + " " + vazio.getAverage() + " " + vazio.getMin() + " " + vazio.getMax());
    }
}
```

```saida
5 14 1 5 2.8
0 0.0 2147483647 -2147483648
```

Numa stream vazia, as estatísticas não lançam exceção: a média é 0.0, e o mínimo e o máximo ficam com `Integer.MAX_VALUE` e `Integer.MIN_VALUE`, os valores iniciais de quem procura um mínimo e um máximo. Confira `getCount()` antes de confiar neles.

> [!PROVA]
> `Stream<Integer>` não tem `sum`, `average` nem `max()` sem comparador: use `mapToInt`. `IntStream.map` devolve `IntStream`; `mapToObj` e `boxed` voltam para objetos. `average()` sempre devolve `OptionalDouble`; `sum()` devolve o primitivo, 0 se vazia. `max()` de `IntStream` dispensa comparador e devolve `OptionalInt`.

## Por baixo dos panos

A diferença de desempenho é real. Somar um milhão de números numa `Stream<Integer>` cria até um milhão de objetos `Integer`, cada um com cabeçalho e um campo, espalhados pelo heap, e cada soma desembala dois e embala um novo. O `IntStream` trabalha com `int` direto, guardados em registradores da CPU, e o JIT consegue até vetorizar o laço, somando vários números por instrução com SIMD.

Por que só três tipos? Cada especialização multiplica a API: `IntStream` tem as suas versões de `map`, `filter`, `reduce` e das interfaces funcionais, como `IntPredicate` e `IntUnaryOperator`, vistas na [temporada de lambdas](/assistir/pleno-t5-e02). Fazer o mesmo para `short`, `byte`, `char`, `float` e `boolean` teria triplicado o tamanho do pacote, e por isso esses tipos são promovidos para `int` ou `double`. É o mesmo problema que o Projeto Valhalla quer resolver para os generics em geral.

## Resumo para a prova

- `IntStream`, `LongStream`, `DoubleStream`; `char`, `short` e `byte` viram `int`, `float` vira `double`
- `sum()` devolve primitivo (0 se vazia); `average()` sempre `OptionalDouble`; `min`/`max` devolvem `OptionalInt` e afins
- `mapToInt`, `mapToLong`, `mapToDouble` entram; `boxed` e `mapToObj` saem; `map` mantém o tipo
- `Stream<Integer>` não tem `sum()`
- `summaryStatistics()` calcula tudo numa passada; vazia, tem média 0.0 e mínimo `MAX_VALUE`
- `range` exclui o fim; `rangeClosed` inclui
