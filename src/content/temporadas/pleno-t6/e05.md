A operação terminal mais poderosa é o `collect`, e a classe `Collectors` é a caixa de ferramentas dele: transformar uma stream em lista, conjunto, mapa ou texto, contar, somar, tirar médias e, principalmente, **agrupar**. Um `groupingBy` faz em uma linha o que antes exigia um mapa, um laço e vários `if`. A prova cobra os tipos devolvidos por cada coletor, e eles são a fonte da maioria dos erros.

## Coletores simples

| Coletor | Resultado |
|---|---|
| `toList()`, `toSet()`, `toUnmodifiableList()` | Coleções |
| `toCollection(TreeSet::new)` | A coleção que você escolher |
| `joining()`, `joining(sep)`, `joining(sep, prefixo, sufixo)` | `String` |
| `counting()` | `Long` |
| `summingInt`, `averagingInt` e afins | `Integer` / `Double` |
| `minBy(Comparator)`, `maxBy(Comparator)` | `Optional<T>` |
| `summarizingInt` | `IntSummaryStatistics` |
| `toMap(chave, valor)` | `Map` |

```java executar
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.TreeMap;
import java.util.TreeSet;
import java.util.stream.Collectors;
import java.util.stream.Stream;

public class Simples {
    record Aluno(String nome, String turma, int nota) { }

    public static void main(String[] args) {
        List<Aluno> alunos = List.of(new Aluno("Ana", "A", 9), new Aluno("Bia", "B", 6), new Aluno("Caio", "A", 7),
            new Aluno("Davi", "B", 4), new Aluno("Eva", "A", 10));

        System.out.println(Stream.of("a", "b", "c").collect(Collectors.joining(", ", "[", "]")) + " " + Stream.<String>empty().collect(Collectors.joining(",", "<", ">")));
        System.out.println(alunos.stream().collect(Collectors.counting()) + " " + alunos.stream().collect(Collectors.summingInt(Aluno::nota)) + " " + alunos.stream().collect(Collectors.averagingInt(Aluno::nota)));
        Set<String> turmas = alunos.stream().map(Aluno::turma).collect(Collectors.toCollection(TreeSet::new));
        System.out.println(turmas);

        Map<String, Integer> contagem = Stream.of("a", "b", "a").collect(Collectors.toMap(s -> s, s -> 1, Integer::sum, TreeMap::new));
        System.out.println(contagem);
        try {
            Stream.of("a", "b", "a").collect(Collectors.toMap(s -> s, s -> 1));
        } catch (IllegalStateException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

```saida
[a, b, c] <>
5 36 7.2
[A, B]
{a=2, b=1}
Duplicate key a (attempted merging values 1 and 1)
```

`joining` com prefixo e sufixo os mantém até numa stream vazia. `counting` devolve `Long`, e `averagingInt` devolve `Double`, mesmo com notas inteiras. E o `toMap` simples lança `IllegalStateException` ao encontrar uma chave repetida; a versão com uma **função de mesclagem** como terceiro argumento resolve o conflito, e a com um quarto argumento escolhe o tipo do mapa.

## groupingBy: agrupando

`groupingBy(classificador)` cria um `Map` em que a chave é o resultado do classificador e o valor é a lista dos elementos com aquela chave. Duas versões a mais permitem escolher o tipo do mapa e o que fazer com cada grupo, o **coletor de baixo** (*downstream*):

| Forma | Resultado |
|---|---|
| `groupingBy(f)` | `Map<K, List<T>>`, um `HashMap` |
| `groupingBy(f, coletor)` | `Map<K, D>`, com cada grupo coletado pelo coletor |
| `groupingBy(f, TreeMap::new, coletor)` | O mapa que você escolher |

```java executar
import java.util.Comparator;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class Agrupando {
    record Aluno(String nome, String turma, int nota) { }

    public static void main(String[] args) {
        List<Aluno> alunos = List.of(new Aluno("Ana", "A", 9), new Aluno("Bia", "B", 6), new Aluno("Caio", "A", 7),
            new Aluno("Davi", "B", 4), new Aluno("Eva", "A", 10));

        Map<String, List<String>> nomes = alunos.stream()
            .collect(Collectors.groupingBy(Aluno::turma, TreeMap::new, Collectors.mapping(Aluno::nome, Collectors.toList())));
        Map<String, Long> quantos = alunos.stream()
            .collect(Collectors.groupingBy(Aluno::turma, TreeMap::new, Collectors.counting()));
        Map<String, Double> medias = alunos.stream()
            .collect(Collectors.groupingBy(Aluno::turma, TreeMap::new, Collectors.averagingInt(Aluno::nota)));
        Map<String, String> melhor = alunos.stream()
            .collect(Collectors.groupingBy(Aluno::turma, TreeMap::new,
                Collectors.collectingAndThen(Collectors.maxBy(Comparator.comparingInt(Aluno::nota)), o -> o.get().nome())));
        Map<String, Long> aprovados = alunos.stream()
            .collect(Collectors.groupingBy(Aluno::turma, TreeMap::new, Collectors.filtering(a -> a.nota() >= 7, Collectors.counting())));

        System.out.println(nomes);
        System.out.println(quantos + " " + medias);
        System.out.println(melhor + " " + aprovados);
    }
}
```

```saida
{A=[Ana, Caio, Eva], B=[Bia, Davi]}
{A=3, B=2} {A=8.666666666666666, B=5.0}
{A=Eva, B=Bia} {A=3, B=0}
```

Os coletores de baixo se encaixam como peças: `mapping` transforma cada elemento antes de coletar, `filtering` (Java 9) filtra dentro do grupo, `collectingAndThen` aplica uma função ao resultado final. Repare em `aprovados`: com `filtering`, a turma B aparece com 0. Um `filter` antes do `groupingBy` teria feito a turma B sumir do mapa.

Os exemplos usam `TreeMap::new` para que a saída tenha ordem. O `groupingBy` simples devolve um `HashMap`, sem ordem garantida.

## partitioningBy: dois grupos

`partitioningBy(predicado)` é um agrupamento com chave `boolean`. A diferença para `groupingBy(predicado)` é que o mapa **sempre** tem as duas chaves, `false` e `true`, mesmo que um dos lados fique vazio:

```java executar
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;
import java.util.stream.Stream;

public class Particionando {
    public static void main(String[] args) {
        Map<Boolean, List<Integer>> pares = Stream.of(1, 3, 5).collect(Collectors.partitioningBy(n -> n % 2 == 0));
        System.out.println(pares);
        Map<Boolean, Long> longas = Stream.of("sol", "estrela", "lua", "planeta").collect(Collectors.partitioningBy(s -> s.length() > 3, Collectors.counting()));
        System.out.println(longas);
    }
}
```

```saida
{false=[1, 3, 5], true=[]}
{false=2, true=2}
```

> [!PROVA]
> Tipos que caem: `counting()` dá `Long`; `averagingX` dá `Double`; `minBy`/`maxBy` dão `Optional`; `groupingBy(f)` dá `Map<K, List<T>>`; `partitioningBy` dá `Map<Boolean, ...>` com as duas chaves sempre presentes. `toMap` com chave repetida, sem função de mesclagem, lança `IllegalStateException`.

## Quando a inferência se perde

Um detalhe prático: passar um `collect` com `TreeMap::new` direto para o `System.out.println` pode não compilar. O `println` tem várias sobrecargas, e o compilador não consegue decidir o tipo do resultado. Guardar o resultado numa variável com o tipo declarado, como nos exemplos acima, resolve. É o mesmo problema de tipo-alvo da [temporada de lambdas](/assistir/pleno-t5-e01).

## Por baixo dos panos

Um `Collector` é um objeto com quatro funções: um `supplier`, que cria o recipiente vazio; um `accumulator`, que põe um elemento no recipiente; um `combiner`, que junta dois recipientes (para o paralelismo); e um `finisher`, que transforma o recipiente no resultado. São exatamente as três peças do `collect` de três argumentos do [episódio 2](/assistir/pleno-t6-e02), mais o acabamento. Um `groupingBy` com coletor de baixo é um coletor que cria um mapa e, para cada chave nova, chama o `supplier` do coletor de baixo; no fim, aplica o `finisher` de baixo em cada valor.

`Collectors.teeing`, do Java 12, completa o jogo: ele envia cada elemento a **dois** coletores ao mesmo tempo e junta os resultados, por exemplo o menor e o maior numa só passada. Com essas peças, é possível escrever seu próprio coletor, implementando a interface ou usando `Collector.of`.

## Resumo para a prova

- `toList`, `toSet`, `toCollection`, `joining`, `counting` (`Long`), `averagingX` (`Double`), `minBy`/`maxBy` (`Optional`)
- `toMap` exige chaves únicas, a menos que receba uma função de mesclagem
- `groupingBy(f)` cria `Map<K, List<T>>` num `HashMap`; com fábrica, outro mapa; com coletor de baixo, outro valor
- `mapping`, `filtering`, `flatMapping` e `collectingAndThen` montam o valor de cada grupo
- `partitioningBy` sempre tem as chaves `false` e `true`
- Um `Collector` é `supplier`, `accumulator`, `combiner` e `finisher`
