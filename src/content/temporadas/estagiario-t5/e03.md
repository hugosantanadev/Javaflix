Se `String` é imutável, montar um texto em pedaços (um relatório, um JSON, um CSV) cria um objeto novo a cada concatenação. O `StringBuilder` é a versão **mutável**: um buffer de caracteres que cresce e é alterado no lugar. Este episódio mostra os métodos que a prova cobra, a diferença de comportamento em relação à `String` (inclusive no `equals`) e por que ele faz tanta diferença dentro de laços.

## Mutável e encadeável

Os métodos de alteração do `StringBuilder` modificam o próprio objeto **e devolvem o próprio objeto** (`this`). Isso permite encadear chamadas, mas também significa que duas variáveis podem apontar para o mesmo buffer:

```java executar
StringBuilder sb = new StringBuilder("java");
sb.append("flix").insert(0, "[").append("]");
System.out.println(sb);
StringBuilder outro = sb;
outro.reverse();
System.out.println(sb);
System.out.println(sb == outro);
```

```saida
[javaflix]
]xilfavaj[
true
```

Ao contrário da `String`, chamar um método e ignorar o retorno **altera** o objeto: o `outro.reverse()` inverteu o mesmo buffer que `sb` usa.

## Os métodos

| Método | Faz |
|---|---|
| `append(x)` | acrescenta no fim; aceita qualquer tipo |
| `insert(pos, x)` | insere a partir da posição |
| `delete(inicio, fim)` | remove do `inicio` até o `fim` (**excluído**) |
| `deleteCharAt(pos)` | remove um caractere |
| `replace(inicio, fim, texto)` | troca o trecho `[inicio, fim)` pelo texto |
| `reverse()` | inverte |
| `setCharAt(pos, c)` / `setLength(n)` | troca um caractere / corta ou estende o tamanho |
| `length()`, `charAt(i)`, `indexOf(s)` | iguais aos de `String` |
| `substring(...)` | devolve uma **`String`** nova; não altera o buffer |
| `toString()` | devolve uma `String` com o conteúdo atual |

```java executar
StringBuilder sb = new StringBuilder("0123456789");
sb.delete(2, 5);
System.out.println(sb);
sb.deleteCharAt(0);
System.out.println(sb);
sb.replace(1, 3, "ABC");
System.out.println(sb);
sb.setCharAt(0, '*');
System.out.println(sb + " " + sb.length());
String parte = sb.substring(1, 4);
System.out.println(parte + " " + sb);
```

```saida
0156789
156789
1ABC789
*ABC789 7
ABC *ABC789
```

Repare que o `replace` do `StringBuilder` trabalha com **posições** (`replace(1, 3, "ABC")` troca as posições 1 e 2), enquanto o `replace` da `String` troca **texto** por texto. E o `substring` é a exceção da tabela: devolve uma `String` e deixa o buffer como estava.

## `equals` não compara o conteúdo

`StringBuilder` não sobrescreve o `equals` herdado de `Object`, que compara **referências**. Dois buffers com o mesmo texto não são "iguais":

```java executar
StringBuilder a = new StringBuilder("ok");
StringBuilder b = new StringBuilder("ok");
System.out.println(a.equals(b));
System.out.println(a.toString().equals(b.toString()));
System.out.println(a.compareTo(b) == 0);
System.out.println("ok".contentEquals(a));
```

```saida
false
true
true
true
```

Para comparar conteúdo, converta com `toString()`, use `compareTo` (Java 11) ou `String.contentEquals`. A mesma regra vale para colocar um `StringBuilder` num `HashSet`: dois buffers iguais por conteúdo contam como elementos diferentes.

> [!PROVA]
> Atribuições entre os tipos não são automáticas: `StringBuilder sb = "abc";` e `String s = sb;` não compilam. Use `new StringBuilder("abc")` e `sb.toString()`. Já o `+` com um `StringBuilder` funciona, porque a concatenação chama `toString()` sozinha.

## Capacidade

Por dentro, o `StringBuilder` guarda um array com folga, a **capacidade**, para não precisar realocar a cada `append`. A capacidade inicial é 16 (ou 16 mais o tamanho do texto inicial), e quando o array enche, ele cresce para mais ou menos o dobro:

```java executar
StringBuilder sb = new StringBuilder();
System.out.println(sb.length() + " " + sb.capacity());
sb.append("12345678901234567");
System.out.println(sb.length() + " " + sb.capacity());
StringBuilder grande = new StringBuilder(100);
System.out.println(grande.capacity());
```

```saida
0 16
17 34
100
```

`length()` é quanto texto existe; `capacity()` é quanto cabe antes do próximo crescimento. O construtor com um `int` define a capacidade (e não o conteúdo): `new StringBuilder(100)` começa vazio. É o mesmo crescimento geométrico do `ArrayList`, com custo amortizado O(1) por `append`, que você viu no episódio de [Big-O](/assistir/aprendiz-t3-e05).

## Por que usar dentro de laços

Concatenar com `+` num laço cria uma `String` nova a cada volta e **copia tudo** o que já existia. Para juntar n pedaços, são 1 + 2 + ... + n cópias: O(n²). Com `StringBuilder`, cada `append` copia só o pedaço novo:

```java
String lento = "";
for (int i = 0; i < 100_000; i++) {
    lento += i + ",";          // copia a string inteira a cada volta
}

StringBuilder rapido = new StringBuilder();
for (int i = 0; i < 100_000; i++) {
    rapido.append(i).append(','); // copia só o pedaço novo
}
```

Com 100 mil números, a primeira versão leva segundos, e a segunda, milissegundos. Fora de laços, `+` é ótimo: numa única expressão, o compilador já otimiza a concatenação.

## `StringBuilder` ou `StringBuffer`?

O `StringBuffer` é a versão antiga, do Java 1.0, com os mesmos métodos, mas todos `synchronized`: seguros para várias threads ao mesmo tempo, e mais lentos por isso. Como um buffer quase sempre é usado por uma só thread, prefira `StringBuilder` (Java 5).

> [!VERSAO]
> **Java 21 (1Z0-830 e 1Z0-831).** `StringBuilder` ganhou `repeat`, com uma versão para texto e outra para um caractere.

```java executar java21
StringBuilder sb = new StringBuilder("ha");
sb.repeat("!", 3).repeat('-', 2);
System.out.println(sb);
```

```saida
ha!!!--
```

## Por baixo dos panos

`StringBuilder` e `StringBuffer` estendem a mesma classe interna, `AbstractStringBuilder`, que guarda um `byte[]` e um contador de quantos bytes estão em uso. Assim como a `String` desde o Java 9, o buffer começa em Latin-1 (1 byte por caractere) e só passa para UTF-16 quando alguém acrescenta um caractere que não cabe. O `toString()` copia o array: a `String` resultante precisa ser imutável, e o buffer continua podendo mudar. O crescimento usa a fórmula `(capacidade antiga × 2) + 2`, ou o tamanho necessário, se for maior.

## Resumo para a prova

- `StringBuilder` é mutável: os métodos alteram o objeto e devolvem `this`, o que permite encadear
- Duas variáveis podem apontar para o mesmo buffer; alterar por uma muda o que a outra vê
- `delete`, `replace` e `insert` trabalham com posições; `fim` é excluído
- `substring` e `toString` devolvem `String`; não alteram o buffer
- `equals` compara referências; compare conteúdo com `toString().equals`, `compareTo` ou `contentEquals`
- Não há conversão automática entre `String` e `StringBuilder` na atribuição
- Capacidade inicial 16 (ou 16 + tamanho do texto); `new StringBuilder(100)` começa vazio
- Em laços, `StringBuilder` é O(n); `+=` com `String` é O(n²)
- `StringBuffer` é a versão sincronizada e mais lenta
