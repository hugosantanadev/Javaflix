Escrever um JSON, um SQL ou um trecho de HTML numa `String` comum é um exercício de paciência: aspas escapadas, `\n` no fim de cada linha e um `+` entre elas. Os **text blocks**, do Java 15, resolvem isso com strings de várias linhas delimitadas por três aspas. O que a prova cobra é o algoritmo que decide quanto espaço à esquerda fica no resultado, e as novas sequências de escape.

## Sintaxe

Um text block começa com `"""` seguido de uma **quebra de linha**, e termina com `"""`. O conteúdo vai na linha de baixo da abertura:

```java executar
String json = """
    {
      "nome": "Ana"
    }
    """;
System.out.print(json.replace(' ', '.'));
System.out.println(json.endsWith("\n"));
```

```saida
{
.."nome":."Ana"
}
true
```

O `replace(' ', '.')` deixa os espaços visíveis: os 4 espaços que alinham o bloco com o código sumiram, e os 2 que indentam `"nome"` dentro das chaves ficaram. As aspas não precisaram de escape. E como o `"""` de fechamento está numa linha própria, o texto termina com uma quebra de linha.

O conteúdo não pode começar na mesma linha da abertura:

```java nao-compila
String s = """abc""";
```

## Espaço incidental e espaço essencial

O compilador separa o espaço à esquerda em dois tipos. O **incidental** só existe porque o bloco está indentado junto com o código; o **essencial** faz parte do texto. A regra: ele encontra a **menor indentação** entre as linhas com conteúdo **e a linha do `"""` de fechamento**, e remove essa quantidade de espaços de todas as linhas. Por isso a posição do fechamento controla a indentação do resultado:

```java executar
String a = """
        linha
    """;
String b = """
    linha
    """;
String c = """
    linha""";
System.out.println("[" + a.replace(' ', '.') + "]");
System.out.println("[" + b + "]");
System.out.println("[" + c + "]");
```

```saida
[....linha
]
[linha
]
[linha]
```

Em `a`, o fechamento está 4 espaços à esquerda do conteúdo, então só 4 dos 8 espaços são incidentais. Em `b`, os dois estão alinhados e todo o espaço some. Em `c`, o fechamento está na mesma linha do conteúdo: não há quebra de linha no fim, e a menor indentação é a da própria linha. Espaços no **fim** das linhas também são removidos sempre.

## Escapes

Os escapes de sempre (`\n`, `\t`, `\\`) continuam valendo, e os text blocks ganharam dois novos:

| Escape | Efeito |
|---|---|
| `\<quebra de linha>` | junta a linha com a próxima, sem inserir quebra |
| `\s` | um espaço que não é removido (útil no fim da linha) |
| `\"""` | três aspas dentro do bloco |

```java executar
String s = """
    Ela disse: "oi"
    três aspas: \"""
    linha \
    continuada
    espaço no fim:\s
    """;
System.out.print(s.replace(' ', '.'));
```

```saida
Ela.disse:."oi"
três.aspas:."""
linha.continuada
espaço.no.fim:.
```

Aspas simples e duplas soltas não precisam de escape; só uma sequência de três aspas seguidas, que fecharia o bloco. A ordem de processamento importa: primeiro o compilador remove o espaço incidental e o espaço do fim das linhas, e **só depois** interpreta os escapes. É por isso que o `\s` sobrevive no fim da linha e o espaço antes do `\` da continuação também.

## Uma `String` como outra qualquer

O resultado de um text block é uma `String` comum, criada na compilação. Ela vai para o mesmo [pool](/assistir/estagiario-t5-e05) que os literais, e todos os métodos funcionam nela, inclusive os pensados para texto de várias linhas:

```java executar
String a = """
    Javaflix""";
String b = "Javaflix";
System.out.println(a == b);
System.out.println("""
    um
    dois
    """.lines().count());
String carta = """
    Olá, %s!
    Seu saldo é %d pontos.
    """.formatted("Ana", 150);
System.out.print(carta);
```

```saida
true
2
Olá, Ana!
Seu saldo é 150 pontos.
```

`a == b` é verdadeiro porque as duas são a mesma constante de compilação, compartilhada no pool. `lines()` divide por quebras de linha, e `formatted()` (Java 15) é o `String.format` como método de instância. Para texto que vem de fora (um arquivo, por exemplo), `stripIndent()` aplica o mesmo algoritmo de espaço incidental, e `translateEscapes()` interpreta os escapes.

## Por baixo dos panos

Text blocks não existem no bytecode. Todo o trabalho (remover indentação, juntar linhas, interpretar escapes) é feito pelo `javac`, na [análise léxica](/assistir/aprendiz-t2-e03), e o resultado vai para o arquivo `.class` como uma constante de texto, exatamente como `"{\n  \"nome\": \"Ana\"\n}\n"` iria. Não há nenhum custo em tempo de execução, e um programa compilado com text blocks roda em qualquer JVM a partir da versão alvo. As quebras de linha do resultado são sempre `\n`, mesmo que o arquivo-fonte tenha sido salvo no Windows com `\r\n`: o compilador normaliza, e o texto fica igual em qualquer sistema.

## Resumo para a prova

- `"""` de abertura seguido de quebra de linha; conteúdo na linha seguinte
- Fechamento numa linha própria: o texto termina com `\n`; na mesma linha do conteúdo: não termina
- A menor indentação entre as linhas com conteúdo e a linha do fechamento é removida de todas
- Espaços no fim das linhas são sempre removidos
- `\` no fim da linha junta com a próxima; `\s` é um espaço que não some; `\"""` são três aspas
- Aspas sozinhas não precisam de escape
- O resultado é uma `String` comum, constante, no mesmo pool dos literais
- `lines()`, `stripIndent()`, `formatted()` e `translateEscapes()` combinam com text blocks
