Algumas classes só fazem sentido junto de outra: o endereço de entrega de um pedido, a faixa de uma playlist, um filtro usado uma única vez. Java permite declarar uma classe **dentro** de outra, ou até dentro de um método. São quatro tipos, cada um com regras próprias de criação e de acesso, e a prova cobra as quatro.

> [!ANTES]
> O Java 1.0, de 1996, não tinha classes aninhadas: toda classe era de topo. Elas chegaram no Java 1.1, de 1997, principalmente para a interface gráfica AWT, em que cada botão precisava de um objeto "ouvinte" com o código do clique. Escrever uma classe de topo para cada botão era insuportável, e as classes anônimas resolveram isso.

| Tipo | Onde é declarada | Precisa de um objeto da externa? |
|---|---|---|
| Aninhada estática | no corpo da classe, com `static` | não |
| Interna (*inner*) | no corpo da classe, sem `static` | sim |
| Local | dentro de um método | depende do método |
| Anônima | numa expressão `new`, sem nome | depende de onde está |

## Classe aninhada estática

É uma classe comum guardada dentro de outra, como num pacote. Não está ligada a nenhum objeto da externa, e se cria com o nome qualificado. Como faz parte da classe externa, enxerga até os membros `private static` dela:

```java executar
public class Pedido {
    private static int contador = 0;
    private final int numero;
    private final Endereco entrega;

    static class Endereco {
        private final String rua;
        private final String cidade;

        Endereco(String rua, String cidade) {
            this.rua = rua;
            this.cidade = cidade;
            contador++;
        }

        String formatar() {
            return rua + ", " + cidade;
        }
    }

    Pedido(int numero, Endereco entrega) {
        this.numero = numero;
        this.entrega = entrega;
    }

    public static void main(String[] args) {
        Pedido.Endereco e = new Pedido.Endereco("Rua A, 10", "Recife");
        Pedido p = new Pedido(1, e);
        System.out.println("#" + p.numero + " para " + p.entrega.formatar() + " (" + contador + " endereço)");
    }
}
```

```saida
#1 para Rua A, 10, Recife (1 endereço)
```

## Classe interna

Sem `static`, cada objeto da classe interna pertence a **um objeto** da externa e enxerga os campos de instância dele, inclusive os `private`. Por isso, para criá-la, é preciso um objeto da externa, numa sintaxe que só aparece aqui: `externa.new Interna()`.

```java executar
public class Playlist {
    private final String nome;
    private int tocadas = 0;

    Playlist(String nome) {
        this.nome = nome;
    }

    class Faixa {
        private final String titulo;

        Faixa(String titulo) {
            this.titulo = titulo;
        }

        void tocar() {
            tocadas++; //> O tocadas da playlist dona desta faixa.
            System.out.println(titulo + " em " + nome + " (" + tocadas + ")");
        }
    }

    public static void main(String[] args) {
        Playlist rock = new Playlist("Rock");
        Playlist.Faixa f1 = rock.new Faixa("Faixa 1"); //> A faixa nasce presa a um objeto Playlist.
        Faixa f2 = rock.new Faixa("Faixa 2");
        f1.tocar();
        f2.tocar();
    }
}
```

```saida
Faixa 1 em Rock (1)
Faixa 2 em Rock (2)
```

![O objeto Playlist com nome Rock e tocadas 2; dois objetos Faixa, cada um com um campo escondido this$0 apontando para a playlist; e um objeto Endereco, de classe aninhada estática, sem esse campo](/figuras/classe-interna.svg "Uma interna sempre sabe a qual objeto externo pertence. Uma aninhada estática não pertence a nenhum.")

As duas faixas incrementam o mesmo `tocadas`, o da playlist "Rock". Num método `static` da externa, como o `main`, não há `this`, então `new Faixa(...)` sozinho não compila:

```java nao-compila
public class Externa {
    class Interna {
    }

    public static void main(String[] args) {
        Interna i = new Interna();
    }
}
```

Quando um nome se repete em vários níveis, cada um tem a sua forma de acesso: o nome sozinho é o mais próximo, `this.x` é o da classe interna e `Externa.this.x` é o do objeto externo.

> [!PENSE]
> No programa abaixo, há três variáveis `x`: um campo de `Camadas`, um campo de `Meio` e um parâmetro. Antes de olhar a saída, diga qual delas cada expressão do `println` lê.

```java executar
public class Camadas {
    int x = 1;

    class Meio {
        int x = 2;

        void mostrar(int x) {
            System.out.println(x + " " + this.x + " " + Camadas.this.x);
        }
    }

    public static void main(String[] args) {
        new Camadas().new Meio().mostrar(3);
    }
}
```

```saida
3 2 1
```

## Classe local

Uma classe pode ser declarada dentro de um método, e só existe ali. Ela enxerga as variáveis locais e os parâmetros do método, com uma condição: eles precisam ser `final` ou **efetivamente final**, isto é, nunca reatribuídos depois de receber valor.

```java executar
public class Relatorio {
    static String gerar(String titulo, int largura) {
        class Linha {
            String de(char c) {
                return String.valueOf(c).repeat(largura); //> largura é capturada: precisa ser efetivamente final.
            }
        }
        Linha linha = new Linha();
        return linha.de('=') + "\n" + titulo + "\n" + linha.de('-');
    }

    public static void main(String[] args) {
        System.out.println(gerar("VENDAS", 6));
    }
}
```

```saida
======
VENDAS
------
```

Tentar alterar uma variável capturada, de dentro da classe ou de fora dela depois da captura, não compila:

```java nao-compila
public class Captura {
    public static void main(String[] args) {
        int total = 0;
        class Somador {
            void somar(int v) {
                total += v;
            }
        }
        new Somador().somar(5);
    }
}
```

> [!PERGUNTAS]
> **P:** Como escolher entre os quatro tipos?
>
> **R:** Se a classe auxiliar não precisa do objeto externo, aninhada estática. Se precisa, interna. Se só faz sentido dentro de um método, local. E se é usada uma única vez, num ponto só, anônima.
>
> **P:** Uma classe interna pode ter membros `static`?
>
> **R:** Desde o Java 16, sim. Antes, só constantes `static final` eram permitidas nela.
>
> **P:** Uma classe anônima pode implementar duas interfaces?
>
> **R:** Não: ela estende uma classe ou implementa uma interface, uma coisa só. Para mais que isso, dê um nome à classe.

## Classe anônima

É uma classe local sem nome, declarada e instanciada numa só expressão. Ela estende uma classe ou implementa **uma** interface, e serve para comportamentos usados uma única vez. A expressão termina com `;`, como qualquer atribuição:

```java executar
interface Desconto {
    double aplicar(double valor);
}

public class Loja {
    public static void main(String[] args) {
        Desconto blackFriday = new Desconto() {
            @Override
            public double aplicar(double valor) {
                return valor * 0.5;
            }
        };
        Desconto fixo = new Desconto() {
            public double aplicar(double valor) {
                return Math.max(0, valor - 30);
            }
        };
        System.out.println(blackFriday.aplicar(200) + " " + fixo.aplicar(200) + " " + fixo.aplicar(20));
        System.out.println(blackFriday.getClass().getName());
    }
}
```

```saida
100.0 170.0 0.0
Loja$1
```

Uma classe anônima não tem construtor, porque não tem nome. Se ela estende uma classe, os argumentos do `new` vão para o construtor da superclasse: `new Saudacao("Ana") { ... }`. Ela segue as mesmas regras de captura das classes locais. Muitas classes anônimas de uma interface com um único método viraram **lambdas** no Java 8, assunto do cargo Pleno.

> [!LAPIS]
> Qual é a saída?
>
> ```java
> interface Contador { int proximo(); }
>
> static Contador criar(int inicio) {
>     return new Contador() {
>         int atual = inicio;
>         public int proximo() { return atual++; }
>     };
> }
>
> Contador a = criar(10);
> Contador b = criar(10);
> a.proximo();
> a.proximo();
> System.out.println(a.proximo() + " " + b.proximo());
> ```
>
> **Resposta:** `12 10`. Cada chamada de `criar` gera um objeto anônimo novo, com o seu próprio `atual`. O parâmetro `inicio` foi capturado sem ser alterado; quem muda é o campo `atual`, que é do objeto, e campos podem mudar à vontade. `a` já foi chamado duas vezes; `b`, nenhuma.

> [!PROVA]
> Os erros mais cobrados: criar uma classe interna num contexto `static` sem um objeto da externa; usar `new Externa.Interna()` para uma classe interna (é `externa.new Interna()`); usar `externa.new` para uma aninhada estática (é `new Externa.Estatica()`); esquecer o `;` depois da classe anônima; e alterar uma variável local capturada.

> [!ENGENHARIA]
> Se a classe aninhada não usa nada do objeto externo, declare-a `static`. Uma classe interna sem necessidade carrega uma referência escondida para o objeto externo em cada instância, ocupa memória à toa e impede o coletor de lixo de liberar o objeto externo enquanto ela existir. É uma das recomendações do *Effective Java*.

> [!MATEMATICA]
> Cada classe aninhada vira um arquivo `.class`. Uma classe com 1 aninhada estática, 1 interna e 3 anônimas gera 1 + 1 + 1 + 3 = **6** arquivos. E cada objeto de classe interna carrega a referência escondida para o externo: 4 bytes com referências comprimidas. Um milhão de faixas são 1.000.000 × 4 = **4 MB** só nessas referências, além de manter vivas todas as playlists a que pertencem.

> [!IA]
> A IA costuma gerar classes internas sem `static` por padrão, mesmo quando elas não usam o objeto externo, e às vezes propõe alterar uma variável local de dentro de uma classe anônima, o que não compila. Peça que ela justifique cada classe interna não `static` e compile o resultado.

## Na IDE

- **Interna que pode ser `static`.** A inspeção "Inner class may be 'static'" aponta classes internas que não usam o objeto externo, e o **Alt + Enter** acrescenta o `static`.
- **Anônima que vira lambda.** Uma anônima de interface com um método só recebe "Anonymous type can be replaced with lambda".
- **Ver os arquivos gerados.** Depois de compilar, a pasta `out` ou `target/classes` mostra os `.class` com `$` no nome, um por classe aninhada.

## Por baixo dos panos

Para a JVM, não existem classes aninhadas: o compilador gera um arquivo `.class` separado para cada uma, com nomes como `Pedido$Endereco.class`, `Playlist$Faixa.class` e, para as anônimas, números em ordem: `Loja$1.class`, `Loja$2.class`. É o `$` que aparece no `getClass().getName()`.

Uma classe interna ganha um campo escondido, `this$0`, com a referência para o objeto externo, preenchido pelo construtor. É por isso que ela precisa de um objeto da externa para nascer, e é também uma fonte clássica de vazamento de memória: enquanto a faixa existir, a playlist inteira continua viva para o [coletor de lixo](/assistir/junior-t1-e03). O Effective Java recomenda: se a classe aninhada não usa o objeto externo, declare-a `static`.

As variáveis capturadas por classes locais e anônimas são **copiadas** para campos escondidos (como `val$largura`) no momento da criação. Se a variável original pudesse mudar depois, a cópia ficaria desatualizada sem ninguém perceber. A exigência de "efetivamente final" existe para que a cópia e o original sejam sempre iguais.

## Resumo para a prova

- Aninhada estática: `new Externa.Estatica()`; não acessa campos de instância da externa sem um objeto
- Interna: `externa.new Interna()`; acessa os membros da externa, inclusive `private`
- `Externa.this.x` acessa o campo do objeto externo quando há nomes repetidos
- Local: declarada num método; só captura variáveis `final` ou efetivamente final
- Anônima: estende uma classe ou implementa uma interface, não tem construtor, termina com `;`
- Cada classe aninhada vira um `.class` próprio, com `$` no nome
- Classes internas guardam uma referência ao objeto externo
