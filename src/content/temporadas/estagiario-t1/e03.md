Java tem oito tipos primitivos, e quase toda questão de "qual é a saída?" passa por eles. Este episódio cobre o tamanho de cada um, como escrever literais e quais atribuições o compilador aceita sem reclamar.

## Os oito primitivos

| Tipo | Tamanho | Faixa | Exemplo de literal |
|---|---|---|---|
| `byte` | 8 bits | -128 a 127 | `(byte) 10` |
| `short` | 16 bits | -32.768 a 32.767 | `(short) 10` |
| `int` | 32 bits | cerca de ±2,1 bilhões | `10` |
| `long` | 64 bits | cerca de ±9,2 quintilhões | `10L` |
| `float` | 32 bits | ponto flutuante simples | `10.5f` |
| `double` | 64 bits | ponto flutuante dupla | `10.5` |
| `char` | 16 bits | 0 a 65.535, sem sinal | `'A'` |
| `boolean` | não definido | `true` ou `false` | `true` |

![Barras com o tamanho de cada primitivo em bytes, de 1 byte do byte a 8 bytes do long e do double](/figuras/tamanho-dos-primitivos.svg "Laranja para os inteiros com sinal, verde para o char, amarelo para o ponto flutuante. Do byte ao long, cada tipo tem o dobro de bytes do anterior.")

Não precisa decorar as faixas de `int` e `long` até a última casa, mas `byte` (-128 a 127) e `char` (0 a 65.535) caem com frequência. Repare que `char` é **numérico e sem sinal**: guarda o código Unicode do caractere.

> [!MATEMATICA]
> Com n bits existem 2ⁿ combinações. Um `byte` tem 2⁸ = 256: metade para os negativos, de -128 a -1, e metade para o zero e os positivos, de 0 a 127. Um `int` tem 2³², cerca de 4,3 bilhões de combinações, e vai de -2³¹ = -2.147.483.648 a 2³¹ - 1 = 2.147.483.647. O "menos 1" é a vaga ocupada pelo zero. Cada posição vale o dobro da que está à direita: `0010 1010` é 32 + 8 + 2 = 42.

![Os 8 bits do número 42, com o peso de cada posição](/figuras/bits-de-um-byte.svg "Cada bit vale uma potência de 2. Somando as posições que têm 1, 0010 1010 vale 42.")

> [!PROVA]
> `String` não é primitivo, é uma classe. Os primitivos são exatamente os oito da tabela, todos com nome em minúsculas.

## Literais inteiros

Um número inteiro escrito no código é `int` por padrão. Para ser `long`, precisa do sufixo `L` (o `l` minúsculo também vale, mas confunde com o número 1):

```java nao-compila
long populacao = 8100000000;     // não compila: o literal é int e não cabe
```

```java compila
long populacao = 8100000000L;    // agora é um literal long
```

O mesmo número pode ser escrito em quatro bases:

```java executar
public class Bases {
    public static void main(String[] args) {
        int decimal = 26;
        int hexa = 0x1A; //> `0x`: base 16. O dígito `A` vale 10.
        int octal = 032; //> Um zero à esquerda: base 8. Só um zero!
        int binario = 0b11010; //> `0b`: base 2. Só os dígitos 0 e 1.
        System.out.println(decimal + " " + hexa + " " + octal + " " + binario);
    }
}
```

```saida
26 26 26 26
```

O octal é a pegadinha clássica: um zero à esquerda muda a base. `010` vale 8, não 10. E `08` nem compila, porque 8 não é um dígito octal.

> [!MATEMATICA]
> Para passar 26 para binário, divida por 2 até chegar a 0 e anote os restos: 26 ÷ 2 = 13, resto **0**; 13 ÷ 2 = 6, resto **1**; 6 ÷ 2 = 3, resto **0**; 3 ÷ 2 = 1, resto **1**; 1 ÷ 2 = 0, resto **1**. Lidos de baixo para cima, os restos dão `11010`. Para chegar ao hexadecimal, agrupe os bits de 4 em 4 a partir da direita: `1 1010` vira 1 e A, ou `0x1A`. Para o octal, de 3 em 3: `11 010` vira 3 e 2, ou `032`. De volta ao decimal: 1 × 16 + 10 = 26 e 3 × 8 + 2 = 26.

> [!LAPIS]
> Sem rodar nada, quanto vale cada literal em decimal? `0x2F`, `0b1011`, `017` e `0x100`.
>
> **Resposta:** `0x2F` = 2 × 16 + 15 = **47**; `0b1011` = 8 + 2 + 1 = **11**; `017` = 1 × 8 + 7 = **15**, porque o zero na frente faz dele octal; `0x100` = 1 × 16² = **256**. Se errou o `017`, caiu na pegadinha favorita da prova.

## Underscore nos números

Desde o Java 7 dá para separar dígitos com `_` para facilitar a leitura. A regra é simples: o `_` só pode ficar **entre dois dígitos**.

```java
int milhao = 1_000_000;        // ok
double pi = 3.141_592;         // ok
long cartao = 1234_5678_9012_3456L; // ok

int a = _1000;      // não é número: é um identificador chamado _1000
int b = 1000_;      // erro: termina com _
double c = 3._14;   // erro: _ colado no ponto
long d = 100_L;     // erro: _ colado no sufixo
int e = 0x_FF;      // erro: _ logo depois do prefixo
```

> [!ANTES]
> Até o Java 6, não existiam nem o `_` nos números nem o prefixo `0b`: os dois chegaram juntos no Java 7. Em código antigo você vai ver `1000000` sem separador e binário escrito como texto, convertido com `Integer.parseInt("11010", 2)`.

## Ponto flutuante

Um número com ponto decimal (ou expoente, como `1e3`) é `double` por padrão. Para `float`, use o sufixo `f`:

```java nao-compila
float preco = 9.99;     // não compila: 9.99 é double, e double não cabe em float sem cast
```

```java compila
float preco = 9.99f;    // ok
double taxa = 5;        // ok: um int cabe num double
double grande = 1.5e3;  // 1500.0
```

## char é número

Um `char` guarda um código Unicode de 16 bits. Dá para escrever o caractere, o escape `\uXXXX` ou até um número inteiro constante que caiba na faixa.

> [!PENSE]
> As duas linhas do `main` abaixo imprimem os mesmos três `char`: `a`, `b` e `c`. O que você acha que cada uma mostra? Responda antes de olhar a saída.

```java executar
public class Caracteres {
    public static void main(String[] args) {
        char a = 'A';
        char b = '\u0042';  // B
        char c = 67;        // C
        System.out.println("" + a + b + c);
        System.out.println(a + b + c);
    }
}
```

```saida
ABC
198
```

A segunda linha imprime um número porque somar `char` com `char` produz `int` (65 + 66 + 67). Na primeira, a String vazia no começo transforma tudo em concatenação de texto.

> [!ANTES]
> O Java nasceu em 1996 com o Unicode da época, que cabia em 16 bits: daí o `char` de 16 bits. O Unicode cresceu e hoje passa de um milhão de códigos. A solução, adotada de vez no Java 5, foi usar **dois** `char` para cada caractere de fora dos 16 bits, como um emoji. Por isso o `length()` de uma String com um emoji sozinho vale 2.

## boolean não é número

Em Java, `boolean` só aceita `true` e `false`. Diferente de C, `0` e `1` não servem como booleanos, e não existe conversão entre `boolean` e qualquer tipo numérico, nem com cast.

> [!PERGUNTAS]
> **P:** Se o `char` é um número, por que ele não tem sinal, como o `byte`?
>
> **R:** Porque ele representa códigos de caracteres, e não existe caractere de código negativo. Sem o sinal, os 16 bits vão todos para os códigos positivos: de 0 a 65.535.
>
> **P:** Quanto espaço um `boolean` ocupa?
>
> **R:** A especificação da linguagem não diz. Na prática, a JVM costuma tratar um `boolean` solto como um `int` e guardar cada item de um array de `boolean` num byte. Não há como descobrir isso de dentro do Java, e a prova não pergunta.
>
> **P:** Quando usar `float` em vez de `double`?
>
> **R:** Quase nunca no dia a dia: o `double` tem o dobro da precisão, e a diferença de velocidade é desprezível. O `float` aparece quando há milhões de números e memória importa, como em gráficos 3D e em modelos de aprendizado de máquina.

> [!DESEMPENHO]
> Usar `byte` ou `short` numa variável local não deixa as contas mais rápidas: a JVM promove os dois para `int` em toda operação, como você vai ver na temporada [Operadores](/?t=estagiario-t2). A economia aparece só em arrays grandes, em que um `byte[]` de um milhão de itens ocupa 1 MB e um `int[]` ocupa 4 MB.

## Atribuição de constantes

Esta regra explica várias questões de "compila ou não compila". Normalmente você não pode colocar um `int` num `byte` sem cast. Mas se o valor for uma **constante de compilação** e couber na faixa, o compilador aceita:

```java
byte b1 = 100;          // ok: 100 é constante e cabe em byte
byte b2 = 200;          // erro: não cabe

int x = 100;
byte b3 = x;            // erro: x não é constante

final int y = 100;
byte b4 = y;            // ok: y é final e foi inicializada com constante
```

Isso vale para atribuições a `byte`, `short` e `char`.

## Overflow

> [!PENSE]
> O maior `int` é 2.147.483.647. O que acontece quando você soma 1 a ele: erro de compilação, uma exceção ou outra coisa?

Quando uma conta passa do limite do tipo, o valor dá a volta, sem erro nem exceção:

```java executar
public class Volta {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        System.out.println(max);
        System.out.println(max + 1);
    }
}
```

```saida
2147483647
-2147483648
```

## Valores padrão

Campos de uma classe (variáveis declaradas fora dos métodos) recebem um valor padrão se você não inicializar:

| Tipo | Valor padrão |
|---|---|
| `byte`, `short`, `int`, `long` | `0` |
| `float`, `double` | `0.0` |
| `char` | `'\u0000'` (o caractere de código 0) |
| `boolean` | `false` |
| qualquer referência, como `String` | `null` |

Variáveis **locais**, as declaradas dentro de métodos, não ganham valor padrão. Esse é o assunto do próximo episódio.

## Na IDE

O IntelliJ responde boa parte das dúvidas deste episódio sem você precisar rodar nada:

- **O tipo de uma expressão.** Selecione `a + b + c` e aperte **Ctrl + Shift + P** (*Type Info*): aparece `int`. É o jeito mais rápido de resolver um "isso é `char` ou `int`?".
- **Literais errados na hora.** `long populacao = 8100000000;` fica sublinhado em vermelho com a mesma mensagem do `javac`, *Integer number too large*. Em `float preco = 9.99;`, **Alt + Enter** oferece correções, como um cast para `float`; prefira escrever `9.99f`, que diz o mesmo sem ruído.
- **Trocar de base.** Com o cursor num número, **Alt + Enter** oferece convertê-lo para hexadecimal, octal, binário ou decimal, e também inserir os `_` separadores. Bom para conferir as suas contas.

![O editor do IntelliJ com a expressão a + b + c selecionada e o popup do Type Info mostrando int](/figuras/intellij-tipo.svg "1: selecione a expressão. 2: Ctrl + Shift + P mostra o tipo que o compilador vai usar.")

> [!BOAPRATICA]
> Quando a IDE converter um número de base, confira se o resultado ficou mais legível. Uma máscara de bits fica clara em binário (`0b1111_0000`); uma cor, em hexadecimal (`0xFF7A1A`); uma quantidade, em decimal com `_` (`1_000_000`). Octal quase nunca é a melhor escolha.

## Por baixo dos panos

Por que o `byte` vai de -128 a 127, e não de 0 a 255? Com 8 bits existem 2⁸ = 256 combinações, e Java usa **complemento de dois**: o bit mais à esquerda vale -128 em vez de +128. O resto continua valendo 64, 32, 16, 8, 4, 2 e 1.

| Bits | Conta | Valor |
|---|---|---|
| `0000 0001` | 1 | 1 |
| `0111 1111` | 64 + 32 + 16 + 8 + 4 + 2 + 1 | 127 |
| `1000 0000` | -128 | -128 |
| `1111 1111` | -128 + 127 | -1 |

Para negar um número, inverta todos os bits e some 1. E dá para ver por que o overflow "dá a volta": 127 + 1 em 8 bits vira `1000 0000`, que é -128. A vantagem desse formato é que o mesmo circuito somador do processador serve para números positivos e negativos.

```java executar
public class Bits {
    public static void main(String[] args) {
        System.out.println(Integer.toBinaryString(5));
        System.out.println(Integer.toBinaryString(-5));
        byte b = (byte) 200;
        System.out.println(b);
    }
}
```

```saida
101
11111111111111111111111111111011
-56
```

`-5` aparece com 32 bits porque `int` tem 32 bits: é `5` invertido mais 1. E 200 em binário é `1100 1000`; num `byte` o primeiro bit vale -128, então sobra -128 + 64 + 8 = -56.

O `char` é a exceção: 16 bits **sem** sinal, por isso vai de 0 a 65.535.

E o ponto flutuante? `float` e `double` seguem o padrão IEEE 754: um bit de sinal, um expoente e uma mantissa, como uma notação científica em base 2. O efeito colateral é que muitos decimais não têm representação exata, assim como 1/3 não tem em base 10:

```java executar
public class Flutuante {
    public static void main(String[] args) {
        System.out.println(0.1 + 0.2);
        System.out.println(0.1 + 0.2 == 0.3);
        System.out.println(0.5 + 0.25 == 0.75);
    }
}
```

```saida
0.30000000000000004
false
true
```

`0.5` e `0.25` são potências de 2 (2⁻¹ e 2⁻²) e cabem exatamente em binário; `0.1` não. É por isso que dinheiro não se guarda em `double`: use `BigDecimal` ou centavos num `long`.

> [!ERRO]
> Comparar `double` com `==`. `0.1 + 0.2 == 0.3` dá `false`, e um `if` assim falha sem nenhum aviso. Para números com casas decimais, compare a distância entre eles com uma tolerância, `Math.abs(a - b) < 1e-9`, ou faça as contas em inteiros.

> [!IA]
> Peça a uma IA uma classe de conta bancária e é comum ela guardar o saldo em `double`. O `0.1 + 0.2` acima mostra o problema: em milhares de operações, os centavos começam a sumir. Outra confusão frequente é tratar o `char` do Java como o de C, com 8 bits e sinal. Confira os tipos que ela escolher antes de aceitar.

> [!DICA]
> Para ver os bits de um `float`, use o [Float Converter](https://www.h-schmidt.net/FloatConverter/IEEE754.html). A trilha Aprendiz tem episódios inteiros sobre [complemento de dois](/assistir/aprendiz-t3-e02) e sobre [IEEE 754](/assistir/aprendiz-t3-e03).

## Resumo para a prova

- Literal inteiro é `int`; literal com ponto é `double`
- `long` precisa de `L` quando o valor não cabe em `int`; `float` sempre precisa de `f`
- Zero à esquerda é octal: `010` vale 8
- `_` só entre dígitos
- `char` é número de 0 a 65.535; `char + char` dá `int`
- Constante que cabe pode ir para `byte`, `short` e `char` sem cast; variável não
- Overflow dá a volta silenciosamente
