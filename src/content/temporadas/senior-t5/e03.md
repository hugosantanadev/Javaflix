Os dois episódios anteriores localizaram textos fixos e números. Faltam as **datas**, que mudam de ordem e de nomes de país para país, e as **mensagens** com partes variáveis, como "Ana comprou 3 itens por R$ 99,90". Uma mensagem dessas não pode ser montada concatenando pedaços traduzidos, porque cada idioma põe as palavras numa ordem diferente. Este episódio fecha a parte de localização com o `DateTimeFormatter` localizado e o `MessageFormat`.

## Datas no formato de cada país

O `DateTimeFormatter` do [Pleno](/assistir/pleno-t4-e05) tem formatos **localizados**, que seguem o costume do `Locale` em vez de um padrão fixo. Eles vêm em quatro estilos, de `FormatStyle`:

| Estilo | Brasil | Estados Unidos |
|---|---|---|
| `SHORT` | `16/09/2025` | `9/16/25` |
| `MEDIUM` | Com o mês abreviado | Com o mês abreviado |
| `LONG` | `16 de setembro de 2025` | `September 16, 2025` |
| `FULL` | `terça-feira, 16 de setembro de 2025` | `Tuesday, September 16, 2025` |

As fábricas são `ofLocalizedDate`, `ofLocalizedTime` e `ofLocalizedDateTime`, e o `Locale` vem pelo `withLocale`. Sem ele, vale o `Locale` padrão. Um padrão próprio também pode receber um `Locale`, que decide o idioma dos nomes de mês e de dia: `ofPattern("EEEE, d 'de' MMMM", locale)`. E `Month` e `DayOfWeek` traduzem os próprios nomes com `getDisplayName(TextStyle, Locale)`.

```java executar
import java.time.DayOfWeek;
import java.time.LocalDate;
import java.time.Month;
import java.time.format.DateTimeFormatter;
import java.time.format.FormatStyle;
import java.time.format.TextStyle;
import java.util.List;
import java.util.Locale;

public class DatasLocais {
    public static void main(String[] args) {
        Locale br = Locale.forLanguageTag("pt-BR");
        LocalDate data = LocalDate.of(2025, 9, 16);
        for (Locale l : List.of(br, Locale.US, Locale.GERMANY)) {
            System.out.println(l + ": " + data.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.SHORT).withLocale(l)) + " | "
                + data.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG).withLocale(l)) + " | "
                + data.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.FULL).withLocale(l)));
        }
        System.out.println(data.format(DateTimeFormatter.ofPattern("EEEE, d 'de' MMMM 'de' yyyy", br)));
        System.out.println(Month.MARCH.getDisplayName(TextStyle.FULL, br) + " " + DayOfWeek.SATURDAY.getDisplayName(TextStyle.FULL, Locale.US) + " " + DayOfWeek.MONDAY.getDisplayName(TextStyle.NARROW, br));
    }
}
```

```saida
pt_BR: 16/09/2025 | 16 de setembro de 2025 | terça-feira, 16 de setembro de 2025
en_US: 9/16/25 | September 16, 2025 | Tuesday, September 16, 2025
de_DE: 16.09.25 | 16. September 2025 | Dienstag, 16. September 2025
terça-feira, 16 de setembro de 2025
março Saturday S
```

O estilo `SHORT` americano usa o ano com dois dígitos e põe o mês primeiro; o alemão separa com pontos. Em português, os nomes de meses e dias são minúsculos, como manda a ortografia.

## Data e hora: o fuso faz falta

Para data e hora juntas, os estilos `SHORT` e `MEDIUM` funcionam com um `LocalDateTime`. Já `LONG` e `FULL` incluem o **fuso horário** no texto, e um `LocalDateTime` não tem fuso: a formatação lança `DateTimeException`. Com um `ZonedDateTime`, funciona.

```java executar
import java.time.DateTimeException;
import java.time.LocalDateTime;
import java.time.ZoneId;
import java.time.ZonedDateTime;
import java.time.format.DateTimeFormatter;
import java.time.format.FormatStyle;
import java.util.Locale;

public class DataHora {
    static String txt(String s) {
        return s.replace((char) 160, ' ').replace((char) 0x202F, ' ');
    }

    public static void main(String[] args) {
        Locale br = Locale.forLanguageTag("pt-BR");
        LocalDateTime agora = LocalDateTime.of(2025, 9, 16, 14, 30);
        System.out.println(agora.format(DateTimeFormatter.ofLocalizedDateTime(FormatStyle.SHORT).withLocale(br)) + " | "
            + txt(agora.format(DateTimeFormatter.ofLocalizedDateTime(FormatStyle.SHORT).withLocale(Locale.US))));
        try {
            agora.format(DateTimeFormatter.ofLocalizedDateTime(FormatStyle.LONG).withLocale(br));
        } catch (DateTimeException e) {
            System.out.println("LONG sem fuso: " + e.getClass().getSimpleName());
        }
        ZonedDateTime sp = agora.atZone(ZoneId.of("America/Sao_Paulo"));
        System.out.println(sp.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG).withLocale(br)) + " às " + sp.format(DateTimeFormatter.ofPattern("HH:mm")));
    }
}
```

```saida
16/09/2025 14:30 | 9/16/25, 2:30 PM
LONG sem fuso: DateTimeException
16 de setembro de 2025 às 14:30
```

> [!VERSAO]
> Os formatos vêm do CLDR, que muda a cada versão do Java. No Java 20, por exemplo, o espaço antes de `AM` e `PM` no inglês passou a ser o espaço estreito não separável (caractere 8239), o que quebrou testes que comparavam `"2:30 PM"` com espaço comum. O exemplo acima o troca por um espaço comum com o método `txt`. As abreviações do estilo `MEDIUM`, como o nome curto do mês, também variam entre versões.

## MessageFormat: mensagens com partes variáveis

`java.text.MessageFormat` monta mensagens a partir de um **padrão** com marcadores numerados, `{0}`, `{1}`, que indicam a posição de cada argumento. Como a tradução de cada idioma tem o seu próprio padrão, os argumentos podem aparecer em qualquer ordem: em português, "Ana comprou 3 itens"; noutro idioma, a quantidade pode vir antes do nome. Um marcador pode dizer como formatar o argumento:

| Marcador | Formata |
|---|---|
| `{0}` | O argumento como texto; números e datas com o formato padrão do `Locale` |
| `{1,number}`, `{1,number,integer}` | Número, com ou sem casas decimais |
| `{2,number,currency}`, `{2,number,percent}` | Moeda ou percentual |
| `{3,date,short}`, `{3,date,long}` | Data (de `java.util.Date`) |
| `{4,choice,0#nenhum\|1#um\|1<muitos}` | Escolhe um texto pela faixa do número |

O atalho estático `MessageFormat.format(padrao, args...)` usa o `Locale` padrão. Para escolher o `Locale`, cria-se o objeto: `new MessageFormat(padrao, locale)`.

```java executar
import java.text.MessageFormat;
import java.time.Instant;
import java.util.Date;
import java.util.Locale;

public class Mensagens {
    static String txt(String s) {
        return s.replace((char) 160, ' ').replace((char) 0x202F, ' ');
    }

    public static void main(String[] args) {
        Locale br = Locale.forLanguageTag("pt-BR");
        Date quando = Date.from(Instant.parse("2025-09-16T12:00:00Z"));
        MessageFormat mf = new MessageFormat("{0} comprou {1,number,integer} itens por {2,number,currency} em {3,date,long}.", br);
        System.out.println(txt(mf.format(new Object[] {"Ana", 1234, 99.9, quando})));
        MessageFormat us = new MessageFormat("{0} bought {1,number,integer} items for {2,number,currency}.", Locale.US);
        System.out.println(us.format(new Object[] {"Ana", 1234, 99.9}));

        System.out.println(MessageFormat.format("{1} e {0} e {1} de novo, {2}", "a", "b"));
        String plural = "{0,choice,0#nenhum item|1#um item|1<{0,number,integer} itens}";
        for (int n : new int[] {0, 1, 2, 1500}) {
            System.out.println(new MessageFormat(plural, br).format(new Object[] {n}));
        }
    }
}
```

```saida
Ana comprou 1.234 itens por R$ 99,90 em 16 de setembro de 2025.
Ana bought 1,234 items for $99.90.
b e a e b de novo, {2}
nenhum item
um item
2 itens
1.500 itens
```

O `{3,date,long}` formata um `java.util.Date`, a classe de datas anterior ao Java 8, no fuso padrão da JVM; por isso o exemplo usa meio-dia em UTC, que cai no mesmo dia em quase todos os fusos. Com `java.time`, o caminho mais limpo é formatar a data antes com `DateTimeFormatter` e passá-la como texto, num `{3}` simples. Um marcador pode aparecer mais de uma vez, e um marcador sem argumento correspondente fica no texto, como o `{2}`. No `choice`, `1#` vale para exatamente 1 e `1<` para qualquer valor acima de 1; dentro da opção, o próprio argumento pode ser formatado de novo.

## A armadilha do apóstrofo

No padrão do `MessageFormat`, o **apóstrofo** tem função especial: ele abre um trecho literal, em que as chaves não são marcadores. Para escrever um apóstrofo de verdade, é preciso dobrá-lo. Isso pega quem traduz textos com nomes como "D'Ávila" ou com o apóstrofo do inglês:

```java executar
import java.text.MessageFormat;

public class Apostrofo {
    public static void main(String[] args) {
        System.out.println(MessageFormat.format("D'Ávila tem {0} anos", 30));
        System.out.println(MessageFormat.format("D''Ávila tem {0} anos", 30));
        System.out.println(MessageFormat.format("Use '{0}' para o primeiro argumento: {0}", "x"));
    }
}
```

```saida
DÁvila tem {0} anos
D'Ávila tem 30 anos
Use {0} para o primeiro argumento: x
```

Na primeira linha, o apóstrofo sumiu e abriu um trecho literal que vai até o fim: o `{0}` nem foi substituído. Na terceira, o efeito é proposital: `'{0}'` escreve as chaves sem tratá-las como marcador.

> [!PROVA]
> `DateTimeFormatter.ofLocalizedDate(FormatStyle.X).withLocale(locale)`; `ofLocalizedDateTime` com `LONG` ou `FULL` exige fuso, e um `LocalDateTime` lança `DateTimeException`. `MessageFormat`: marcadores `{0}`, `{1,number}`, `{2,date}`, `{3,choice,...}`; o estático `format` usa o `Locale` padrão. Apóstrofo abre trecho literal; `''` escreve um apóstrofo. Marcador sem argumento fica como está.

## Por baixo dos panos

Um `MessageFormat` analisa o padrão uma vez, no construtor, e o transforma numa lista de trechos fixos e de subformatos: um `NumberFormat` para `{1,number}`, um `DateFormat` para `{3,date,long}`, um `ChoiceFormat` para `{4,choice,...}`, todos criados para o `Locale` do `MessageFormat`. Na formatação, ele só percorre essa lista e chama cada subformato. Por isso vale a pena reutilizar o objeto quando a mesma mensagem é formatada muitas vezes, com o mesmo cuidado de thread-safety do `NumberFormat`: o `MessageFormat` também não é seguro para uso simultâneo.

Os formatos localizados do `DateTimeFormatter`, por outro lado, são imutáveis e thread-safe. O `ofLocalizedDate` não guarda um padrão: guarda o estilo, e na hora de formatar pede ao provedor de dados do `Locale` o padrão correspondente, como `d 'de' MMMM 'de' y` para o `LONG` do Brasil. É isso que permite que o mesmo objeto, com `withLocale`, produza formatos completamente diferentes. Aplicações com mensagens no plural mais complexas, como as do russo ou do árabe, que têm várias formas de plural, costumam usar bibliotecas como o ICU4J, que implementam as regras completas do CLDR.

## Resumo para a prova

- `DateTimeFormatter.ofLocalizedDate/Time/DateTime(FormatStyle)` com `withLocale`; estilos `SHORT`, `MEDIUM`, `LONG`, `FULL`
- `LONG` e `FULL` com hora exigem fuso: `LocalDateTime` lança `DateTimeException`
- `ofPattern(padrao, locale)` e `getDisplayName(TextStyle, locale)` traduzem nomes de mês e de dia
- `MessageFormat`: `{n}`, `{n,number,integer|currency|percent}`, `{n,date,short|long}`, `{n,choice,...}`
- `MessageFormat.format` estático usa o `Locale` padrão; `new MessageFormat(padrao, locale)` escolhe
- Apóstrofo abre trecho literal; `''` é um apóstrofo; marcador sem argumento permanece no texto
