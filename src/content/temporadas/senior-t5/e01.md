Um sistema que atende o Brasil e Portugal precisa mostrar "Olá" para os dois, mas "carrinho" num e "carrinho de compras" noutro; datas como `16/09/2025` aqui e `9/16/2025` nos Estados Unidos; valores como `R$ 1.234,50` e `$1,234.50`. Preparar o código para isso se chama **internacionalização** (i18n, de *i*, 18 letras, *n*), e adaptar o conteúdo a cada lugar, **localização** (l10n). Em Java, as duas giram em torno da classe `Locale` e dos **resource bundles**.

## Locale: idioma e região

Um `Locale` identifica um idioma e, opcionalmente, uma região. No formato do Java, o idioma vem em minúsculas (código ISO 639) e o país em maiúsculas (ISO 3166), separados por sublinhado: `pt_BR`, `en_US`, `fr`. No formato das *language tags* (BCP 47), usado na web, o separador é o hífen: `pt-BR`.

| Forma de criar | Exemplo |
|---|---|
| Constantes | `Locale.US`, `Locale.GERMANY`, `Locale.FRENCH`, `Locale.UK` (não há constante para o Brasil) |
| A partir de uma tag | `Locale.forLanguageTag("pt-BR")` |
| Construtor | `new Locale("pt", "BR")`, obsoleto desde o Java 19 |
| Fábrica (Java 19) | `Locale.of("pt", "BR")` |
| Construtor fluente | `new Locale.Builder().setLanguage("fr").setRegion("CA").build()` |

```java executar
import java.util.Locale;

public class Locais {
    public static void main(String[] args) {
        Locale br = Locale.forLanguageTag("pt-BR");
        Locale canada = new Locale.Builder().setLanguage("fr").setRegion("CA").build();
        System.out.println(br + " " + br.getLanguage() + " " + br.getCountry() + " " + br.toLanguageTag());
        System.out.println(Locale.US + " " + Locale.GERMANY + " " + Locale.FRENCH + " " + canada);
        System.out.println(br.getDisplayName(Locale.US) + " | " + br.getDisplayName(br) + " | " + Locale.GERMANY.getDisplayCountry(br));
        System.out.println("[" + Locale.forLanguageTag("pt_BR") + "] [" + Locale.forLanguageTag("PT-br") + "]");
    }
}
```

```saida
pt_BR pt BR pt-BR
en_US de_DE fr fr_CA
Portuguese (Brazil) | português (Brasil) | Alemanha
[] [pt_BR]
```

`Locale.FRENCH` só tem idioma; `Locale.FRANCE` seria `fr_FR`. Os nomes de exibição são traduzidos para o `Locale` pedido: o Brasil se chama "Brazil" em inglês e a Alemanha, "Alemanha" em português. A última linha tem duas pegadinhas: `forLanguageTag` não aceita o sublinhado, e devolve um `Locale` **vazio** em vez de lançar exceção; já as maiúsculas e minúsculas são corrigidas sozinhas.

Todo programa tem um **`Locale` padrão**, que vem do sistema operacional e é lido com `Locale.getDefault()`. Formatações sem `Locale` explícito usam esse padrão, e por isso o mesmo programa imprime coisas diferentes em máquinas diferentes. `Locale.setDefault(...)` troca o padrão para o programa inteiro; há ainda as categorias `Locale.Category.DISPLAY` e `FORMAT`, que permitem um padrão para textos de interface e outro para números e datas.

> [!VERSAO]
> O Java 19 tornou obsoletos os construtores de `Locale` e trouxe a fábrica `Locale.of`, que faz o mesmo: `Locale.of("pt", "BR")`. No Java 17, só existem os construtores, `forLanguageTag` e o `Builder`. Os construtores continuam funcionando, com um aviso de compilação.

```java executar java21
import java.util.Locale;

public class Fabrica {
    public static void main(String[] args) {
        Locale a = Locale.of("pt", "BR");
        Locale b = new Locale("pt", "BR");
        System.out.println(a + " " + a.equals(b) + " " + Locale.of("es"));
    }
}
```

```saida
pt_BR true es
```

## Resource bundles

Os textos que mudam com o idioma não ficam no código: ficam em **resource bundles**, conjuntos de pares chave e valor, um por `Locale`. A forma mais comum são arquivos `.properties` com o mesmo nome base e sufixos:

```text
loja.properties          saudacao=Hello          carrinho=Cart        sair=Exit
loja_pt.properties       saudacao=Olá            carrinho=Carrinho
loja_pt_BR.properties    saudacao=E aí
loja_es.properties       saudacao=Hola
```

O código pede o bundle pelo nome base e pelo `Locale`, com `ResourceBundle.getBundle("loja", locale)`, e lê cada texto com `getString(chave)`. O arquivo sem sufixo é o **bundle base**, a última instância. Desde o Java 9, os arquivos `.properties` de resource bundles são lidos em UTF-8.

## Como o bundle é escolhido

O Java monta uma lista de candidatos e fica com **o primeiro que existir**. Para `pt_BR`, com o padrão `en_US`, a ordem é:

1. `loja_pt_BR`, o `Locale` pedido completo
2. `loja_pt`, só o idioma pedido
3. `loja_en_US`, o `Locale` padrão completo
4. `loja_en`, só o idioma padrão
5. `loja`, o bundle base

Escolhido o bundle, cada chave é procurada nele e depois nos seus **pais**, que são os mais gerais da mesma linha: `pt_BR`, depois `pt`, depois o base. Os bundles do `Locale` padrão **não** entram nessa busca de chaves, só na escolha. Se a chave não estiver em nenhum, `getString` lança `MissingResourceException`.

O exemplo grava os quatro arquivos numa pasta temporária e aponta um carregador de classes para ela, como se estivessem dentro do JAR da aplicação:

```java executar
import java.io.IOException;
import java.net.URL;
import java.net.URLClassLoader;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Locale;
import java.util.MissingResourceException;
import java.util.ResourceBundle;
import java.util.TreeSet;

public class Bundles {
    public static void main(String[] args) throws IOException {
        Path pasta = Files.createTempDirectory("bundles");
        Files.writeString(pasta.resolve("loja.properties"), "saudacao=Hello\ncarrinho=Cart\nsair=Exit\n");
        Files.writeString(pasta.resolve("loja_pt.properties"), "saudacao=Olá\ncarrinho=Carrinho\n");
        Files.writeString(pasta.resolve("loja_pt_BR.properties"), "saudacao=E aí\n");
        Files.writeString(pasta.resolve("loja_es.properties"), "saudacao=Hola\n");

        try (URLClassLoader textos = new URLClassLoader(new URL[] {pasta.toUri().toURL()})) {
            Locale.setDefault(Locale.US);
            ResourceBundle br = ResourceBundle.getBundle("loja", Locale.forLanguageTag("pt-BR"), textos);
            System.out.println(br.getLocale() + ": " + br.getString("saudacao") + " / " + br.getString("carrinho") + " / " + br.getString("sair"));
            System.out.println(new TreeSet<>(br.keySet()));

            ResourceBundle pt = ResourceBundle.getBundle("loja", Locale.forLanguageTag("pt-PT"), textos);
            System.out.println(pt.getLocale() + ": " + pt.getString("saudacao"));

            ResourceBundle fr = ResourceBundle.getBundle("loja", Locale.FRANCE, textos);
            System.out.println("[" + fr.getLocale() + "]: " + fr.getString("saudacao"));

            Locale.setDefault(Locale.forLanguageTag("es-MX"));
            ResourceBundle fr2 = ResourceBundle.getBundle("loja", Locale.FRANCE, textos);
            System.out.println(fr2.getLocale() + ": " + fr2.getString("saudacao") + " / " + fr2.getString("sair"));

            try {
                br.getString("frete");
            } catch (MissingResourceException e) {
                System.out.println("chave ausente: " + e.getKey());
            }
        }
        Files.delete(pasta.resolve("loja.properties"));
        Files.delete(pasta.resolve("loja_pt.properties"));
        Files.delete(pasta.resolve("loja_pt_BR.properties"));
        Files.delete(pasta.resolve("loja_es.properties"));
        Files.delete(pasta);
    }
}
```

```saida
pt_BR: E aí / Carrinho / Exit
[carrinho, sair, saudacao]
pt: Olá
[]: Hello
es: Hola / Exit
chave ausente: frete
```

Linha a linha: para `pt_BR`, a saudação vem do próprio arquivo, o carrinho do pai `pt` e o "Exit" do base; o `keySet` junta as chaves de toda a linha. Para `pt_PT`, não há arquivo próprio, e fica o `pt`. Para `fr_FR`, com o padrão `en_US`, não existe nem francês nem inglês, e sobra o base, cujo `Locale` é o vazio. Trocando o padrão para `es_MX`, o mesmo pedido em francês passa a cair no `loja_es`: o padrão entra na escolha do bundle.

Um bundle também pode ser uma **classe Java** que estende `ListResourceBundle` e devolve os pares num `Object[][]`, útil quando os valores não são texto. Com o mesmo nome base, uma classe tem preferência sobre um arquivo `.properties`.

> [!PROVA]
> `Locale`: idioma minúsculo, país maiúsculo, `pt_BR`; tag com hífen, `pt-BR`. `getBundle` escolhe o primeiro existente entre: pedido completo, idioma pedido, padrão completo, idioma padrão, base. As chaves são buscadas no bundle escolhido e nos pais dele, nunca nos do `Locale` padrão. Chave ausente: `MissingResourceException`. Classe tem preferência sobre `.properties`.

## Por baixo dos panos

A lista de candidatos é calculada por um objeto `ResourceBundle.Control`, que pode ser substituído para mudar a política, por exemplo para não usar o `Locale` padrão como recurso (`Control.getNoFallbackControl`) ou para ler bundles de XML. Para cada candidato, o `Control` primeiro tenta carregar uma **classe** com o nome do bundle e, se não achar, um **recurso** `.properties`. Os bundles carregados ficam num cache, por carregador de classes e nome, e por isso abrir o mesmo bundle várias vezes não relê os arquivos.

Os textos traduzidos dos próprios `Locale`, como "português (Brasil)", e todos os formatos de números e datas vêm do **CLDR** (*Common Locale Data Repository*), um banco de dados mantido pelo Unicode Consortium e usado também por navegadores e sistemas operacionais. O JDK o adotou como fonte padrão no Java 9 (JEP 252), e cada versão do Java traz uma versão mais nova do CLDR. Por isso alguns formatos mudam ligeiramente de uma versão do Java para outra, como uma abreviação de mês, e testes que comparam textos formatados precisam fixar o `Locale` e, às vezes, a versão.

## Resumo para a prova

- `Locale` = idioma (minúsculo) + país (maiúsculo): `pt_BR`; tag BCP 47 com hífen: `pt-BR`
- Criar: constantes, `forLanguageTag`, construtores (obsoletos no 19), `Locale.of` (Java 19), `Locale.Builder`
- `Locale.getDefault()` e `setDefault()`; formatação sem `Locale` usa o padrão
- `ResourceBundle.getBundle(nome, locale)`: candidatos na ordem pedido, idioma, padrão, idioma padrão, base
- Chaves herdadas dos pais do bundle escolhido; ausente, `MissingResourceException`
- Bundles em `.properties` (UTF-8 desde o Java 9) ou em classes `ListResourceBundle`, que têm preferência
