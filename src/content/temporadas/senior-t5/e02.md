O número 1234567,891 se escreve `1,234,567.891` nos Estados Unidos, `1.234.567,891` no Brasil e na Alemanha, e `1 234 567,891` na França. O símbolo da moeda vem antes ou depois, colado ou separado, e o percentual pode ter espaço ou não. Escrever esses formatos à mão é receita para erro. O pacote `java.text` traz as classes que conhecem as regras de cada `Locale`: **`NumberFormat`**, para os formatos prontos, e **`DecimalFormat`**, para padrões sob medida.

## NumberFormat: os formatos prontos

| Fábrica | Formata |
|---|---|
| `NumberFormat.getInstance(locale)` ou `getNumberInstance` | Números com separadores de milhar e decimal |
| `getIntegerInstance(locale)` | Números arredondados para inteiro |
| `getCurrencyInstance(locale)` | Valores em dinheiro, com o símbolo e as casas da moeda |
| `getPercentInstance(locale)` | Percentuais: `0.256` vira `26%` |
| `getCompactNumberInstance(locale, estilo)` | Forma curta, como `1M` ou `2 milhões` (Java 12) |

Um detalhe que pega muita gente: vários formatos usam um **espaço especial**, o espaço que não quebra linha (o caractere 160 do Unicode), e o francês usa um espaço estreito (o 8239). Na tela parecem espaços comuns, mas não são: comparar o resultado com `"R$ 10,00"` digitado dá `false`. Os exemplos trocam esses caracteres por espaços comuns com o método `txt`, para a saída ser legível.

```java executar
import java.text.NumberFormat;
import java.util.List;
import java.util.Locale;

public class Formatos {
    static String txt(String s) {
        return s.replace((char) 160, ' ').replace((char) 0x202F, ' ');
    }

    public static void main(String[] args) {
        Locale br = Locale.forLanguageTag("pt-BR");
        double valor = 1234567.891;
        for (Locale l : List.of(Locale.US, br, Locale.GERMANY, Locale.FRANCE)) {
            System.out.println(l + ": " + txt(NumberFormat.getInstance(l).format(valor)) + " | " + txt(NumberFormat.getCurrencyInstance(l).format(valor)) + " | " + txt(NumberFormat.getPercentInstance(l).format(0.256)));
        }
        String moeda = NumberFormat.getCurrencyInstance(br).format(10);
        System.out.println(moeda.equals("R$ 10,00") + " " + (int) moeda.charAt(2));
        System.out.println(txt(NumberFormat.getCompactNumberInstance(Locale.US, NumberFormat.Style.SHORT).format(1_250_000)) + " | "
            + txt(NumberFormat.getCompactNumberInstance(br, NumberFormat.Style.SHORT).format(1_250_000)) + " | "
            + txt(NumberFormat.getCompactNumberInstance(br, NumberFormat.Style.LONG).format(2_000_000)));
    }
}
```

```saida
en_US: 1,234,567.891 | $1,234,567.89 | 26%
pt_BR: 1.234.567,891 | R$ 1.234.567,89 | 26%
de_DE: 1.234.567,891 | 1.234.567,89 € | 26 %
fr_FR: 1 234 567,891 | 1 234 567,89 € | 26 %
false 160
1M | 1 mi | 2 milhões
```

A moeda é a do **país** do `Locale`: real no Brasil, euro na Alemanha e na França. O formato de número comum mostra até três casas decimais; o de moeda usa as casas da moeda, duas para o real. A forma compacta arredonda: 1.250.000 vira `1M`.

## Casas decimais e arredondamento

Os objetos de `NumberFormat` são configuráveis com `setMinimumFractionDigits`, `setMaximumFractionDigits`, `setGroupingUsed` (os separadores de milhar) e `setRoundingMode`. O arredondamento padrão é o **`HALF_EVEN`**, o arredondamento bancário: no empate exato, vai para o vizinho **par**. Por isso `getIntegerInstance` formata 2,5 como `2` e 3,5 como `4`.

```java executar
import java.math.RoundingMode;
import java.text.NumberFormat;
import java.util.Locale;

public class Arredondando {
    public static void main(String[] args) {
        NumberFormat inteiro = NumberFormat.getIntegerInstance(Locale.US);
        System.out.println(inteiro.format(2.5) + " " + inteiro.format(3.5) + " " + inteiro.format(-2.5));

        NumberFormat f = NumberFormat.getInstance(Locale.US);
        System.out.println(f.format(1.23456) + " " + f.format(2.0) + " " + f.format(0.125));
        f.setMinimumFractionDigits(2);
        f.setMaximumFractionDigits(2);
        f.setRoundingMode(RoundingMode.HALF_UP);
        System.out.println(f.format(2.0) + " " + f.format(0.125) + " " + f.format(1234.5));
        f.setGroupingUsed(false);
        System.out.println(f.format(1234.5));
    }
}
```

```saida
2 4 -2
1.235 2 0.125
2.00 0.13 1,234.50
1234.50
```

## Lendo números: parse

`parse(texto)` faz o caminho inverso, com as regras do `Locale`, e devolve um `Number`. Três comportamentos caem em prova:

- O tipo devolvido depende do valor: um `Long` se o número for inteiro, um `Double` se não for.
- A leitura **para no primeiro caractere inválido** e devolve o que leu até ali: `"12abc"` vira 12, sem erro.
- Só se nada puder ser lido, ela lança `ParseException`, uma exceção **checked**. O formato de moeda exige o símbolo.

```java executar
import java.text.NumberFormat;
import java.text.ParseException;
import java.util.Locale;

public class Lendo {
    public static void main(String[] args) throws ParseException {
        NumberFormat us = NumberFormat.getInstance(Locale.US);
        Number a = us.parse("1,234.56");
        Number b = us.parse("1,000");
        Number c = NumberFormat.getInstance(Locale.forLanguageTag("pt-BR")).parse("1.234,56");
        Number d = us.parse("12abc");
        System.out.println(a + " " + a.getClass().getSimpleName() + " | " + b + " " + b.getClass().getSimpleName() + " | " + c + " | " + d);
        try {
            us.parse("abc");
        } catch (ParseException e) {
            System.out.println("ParseException na posição " + e.getErrorOffset());
        }
        try {
            NumberFormat.getCurrencyInstance(Locale.US).parse("12.50");
        } catch (ParseException e) {
            System.out.println("moeda sem símbolo não é aceita");
        }
        System.out.println(NumberFormat.getCurrencyInstance(Locale.US).parse("$12.50"));
    }
}
```

```saida
1234.56 Double | 1000 Long | 1234.56 | 12
ParseException na posição 0
moeda sem símbolo não é aceita
12.5
```

## DecimalFormat: padrões sob medida

Quando os formatos prontos não bastam, `DecimalFormat` recebe um **padrão**:

| Símbolo | Significa |
|---|---|
| `0` | Um dígito; mostra zero se não houver |
| `#` | Um dígito; omitido se for zero à esquerda ou à direita |
| `.` | Separador decimal |
| `,` | Separador de milhar |
| `%` | Multiplica por 100 e mostra o sinal |
| `¤` | Símbolo da moeda |

Os separadores do padrão são sempre `.` e `,`, mas o resultado usa os da localidade dos símbolos, informada com `DecimalFormatSymbols.getInstance(locale)`. Sem ela, vale o `Locale` padrão da máquina.

```java executar
import java.text.DecimalFormat;
import java.text.DecimalFormatSymbols;
import java.util.List;
import java.util.Locale;

public class Padroes {
    public static void main(String[] args) {
        DecimalFormatSymbols us = DecimalFormatSymbols.getInstance(Locale.US);
        for (String padrao : List.of("#,##0.00", "0000", "#.##", "0.0%", "000.###")) {
            DecimalFormat f = new DecimalFormat(padrao, us);
            System.out.println(padrao + " -> " + f.format(1234.5) + " / " + f.format(0.5));
        }
        System.out.println(new DecimalFormat("#,##0.00", DecimalFormatSymbols.getInstance(Locale.forLanguageTag("pt-BR"))).format(1234.5));
    }
}
```

```saida
#,##0.00 -> 1,234.50 / 0.50
0000 -> 1234 / 0000
#.## -> 1234.5 / 0.5
0.0% -> 123450.0% / 50.0%
000.### -> 1234.5 / 000.5
1.234,50
```

Repare em `0000`: sem casas decimais, 1234,5 é arredondado com `HALF_EVEN` para 1234, o par mais próximo. Os zeros do padrão `000.###` à esquerda aparecem; os `#` à direita, não.

Para dinheiro, há ainda a classe `Currency`: `Currency.getInstance(locale)` devolve a moeda do país, com `getCurrencyCode()` (`BRL`), `getSymbol(locale)` e `getDefaultFractionDigits()` (2 para o real, 0 para o iene). E os cálculos com dinheiro devem usar `BigDecimal`, não `double`: `0.1 + 0.2` em `double` dá `0.30000000000000004`.

> [!PROVA]
> `getInstance`, `getIntegerInstance`, `getCurrencyInstance`, `getPercentInstance` e `getCompactNumberInstance` (Java 12). O arredondamento padrão é `HALF_EVEN`. `parse` devolve `Number` (`Long` ou `Double`), para no primeiro caractere inválido e só lança `ParseException`, checked, se nada for lido. No `DecimalFormat`, `0` mostra zeros e `#` os omite.

## Por baixo dos panos

`NumberFormat.getInstance(locale)` não guarda regras no código: consulta um **provedor de dados de localidade**, que por padrão é o CLDR, e monta um `DecimalFormat` com o padrão e os símbolos daquele `Locale`. O padrão do Brasil para moeda é algo como `¤ #,##0.00`, e os símbolos dizem que o decimal é `,`, o milhar é `.` e o espaço depois do `¤` é o não separável. Por isso dá para inspecionar o padrão de qualquer formato pronto com `((DecimalFormat) formato).toPattern()`.

Instâncias de `NumberFormat` e `DecimalFormat` **não são thread-safe**: guardam estado interno durante a formatação, e uma mesma instância compartilhada entre threads pode produzir textos misturados. O certo é criar uma por uso, ou uma por thread. É um contraste com o `DateTimeFormatter` do Java 8, imutável e seguro para compartilhar.

## Resumo para a prova

- `NumberFormat` com `Locale`: números, inteiros, moeda, percentual e compactos
- Formatos usam o espaço não separável (caractere 160): não compare com texto digitado
- `setMinimumFractionDigits`, `setMaximumFractionDigits`, `setGroupingUsed`, `setRoundingMode`; padrão `HALF_EVEN`
- `parse` devolve `Long` ou `Double`, lê até o primeiro caractere inválido e lança `ParseException` (checked) se não ler nada
- `DecimalFormat`: `0` (dígito obrigatório), `#` (opcional), `,`, `.`, `%`, `¤`; símbolos com `DecimalFormatSymbols`
- `Currency` para código e casas da moeda; `BigDecimal` para cálculos com dinheiro
