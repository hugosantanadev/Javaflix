Ordenar é provavelmente o problema mais estudado da computação. Dados ordenados permitem busca binária, achar duplicatas, juntar listas e mostrar resultados que fazem sentido. Este episódio implementa quatro algoritmos clássicos, mede quanto cada um trabalha, prova o limite de quão rápido uma ordenação pode ser e mostra o que o `Arrays.sort` do Java usa de verdade.

## Duas propriedades que importam

Antes dos algoritmos, dois termos:

- **Estável**: elementos iguais mantêm a ordem em que estavam. Ordene pedidos por valor com um algoritmo estável e, entre pedidos de mesmo valor, a ordem anterior (por data, digamos) é preservada.
- **No lugar** (*in-place*): ordena dentro do próprio array, usando pouca memória extra.

## Bubble sort

Percorre o array comparando vizinhos e trocando os que estão fora de ordem. A cada passada, o maior elemento ainda desordenado "borbulha" até o fim. Se uma passada inteira não troca nada, o array já está ordenado e dá para parar.

```java
static void bubble(int[] a) {
    for (int fim = a.length - 1; fim > 0; fim--) {
        boolean trocou = false;
        for (int i = 0; i < fim; i++) {
            if (a[i] > a[i + 1]) {
                int t = a[i]; a[i] = a[i + 1]; a[i + 1] = t;
                trocou = true;
            }
        }
        if (!trocou) return;
    }
}
```

São (n − 1) + (n − 2) + ... + 1 = n(n − 1)/2 comparações no pior caso: O(n²). É estável e no lugar, mas é o algoritmo que ninguém usa na prática; serve para aprender.

## Insertion sort

Funciona como organizar cartas na mão: pegue o próximo elemento e deslize-o para a esquerda até encontrar a posição certa entre os já ordenados.

```java
static void insertion(int[] a) {
    for (int i = 1; i < a.length; i++) {
        int x = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > x) {
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = x;
    }
}
```

No pior caso (array invertido) também é O(n²). Mas num array **quase ordenado**, cada elemento anda pouco e o algoritmo vira praticamente O(n). Por isso o insertion sort ainda vive dentro das ordenações profissionais: elas o usam para pedaços pequenos.

## Merge sort: dividir para conquistar

O merge sort aplica a recursão do [episódio 1](/assistir/aprendiz-t4-e01): divida o array ao meio, ordene cada metade recursivamente e **intercale** (*merge*) as duas metades ordenadas. Intercalar duas listas ordenadas é fácil: compare os primeiros de cada uma e tire o menor, até acabar.

```java
static void mergeSort(int[] a, int[] aux, int ini, int fim) {
    if (fim - ini < 2) return;               // 0 ou 1 elemento: já ordenado
    int meio = (ini + fim) >>> 1;
    mergeSort(a, aux, ini, meio);
    mergeSort(a, aux, meio, fim);
    int i = ini, j = meio, k = ini;
    while (i < meio && j < fim) {
        aux[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
    }
    while (i < meio) aux[k++] = a[i++];
    while (j < fim) aux[k++] = a[j++];
    System.arraycopy(aux, ini, a, ini, fim - ini);
}
```

Por que é O(n log n)? Desenhe a árvore de chamadas: no topo, uma intercalação de n elementos; no nível de baixo, duas de n/2; depois, quatro de n/4. **Cada nível intercala n elementos no total**, e há log₂ n níveis até os pedaços terem tamanho 1. Total: n · log₂ n. Em forma de recorrência, T(n) = 2T(n/2) + n.

O merge sort é **estável** (o `<=` tira do lado esquerdo nos empates) e garante O(n log n) em qualquer caso. O preço é o array auxiliar: O(n) de memória extra.

## Quicksort

O quicksort escolhe um **pivô** e **particiona** o array: menores que o pivô à esquerda, maiores à direita. O pivô já fica na posição final, e cada lado é ordenado recursivamente.

```java
static void quick(int[] a, int ini, int fim) {    // ordena a[ini..fim]
    if (ini >= fim) return;
    int pivo = a[fim];
    int i = ini;
    for (int j = ini; j < fim; j++) {
        if (a[j] < pivo) {
            int t = a[i]; a[i] = a[j]; a[j] = t;
            i++;
        }
    }
    int t = a[i]; a[i] = a[fim]; a[fim] = t;   // pivô na posição final
    quick(a, ini, i - 1);
    quick(a, i + 1, fim);
}
```

Se o pivô divide o array mais ou menos ao meio, a conta é a mesma do merge sort: O(n log n). Se o pivô é sempre o menor ou o maior elemento, um lado fica vazio e o outro com n − 1: são n níveis e O(n²). Com o pivô no último elemento, como acima, isso acontece justamente com um array **já ordenado**. Implementações reais escolhem o pivô com mais cuidado (a mediana de três elementos, por exemplo). Na média, o quicksort é o mais rápido dos quatro: ordena no lugar e acessa a memória de forma sequencial, o que agrada ao cache. Não é estável.

## Medindo

Este programa conta as comparações de três algoritmos com 1.024 elementos, num array em ordem inversa e num já ordenado:

```java executar
public class Comparacoes {
    static long comps;

    static void bubble(int[] a) {
        for (int fim = a.length - 1; fim > 0; fim--) {
            boolean trocou = false;
            for (int i = 0; i < fim; i++) {
                comps++;
                if (a[i] > a[i + 1]) {
                    int t = a[i]; a[i] = a[i + 1]; a[i + 1] = t;
                    trocou = true;
                }
            }
            if (!trocou) return;
        }
    }

    static void insertion(int[] a) {
        for (int i = 1; i < a.length; i++) {
            int x = a[i];
            int j = i - 1;
            while (j >= 0) {
                comps++;
                if (a[j] <= x) break;
                a[j + 1] = a[j];
                j--;
            }
            a[j + 1] = x;
        }
    }

    static void merge(int[] a, int[] aux, int ini, int fim) {
        if (fim - ini < 2) return;
        int meio = (ini + fim) >>> 1;
        merge(a, aux, ini, meio);
        merge(a, aux, meio, fim);
        int i = ini, j = meio, k = ini;
        while (i < meio && j < fim) {
            comps++;
            aux[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
        }
        while (i < meio) aux[k++] = a[i++];
        while (j < fim) aux[k++] = a[j++];
        System.arraycopy(aux, ini, a, ini, fim - ini);
    }

    static long contar(String algoritmo, boolean invertido) {
        int n = 1024;
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = invertido ? n - i : i;
        comps = 0;
        switch (algoritmo) {
            case "bubble" -> bubble(a);
            case "insertion" -> insertion(a);
            default -> merge(a, new int[n], 0, n);
        }
        return comps;
    }

    public static void main(String[] args) {
        System.out.printf("%-10s %-10s %s%n", "algoritmo", "invertido", "ordenado");
        for (String alg : new String[] {"bubble", "insertion", "merge"}) {
            System.out.printf("%-10s %-10d %d%n", alg, contar(alg, true), contar(alg, false));
        }
    }
}
```

```saida
algoritmo  invertido  ordenado
bubble     523776     1023
insertion  523776     1023
merge      5120       5120
```

Os números batem com a teoria: 1024 × 1023 / 2 = 523.776 comparações para os quadráticos no pior caso, e só n − 1 quando o array já está em ordem. O merge sort faz 5.120 nos dois casos: 10 níveis (log₂ 1024) com 512 comparações cada. Cem vezes menos.

## O limite: n log n

Dá para ordenar com menos de n log n comparações? Não, se o algoritmo só puder **comparar** elementos. Um array de n elementos distintos pode estar em qualquer uma das n! ordens, e o algoritmo precisa descobrir qual. Cada comparação tem duas respostas, então k comparações distinguem no máximo 2ᵏ casos. Para cobrir n! casos, é preciso 2ᵏ ≥ n!, ou seja, k ≥ log₂(n!), que é aproximadamente n log₂ n. Para n = 1024, log₂(1024!) ≈ 8.769: o merge sort, com 5.120, está abaixo disso porque o array invertido é um caso favorável, mas nenhum algoritmo de comparação ordena **todo** array de 1.024 elementos com menos de 8.769 comparações no pior caso.

Algoritmos que não comparam, como o *counting sort* e o *radix sort*, escapam desse limite usando o valor dos elementos como índice, mas só funcionam para chaves pequenas, como inteiros numa faixa curta.

## O que o Java usa

| Método | Algoritmo | Estável |
|---|---|---|
| `Arrays.sort(int[])` e outros primitivos | Dual-Pivot Quicksort (com insertion sort em pedaços pequenos) | não precisa: dois `int` iguais são indistinguíveis |
| `Arrays.sort(Object[])`, `List.sort`, `Collections.sort` | TimSort, um merge sort adaptativo | sim, garantido pela documentação |

O **TimSort**, criado por Tim Peters para o Python em 2002, procura trechos já ordenados (*runs*) no array e os intercala. Dados reais quase sempre têm trechos assim, e nesses casos ele chega perto de O(n). Para objetos, a estabilidade importa, e é ela que permite ordenar por vários critérios:

```java executar
record Pedido(String cliente, int valor) {}

List<Pedido> pedidos = new ArrayList<>(List.of(
        new Pedido("Bia", 50), new Pedido("Ana", 30),
        new Pedido("Caio", 50), new Pedido("Duda", 30)));
pedidos.sort(Comparator.comparingInt(Pedido::valor));
System.out.println(pedidos.stream().map(Pedido::cliente).toList());
pedidos.sort(Comparator.comparingInt(Pedido::valor).reversed().thenComparing(Pedido::cliente));
System.out.println(pedidos.stream().map(Pedido::cliente).toList());
```

```saida
[Ana, Duda, Bia, Caio]
[Bia, Caio, Ana, Duda]
```

Na primeira ordenação, Ana veio antes de Duda e Bia antes de Caio porque essa era a ordem original: estabilidade. Na segunda, `thenComparing` desempata pelo nome.

## Resumo

| Algoritmo | Melhor | Médio | Pior | Memória extra | Estável |
|---|---|---|---|---|---|
| Bubble sort | O(n) | O(n²) | O(n²) | O(1) | sim |
| Insertion sort | O(n) | O(n²) | O(n²) | O(1) | sim |
| Merge sort | O(n log n) | O(n log n) | O(n log n) | O(n) | sim |
| Quicksort | O(n log n) | O(n log n) | O(n²) | O(log n) de pilha | não |

- Ordenação por comparação precisa de pelo menos log₂(n!) ≈ n log n comparações no pior caso
- Merge sort: T(n) = 2T(n/2) + n, log n níveis com n de trabalho cada
- Quicksort degenera para O(n²) com pivô ruim, como o último elemento num array ordenado
- Insertion sort é ótimo para arrays pequenos ou quase ordenados
- Java: Dual-Pivot Quicksort para primitivos; TimSort, estável, para objetos
