Redes sociais, mapas, links entre páginas, dependências entre bibliotecas, rotas de entrega: tudo isso é um **grafo**. Árvores e listas são casos particulares de grafo. Este episódio fecha a temporada com a estrutura mais geral de todas e com os dois algoritmos que percorrem qualquer grafo: a busca em largura (BFS) e a busca em profundidade (DFS). Com eles dá para achar o menor caminho, contar ilhas num mapa e descobrir a ordem de build de um projeto.

## O que é um grafo

Um grafo G = (V, E) é um conjunto de **vértices** (V) ligados por **arestas** (E). A teoria nasceu em 1736, quando Euler provou que era impossível atravessar as sete pontes de Königsberg passando por cada uma exatamente uma vez. As variações:

| Tipo | Arestas | Exemplo |
|---|---|---|
| Não dirigido | mão dupla | amizade numa rede social |
| Dirigido | mão única | "segue" no Instagram, dependência entre módulos |
| Com pesos | têm um custo | distância entre cidades, tempo de uma rota |

Duas contas úteis. Um grafo não dirigido com n vértices tem no máximo n(n − 1)/2 arestas, a [soma de Gauss](/assistir/aprendiz-t3-e05) de novo. E uma árvore é um grafo conexo sem ciclos, com exatamente n − 1 arestas.

## Como guardar um grafo

| Representação | Memória | "a e b são vizinhos?" | Percorrer vizinhos de a |
|---|---|---|---|
| Matriz de adjacência (`boolean[n][n]`) | O(V²) | O(1) | O(V) |
| Lista de adjacência (`Map<V, List<V>>`) | O(V + E) | O(grau de a) | O(grau de a) |

Grafos reais costumam ser **esparsos**: um milhão de usuários com 200 amigos cada. A matriz teria 10¹² células; a lista guarda só as 200 milhões de ligações. Em Java, a lista de adjacência sai em poucas linhas com `computeIfAbsent`.

## Busca em largura (BFS)

A **BFS** (*breadth-first search*) explora o grafo em camadas: primeiro o vértice inicial, depois todos os vizinhos dele, depois os vizinhos dos vizinhos. A ferramenta é uma [fila](/assistir/aprendiz-t4-e04): quem foi descoberto primeiro é visitado primeiro. Um conjunto (ou mapa) de visitados impede que um vértice entre duas vezes, o que, num grafo com ciclos, levaria a um laço infinito.

Como a BFS visita por distância crescente, ela encontra o **menor caminho em número de arestas**. Guardando de onde cada vértice foi descoberto (o "pai"), dá para reconstruir esse caminho de trás para a frente. Num grafo de amigos:

```text
Ana ── Bia ── Duda ── Fabi
 │             │       │
Caio ──────────┘       │
 │                     │
Edu ───────────────────┘
```

```java executar
import java.util.*;

public class Amigos {
    static Map<String, List<String>> grafo = new LinkedHashMap<>();

    static void ligar(String a, String b) {
        grafo.computeIfAbsent(a, k -> new ArrayList<>()).add(b);
        grafo.computeIfAbsent(b, k -> new ArrayList<>()).add(a);
    }

    static Map<String, String> largura(String inicio) {
        Map<String, String> pai = new LinkedHashMap<>();
        Deque<String> fila = new ArrayDeque<>();
        pai.put(inicio, null);
        fila.offer(inicio);
        while (!fila.isEmpty()) {
            String atual = fila.poll();
            for (String vizinho : grafo.get(atual)) {
                if (!pai.containsKey(vizinho)) {
                    pai.put(vizinho, atual);
                    fila.offer(vizinho);
                }
            }
        }
        return pai;
    }

    static void profundidade(String atual, Set<String> visitados, List<String> ordem) {
        visitados.add(atual);
        ordem.add(atual);
        for (String vizinho : grafo.get(atual)) {
            if (!visitados.contains(vizinho)) {
                profundidade(vizinho, visitados, ordem);
            }
        }
    }

    public static void main(String[] args) {
        ligar("Ana", "Bia");
        ligar("Ana", "Caio");
        ligar("Bia", "Duda");
        ligar("Caio", "Duda");
        ligar("Caio", "Edu");
        ligar("Duda", "Fabi");
        ligar("Edu", "Fabi");

        Map<String, String> pai = largura("Ana");
        System.out.println("BFS: " + String.join(" ", pai.keySet()));

        List<String> caminho = new ArrayList<>();
        for (String v = "Fabi"; v != null; v = pai.get(v)) {
            caminho.add(0, v);
        }
        System.out.println("Ana até Fabi: " + String.join(" -> ", caminho));

        List<String> ordem = new ArrayList<>();
        profundidade("Ana", new HashSet<>(), ordem);
        System.out.println("DFS: " + String.join(" ", ordem));
    }
}
```

```saida
BFS: Ana Bia Caio Duda Edu Fabi
Ana até Fabi: Ana -> Bia -> Duda -> Fabi
DFS: Ana Bia Duda Caio Edu Fabi
```

A BFS visitou primeiro os amigos diretos de Ana (Bia e Caio), depois os amigos de segundo grau (Duda e Edu), e por fim Fabi, a três passos. O caminho reconstruído tem 3 arestas, e nenhum é mais curto. É assim que uma rede social calcula "conexão de 2º grau", e é a mesma ideia que um GPS usa, em versão com pesos.

Repare que o vértice é marcado como visitado **quando entra na fila**, não quando sai. Marcando só na saída, o mesmo vértice poderia entrar várias vezes na fila antes de ser processado.

## Busca em profundidade (DFS)

A **DFS** (*depth-first search*) segue um caminho até não poder mais e só então volta para tentar outro: como explorar um labirinto com a mão sempre na parede. A ferramenta é uma pilha, e a pilha de chamadas da [recursão](/assistir/aprendiz-t4-e01) já serve. No exemplo, a DFS foi de Ana a Bia, de Bia a Duda, de Duda a Caio (o primeiro vizinho não visitado), de Caio a Edu e de Edu a Fabi, antes de voltar.

A DFS não acha menores caminhos, mas resolve outros problemas:

- **componentes conexos**: quantos "pedaços" separados o grafo tem;
- **detecção de ciclos**: chegar a um vértice que ainda está na pilha atual é um ciclo;
- **ordenação topológica**: a ordem de build de um projeto, como você vai ver no desafio;
- **labirintos e quebra-cabeças**, com o *backtracking* do episódio 1.

As duas buscas visitam cada vértice uma vez e olham cada aresta uma vez (duas, em grafos não dirigidos): **O(V + E)**.

## Grades são grafos

Um mapa em grade também é um grafo: cada célula é um vértice, ligado às vizinhas de cima, de baixo, da esquerda e da direita. O problema "Number of Islands" do LeetCode, resolvido no seu curso, pede para contar as ilhas (`#`) num mapa de água (`~`). A solução é percorrer a grade e, a cada terra ainda não visitada, contar uma ilha e "afundar" a ilha inteira com uma DFS:

```java executar
public class Ilhas {
    static void afundar(char[][] mapa, int l, int c) {
        if (l < 0 || c < 0 || l >= mapa.length || c >= mapa[0].length || mapa[l][c] != '#') {
            return;
        }
        mapa[l][c] = '~';
        afundar(mapa, l + 1, c);
        afundar(mapa, l - 1, c);
        afundar(mapa, l, c + 1);
        afundar(mapa, l, c - 1);
    }

    public static void main(String[] args) {
        String[] linhas = {
            "##~~~",
            "##~~#",
            "~~~##",
            "#~~~~",
            "#~#~#",
        };
        char[][] mapa = new char[linhas.length][];
        for (int i = 0; i < linhas.length; i++) {
            mapa[i] = linhas[i].toCharArray();
        }
        int ilhas = 0;
        for (int l = 0; l < mapa.length; l++) {
            for (int c = 0; c < mapa[0].length; c++) {
                if (mapa[l][c] == '#') {
                    ilhas++;
                    afundar(mapa, l, c);
                }
            }
        }
        System.out.println(ilhas);
    }
}
```

```saida
5
```

O bloco 2 × 2 do canto, o grupo em forma de L à direita, a coluna de dois no canto de baixo e duas ilhas de uma célula. Trocar o `'#'` por `'~'` é o "visitado", sem gastar memória extra. Esse algoritmo tem nome: *flood fill*, o balde de tinta dos editores de imagem.

## Próximos passos: pesos

Quando as arestas têm custo, o menor caminho não é mais o de menos arestas. O **algoritmo de Dijkstra** (1956) generaliza a BFS trocando a fila comum por uma [fila de prioridade](/assistir/aprendiz-t4-e05): sempre expande o vértice mais próximo ainda não fechado. O **A\*** acrescenta uma estimativa da distância até o destino e é a base da navegação em jogos e mapas. Os dois partem da mesma estrutura de BFS que você acabou de escrever.

## Resumo

- Grafo: vértices e arestas; dirigido ou não; com ou sem pesos
- Lista de adjacência: O(V + E) de memória, a escolha certa para grafos esparsos
- BFS: fila, visita em camadas, acha o menor caminho em número de arestas
- DFS: pilha ou recursão, vai fundo; componentes, ciclos, ordenação topológica
- Marque como visitado ao descobrir; sem marcação, grafos com ciclos não terminam
- As duas buscas são O(V + E)
- Grades são grafos implícitos; *flood fill* é uma DFS
- Com pesos: Dijkstra (fila de prioridade) e A*
