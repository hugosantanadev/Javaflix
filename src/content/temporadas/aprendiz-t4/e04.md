Arrays guardam elementos lado a lado na memória e dão acesso a qualquer posição em tempo constante. Mas muitos problemas não precisam de "qualquer posição": precisam do último que chegou, ou do primeiro da fila. Este episódio constrói as três estruturas lineares mais usadas, pilha, fila e lista ligada, mostra onde cada uma aparece por baixo dos panos e quais classes do Java usar para cada uma.

## Tipo abstrato e implementação

Um **tipo abstrato de dados** (TAD) define **o que** uma estrutura faz, sem dizer como. "Pilha" é um TAD: empilhar, desempilhar, olhar o topo. Uma implementação diz **como**: com um array, com nós ligados. Em Java, o TAD costuma ser uma interface (`Deque`, `Queue`, `List`) e a implementação, uma classe (`ArrayDeque`, `LinkedList`, `ArrayList`). Por isso o bom hábito é declarar a variável pela interface:

```java
Deque<String> pilha = new ArrayDeque<>();
Queue<Pedido> fila = new ArrayDeque<>();
```

## Pilha: o último a entrar é o primeiro a sair

![Os números 1, 2 e 3 entram numa pilha e numa fila: a pilha devolve primeiro o 3, pelo topo; a fila devolve primeiro o 1, pelo começo](/figuras/pilha-e-fila.svg "LIFO e FIFO com a mesma entrada.")

A **pilha** (*stack*) é LIFO (*last in, first out*): como uma pilha de pratos, só se mexe no topo. Três operações, todas O(1): `push` empilha, `pop` desempilha e `peek` olha o topo sem tirar.

Pilhas estão em todo lugar:

- a **pilha de chamadas** de toda thread, que você viu no [episódio de recursão](/assistir/aprendiz-t4-e01);
- o **desfazer** (Ctrl+Z) de editores: cada ação é empilhada, e desfazer é desempilhar;
- o botão **voltar** do navegador;
- a **máquina de pilha** da JVM, que avalia `a * b + c` empilhando operandos, como no [episódio da JVM](/assistir/aprendiz-t2-e04);
- a verificação de **parênteses balanceados**, que todo compilador faz:

```java executar
import java.util.ArrayDeque;
import java.util.Deque;

public class Balanceado {
    static boolean balanceado(String s) {
        Deque<Character> pilha = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            switch (c) {
                case '(', '[', '{' -> pilha.push(c);
                case ')', ']', '}' -> {
                    if (pilha.isEmpty()) {
                        return false;
                    }
                    char aberto = pilha.pop();
                    if ((c == ')' && aberto != '(') || (c == ']' && aberto != '[') || (c == '}' && aberto != '{')) {
                        return false;
                    }
                }
                default -> { }
            }
        }
        return pilha.isEmpty();
    }

    public static void main(String[] args) {
        for (String s : new String[] {"(a[b]{c})", "([)]", "((x)", "f(x) = {y[0]}"}) {
            System.out.println(s + " -> " + balanceado(s));
        }
    }
}
```

```saida
(a[b]{c}) -> true
([)] -> false
((x) -> false
f(x) = {y[0]} -> true
```

> [!PENSE]
> Antes de ver a explicação: por que uma pilha, e não um contador de parênteses abertos, é necessária para `([)]`?

Cada fechamento precisa casar com a abertura **mais recente** ainda aberta: é exatamente o que o topo da pilha guarda. Em `([)]`, o `)` chega quando o topo é `[`. Em `((x)`, sobra um `(` na pilha no fim.

> [!ATENCAO]
> Não use a classe `java.util.Stack`. Ela é da primeira versão do Java, estende `Vector`, tem todos os métodos sincronizados (lentos sem necessidade) e permite acessar qualquer posição, o que quebra a ideia de pilha. A própria documentação recomenda `Deque`, com `ArrayDeque` como implementação.

## Fila: o primeiro a entrar é o primeiro a sair

A **fila** (*queue*) é FIFO (*first in, first out*): entra no fim, sai do começo. Em Java, `offer` insere no fim, `poll` retira do começo e `peek` olha o começo. Filas aparecem em impressoras, em atendimento de requisições num servidor, em sistemas de mensageria (como o RabbitMQ do seu curso) e na busca em largura em grafos, assunto do [último episódio](/assistir/aprendiz-t4-e06).

A interface `Queue` tem dois jeitos de fazer cada operação:

| Operação | Lança exceção se não der | Devolve valor especial |
|---|---|---|
| Inserir | `add(e)` | `offer(e)`: `false` |
| Remover o primeiro | `remove()` | `poll()`: `null` |
| Olhar o primeiro | `element()` | `peek()`: `null` |

> [!CONVERSA]
> **Pilha:** Eu atendo quem chegou por último. Parece injusto, mas é exatamente o que um Ctrl+Z precisa.
>
> **Fila:** E eu atendo na ordem de chegada. É o que um servidor precisa para não deixar ninguém esperando para sempre.
>
> **Pilha:** E o `ArrayDeque`, de que lado está?
>
> **Fila:** Dos dois: ele mexe nas duas pontas em O(1). Use `push` e `pop` para ser pilha, `offer` e `poll` para ser fila, e nunca misture os dois pares.

Cuidado com a `PriorityQueue`: ela implementa `Queue`, mas **não é FIFO**. Sempre sai o menor elemento (ou o de maior prioridade, conforme o comparador):

```java executar
Queue<Integer> fila = new ArrayDeque<>(List.of(5, 1, 4));
Queue<Integer> prioridade = new PriorityQueue<>(List.of(5, 1, 4)); //> Sai sempre o menor, não o primeiro que entrou.
fila.offer(2);
prioridade.offer(2);
System.out.println(fila.poll() + " " + fila.poll());
System.out.println(prioridade.poll() + " " + prioridade.poll());

Deque<Integer> pilha = new ArrayDeque<>();
pilha.push(1);
pilha.push(2);
pilha.push(3);
System.out.println(pilha.pop() + " " + pilha.peek());
System.out.println(new ArrayDeque<Integer>().poll()); //> Fila vazia: poll devolve null, sem exceção.
```

```saida
5 1
1 2
3 2
null
```

> [!ERRO]
> Usar um `Deque` como fila e chamar `push` para inserir. O `push` põe o elemento na **frente**, e o `poll` também retira da frente: a "fila" vira pilha, e o último pedido é atendido primeiro. Para fila, `offer` (fim) e `poll` (começo); para pilha, `push` e `pop`, ambos na frente.

O `ArrayDeque` (*double-ended queue*, fila com duas pontas) serve como pilha e como fila ao mesmo tempo, porque insere e remove nas duas extremidades em O(1). Um detalhe: ele **não aceita `null`**, justamente porque `null` é o valor especial que `poll` e `peek` devolvem para dizer "vazio".

## Fila num array circular

Como uma fila num array consegue retirar do começo em O(1), sem deslocar todos os elementos? Com um **array circular**: o começo da fila é um índice que anda, e as posições dão a volta ao chegar no fim do array, com a [aritmética modular](/assistir/aprendiz-t3-e04). É assim que o `ArrayDeque` funciona por dentro:

```java executar
public class FilaCircular {
    private final int[] dados;
    private int inicio = 0;
    private int tamanho = 0;

    FilaCircular(int capacidade) {
        dados = new int[capacidade];
    }

    boolean oferecer(int x) {
        if (tamanho == dados.length) {
            return false;
        }
        dados[(inicio + tamanho) % dados.length] = x;
        tamanho++;
        return true;
    }

    int retirar() {
        int x = dados[inicio];
        inicio = (inicio + 1) % dados.length;
        tamanho--;
        return x;
    }

    public static void main(String[] args) {
        FilaCircular f = new FilaCircular(3);
        f.oferecer(10);
        f.oferecer(20);
        f.oferecer(30);
        System.out.println(f.oferecer(40));
        System.out.println(f.retirar() + " " + f.retirar());
        f.oferecer(40);
        f.oferecer(50);
        System.out.println(f.retirar() + " " + f.retirar() + " " + f.retirar());
        System.out.println("início em " + f.inicio);
    }
}
```

```saida
false
10 20
30 40 50
início em 2
```

> [!MATEMATICA]
> Por que o array circular importa: numa fila de 1.000.000 de pedidos feita com `ArrayList`, cada `remove(0)` desloca todos os outros, uns 1.000.000 de cópias. Atender todos custa 1.000.000 + 999.999 + ... + 1 ≈ 5 × 10¹¹ cópias, O(n²). Com o array circular, cada retirada só avança o índice `inicio`: 1.000.000 de operações no total, O(n).

Depois de retirar 10 e 20, o 40 e o 50 foram gravados nas posições 0 e 1, que tinham ficado livres: a fila "deu a volta" no array. O `ArrayDeque` real, quando enche, aloca um array do dobro do tamanho e copia tudo, com o mesmo custo amortizado O(1) do `ArrayList`.

## Lista ligada

Uma **lista ligada** (ou encadeada) guarda cada elemento num **nó** que aponta para o próximo. Os nós podem estar espalhados pela memória; a ordem vem das referências.

```text
cabeça
  │
  ▼
┌───┬───┐   ┌───┬───┐   ┌───┬───┐
│ 1 │ ●─┼──►│ 2 │ ●─┼──►│ 3 │ / │
└───┴───┘   └───┴───┘   └───┴───┘
```

> [!ANTES]
> As listas ligadas foram inventadas em 1955 por Allen Newell, Cliff Shaw e Herbert Simon, para a linguagem IPL, e viraram a estrutura central do Lisp em 1958. A pilha como ideia de computação foi proposta por Friedrich Bauer e Klaus Samelson em 1957, para avaliar expressões. No Java, `Stack` e `Vector` vêm da versão 1.0; `ArrayDeque` só chegou no Java 6, em 2006.

Inserir no começo é O(1): crie um nó que aponta para a cabeça atual. Achar o elemento de posição i é O(n): é preciso seguir i referências. Um exercício clássico de entrevista é **inverter** a lista mudando só as referências:

```java executar
public class ListaLigada {
    static class No {
        int valor;
        No proximo;

        No(int valor, No proximo) {
            this.valor = valor;
            this.proximo = proximo;
        }
    }

    static String mostrar(No cabeca) {
        StringBuilder sb = new StringBuilder();
        for (No n = cabeca; n != null; n = n.proximo) {
            sb.append(n.valor).append(n.proximo != null ? " -> " : "");
        }
        return sb.toString();
    }

    static No inverter(No cabeca) {
        No anterior = null;
        No atual = cabeca;
        while (atual != null) {
            No proximo = atual.proximo;
            atual.proximo = anterior;
            anterior = atual;
            atual = proximo;
        }
        return anterior;
    }

    public static void main(String[] args) {
        No lista = null;
        for (int v : new int[] {4, 3, 2, 1}) {
            lista = new No(v, lista);
        }
        System.out.println(mostrar(lista));
        lista = inverter(lista);
        System.out.println(mostrar(lista));
    }
}
```

```saida
1 -> 2 -> 3 -> 4
4 -> 3 -> 2 -> 1
```

A inversão anda pela lista uma vez, virando cada seta para trás: O(n) de tempo e O(1) de memória. A `LinkedList` do Java é **duplamente** ligada: cada nó aponta para o próximo e para o anterior, o que permite inserir e remover nas duas pontas em O(1).

## `ArrayList` ou `LinkedList`?

| Operação | `ArrayList` | `LinkedList` | `ArrayDeque` |
|---|---|---|---|
| `get(i)` | O(1) | O(n) | não tem |
| Inserir ou remover no fim | O(1) amortizado | O(1) | O(1) amortizado |
| Inserir ou remover no começo | O(n) | O(1) | O(1) |
| Inserir no meio, já tendo o nó | O(n) | O(1) | não tem |
| Memória por elemento | uma referência (4 bytes, em geral) | um nó com três referências (cerca de 24 bytes) | uma referência |

Pela tabela, a `LinkedList` parece ganhar nas inserções. Na prática, quase sempre perde. Os nós ficam espalhados pela memória, e cada passo da caminhada é uma provável falha de cache, enquanto o `ArrayList` percorre memória contígua, que o processador carrega em blocos (lembre da [hierarquia de memória](/assistir/aprendiz-t1-e04)). Até para inserir no meio, achar a posição custa O(n) na lista ligada, e copiar um bloco contíguo no array é muito rápido. A regra prática: `ArrayList` para listas, `ArrayDeque` para pilhas e filas, e `LinkedList` quase nunca.

> [!PERGUNTAS]
> **P:** Se a `LinkedList` quase sempre perde, por que ela ainda existe?
>
> **R:** Por compatibilidade e por casos raros: quando você já tem a referência para um nó e precisa remover ou inserir ali muitas vezes, como num cache LRU feito à mão. Mas a `LinkedList` do Java não expõe os nós, então até esse caso costuma usar outra estrutura, como o `LinkedHashMap`.

> [!IA]
> Código gerado por IA ainda usa `Stack<Integer>` e `LinkedList` como fila por hábito de material antigo. Também mistura `push` com `poll`, ou testa a fila vazia com `size() == 0` depois de um `pop` que já lançou exceção. Peça `Deque` com `ArrayDeque` e confira o par de métodos de cada uso.

## Na IDE

- **Classe obsoleta.** A inspeção "Use of obsolete collection type" marca `Stack` e `Vector` e sugere `ArrayDeque` e `ArrayList`.
- **Ver a estrutura.** No depurador, um `ArrayDeque` aparece com o array interno e os índices `head` e `tail`: dá para ver a fila dando a volta.
- **Interface na declaração.** **Alt + Enter** numa declaração `ArrayDeque<...> x = ...` oferece trocar o tipo da variável pela interface `Deque`.

## Resumo

- Pilha: LIFO, `push`/`pop`/`peek` em O(1); pilha de chamadas, desfazer, parênteses
- Fila: FIFO, `offer`/`poll`/`peek` em O(1); atendimento, mensageria, busca em largura
- Use `Deque` com `ArrayDeque` para os dois; evite `Stack`
- `poll` e `peek` devolvem `null` com a fila vazia; `remove`, `element` e `pop` lançam exceção
- `ArrayDeque` não aceita `null`; `PriorityQueue` não é FIFO
- Array circular: índices dão a volta com `% capacidade`
- Lista ligada: inserir no começo O(1), acessar a posição i O(n)
- Na prática, `ArrayList` e `ArrayDeque` vencem a `LinkedList` por causa do cache
