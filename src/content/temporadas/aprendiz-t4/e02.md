Procurar é a operação mais comum da computação: um usuário pelo e-mail, um produto pelo código, uma palavra no dicionário. Existem dois jeitos básicos de procurar num array, e a diferença entre eles é a diferença entre um milhão de passos e vinte. Este episódio mostra os dois, a matemática por trás e os detalhes que fazem a busca binária ser famosa por ter bugs.

## Busca linear

A busca linear (ou sequencial) olha um elemento de cada vez, do começo ao fim:

```java
static int buscaLinear(int[] v, int alvo) {
    for (int i = 0; i < v.length; i++) {
        if (v[i] == alvo) {
            return i;
        }
    }
    return -1;
}
```

| Caso | Comparações | Quando acontece |
|---|---|---|
| Melhor | 1 | o alvo é o primeiro |
| Pior | n | o alvo é o último ou não está |
| Médio | (n + 1)/2 | o alvo está, numa posição qualquer |

É O(n). A vantagem é que funciona com **qualquer** array, ordenado ou não, e com qualquer critério de igualdade. Ela está escondida em vários métodos do Java: `List.indexOf`, `List.contains`, `String.indexOf` e `Stream.filter(...).findFirst()` são todos buscas lineares.

## Busca binária

Se o array está **ordenado**, dá para fazer muito melhor. Compare o alvo com o elemento do meio: se for menor, ele só pode estar na metade da esquerda; se for maior, na da direita. Cada comparação descarta metade do que sobrou. É o que você faz ao procurar uma palavra num dicionário de papel.

O algoritmo mantém um **invariante**: se o alvo está no array, ele está entre as posições `inicio` e `fim`. Veja a busca pelo 23:

```java executar
public class BuscaBinaria {
    static int busca(int[] v, int alvo) {
        int inicio = 0;
        int fim = v.length - 1;
        while (inicio <= fim) {
            int meio = (inicio + fim) >>> 1;
            System.out.println("inicio=" + inicio + " fim=" + fim + " meio=" + meio + " valor=" + v[meio]);
            if (v[meio] == alvo) {
                return meio;
            } else if (v[meio] < alvo) {
                inicio = meio + 1;
            } else {
                fim = meio - 1;
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        int[] v = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
        System.out.println("achou na posição " + busca(v, 23));
    }
}
```

```saida
inicio=0 fim=9 meio=4 valor=16
inicio=5 fim=9 meio=7 valor=56
inicio=5 fim=6 meio=5 valor=23
achou na posição 5
```

Três comparações em vez de seis. Como cada volta corta o intervalo pela metade, o número de voltas é no máximo ⌊log₂ n⌋ + 1: 20 para um milhão de elementos, 30 para um bilhão. É O(log n), como você viu no episódio de [logaritmos](/assistir/aprendiz-t3-e05).

## Os bugs clássicos

Jon Bentley conta, no livro *Programming Pearls*, que deu a busca binária como exercício para programadores profissionais e cerca de 90% das soluções tinham erros. Os mais comuns:

| Erro | Consequência |
|---|---|
| `while (inicio < fim)` em vez de `<=` | não examina o último candidato: elementos presentes dão "não achou" |
| `inicio = meio` em vez de `meio + 1` | quando sobram dois elementos, o meio não muda e o laço nunca termina |
| `fim = v.length` com `<=` | lê a posição `v.length` e lança `ArrayIndexOutOfBoundsException` |
| `(inicio + fim) / 2` | a soma estoura com arrays de mais de um bilhão de posições |
| Array não ordenado | não dá erro nenhum: só devolve uma resposta errada |

O quarto foi o bug que ficou nove anos escondido no próprio JDK; você viu a matemática dele no episódio de [complemento de dois](/assistir/aprendiz-t3-e02). A forma segura é `(inicio + fim) >>> 1` ou `inicio + (fim - inicio) / 2`.

## A busca binária do Java

Não escreva a sua em código de produção: use `Arrays.binarySearch` (para arrays) e `Collections.binarySearch` (para listas). O detalhe é o valor de retorno quando o alvo **não** está: o método devolve `-(ponto de inserção) - 1`, em que o ponto de inserção é a posição onde o alvo deveria entrar para manter a ordem.

```java executar
int[] v = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
System.out.println(Arrays.binarySearch(v, 23));
System.out.println(Arrays.binarySearch(v, 20));
int r = Arrays.binarySearch(v, 20);
System.out.println(-r - 1);
System.out.println(Arrays.binarySearch(v, 100));
```

```saida
5
-6
5
-11
```

O 20 deveria ficar na posição 5 (antes do 23), então o retorno é −5 − 1 = −6. Por que o "−1"? Para que o ponto de inserção 0 também dê um número negativo: −0 seria 0, indistinguível de "achou na posição 0". Com esse retorno, um único método serve para buscar **e** para descobrir onde inserir mantendo a lista ordenada.

> [!ATENCAO]
> Se houver elementos repetidos, `Arrays.binarySearch` não garante **qual** das posições iguais devolve. E num array desordenado, o resultado é indefinido: pode dizer que um elemento presente não está lá.

## Busca binária na resposta

A ideia funciona com qualquer pergunta de "sim ou não" que muda de resposta uma única vez ao longo de um intervalo. A raiz quadrada inteira de n é o maior x com x² ≤ n: "x² ≤ n?" é sim para todo x pequeno e não a partir de certo ponto. Basta procurar a fronteira:

```java executar
public class Raiz {
    static long raiz(long n) {
        long inicio = 0;
        long fim = n;
        while (inicio < fim) {
            long meio = (inicio + fim + 1) >>> 1;
            if (meio * meio <= n) {
                inicio = meio;
            } else {
                fim = meio - 1;
            }
        }
        return inicio;
    }

    public static void main(String[] args) {
        System.out.println(raiz(10));
        System.out.println(raiz(1_000_000_000));
    }
}
```

```saida
3
31622
```

Aqui o laço é `inicio < fim` e o meio arredonda para **cima** (o `+ 1`), porque o intervalo guarda sempre um candidato válido em `inicio`; com o meio arredondado para baixo, o `inicio = meio` não sairia do lugar. Cada variante da busca binária tem o seu par de escolhas, e é por isso que ela engana tanto.

O mesmo raciocínio aparece fora do código. O `git bisect` encontra o commit que introduziu um bug fazendo busca binária no histórico: com 1.000 commits, basta testar uns 10.

## Quando usar cada uma

| Situação | Melhor escolha |
|---|---|
| Uma busca só, dados desordenados | busca linear, O(n): ordenar custaria O(n log n) |
| Muitas buscas nos mesmos dados | ordenar uma vez e usar busca binária: O(log n) cada |
| Muitas buscas e inserções | `HashSet`/`HashMap` (O(1) em média) ou `TreeSet`/`TreeMap` (O(log n), mantém a ordem) |
| Lista ligada | busca linear: chegar ao meio de uma `LinkedList` já custa O(n) |

A busca binária precisa de **acesso direto** a qualquer posição em tempo constante. Num array, `v[meio]` é uma conta de endereço; numa lista ligada, é uma caminhada.

## Resumo

- Busca linear: O(n), funciona com dados desordenados; está em `indexOf` e `contains`
- Busca binária: O(log n), exige dados ordenados e acesso direto por índice
- Invariante: se o alvo existe, está entre `inicio` e `fim`
- Use `<=` no laço, `meio + 1` e `meio - 1` nos cortes, e `(inicio + fim) >>> 1` no meio
- `Arrays.binarySearch` devolve `-(ponto de inserção) - 1` quando não acha
- Com repetidos, não há garantia de qual posição volta; com array desordenado, o resultado é indefinido
- Busca binária serve para qualquer pergunta "sim ou não" que muda uma vez num intervalo
