Antes de qualquer linguagem existir, já existiam algoritmos: o de Euclides tem mais de dois mil anos. Esta temporada é sobre eles e sobre as estruturas de dados que os sustentam, implementados em Java do zero. O ponto de partida é entender o que é um algoritmo, como descrevê-lo, como ter certeza de que ele está certo, e a ferramenta mais elegante para escrever vários deles: a **recursão**.

## O que é um algoritmo

Um algoritmo é uma sequência finita de passos bem definidos que transforma uma entrada numa saída. Donald Knuth, autor de *The Art of Computer Programming*, lista cinco propriedades:

| Propriedade | Significa | Contraexemplo |
|---|---|---|
| Finitude | termina depois de um número finito de passos | "repita até ficar bom" |
| Definição | cada passo tem um único significado | "adicione sal a gosto" |
| Entrada | recebe zero ou mais valores | |
| Saída | produz pelo menos um resultado | |
| Eficácia | cada passo pode ser feito, de fato, com lápis e papel | "escolha o número primo mais próximo do infinito" |

Uma receita de bolo quase é um algoritmo; o que falha é a definição. Um programa Java é um algoritmo escrito numa linguagem que a máquina entende.

## Pseudocódigo

Para pensar no algoritmo sem se prender à sintaxe, usa-se **pseudocódigo**: uma descrição estruturada, em português, que qualquer programador traduz para a sua linguagem. Para achar o maior valor de uma lista:

```text
função maior(v):
    maior ← v[0]
    para i de 1 até tamanho(v) − 1:
        se v[i] > maior:
            maior ← v[i]
    devolva maior
```

Em Java:

```java
static int maior(int[] v) {
    int maior = v[0];
    for (int i = 1; i < v.length; i++) {
        if (v[i] > maior) {
            maior = v[i];
        }
    }
    return maior;
}
```

Repare no que o pseudocódigo deixou de fora: tipos, `;`, chaves. E no que ele deixou claro: a lista não pode ser vazia, porque o algoritmo lê `v[0]`. Pensar no algoritmo antes do código revela os casos especiais.

## Como saber que um algoritmo está certo

Testes mostram que um algoritmo funciona para alguns casos. Para ter certeza para **todos**, usa-se um **invariante de laço**: uma afirmação que é verdadeira antes de cada volta. No `maior`, o invariante é "no começo da volta i, `maior` guarda o maior valor entre `v[0]` e `v[i − 1]`". A prova tem três partes:

1. **Inicialização**: antes da primeira volta (i = 1), `maior` é `v[0]`, o maior entre `v[0]` e `v[0]`. Verdade.
2. **Manutenção**: se vale no começo da volta i, a volta compara com `v[i]` e guarda o maior; então vale no começo da volta i + 1.
3. **Término**: o laço para com i = n. Pelo invariante, `maior` é o maior entre `v[0]` e `v[n − 1]`: a lista inteira.

É a **indução matemática** do ensino médio aplicada a código: um caso base e um passo que leva de um caso ao próximo. Essa mesma ideia é a chave para entender a recursão.

## Recursão

Uma função é **recursiva** quando chama a si mesma. Funciona quando cada chamada resolve um problema **menor** do mesmo tipo e existe um **caso base**, pequeno o bastante para ser resolvido direto. O fatorial é o exemplo clássico: n! = n × (n − 1)!, e 1! = 1.

Para ver o que acontece, este programa imprime cada chamada com recuo:

```java executar
public class Rastro {
    static int fatorial(int n, String recuo) {
        System.out.println(recuo + "fatorial(" + n + ")");
        int r = (n <= 1) ? 1 : n * fatorial(n - 1, recuo + "  ");
        System.out.println(recuo + "= " + r);
        return r;
    }

    public static void main(String[] args) {
        fatorial(4, "");
    }
}
```

```saida
fatorial(4)
  fatorial(3)
    fatorial(2)
      fatorial(1)
      = 1
    = 2
  = 6
= 24
```

A ida desce até o caso base; a volta faz as multiplicações. Cada chamada pendente fica guardada num **frame** na pilha de chamadas, com o seu próprio `n` e o seu próprio `r` (você viu essa pilha no episódio sobre [a CPU](/assistir/aprendiz-t1-e04)). Quando `fatorial(1)` retorna, o frame de `fatorial(2)` volta ao topo e continua de onde parou.

Para escrever uma função recursiva sem se perder, use o "salto de fé" da indução: **suponha que a chamada menor já funciona** e pense só em como usar o resultado dela. Para somar os dígitos de um número: se `somaDigitos(n / 10)` já dá a soma dos dígitos sem o último, basta somar `n % 10`.

## Sem caso base, a pilha estoura

Se o caso base nunca é alcançado, as chamadas se acumulam até a pilha da thread acabar, e a JVM lança `StackOverflowError`:

```java executar
public class SemFim {
    static int contar(int n) {
        return contar(n + 1);
    }

    public static void main(String[] args) {
        try {
            contar(0);
        } catch (StackOverflowError e) {
            System.out.println("StackOverflowError");
        }
    }
}
```

```saida
StackOverflowError
```

A pilha padrão de uma thread tem algo como 512 KB a 1 MB, o que costuma caber de alguns milhares a dezenas de milhares de chamadas, conforme o tamanho de cada frame. Outras linguagens fazem **otimização de chamada de cauda**: quando a chamada recursiva é a última coisa da função, reaproveitam o frame. **A JVM não faz isso.** Em Java, recursão muito profunda (percorrer uma lista de um milhão de nós, por exemplo) deve virar laço.

## A Torre de Hanói

Mova uma pilha de n discos da haste A para a C, usando B como apoio, sem nunca pôr um disco maior sobre um menor. A solução iterativa é difícil de enxergar; a recursiva cabe em três linhas: mova n − 1 discos de A para B, mova o maior de A para C, e mova os n − 1 de B para C.

```java executar
public class Hanoi {
    static int movimentos = 0;

    static void mover(int n, char de, char para, char via) {
        if (n == 0) {
            return;
        }
        mover(n - 1, de, via, para);
        movimentos++;
        System.out.println("disco " + n + ": " + de + " -> " + para);
        mover(n - 1, via, para, de);
    }

    public static void main(String[] args) {
        mover(3, 'A', 'C', 'B');
        System.out.println(movimentos + " movimentos");
    }
}
```

```saida
disco 1: A -> C
disco 2: A -> B
disco 1: C -> B
disco 3: A -> C
disco 1: B -> A
disco 2: B -> C
disco 1: A -> C
7 movimentos
```

Quantos movimentos para n discos? O código responde com uma **recorrência**: M(n) = 2 · M(n − 1) + 1, com M(0) = 0. Calculando: 1, 3, 7, 15, 31... é sempre **2ⁿ − 1**, e dá para provar por indução: se M(n − 1) = 2ⁿ⁻¹ − 1, então M(n) = 2 · (2ⁿ⁻¹ − 1) + 1 = 2ⁿ − 1. Com 64 discos, como na lenda, a um movimento por segundo, seriam quase 585 bilhões de anos.

## Memoização: não calcule duas vezes

O Fibonacci recursivo ingênuo, que você mediu no episódio de [Big-O](/assistir/aprendiz-t3-e05), recalcula os mesmos valores milhões de vezes. A correção é guardar cada resultado na primeira vez que ele é calculado, a **memoização**:

```java executar
public class FibMemo {
    static long[] memo = new long[91];
    static int chamadas = 0;

    static long fib(int n) {
        chamadas++;
        if (n < 2) {
            return n;
        }
        if (memo[n] != 0) {
            return memo[n];
        }
        memo[n] = fib(n - 1) + fib(n - 2);
        return memo[n];
    }

    public static void main(String[] args) {
        System.out.println(fib(40) + " em " + chamadas + " chamadas");
    }
}
```

```saida
102334155 em 79 chamadas
```

Sem memória seriam 331.160.281 chamadas. Com ela, cada valor de 2 a 40 é calculado uma vez e faz duas chamadas: 39 × 2 + 1 = 79. Isso é o começo da **programação dinâmica**: resolver um problema grande combinando soluções de subproblemas que se repetem, sem refazê-las. O problema "Climbing Stairs" do LeetCode, resolvido no seu curso, é este Fibonacci disfarçado.

## Recursão ou laço?

| | Recursão | Laço |
|---|---|---|
| Clareza | ótima para problemas que se dividem em partes do mesmo tipo (árvores, Hanói, ordenação) | ótima para percorrer sequências |
| Memória | O(profundidade) na pilha | O(1) extra |
| Risco | `StackOverflowError` em profundidade grande | laço infinito |
| Em Java | sem otimização de cauda | sem custo de chamada |

Todo laço pode ser escrito como recursão e vice-versa (com uma pilha explícita). Nos próximos episódios, a recursão vai aparecer onde ela brilha: na busca binária, no merge sort, no quicksort, nas árvores e na busca em profundidade.

## Resumo

- Algoritmo: passos finitos e bem definidos, com entrada e saída
- Pseudocódigo descreve a ideia sem a sintaxe e revela casos especiais
- Invariante de laço: inicialização, manutenção e término; é indução aplicada a código
- Recursão precisa de caso base e de chamadas com problemas menores
- Cada chamada ocupa um frame na pilha; sem caso base, `StackOverflowError`
- A JVM não otimiza chamadas de cauda: recursão profunda vira laço
- Hanói: M(n) = 2M(n − 1) + 1 = 2ⁿ − 1
- Memoização guarda resultados de subproblemas: o começo da programação dinâmica
