Funções que recebem e devolvem funções são o coração da programação funcional. No Java, elas aparecem nos métodos `default` das interfaces funcionais, como `andThen` e `negate`, e em métodos seus que devolvem lambdas. Este episódio fecha a temporada com a composição: a ordem de aplicação, o curto-circuito dos predicados, e como montar comportamento a partir de peças pequenas.

## Function: andThen e compose

`f.andThen(g)` cria uma função que aplica `f` e depois `g` ao resultado. `f.compose(g)` faz o contrário: aplica `g` primeiro e entrega o resultado a `f`. Em notação matemática, `f.compose(g)` é f(g(x)), e `f.andThen(g)` é g(f(x)).

```java executar
import java.util.function.Function;

public class Composicao {
    public static void main(String[] args) {
        Function<Integer, Integer> dobro = x -> x * 2;
        Function<Integer, Integer> mais3 = x -> x + 3;
        System.out.println(dobro.andThen(mais3).apply(5));
        System.out.println(dobro.compose(mais3).apply(5));
        System.out.println(mais3.andThen(dobro).andThen(dobro).apply(1));

        Function<String, Integer> tamanho = String::length;
        Function<String, String> descrever = tamanho.andThen(n -> "tamanho " + n);
        System.out.println(descrever.apply("java"));
    }
}
```

```saida
13
16
16
tamanho 4
```

Em `dobro.andThen(mais3)`, 5 vira 10 e depois 13. Em `dobro.compose(mais3)`, 5 vira 8 e depois 16. A composição pode mudar o tipo: `tamanho.andThen(...)` vai de `String` para `Integer` e depois para `String`. O tipo do resultado é sempre uma `Function`: compor dois `UnaryOperator` com `andThen` não devolve um `UnaryOperator`, e atribuir o resultado a um não compila.

## Predicate: and, or, negate e o curto-circuito

`and`, `or` e `negate` combinam predicados com a lógica booleana, e `and` e `or` seguem o **curto-circuito** de `&&` e `||`: o segundo predicado só é avaliado se o primeiro não decidir sozinho.

```java executar
import java.util.function.Predicate;

public class Logica {
    public static void main(String[] args) {
        Predicate<Integer> positivo = n -> {
            System.out.print("positivo? ");
            return n > 0;
        };
        Predicate<Integer> par = n -> {
            System.out.print("par? ");
            return n % 2 == 0;
        };
        System.out.println(positivo.and(par).test(-2));
        System.out.println(positivo.or(par).test(4));
        System.out.println(positivo.and(par).negate().test(3));
    }
}
```

```saida
positivo? false
positivo? true
positivo? par? true
```

Com -2, `positivo` já dá `false`, e `and` nem pergunta se é par. Com 4, `positivo` dá `true`, e `or` também para. Com 3, os dois são avaliados, o `and` dá `false`, e o `negate` inverte.

Encadeamentos longos seguem a ordem das chamadas, da esquerda para a direita, sem a precedência de `&&` sobre `||`: `a.and(b).or(c)` é `(a && b) || c`, e `a.or(b).and(c)` é `(a || b) && c`.

## Consumer e BiFunction

`Consumer.andThen` executa os dois consumidores em sequência, com o mesmo argumento. `BiFunction.andThen` recebe uma `Function` que transforma o resultado. Não existe `compose` em `BiFunction`, nem `andThen` em `Supplier`.

```java executar
import java.util.ArrayList;
import java.util.List;
import java.util.function.BiFunction;
import java.util.function.Consumer;

public class Sequencias {
    public static void main(String[] args) {
        Consumer<List<String>> a = l -> l.add("a");
        Consumer<List<String>> b = l -> l.add("b");
        List<String> lista = new ArrayList<>();
        a.andThen(b).andThen(a).accept(lista);
        System.out.println(lista);

        BiFunction<Integer, Integer, Integer> soma = Integer::sum;
        System.out.println(soma.andThen(x -> x * 10).apply(2, 3));
    }
}
```

```saida
[a, b, a]
50
```

> [!PROVA]
> `f.andThen(g)` aplica `f` primeiro; `f.compose(g)` aplica `g` primeiro. `and` e `or` param no primeiro predicado que decidir. `compose` existe em `Function` (e em `UnaryOperator`, que a herda) e nos operadores unários primitivos, como `IntUnaryOperator`; `BiFunction` não tem `compose`, e `Supplier` não tem `andThen`.

## Funções que criam funções

Um método pode devolver uma lambda montada com os seus parâmetros. É a forma de criar famílias de funções parecidas, e de aplicar uma função "por partes", o *currying*:

```java executar
import java.util.List;
import java.util.function.Function;

public class Fabricas {
    static Function<Integer, Integer> somar(int n) {
        return x -> x + n;
    }

    public static void main(String[] args) {
        Function<Integer, Function<Integer, Integer>> multiplicar = x -> y -> x * y;
        Function<Integer, Integer> triplo = multiplicar.apply(3);
        System.out.println(triplo.apply(4) + " " + somar(10).apply(5));

        List<Function<Integer, Integer>> etapas = List.of(x -> x * 2, somar(3), x -> x * 2);
        Function<Integer, Integer> pipeline = Function.identity();
        for (Function<Integer, Integer> etapa : etapas) {
            pipeline = pipeline.andThen(etapa);
        }
        System.out.println(pipeline.apply(1));
    }
}
```

```saida
12 15
10
```

`x -> y -> x * y` é uma função que recebe `x` e devolve outra função, que recebe `y`. O laço monta um *pipeline* a partir de uma lista de etapas, começando pela identidade, a função neutra. Repare que `pipeline` é reatribuída a cada volta: ela não é capturada por nenhuma lambda, então pode mudar.

## Por baixo dos panos

Os métodos de composição são métodos `default` curtos. O `andThen` de `Function` é, em essência:

```java compila
import java.util.Objects;
import java.util.function.Function;

interface MinhaFuncao<T, R> extends Function<T, R> {
    default <V> Function<T, V> depois(Function<? super R, ? extends V> proxima) {
        Objects.requireNonNull(proxima);
        return (T t) -> proxima.apply(apply(t));
    }
}
```

A lambda devolvida captura `this` e a `proxima`: compor não executa nada, só cria um objeto novo que guarda as duas funções. Cada composição acrescenta uma camada de chamadas, e por isso cadeias muito longas de `andThen` custam uma chamada a mais por etapa. O `Objects.requireNonNull` faz um `andThen(null)` falhar na hora da composição, e não mais tarde, quando a função for usada. Repare também no PECS da [temporada de generics](/assistir/pleno-t2-e05): a próxima função consome um `R` (`? super R`) e produz um `V` (`? extends V`).

Essa forma de programar, em que o comportamento é montado combinando funções, é a base dos streams, assunto da próxima temporada: cada `filter` e cada `map` é uma etapa de um pipeline, executada só quando alguém pede o resultado.

## Resumo para a prova

- `f.andThen(g)` = g(f(x)); `f.compose(g)` = f(g(x))
- `Predicate`: `and`, `or`, `negate`, com curto-circuito; `Predicate.not` como fábrica estática
- `Consumer.andThen` executa em sequência; `BiFunction.andThen` recebe uma `Function`
- Compor dois `UnaryOperator` devolve uma `Function`; `Supplier` não tem `andThen`
- Métodos podem devolver lambdas; `x -> y -> ...` é uma função que devolve função
- `andThen(null)` lança `NullPointerException` na composição
