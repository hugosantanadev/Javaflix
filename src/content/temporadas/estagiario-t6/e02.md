Uma planilha, um tabuleiro, uma imagem, a tabela de horários de uma escola: muita coisa tem linhas e colunas. Em Java, isso se representa com um **array de arrays**. O nome oficial é array multidimensional, mas a linguagem não tem uma matriz de verdade: cada linha é um array separado, e é daí que vêm as possibilidades, como linhas de tamanhos diferentes, e as armadilhas.

## Criar e acessar

`new int[2][3]` cria um array com 2 posições, e cada posição guarda um `int[]` de 3 posições. O primeiro índice escolhe a linha; o segundo, a coluna dentro dela:

```java executar
int[][] m = new int[2][3]; //> 2 linhas, cada uma um int[] de 3 posições.
m[1][2] = 9; //> Primeiro a linha, depois a coluna.
System.out.println(m.length + " " + m[0].length + " " + m[1][2]);
System.out.println(Arrays.deepToString(m));
```

```saida
2 3 9
[[0, 0, 0], [0, 0, 9]]
```

`m.length` é o número de **linhas**, e `m[i].length` é o tamanho da linha `i`. Para imprimir, `Arrays.toString(m)` não basta: ele chamaria o `toString` de cada linha e mostraria algo como `[[I@1b6d3586, [I@4554617c]`. É o `Arrays.deepToString` que desce nos arrays internos.

## Declarar

As regras dos colchetes do [episódio anterior](/assistir/estagiario-t6-e01) continuam valendo, agora com mais pares. Todas estas formas declaram um `int[][]`, e a última linha mistura um `int[]` com um `int[][]`:

```java executar
int[][] a = new int[2][2];
int b[][] = new int[2][3];
int[] c[] = new int[2][4];
int[] d, e[]; //> O [] do tipo vale para os dois; e ganha mais um: int[][].
d = new int[1];
e = new int[2][5];
System.out.println(a[0].length + b[0].length + c[0].length + e[1].length + d.length);
```

```saida
15
```

O atalho com chaves também funciona, com uma chave por linha:

```java
int[][] velha = {
    {1, 0, 2},
    {0, 1, 2},
    {0, 0, 1}
};
```

## Linhas de tamanhos diferentes

Só a **primeira** dimensão é obrigatória na criação. `new int[3][]` cria as 3 linhas como `null`, e cada uma pode receber depois um array de qualquer tamanho. É o array *irregular*, ou *jagged*.

![À esquerda, new int[3][] com as três posições valendo null; à direita, o array notas com três referências apontando para linhas separadas de tamanhos 2, 1 e 3](/figuras/array-de-arrays.svg "Cada linha é um array independente, com o próprio length. O array externo só guarda as setas.")

> [!PENSE]
> Antes do laço abaixo, o array tem 3 linhas, mas nenhuma foi criada. O que o primeiro `println` vai mostrar?

```java executar
int[][] triangulo = new int[3][];
System.out.println(triangulo[0]);
for (int i = 0; i < triangulo.length; i++) {
    triangulo[i] = new int[i + 1];
    for (int j = 0; j < triangulo[i].length; j++) {
        triangulo[i][j] = i + 1;
    }
}
System.out.println(Arrays.deepToString(triangulo));
int[][] notas = {{7, 8}, {5}, {9, 10, 6}};
System.out.println(notas[2].length + " " + notas[1][0]);
```

```saida
null
[[1], [2, 2], [3, 3, 3]]
3 5
```

Informar só a segunda dimensão não faz sentido, porque não haveria onde guardar as linhas, e não compila:

```java nao-compila
int[][] m = new int[][3];
```

> [!ERRO]
> Usar o número de linhas como limite das colunas: `for (int j = 0; j < m.length; j++)` dentro do laço das linhas. Numa matriz quadrada passa despercebido; numa retangular ou irregular, lança `ArrayIndexOutOfBoundsException` ou deixa colunas de fora. O limite das colunas é sempre o tamanho da linha atual, `m[i].length`.

> [!PROVA]
> Num array criado com `new int[3][]`, acessar `m[0][0]` lança `NullPointerException`, não `ArrayIndexOutOfBoundsException`: a linha 0 ainda não existe. E num array irregular, usar `m.length` como limite das colunas é erro: o certo é sempre `m[i].length`.

## Percorrer

Dois laços aninhados, como no episódio de [laços aninhados](/assistir/estagiario-t4-e05). Com for-each, a variável do laço externo é uma **linha inteira**, do tipo `int[]`:

```java executar
int[][] vendas = {
    {10, 20, 30},
    {5, 15},
    {40}
};
int total = 0;
for (int[] linha : vendas) {
    int somaLinha = 0;
    for (int valor : linha) {
        somaLinha += valor;
    }
    System.out.println(Arrays.toString(linha) + " = " + somaLinha);
    total += somaLinha;
}
System.out.println("Total: " + total);
```

```saida
[10, 20, 30] = 60
[5, 15] = 20
[40] = 40
Total: 120
```

Como cada linha é um objeto, ela pode ser guardada numa variável, trocada por outra ou até compartilhada entre duas posições. Trocar duas linhas de lugar custa só a troca de duas referências, por maior que elas sejam. Mais dimensões seguem a mesma lógica: `new int[2][3][4]` é um array de 2 posições, cada uma com um `int[3][4]`, num total de 24 números.

> [!LAPIS]
> Qual é a saída?
>
> ```java
> int[][] m = new int[2][2];
> m[1] = m[0];
> m[0][1] = 5;
> System.out.println(m[1][1] + " " + Arrays.deepToString(m));
> ```
>
> **Resposta:** `5 [[0, 5], [0, 5]]`. Depois de `m[1] = m[0]`, as duas posições do array externo apontam para a **mesma** linha. Escrever em `m[0][1]` é escrever em `m[1][1]`. A linha original de `m[1]` ficou sem referência e vai para o coletor de lixo.

> [!ANTES]
> O Fortran, de 1957, guarda as matrizes coluna por coluna; o C, de 1972, linha por linha. Quem traduzia código numérico de uma linguagem para a outra precisava inverter a ordem dos laços para não perder desempenho, e bibliotecas como a LAPACK ainda pedem matrizes "no formato do Fortran". O Java, de 1995, não escolheu nenhum dos dois: não tem matriz, só arrays de arrays.

> [!CONVERSA]
> **Matriz do C:** Eu sou um bloco só. Doze inteiros seguidos, e qualquer posição sai de uma conta.
>
> **Array de arrays do Java:** E eu sou quatro objetos: o externo e três linhas. Para ler `m[i][j]`, busco a linha e depois o número.
>
> **Matriz do C:** Dois acessos? Eu faço com um.
>
> **Array de arrays do Java:** Mas eu tenho linhas de tamanhos diferentes, troco duas linhas de lugar trocando duas setas, e confiro cada índice. Você deixa ler fora do bloco sem reclamar.
>
> **Matriz do C:** Quem precisa de velocidade em Java acaba me imitando: um array só e a conta `i × colunas + j`.

## Por baixo dos panos

Em C, `int m[3][4]` reserva 12 inteiros seguidos na memória, e `m[i][j]` é uma conta só: início + (i × 4 + j) × 4 bytes. Em Java, `new int[3][4]` cria **quatro** objetos: o array externo, com 3 referências, e as 3 linhas, cada uma num lugar do heap. A JVM tem até uma instrução própria para isso, a `multianewarray`. Ler `m[i][j]` são dois acessos: primeiro busca a linha, depois o elemento, cada um com sua verificação de índice.

Dentro de cada linha, os números ficam lado a lado. Por isso a ordem dos laços importa: percorrer linha por linha (`j` no laço de dentro) lê a memória em sequência e aproveita o [cache](/assistir/aprendiz-t1-e04); percorrer coluna por coluna salta de linha em linha a cada leitura. Em matrizes grandes, a diferença chega a várias vezes, com o mesmo número de operações. Quando o desempenho importa, como em processamento de imagens, é comum guardar a matriz num array só e fazer a conta do C à mão:

```java executar
int linhas = 3, colunas = 4;
int[] plano = new int[linhas * colunas];
for (int i = 0; i < linhas; i++) {
    for (int j = 0; j < colunas; j++) {
        plano[i * colunas + j] = i * 10 + j;
    }
}
System.out.println(plano[2 * colunas + 3] + " " + plano.length);
```

```saida
23 12
```

> [!MATEMATICA]
> No array plano, a posição de `(i, j)` é `k = i × colunas + j`. O caminho de volta usa a divisão inteira e o resto, da [aritmética modular](/assistir/aprendiz-t3-e04): `i = k / colunas` e `j = k % colunas`. Com 4 colunas, a posição 11 é a linha 11 / 4 = **2**, coluna 11 % 4 = **3**: o mesmo `23` do exemplo. E a economia: `new int[1000][1000]` cria 1001 objetos, com 1001 cabeçalhos de 16 bytes; `new int[1_000_000]` cria um só.

> [!DESEMPENHO]
> Percorra matrizes com o índice da linha no laço de fora. Se o código faz muitas leituras em matrizes grandes, considere o array plano com `i × colunas + j`: um acesso em vez de dois, e os dados todos contíguos na memória.

> [!IA]
> Ao gerar código com matrizes, a IA costuma usar `m.length` para as duas dimensões quando o exemplo é quadrado, e o erro só aparece com uma matriz retangular. Também é comum ela imprimir com `Arrays.toString(m)`. Teste o código dela com uma matriz de 2 × 3 e com uma irregular.

## Na IDE

- **Impressão errada.** O IntelliJ marca `Arrays.toString(m)` com uma matriz e sugere `Arrays.deepToString(m)` pelo **Alt + Enter**.
- **Ver as linhas.** No depurador, `m` aparece como `int[3][]`; ao expandir, cada linha mostra o próprio tamanho, e uma linha `null` aparece como `null`.
- **Laço pronto.** Digite `itar` e **Tab** para gerar um laço com índice sobre o array; dentro dele, outro `itar` sobre `m[i]` monta o interno.

## Resumo para a prova

- `int[][]`, `int[] m[]` e `int m[][]` são o mesmo tipo; `int[] a, b[]` faz `b` ser `int[][]`
- `m.length` é o número de linhas; `m[i].length`, o tamanho da linha `i`
- `new int[3][]` compila e deixa as linhas `null`; `new int[][3]` não compila
- Linhas podem ter tamanhos diferentes (arrays irregulares)
- No for-each externo, a variável é uma linha: `for (int[] linha : m)`
- `Arrays.deepToString` imprime o conteúdo; `Arrays.toString` mostra só as referências das linhas
- `new int[3][4]` cria 4 objetos; percorrer linha por linha aproveita o cache
