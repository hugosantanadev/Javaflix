Ordenar, buscar, comparar, preencher e copiar: quase tudo o que se faz com arrays já está pronto em `java.util.Arrays`, uma classe só de métodos estáticos. A prova cobra o comportamento exato de cada um, inclusive nos casos estranhos: o número negativo que o `binarySearch` devolve, o sinal do `compare` e a lista de tamanho fixo do `asList`.

## Ordenar e buscar

`Arrays.sort` ordena **o próprio array**, sem devolver nada. Números vão em ordem crescente; textos, na ordem natural da `String`, que compara os códigos dos caracteres: dígitos antes de maiúsculas, maiúsculas antes de minúsculas.

`Arrays.binarySearch` faz a [busca binária](/assistir/aprendiz-t4-e02) e só funciona num array **já ordenado**. Se encontra o valor, devolve o índice. Se não encontra, devolve um número negativo que diz onde ele deveria entrar: `-(ponto de inserção) - 1`. O `- 1` existe para que "deveria entrar na posição 0" não seja confundido com "encontrei na posição 0".

```java executar
int[] numeros = {42, 7, 19, 3, 25};
Arrays.sort(numeros); //> Ordena o próprio array e não devolve nada.
System.out.println(Arrays.toString(numeros));
System.out.println(Arrays.binarySearch(numeros, 19));
System.out.println(Arrays.binarySearch(numeros, 20)); //> Não achou: entraria na posição 3, então -3 - 1.
System.out.println(Arrays.binarySearch(numeros, 1));
String[] palavras = {"banana", "Abacaxi", "10", "abacate", "9"};
Arrays.sort(palavras);
System.out.println(Arrays.toString(palavras));
```

```saida
[3, 7, 19, 25, 42]
2
-4
-1
[10, 9, Abacaxi, abacate, banana]
```

O 20 deveria ficar na posição 3, entre o 19 e o 25: o resultado é -3 - 1 = -4. O 1 deveria ficar na posição 0: -0 - 1 = -1. E `"10"` vem antes de `"9"` porque a comparação é caractere a caractere, e `'1'` vem antes de `'9'`.

![A busca binária do 20 no array ordenado em três passos: o meio 2 vale 19 e a busca vai para a direita; o meio 3 vale 25 e a busca vai para a esquerda; o intervalo fica vazio, e uma marca entre o 19 e o 25 mostra o ponto de inserção 3](/figuras/busca-binaria-insercao.svg "Quando a busca termina sem achar, o início do intervalo é exatamente onde o valor entraria.")

> [!LAPIS]
> Com `int[] v = {2, 4, 6, 8};`, o que devolvem `Arrays.binarySearch(v, 5)`, `Arrays.binarySearch(v, 10)` e `Arrays.binarySearch(v, 2)`?
>
> **Resposta:** `-3`, `-5` e `0`. O 5 entraria na posição 2, entre o 4 e o 6: -2 - 1 = -3. O 10 entraria no fim, na posição 4: -4 - 1 = -5. E o 2 está na posição 0. Para voltar do negativo ao ponto de inserção, faça `-resultado - 1`.

> [!MATEMATICA]
> Cada passo da busca binária descarta metade do que sobrou, então, no pior caso, ela faz ⌊log₂ n⌋ + 1 comparações. Com 5 elementos, ⌊log₂ 5⌋ + 1 = 2 + 1 = **3**, os três passos da figura. Com um milhão de elementos, ⌊log₂ 1.000.000⌋ + 1 = 19 + 1 = **20** comparações, contra até um milhão de uma busca que olha um por um.

> [!PROVA]
> Se o array não estiver ordenado, o resultado do `binarySearch` é **indefinido**: pode ser qualquer número. Quando uma questão chama `binarySearch` num array fora de ordem, a resposta certa é "o resultado não é previsível", não um índice calculado. E com valores repetidos, não há garantia de qual das posições é devolvida.

`sort` e `fill` também aceitam um intervalo: `Arrays.sort(v, 1, 4)` ordena só as posições 1, 2 e 3. Como em `substring`, o início entra e o fim não.

> [!ANTES]
> A classe `Arrays` chegou no Java 1.2, de 1998, junto com o framework de coleções escrito por Joshua Bloch. Antes, ordenar ou buscar num array era escrever o algoritmo à mão em cada projeto. O `compare` e o `mismatch` são do Java 9, e os algoritmos de ordenação atuais, o Dual-Pivot Quicksort e o TimSort, entraram no Java 7, em 2011.

## Comparar

| Método | Devolve |
|---|---|
| `Arrays.equals(a, b)` | `true` se têm o mesmo tamanho e os mesmos elementos, na mesma ordem |
| `Arrays.compare(a, b)` | negativo, zero ou positivo, comparando elemento a elemento |
| `Arrays.mismatch(a, b)` | o primeiro índice em que diferem, ou -1 se forem iguais |

```java executar
int[] a = {1, 2, 3};
int[] b = {1, 2, 3};
int[] c = {1, 2, 4};
int[] d = {1, 2};
System.out.println(a.equals(b) + " " + Arrays.equals(a, b));
System.out.println(Arrays.compare(a, c) + " " + Arrays.compare(a, d) + " " + Arrays.compare(a, b));
System.out.println(Arrays.mismatch(a, b) + " " + Arrays.mismatch(a, c) + " " + Arrays.mismatch(a, d));
```

```saida
false true
-1 1 0
-1 2 2
```

O `compare` segue a ordem do dicionário: o primeiro elemento diferente decide, e, se um array é o começo do outro, o **mais curto** vem antes. Um array `null` vem antes de qualquer outro. A documentação só garante o **sinal** do resultado, então a prova pergunta "positivo, negativo ou zero", não o número. Já o `mismatch` de `a` e `d` é 2: as posições 0 e 1 são iguais, e a 2 só existe em `a`.

## Preencher e copiar

```java executar
int[] setes = new int[5];
Arrays.fill(setes, 7);
System.out.println(Arrays.toString(setes));
int[] base = {1, 2, 3};
int[] maior = Arrays.copyOf(base, 5);
int[] menor = Arrays.copyOf(base, 2);
int[] meio = Arrays.copyOfRange(base, 1, 3);
System.out.println(Arrays.toString(maior) + " " + Arrays.toString(menor) + " " + Arrays.toString(meio));
int[] destino = new int[6];
System.arraycopy(base, 0, destino, 2, 3);
System.out.println(Arrays.toString(destino));
```

```saida
[7, 7, 7, 7, 7]
[1, 2, 3, 0, 0] [1, 2] [2, 3]
[0, 0, 1, 2, 3, 0]
```

`copyOf` cria um array novo do tamanho pedido: se for maior, completa com valores padrão; se for menor, corta. É o jeito de "aumentar" um array, já que o tamanho não muda. `System.arraycopy(origem, posOrigem, destino, posDestino, quantidade)` copia para um array que já existe e funciona até quando origem e destino são o mesmo array, com as posições se sobrepondo.

> [!PERGUNTAS]
> **P:** Como ordenar um `int[]` em ordem decrescente?
>
> **R:** Para primitivos, o `sort` não aceita critério: ordene e inverta o array. Com `Integer[]`, dá para passar um critério: `Arrays.sort(v, Comparator.reverseOrder())`.
>
> **P:** E ordenar textos sem diferenciar maiúsculas?
>
> **R:** `Arrays.sort(nomes, String.CASE_INSENSITIVE_ORDER)`. Os critérios de ordenação, os `Comparator`, aparecem com força no cargo Júnior.
>
> **P:** Quando usar `copyOf` e quando `System.arraycopy`?
>
> **R:** `copyOf` cria um array novo; `arraycopy` copia para um que já existe, inclusive dentro do mesmo array, como para abrir espaço deslocando elementos.

## `Arrays.asList`: a ponte para as listas

> [!PENSE]
> No exemplo abaixo, a lista é criada a partir do array, e depois os dois são alterados, cada um de um lado. A lista é uma cópia ou uma janela para o array?

`Arrays.asList` devolve uma `List` **apoiada no array**: não há cópia, os dois enxergam os mesmos dados. A lista tem tamanho fixo: `set` funciona, mas `add` e `remove` lançam `UnsupportedOperationException`.

```java executar
String[] cores = {"azul", "verde", "amarelo"};
List<String> lista = Arrays.asList(cores);
lista.set(2, "laranja");
cores[0] = "cinza";
System.out.println(lista + " " + Arrays.toString(cores));
try {
    lista.add("preto");
} catch (UnsupportedOperationException e) {
    System.out.println("add: UnsupportedOperationException");
}
int[] numeros = {1, 2, 3};
System.out.println(Arrays.asList(numeros).size());
```

```saida
[cinza, verde, laranja] [cinza, verde, laranja]
add: UnsupportedOperationException
1
```

A última linha é uma armadilha clássica: `asList` trabalha com objetos, e um `int[]` é **um** objeto. O resultado é uma lista com um único elemento, o próprio array. Com `Integer[]`, a lista teria 3 elementos. Compare com `List.of`, que você verá com as coleções: ela não deixa nem o `set`, e não guarda ligação com array nenhum.

> [!ERRO]
> Passar um array de primitivos para `Arrays.asList` esperando uma lista de números: `Arrays.asList(new int[] {1, 2, 3})` é uma `List<int[]>` com um só elemento. O `contains(2)` dá `false`, e o `size()` dá 1. Use `Integer[]`, ou `Arrays.stream(v).boxed().toList()`.

> [!IA]
> A IA usa `Arrays.binarySearch` corretamente, mas às vezes sobre um array que ela mesma não ordenou, ou trata o resultado negativo como "não achou" sem aproveitar o ponto de inserção. Também é comum ela devolver `Arrays.asList(...)` de um método e, em outro trecho, chamar `add` na lista. Pergunte de onde vem a ordenação e se a lista precisa crescer.

## Na IDE

- **Os cinco argumentos.** Com o cursor dentro de `System.arraycopy(...)`, **Ctrl + P** mostra o nome de cada parâmetro: origem, posição na origem, destino, posição no destino e quantidade. A ordem é fácil de trocar.
- **A regra do negativo.** **Ctrl + Q** sobre `binarySearch` abre o Javadoc com a fórmula `(-(insertion point) - 1)`.
- **Testar sem rodar tudo.** Parado num breakpoint, **Alt + F8** (Evaluate Expression) executa `Arrays.binarySearch(numeros, 20)` na hora, com os dados reais.

## Por baixo dos panos

O `Arrays.sort` usa algoritmos diferentes conforme o tipo. Para primitivos, é o *Dual-Pivot Quicksort*, de Vladimir Yaroslavskiy, adotado no Java 7: um [quicksort](/assistir/aprendiz-t4-e03) com dois pivôs, que divide o array em três partes e costuma fazer menos trocas que o clássico. Em pedaços pequenos, ele troca para a ordenação por inserção, mais rápida com poucos elementos. Ele não é estável, mas com primitivos isso não importa: dois `7` são indistinguíveis.

Para objetos, a estabilidade importa (ordenar clientes por cidade não deve embaralhar quem já estava em ordem de nome), e o Java usa o *TimSort*, criado por Tim Peters para o Python em 2002. Ele procura trechos que já estão em ordem, comuns em dados reais, e os intercala como no merge sort. Num array quase ordenado, chega perto de O(n).

O `System.arraycopy` é um método *intrínseco*: o JIT troca a chamada por uma cópia de memória otimizada para o processador, muito mais rápida que um `for`. E o `Arrays.equals` e o `mismatch` comparam vários bytes por vez com instruções vetoriais, em vez de um elemento por iteração.

## Resumo para a prova

- `sort` ordena no lugar e não devolve nada; textos em ordem de código: dígitos, maiúsculas, minúsculas
- `binarySearch` exige array ordenado; sem ordem, o resultado é indefinido
- Não encontrado: `-(ponto de inserção) - 1`
- `equals` de array compara referências; `Arrays.equals` compara o conteúdo
- `compare`: o primeiro elemento diferente decide; prefixo mais curto vem antes; só o sinal é garantido
- `mismatch`: primeiro índice diferente, ou -1 se iguais
- `copyOf` completa com valores padrão ou corta; intervalos incluem o início e excluem o fim
- `asList`: lista de tamanho fixo ligada ao array; `asList(int[])` tem um elemento só
