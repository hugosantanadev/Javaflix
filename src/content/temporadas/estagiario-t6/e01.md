Um array guarda uma quantidade fixa de valores do mesmo tipo, lado a lado, acessíveis por um índice. É a estrutura mais básica da linguagem, e a prova explora cada detalhe da sintaxe: onde os colchetes podem ficar, quais formas de criação compilam, qual valor cada posição recebe e o que acontece quando se passa do limite.

## Declarar

Os colchetes podem vir depois do tipo ou depois do nome, e as duas formas podem até se misturar. A diferença aparece quando se declara mais de uma variável na mesma linha:

| Declaração | Resultado |
|---|---|
| `int[] a, b;` | `a` e `b` são `int[]` |
| `int a[], b;` | `a` é `int[]`, mas `b` é um `int` comum |
| `int[] a, b[];` | `a` é `int[]` e `b` é `int[][]` |

Os colchetes depois do **tipo** valem para todas as variáveis da declaração; depois do **nome**, só para aquela variável:

```java executar
int[] a, b;
int c[], d; //> Os colchetes no nome valem só para c: d é um int comum.
a = new int[1];
b = new int[2];
c = new int[3];
d = 4;
System.out.println(a.length + b.length + c.length + d);
```

```saida
10
```

> [!LAPIS]
> Qual é o tipo de cada variável?
>
> ```java
> int x[], y, z[][];
> long[] p, q[];
> ```
>
> **Resposta:** `x` é `int[]`, `y` é `int` e `z` é `int[][]`: na primeira linha, os colchetes estão nos nomes e valem um por um. Na segunda, o `[]` do tipo vale para as duas, e o de `q` soma mais um: `p` é `long[]` e `q` é `long[][]`.

## Criar

Há três formas, e só três:

```java
int[] a = new int[3];            // tamanho, com valores padrão
int[] b = new int[] {1, 2, 3};   // valores, tamanho deduzido
int[] c = {1, 2, 3};             // atalho, só na declaração
```

Informar o tamanho **e** os valores ao mesmo tempo não compila, e criar sem nenhum dos dois também não:

```java nao-compila
int[] x = new int[3] {1, 2, 3};
```

```java nao-compila
int[] y = new int[];
```

O atalho `{1, 2, 3}` só funciona na declaração. Para passar um array direto para um método ou atribuir a uma variável já declarada, use `new int[] {1, 2, 3}` (o chamado *array anônimo*). Com `var`, também é preciso o `new`: `var v = {1, 2};` não compila, porque o compilador não teria como saber o tipo.

## Valores padrão e acesso

Um array criado com tamanho tem todas as posições preenchidas com o **valor padrão** do tipo, o mesmo dos campos: `0` para números, `false` para `boolean`, o caractere de código 0 para `char` e `null` para referências. O tamanho fica no campo `length` (sem parênteses, ao contrário do `length()` da `String`), e os índices vão de 0 a `length - 1`:

```java executar
int[] numeros = new int[3];
boolean[] flags = new boolean[2];
String[] nomes = new String[2];
char[] letras = new char[1];
System.out.println(numeros[0] + " " + flags[1] + " " + nomes[0] + " " + (int) letras[0]);
int[] primos = {2, 3, 5, 7};
System.out.println(primos.length + " " + primos[primos.length - 1]);
```

```saida
0 false null 0
4 7
```

> [!ERRO]
> Usar `<=` no limite do laço: `for (int i = 0; i <= v.length; i++)`. A última volta acessa `v[v.length]`, uma posição que não existe, e lança `ArrayIndexOutOfBoundsException` depois de processar todos os elementos válidos. O último índice é `length - 1`; o teste certo é `i < v.length`.

O tamanho pode vir de uma variável, calculada em tempo de execução, mas, uma vez criado, o array **nunca muda de tamanho**. O `length` é `final`. Para "aumentar" um array, cria-se outro maior e copiam-se os elementos, que é o que o `ArrayList` faz por dentro.

## Arrays são objetos

Uma variável de array guarda uma **referência**, como uma `String`. Atribuir um array a outra variável não copia nada: as duas apontam para o mesmo objeto. E `==` e `equals` comparam referências.

> [!PENSE]
> No código abaixo, `b` recebe `a` e depois muda a posição 0. O que acontece com `a[0]`? E o `a.equals(c)`, com o mesmo conteúdo, dá verdadeiro?

```java executar
int[] a = {1, 2, 3};
int[] b = a; //> Copia a referência: a e b passam a ser o mesmo array.
b[0] = 99; //> Mudar por b é mudar o array de a.
int[] c = {99, 2, 3};
System.out.println(a[0] + " " + (a == b) + " " + (a == c) + " " + a.equals(c));
System.out.println(Arrays.toString(a));
```

```saida
99 true false false
[99, 2, 3]
```

Para comparar o conteúdo, use `Arrays.equals`, e para imprimir, `Arrays.toString`: o `println` de um array mostra só algo como `[I@1b6d3586` (o tipo e um número de identidade). A classe `Arrays` é o assunto do [episódio 3](/assistir/estagiario-t6-e03).

> [!PERGUNTAS]
> **P:** Por que o primeiro índice é 0, e não 1?
>
> **R:** Porque o índice é a distância a partir do começo do array: o primeiro elemento está a zero posições do início. Na figura do fim do episódio, é a conta início + 16 + i × 4.
>
> **P:** Dá para criar um array de tamanho 0?
>
> **R:** Dá: `new int[0]` é válido e tem `length` 0. É útil para devolver "nenhum resultado" sem usar `null`, e um for-each sobre ele simplesmente não executa.
>
> **P:** Qual é o maior array possível?
>
> **R:** O tamanho é um `int`, então o limite teórico é 2.147.483.647 posições. Na prática, a JVM recusa um pouco antes disso, e a memória costuma acabar bem antes.
>
> **P:** E para aumentar um array que encheu?
>
> **R:** Não se aumenta: cria-se outro, maior, e copiam-se os elementos, por exemplo com `Arrays.copyOf(v, v.length * 2)`.

## Os três erros de execução

```java executar
int[] v = new int[2];
try {
    v[2] = 1;
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println(e.getMessage());
}
try {
    int n = -1;
    int[] w = new int[n];
} catch (NegativeArraySizeException e) {
    System.out.println("NegativeArraySizeException");
}
Object[] objetos = new String[1];
try {
    objetos[0] = 42;
} catch (ArrayStoreException e) {
    System.out.println("ArrayStoreException");
}
```

```saida
Index 2 out of bounds for length 2
NegativeArraySizeException
ArrayStoreException
```

O primeiro é o clássico índice fora do limite. O segundo acontece com tamanho negativo, que só pode ser detectado na execução. O terceiro é mais sutil: arrays são **covariantes**, ou seja, um `String[]` pode ser guardado numa variável `Object[]`. O compilador aceita `objetos[0] = 42`, porque `Integer` é um `Object`, mas a JVM sabe que o array é de `String` e recusa.

> [!PROVA]
> Um array de objetos começa cheio de `null`: `String[] nomes = new String[3];` não cria nenhuma `String`. Chamar `nomes[0].length()` lança `NullPointerException`. Já `nomes[0] + "!"` funciona e dá "null!".

> [!ANTES]
> O índice começando em 0 vem do BCPL e do C, dos anos 1960 e 1970, em que `v[i]` era literalmente "o endereço de `v` mais i posições". O Fortran, mais antigo, começava em 1. O C nunca conferiu os limites, e ler ou escrever fora do array foi a porta de entrada de ataques como o *worm* de Morris, de 1988, que derrubou boa parte da internet da época. O Java manteve o 0 do C e acrescentou a verificação em todo acesso.

> [!IA]
> A IA escreve laços sobre arrays sem errar o limite quase sempre, mas é comum ela imprimir um array direto com `println` ou compará-lo com `equals` em código de teste. Também sugere `Arrays.asList(intArray)` esperando uma lista de números, o que dá uma lista com um único elemento, o próprio array. Confira toda impressão e toda comparação de array no código que ela gerar.

## Na IDE

- **Imprimir um array.** O IntelliJ avisa "Implicit call to 'toString()' on array" no `println(v)` e no `"" + v`, e o **Alt + Enter** embrulha com `Arrays.toString(v)`.
- **Índice constante fora do limite.** `v[3]` num array criado com `new int[3]` aparece marcado antes de rodar.
- **Ver o conteúdo.** No depurador, um array aparece com o tamanho, como `int[4]`, e se expande em `0 = 2`, `1 = 3`...: índice e valor, posição por posição.

## Por baixo dos panos

Na memória, um array é um objeto com um cabeçalho (como todo objeto), o campo `length` e os elementos em sequência, sem espaços entre eles. Ler `v[i]` é uma conta de endereço: início do array + i × tamanho do elemento. É por isso que o acesso é O(1), e por isso os arrays funcionam tão bem com o [cache](/assistir/aprendiz-t1-e04).

![Um int[] de quatro elementos desenhado como uma faixa de memória: cabeçalho de 12 bytes, length na posição 12 e os elementos 2, 3, 5 e 7 a partir da posição 16, com o elemento de índice 2 destacado na posição 24](/figuras/array-na-memoria.svg "O elemento i fica em início + 16 + i × 4. Não importa se o array tem 4 ou 4 milhões de posições: é uma conta só.")

> [!MATEMATICA]
> Com a figura dá para calcular a memória de qualquer array de primitivos: 16 bytes de cabeçalho e `length`, mais `length × tamanho do elemento`, arredondado para múltiplo de 8. `new int[1000]` ocupa 16 + 1000 × 4 = **4016** bytes; `new long[1000]`, 16 + 8000 = 8016; `new boolean[1000]`, 16 + 1000 = 1016, porque cada `boolean` de array usa 1 byte inteiro. E `new int[3]` dá 16 + 12 = 28, arredondado para 32.

A JVM tem instruções próprias para arrays (`newarray`, `iaload`, `iastore`, `arraylength`), e cada leitura e escrita confere o índice antes: é essa verificação que lança `ArrayIndexOutOfBoundsException` em vez de ler a memória vizinha, como aconteceria em [C](/assistir/aprendiz-t2-e02). Cada escrita num array de referências também confere o tipo real do elemento, o que gera o `ArrayStoreException`. O JIT remove essas verificações quando consegue provar que são desnecessárias, como num `for` de 0 a `length - 1`. Os arrays têm classes próprias, criadas pela JVM: o nome interno de `int[]` é `[I`, e o de `String[]` é `[Ljava.lang.String;`, que é o que aparece no `println`.

## Resumo para a prova

- `int[] a, b` declara dois arrays; `int a[], b` declara um array e um `int`
- Criação: `new int[3]`, `new int[] {1, 2, 3}` ou `{1, 2, 3}` (só na declaração)
- `new int[3] {1, 2, 3}` e `new int[]` não compilam; `var v = {1, 2}` também não
- Valores padrão: 0, `false`, caractere 0 e `null`
- `length` é campo e `final`; índices de 0 a `length - 1`
- Arrays são objetos: atribuir copia a referência; `==` e `equals` comparam referências
- Erros de execução: `ArrayIndexOutOfBoundsException`, `NegativeArraySizeException` e `ArrayStoreException`
