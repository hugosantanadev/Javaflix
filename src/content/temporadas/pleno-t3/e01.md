Quase todo programa guarda grupos de objetos, e o Java oferece para isso o **Collections Framework**: um conjunto de interfaces (`List`, `Set`, `Queue`, `Map`), implementações e algoritmos. Esta temporada percorre cada parte, com os métodos que a prova cobra e o que acontece dentro de cada estrutura. Começamos pela mais usada, a lista.

## O mapa do framework

```text
Iterable
  └── Collection
        ├── List      ordenada por posição, aceita repetidos
        ├── Set       sem repetidos
        └── Queue     fila; Deque é a fila de duas pontas
Map                   chave e valor; não é uma Collection
```

`Collection` reúne o que todas têm em comum: `add`, `remove`, `contains`, `size`, `isEmpty`, `clear`, `addAll`, `removeIf` e o `iterator`. `Map` fica fora da hierarquia porque guarda pares, não elementos soltos. A regra de ouro: declare a variável pelo tipo da **interface** (`List<String> nomes = new ArrayList<>()`) e escolha a implementação só no `new`.

## Os métodos de List

Uma `List` guarda elementos em posições numeradas a partir de 0, aceita repetidos e mantém a ordem de inserção. Além dos métodos de `Collection`, ela acrescenta os que usam índice:

| Método | O que faz |
|---|---|
| `add(E)` / `add(int, E)` | Insere no fim ou na posição, empurrando os seguintes |
| `get(int)` | Lê a posição |
| `set(int, E)` | Troca o elemento e **devolve o antigo** |
| `remove(int)` / `remove(Object)` | Remove pela posição ou pelo valor |
| `indexOf` / `lastIndexOf` | Primeira e última posição do valor, ou `-1` |
| `subList(de, até)` | Uma **visão** do trecho, sem cópia |
| `replaceAll` / `removeIf` | Transformam ou filtram com uma lambda |

A armadilha mais famosa da prova está no `remove` de uma `List<Integer>`: `remove(1)` recebe um `int` e escolhe a sobrecarga do **índice**, sem autoboxing.

```java executar
import java.util.ArrayList;
import java.util.List;

public class Remocoes {
    public static void main(String[] args) {
        List<Integer> numeros = new ArrayList<>(List.of(1, 2, 3));
        numeros.remove(1);
        System.out.println(numeros);
        numeros.remove(Integer.valueOf(1));
        System.out.println(numeros);

        List<String> letras = new ArrayList<>(List.of("a", "b", "c"));
        String antiga = letras.set(1, "B");
        letras.add(3, "d");
        System.out.println(antiga + " " + letras);

        List<Integer> valores = new ArrayList<>(List.of(1, 2, 3, 4, 5, 6));
        valores.removeIf(n -> n % 2 == 0);
        valores.replaceAll(n -> n * 10);
        valores.subList(0, 2).clear();
        System.out.println(valores);
    }
}
```

```saida
[1, 3]
[3]
b [a, B, c, d]
[50]
```

`add(3, "d")` funciona porque 3 é igual ao tamanho, a posição logo depois do último. `add(9, "x")` lançaria `IndexOutOfBoundsException`. E limpar a `subList` apagou os elementos da lista original, porque a sublista é só uma janela sobre ela.

## ArrayList e LinkedList

As duas implementam `List`, com estruturas opostas:

| | `ArrayList` | `LinkedList` |
|---|---|---|
| Estrutura | Array que cresce sozinho | Nós ligados nos dois sentidos |
| `get(i)` | O(1), cálculo de endereço | O(n), percorre os nós |
| Inserir ou remover no fim | O(1) amortizado | O(1) |
| Inserir ou remover no meio | O(n), desloca o resto | O(n) para achar a posição, O(1) para ligar |
| Memória por elemento | Uma referência | Um objeto nó com três referências |

`LinkedList` também implementa `Deque`, a fila de duas pontas do [episódio 4](/assistir/pleno-t3-e04). Na prática, `ArrayList` vence quase sempre, mesmo em inserções no meio, por motivos que aparecem no fim desta aula. `new ArrayList<>(20)` define a **capacidade** inicial, não o tamanho: a lista nasce vazia, e `get(0)` lança exceção.

## Listas que não mudam: List.of e Arrays.asList

Há duas fábricas com regras diferentes, e a prova adora compará-las:

| | `List.of(...)` (Java 9) | `Arrays.asList(...)` |
|---|---|---|
| `add` e `remove` | `UnsupportedOperationException` | `UnsupportedOperationException` |
| `set` | `UnsupportedOperationException` | Funciona e altera o array |
| `null` | `NullPointerException`, até em `contains(null)` | Aceita |
| Relação com o array | Cópia independente | Visão do array: um muda o outro |

```java executar
import java.util.Arrays;
import java.util.List;

public class Fabricas {
    public static void main(String[] args) {
        String[] array = {"p", "q"};
        List<String> visao = Arrays.asList(array);
        visao.set(0, "P");
        array[1] = "Q";
        System.out.println(array[0] + " " + visao);

        try {
            visao.add("r");
        } catch (UnsupportedOperationException e) {
            System.out.println("asList não cresce");
        }
        try {
            List.of("a").set(0, "b");
        } catch (UnsupportedOperationException e) {
            System.out.println("List.of não muda");
        }
        try {
            List.of("a", null);
        } catch (NullPointerException e) {
            System.out.println("List.of não aceita null");
        }
        System.out.println(List.of(1, 2).equals(Arrays.asList(1, 2)));
    }
}
```

```saida
P [P, Q]
asList não cresce
List.of não muda
List.of não aceita null
true
```

O `equals` de listas compara os elementos na ordem, sem olhar a implementação. Para uma lista que cresce a partir de valores fixos, a forma comum é `new ArrayList<>(List.of(...))`.

## Percorrer e modificar ao mesmo tempo

Remover elementos dentro de um for-each costuma lançar `ConcurrentModificationException`. O jeito certo é o `remove` do próprio `Iterator` ou, mais simples, `removeIf`:

```java executar
import java.util.ArrayList;
import java.util.ConcurrentModificationException;
import java.util.Iterator;
import java.util.List;

public class Percorrer {
    public static void main(String[] args) {
        List<String> nomes = new ArrayList<>(List.of("Ana", "Bia", "Caio", "Davi"));
        try {
            for (String n : nomes) {
                if (n.startsWith("A")) {
                    nomes.remove(n);
                }
            }
        } catch (ConcurrentModificationException e) {
            System.out.println("ConcurrentModificationException");
        }

        Iterator<String> it = nomes.iterator();
        while (it.hasNext()) {
            if (it.next().length() == 4) {
                it.remove();
            }
        }
        System.out.println(nomes);
    }
}
```

```saida
ConcurrentModificationException
[Bia]
```

O primeiro `remove` aconteceu antes da exceção, e por isso "Ana" já não está na lista.

> [!PROVA]
> Em `List<Integer>`, `remove(1)` remove o **índice** 1; `remove(Integer.valueOf(1))` remove o **valor** 1. E `set` devolve o elemento substituído, não `void` nem `boolean`.

## Por baixo dos panos

O `ArrayList` guarda tudo num array interno, `elementData`. Quando ele enche, o próximo `add` cria um array cerca de **50% maior** (`novo = antigo + antigo >> 1`) e copia os elementos. Cada cópia custa O(n), mas como acontece cada vez mais raramente, o custo médio de um `add` no fim continua O(1): é o que "amortizado" significa.

A vantagem real do `ArrayList` vem do hardware. O array guarda as referências lado a lado, e a CPU carrega a memória em blocos de 64 bytes, as *linhas de cache*: ler um elemento já traz os vizinhos. Os nós da `LinkedList` ficam espalhados pelo heap, cada um num objeto separado com cabeçalho e três referências, e percorrer a lista vira uma sequência de faltas de cache. Por isso, mesmo para inserções no meio, deslocar um array com uma única cópia de memória costuma ganhar de caminhar nó a nó. O próprio Joshua Bloch, que escreveu a `LinkedList`, já disse publicamente que não a usa.

A `ConcurrentModificationException` vem de um contador, `modCount`, que toda alteração estrutural incrementa. O iterador guarda o valor que viu ao nascer e confere a cada `next()`. Esse mecanismo, chamado *fail-fast*, é só uma tentativa de ajudar, não uma garantia: remover o **penúltimo** elemento dentro do for-each não lança nada. O tamanho cai, `hasNext()` devolve `false` antes do próximo `next()`, e o laço termina sem visitar o último elemento.

## Resumo para a prova

- Declare pela interface, escolha a implementação no `new`
- `remove(int)` remove por índice; `remove(Object)` por valor; `set` devolve o antigo
- `add(i, e)` aceita `i` igual ao tamanho; acima disso, `IndexOutOfBoundsException`
- `List.of`: imutável e sem `null`; `Arrays.asList`: tamanho fixo, `set` permitido, visão do array
- `subList` é uma visão: alterá-la altera a original
- Remover dentro do for-each lança `ConcurrentModificationException`; use `Iterator.remove` ou `removeIf`
