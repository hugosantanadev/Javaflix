Até o Java 20, pegar o último elemento de uma coleção ordenada tinha uma forma diferente para cada tipo: `lista.get(lista.size() - 1)`, `deque.getLast()`, `sortedSet.last()`, e para um `LinkedHashSet`, nenhuma forma direta. O Java 21 resolveu isso com três interfaces novas, as **sequenced collections** (JEP 431), que dão a todas as coleções com ordem definida o mesmo conjunto de métodos. Este episódio é da prova 1Z0-830 em diante.

## O problema: ordem sem interface

Várias coleções têm uma ordem de encontro bem definida: `List` pela posição, `Deque` pelas pontas, `LinkedHashSet` pela inserção, `TreeSet` pela comparação. Mas não havia um tipo comum que dissesse "esta coleção tem primeiro e último". Cada uma inventou os próprios métodos:

| Coleção | Primeiro, antes do Java 21 | Último, antes do Java 21 |
|---|---|---|
| `List` | `get(0)` | `get(size() - 1)` |
| `Deque` | `getFirst()` | `getLast()` |
| `SortedSet` | `first()` | `last()` |
| `LinkedHashSet` | `iterator().next()` | Percorrer tudo |

## As três interfaces

```text
SequencedCollection     addFirst, addLast, getFirst, getLast,
  │                     removeFirst, removeLast, reversed
  ├── List
  ├── Deque
  └── SequencedSet       reversed devolve SequencedSet
        ├── LinkedHashSet
        └── SortedSet → NavigableSet → TreeSet

SequencedMap            firstEntry, lastEntry, pollFirstEntry, pollLastEntry,
  │                     putFirst, putLast, reversed,
  │                     sequencedKeySet, sequencedValues, sequencedEntrySet
  ├── LinkedHashMap
  └── SortedMap → NavigableMap → TreeMap
```

`HashSet` e `HashMap` ficam de fora, porque não têm ordem definida. `List`, `Deque`, `SortedSet` e `SortedMap` foram ajustadas para estender as novas interfaces, então todo código antigo ganhou os métodos sem mudar nada.

```java executar
import java.util.ArrayList;
import java.util.List;

public class Listas {
    public static void main(String[] args) {
        List<Integer> l = new ArrayList<>(List.of(1, 2, 3));
        l.addFirst(0);
        l.addLast(4);
        System.out.println(l + " " + l.getFirst() + " " + l.getLast());
        System.out.println(l.reversed());
        System.out.println(l.removeFirst() + " " + l.removeLast() + " " + l);
        System.out.println(List.of("a", "b", "c").getLast());
    }
}
```

```saida
[0, 1, 2, 3, 4] 0 4
[4, 3, 2, 1, 0]
0 4 [1, 2, 3]
c
```

Numa coleção vazia, `getFirst`, `getLast`, `removeFirst` e `removeLast` lançam `NoSuchElementException`. Em coleções imutáveis, como `List.of`, os de leitura funcionam e os de alteração lançam `UnsupportedOperationException`.

## reversed() é uma visão

`reversed()` não copia nada: devolve uma visão da mesma coleção em ordem inversa. Alterar a visão altera a original, com as pontas trocadas:

```java executar
import java.util.ArrayList;
import java.util.List;

public class Visao {
    public static void main(String[] args) {
        List<Integer> l = new ArrayList<>(List.of(1, 2, 3));
        List<Integer> inversa = l.reversed();
        inversa.set(0, 30);
        inversa.addFirst(40);
        inversa.removeLast();
        System.out.println(l + " " + inversa);
    }
}
```

```saida
[2, 30, 40] [40, 30, 2]
```

O `set(0, ...)` na visão trocou o **último** da original; o `addFirst` na visão acrescentou no **fim** da original; e o `removeLast` na visão removeu o **primeiro**. Para percorrer de trás para a frente, basta `for (var x : lista.reversed())`, sem índices.

## Conjuntos: reposicionar e recusar

Num `LinkedHashSet`, `addFirst` e `addLast` com um elemento que **já existe** não o duplicam: movem-no para a ponta pedida. Num `TreeSet`, a posição é decidida pela comparação, então `addFirst` e `addLast` lançam `UnsupportedOperationException`; os métodos de leitura funcionam normalmente.

```java executar
import java.util.LinkedHashSet;
import java.util.List;
import java.util.TreeSet;

public class ConjuntosSequenciados {
    public static void main(String[] args) {
        LinkedHashSet<String> s = new LinkedHashSet<>(List.of("a", "b", "c"));
        s.addFirst("c");
        s.addLast("a");
        System.out.println(s + " " + s.getFirst() + " " + s.reversed());

        TreeSet<Integer> t = new TreeSet<>(List.of(3, 1, 2));
        System.out.println(t.getFirst() + " " + t.getLast() + " " + t.reversed());
        try {
            t.addFirst(0);
        } catch (UnsupportedOperationException e) {
            System.out.println("TreeSet não aceita addFirst");
        }
    }
}
```

```saida
[c, b, a] c [a, b, c]
1 3 [3, 2, 1]
TreeSet não aceita addFirst
```

## SequencedMap

Os mapas com ordem ganharam métodos equivalentes, que trabalham com entradas. `putFirst` e `putLast` num `LinkedHashMap` também reposicionam uma chave existente, atualizando o valor; num `TreeMap`, lançam `UnsupportedOperationException`.

```java executar
import java.util.LinkedHashMap;

public class MapasSequenciados {
    public static void main(String[] args) {
        LinkedHashMap<String, Integer> m = new LinkedHashMap<>();
        m.put("a", 1);
        m.put("b", 2);
        m.put("c", 3);
        m.putFirst("c", 30);
        m.putLast("a", 10);
        System.out.println(m);
        System.out.println(m.firstEntry() + " " + m.lastEntry() + " " + m.reversed());
        System.out.println(m.sequencedKeySet().reversed());
        System.out.println(m.pollFirstEntry() + " " + m);
    }
}
```

```saida
{c=30, b=2, a=10}
c=30 a=10 {a=10, b=2, c=30}
[a, b, c]
c=30 {b=2, a=10}
```

`sequencedKeySet()`, `sequencedValues()` e `sequencedEntrySet()` são versões de `keySet()`, `values()` e `entrySet()` que também têm `reversed()`. O `Collections` ganhou `unmodifiableSequencedCollection`, `unmodifiableSequencedSet` e `unmodifiableSequencedMap`.

> [!PROVA]
> `HashSet` e `HashMap` não são sequenciados. `addFirst`/`addLast` reposicionam em `LinkedHashSet` e lançam `UnsupportedOperationException` em `TreeSet`; `putFirst`/`putLast` fazem o mesmo em `LinkedHashMap` e `TreeMap`. `reversed()` é uma visão, e `getFirst` numa coleção vazia lança `NoSuchElementException`.

> [!VERSAO]
> Tudo isto é do Java 21. No Java 17, `lista.getFirst()` não compila numa `List` (a `LinkedList` já tinha o método por ser `Deque`), e `reversed()` não existe em nenhuma coleção.

## Por baixo dos panos

Acrescentar métodos a interfaces usadas por todo o ecossistema só é possível graças aos métodos `default`. Em `SequencedCollection`, `getFirst()` é implementado como `iterator().next()`, e `addFirst` lança `UnsupportedOperationException` por padrão; cada implementação concreta sobrescreve o que consegue fazer melhor. Assim, uma coleção de terceiros que implementa `List` ganhou os métodos sem recompilar.

A JEP também usa **retornos covariantes** para que `reversed()` devolva o tipo mais útil em cada caso: `List.reversed()` devolve `List`, `Deque.reversed()` devolve `Deque`, `SortedSet.reversed()` devolve `SortedSet`. A `LinkedList`, que é `List` **e** `Deque`, teria dois `reversed()` herdados com retornos diferentes; ela resolve o conflito sobrescrevendo com um retorno que satisfaz os dois:

```java executar
import java.util.ArrayList;
import java.util.Deque;
import java.util.LinkedList;

public class Retornos {
    public static void main(String[] args) throws NoSuchMethodException {
        System.out.println(LinkedList.class.getMethod("reversed").getReturnType().getSimpleName());
        System.out.println(ArrayList.class.getMethod("reversed").getReturnType().getSimpleName());
        System.out.println(Deque.class.getMethod("reversed").getReturnType().getSimpleName());
    }
}
```

```saida
LinkedList
List
Deque
```

A mudança teve um custo raro no mundo Java: incompatibilidade de código-fonte. Classes de terceiros que já tinham um método `reversed()` ou `getFirst()` com outro tipo de retorno deixaram de compilar no Java 21, e a JEP documenta esse risco. O ganho pesou mais: a ordem de encontro virou um conceito com tipo próprio.

## Resumo para a prova

- `SequencedCollection`: `addFirst`, `addLast`, `getFirst`, `getLast`, `removeFirst`, `removeLast`, `reversed`
- `SequencedMap`: `firstEntry`, `lastEntry`, `pollFirstEntry`, `pollLastEntry`, `putFirst`, `putLast`, `reversed`
- Implementam: `List`, `Deque`, `LinkedHashSet`, `TreeSet`, `LinkedHashMap`, `TreeMap`; não implementam: `HashSet`, `HashMap`
- `reversed()` devolve uma visão; alterar a visão altera a original
- `LinkedHashSet` e `LinkedHashMap` reposicionam; `TreeSet` e `TreeMap` lançam `UnsupportedOperationException`
- Coleção vazia: `getFirst` e `removeFirst` lançam `NoSuchElementException`
