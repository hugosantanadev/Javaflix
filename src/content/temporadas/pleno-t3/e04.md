Filas aparecem em todo sistema: pedidos esperando processamento, mensagens, tarefas agendadas. Pilhas aparecem em desfazer e refazer, na navegação de páginas e na avaliação de expressões. No Java, as duas vivem nas interfaces `Queue` e `Deque`, com um detalhe que a prova explora sem dó: cada operação existe em duas versões, uma que lança exceção e outra que devolve um valor especial.

## Queue: a fila

`Queue` é uma fila FIFO (*first in, first out*): entra pelo fim, sai pelo começo. Para cada operação, há duas formas:

| Operação | Lança exceção | Devolve valor especial |
|---|---|---|
| Inserir no fim | `add(e)` | `offer(e)`, devolve `false` se não couber |
| Remover do começo | `remove()` | `poll()`, devolve `null` se vazia |
| Consultar o começo | `element()` | `peek()`, devolve `null` se vazia |

Numa fila vazia, `remove()` e `element()` lançam `NoSuchElementException`, enquanto `poll()` e `peek()` devolvem `null`. Nas filas sem limite de tamanho, como `ArrayDeque` e `LinkedList`, `add` e `offer` se comportam igual.

```java executar
import java.util.ArrayDeque;
import java.util.NoSuchElementException;
import java.util.Queue;

public class Fila {
    public static void main(String[] args) {
        Queue<String> pedidos = new ArrayDeque<>();
        pedidos.offer("pizza");
        pedidos.offer("suco");
        pedidos.add("bolo");
        System.out.println(pedidos.peek() + " " + pedidos.poll() + " " + pedidos);

        Queue<String> vazia = new ArrayDeque<>();
        System.out.println(vazia.peek() + " " + vazia.poll());
        try {
            vazia.remove();
        } catch (NoSuchElementException e) {
            System.out.println("remove() numa fila vazia");
        }
    }
}
```

```saida
pizza pizza [suco, bolo]
null null
remove() numa fila vazia
```

## Deque: as duas pontas

`Deque` (*double-ended queue*, pronuncia-se "deck") estende `Queue` e permite inserir, remover e consultar nas **duas** pontas. Cada operação também vem em par:

| Ponta | Lança exceção | Valor especial |
|---|---|---|
| Começo | `addFirst`, `removeFirst`, `getFirst` | `offerFirst`, `pollFirst`, `peekFirst` |
| Fim | `addLast`, `removeLast`, `getLast` | `offerLast`, `pollLast`, `peekLast` |

Os métodos herdados de `Queue` operam como fila: `offer` é `offerLast`, `poll` é `pollFirst`, `peek` é `peekFirst`. E há os métodos de pilha, que trabalham no **começo**: `push` é `addFirst`, `pop` é `removeFirst`. Misturar os dois estilos na mesma `Deque` é a pegadinha preferida:

```java executar
import java.util.ArrayDeque;
import java.util.Deque;

public class DuasPontas {
    public static void main(String[] args) {
        Deque<Integer> d = new ArrayDeque<>();
        d.offer(1);
        d.push(2);
        d.offer(3);
        d.offerFirst(4);
        d.addLast(5);
        System.out.println(d);
        System.out.println(d.peek() + " " + d.peekLast());
        System.out.println(d.pop() + " " + d.pollLast() + " " + d);
    }
}
```

```saida
[4, 2, 1, 3, 5]
4 5
4 5 [2, 1, 3]
```

Siga a sequência: `offer(1)` põe o 1 no fim; `push(2)` põe o 2 no **começo**; `offer(3)` vai para o fim; `offerFirst(4)` para o começo; `addLast(5)` para o fim. O `toString` mostra do começo ao fim.

## Pilha: use Deque, não Stack

A classe `Stack` existe desde o Java 1.0, estende `Vector` e sincroniza todo método, um custo inútil na maioria dos casos. A documentação recomenda usar `Deque` como pilha. As duas imprimem em ordens opostas, outra pegadinha:

```java executar
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Stack;

public class Pilhas {
    public static void main(String[] args) {
        Deque<String> pilha = new ArrayDeque<>();
        pilha.push("a");
        pilha.push("b");
        pilha.push("c");
        System.out.println(pilha + " " + pilha.pop() + " " + pilha.peek());

        Stack<String> antiga = new Stack<>();
        antiga.push("a");
        antiga.push("b");
        antiga.push("c");
        System.out.println(antiga + " " + antiga.pop() + " " + antiga.peek());
    }
}
```

```saida
[c, b, a] c b
[a, b, c] c b
```

O comportamento de pilha é o mesmo, último a entrar, primeiro a sair. Muda a impressão: a `Deque` mostra do topo para a base, a `Stack`, como `Vector`, da base para o topo.

## ArrayDeque, LinkedList e PriorityQueue

| Implementação | Estrutura | `null` | Observação |
|---|---|---|---|
| `ArrayDeque` | Array circular | `NullPointerException` | A escolha padrão para filas e pilhas |
| `LinkedList` | Lista duplamente ligada | Aceita | Também é `List`; mais memória por elemento |
| `PriorityQueue` | Heap binário | `NullPointerException` | Sai sempre o **menor**, não o mais antigo |

A `PriorityQueue` ordena pela ordem natural ou por um `Comparator`, mas só garante a ordem na **saída**, com `poll` e `peek`. A iteração e o `toString` mostram o array interno, que não está ordenado:

```java executar
import java.util.Comparator;
import java.util.List;
import java.util.PriorityQueue;

public class Prioridade {
    public static void main(String[] args) {
        PriorityQueue<Integer> fila = new PriorityQueue<>();
        for (int n : new int[] {5, 1, 4, 2, 3}) {
            fila.offer(n);
        }
        System.out.println(fila + " " + fila.peek());
        StringBuilder ordem = new StringBuilder();
        while (!fila.isEmpty()) {
            ordem.append(fila.poll());
        }
        System.out.println(ordem);

        PriorityQueue<String> maiores = new PriorityQueue<>(Comparator.reverseOrder());
        maiores.addAll(List.of("b", "d", "a", "c"));
        System.out.println(maiores.poll() + maiores.poll() + " " + maiores.size());
    }
}
```

```saida
[1, 2, 4, 5, 3] 1
12345
dc 2
```

> [!PROVA]
> `offer`, `poll` e `peek` nunca lançam exceção por fila vazia; `add`, `remove` e `element` lançam. Em `Deque`, `push`, `pop` e `peek` usam o **começo**, e `offer` usa o **fim**. `ArrayDeque` e `PriorityQueue` rejeitam `null`, porque `null` é a resposta de `poll` para "vazia".

## Por baixo dos panos

A `PriorityQueue` é um **heap binário** guardado num array: o elemento da posição `i` tem os filhos nas posições `2i + 1` e `2i + 2`, e todo pai é menor ou igual aos filhos. O menor fica sempre na posição 0, por isso `peek` é O(1). Ao inserir, o elemento entra no fim e **sobe** trocando de lugar com o pai enquanto for menor; ao remover, o último vai para o topo e **desce**. As duas operações custam O(log n).

O array `[1, 2, 4, 5, 3]` do exemplo conta essa história. O 5 entrou primeiro; o 1 subiu e trocou com ele; o 4 ficou como filho do 1; o 2 entrou na posição 3, filho do 5, e subiu uma vez; o 3 entrou na posição 4, filho do 2, e ficou. Cada pai é menor que os filhos, mas o array não está ordenado.

O `ArrayDeque` é um **array circular**: dois índices, cabeça e cauda, avançam e dão a volta ao chegar no fim do array. Inserir ou remover em qualquer ponta é só mover um índice, sem deslocar nada, e por isso ele é mais rápido que `LinkedList` e que `Stack`. Ele rejeita `null` porque usa posições `null` no array para saber onde não há elementos. Quando o array enche, ele cresce e os elementos são copiados para a nova área.

## Resumo para a prova

- `Queue`: `offer`/`poll`/`peek` devolvem `false` ou `null`; `add`/`remove`/`element` lançam exceção
- `Deque`: pares `First`/`Last`; `push`/`pop` no começo; `offer`/`poll` como fila
- `toString` de `ArrayDeque` mostra do começo ao fim; de `Stack`, da base ao topo
- `ArrayDeque` é a escolha para filas e pilhas; `Stack` é legado
- `PriorityQueue` entrega o menor primeiro, mas a iteração não é ordenada
- `ArrayDeque` e `PriorityQueue` não aceitam `null`; `LinkedList` aceita
