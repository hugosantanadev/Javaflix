Ordenar é das operações mais comuns com coleções, e o Java separa duas ideias: a **ordem natural** de um tipo, definida por ele mesmo com `Comparable`, e as **ordens alternativas**, definidas de fora com `Comparator`. A prova cobra as duas, os métodos de composição do `Comparator` e algumas armadilhas de sinal e de ordem de texto.

## Comparable: a ordem natural

Uma classe que implementa `Comparable<T>` declara `int compareTo(T outro)`, com um contrato de sinais:

| Resultado | Significado |
|---|---|
| Negativo | `this` vem **antes** de `outro` |
| Zero | Empatam na ordem |
| Positivo | `this` vem **depois** de `outro` |

O valor exato não importa, só o sinal. `String`, os wrappers numéricos, `LocalDate` e os enums já são `Comparable`. É essa ordem que `Collections.sort(lista)`, `list.sort(null)`, `Arrays.sort` e `TreeSet` usam quando nenhum comparador é passado.

```java executar
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class OrdemNatural {
    record Versao(int maior, int menor) implements Comparable<Versao> {
        @Override
        public int compareTo(Versao outra) {
            if (maior != outra.maior) {
                return Integer.compare(maior, outra.maior);
            }
            return Integer.compare(menor, outra.menor);
        }

        @Override
        public String toString() {
            return maior + "." + menor;
        }
    }

    public static void main(String[] args) {
        List<Versao> versoes = new ArrayList<>(List.of(new Versao(1, 10), new Versao(1, 2), new Versao(0, 9)));
        Collections.sort(versoes);
        System.out.println(versoes);

        List<String> textos = new ArrayList<>(List.of("banana", "Abacaxi", "10", "9", "abacate"));
        Collections.sort(textos);
        System.out.println(textos);
    }
}
```

```saida
[0.9, 1.2, 1.10]
[10, 9, Abacaxi, abacate, banana]
```

A ordem natural de `String` é a dos códigos dos caracteres: dígitos antes de maiúsculas, maiúsculas antes de minúsculas. Por isso "10" vem antes de "9" (compara "1" com "9") e "Abacaxi" antes de "abacate". A versão 1.10 fica depois da 1.2 porque a comparação é numérica, campo a campo.

`Collections.sort` numa lista de um tipo que **não** é `Comparable` nem compila: o método é declarado com `<T extends Comparable<? super T>>`, como no [episódio de limites](/assistir/pleno-t2-e05). Já um `TreeSet` desse tipo compila e só falha na execução.

## Comparator: ordens de fora

`Comparator<T>` compara dois objetos com `int compare(T a, T b)`, com o mesmo contrato de sinais. Ele serve quando a classe não tem ordem natural, quando você não pode alterá-la ou quando precisa de outra ordem. Desde o Java 8, quase nunca se escreve `compare` à mão; os métodos de fábrica montam o comparador:

| Método | Cria |
|---|---|
| `Comparator.comparing(chave)` | Compara pelo valor extraído |
| `comparingInt`, `comparingDouble` | O mesmo, sem autoboxing |
| `thenComparing(chave)` | Critério de desempate |
| `reversed()` | Inverte **tudo** o que veio antes |
| `naturalOrder()`, `reverseOrder()` | A ordem natural e a inversa |
| `nullsFirst(c)`, `nullsLast(c)` | Trata `null` sem exceção |

```java executar
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Comparadores {
    record Pessoa(String nome, int idade) { }

    public static void main(String[] args) {
        List<Pessoa> p = new ArrayList<>(List.of(
            new Pessoa("Bia", 30), new Pessoa("Ana", 30), new Pessoa("Caio", 25), new Pessoa("Ana", 20)));

        p.sort(Comparator.comparing(Pessoa::nome).thenComparingInt(Pessoa::idade));
        System.out.println(p);

        p.sort(Comparator.comparing(Pessoa::idade).reversed().thenComparing(Pessoa::nome));
        System.out.println(p);

        p.sort(Comparator.comparing(Pessoa::nome).thenComparing(Pessoa::idade).reversed());
        System.out.println(p);
    }
}
```

```saida
[Pessoa[nome=Ana, idade=20], Pessoa[nome=Ana, idade=30], Pessoa[nome=Bia, idade=30], Pessoa[nome=Caio, idade=25]]
[Pessoa[nome=Ana, idade=30], Pessoa[nome=Bia, idade=30], Pessoa[nome=Caio, idade=25], Pessoa[nome=Ana, idade=20]]
[Pessoa[nome=Caio, idade=25], Pessoa[nome=Bia, idade=30], Pessoa[nome=Ana, idade=30], Pessoa[nome=Ana, idade=20]]
```

Compare a segunda e a terceira ordenação. Na segunda, `reversed()` vem logo depois da idade e inverte só ela; o desempate por nome continua crescente. Na terceira, `reversed()` no fim inverte a cadeia inteira, nome **e** idade. Para inverter só o desempate, passe um comparador a ele: `thenComparing(Pessoa::idade, Comparator.reverseOrder())`.

> [!ATENCAO]
> `Comparator.comparing(p -> p.nome()).reversed()` não compila. Sem um destino que diga o tipo, a lambda dentro de `comparing` é inferida com `Object`, e `Object` não tem `nome()`. A referência de método `Pessoa::nome` carrega o tipo e resolve; outra saída é tipar o parâmetro: `(Pessoa p) -> p.nome()`.

## Duas armadilhas de comparação

A primeira é comparar números com subtração. `(a, b) -> a - b` parece certo, mas estoura com valores grandes de sinais opostos:

```java executar
import java.util.Comparator;

public class Estouro {
    public static void main(String[] args) {
        Comparator<Integer> subtracao = (a, b) -> a - b;
        Comparator<Integer> correto = Integer::compare;
        System.out.println(subtracao.compare(Integer.MIN_VALUE, 1));
        System.out.println(correto.compare(Integer.MIN_VALUE, 1));
    }
}
```

```saida
2147483647
-1
```

`Integer.MIN_VALUE - 1` dá a volta e vira o maior `int` positivo, dizendo que o menor número do mundo vem **depois** do 1. Use `Integer.compare`, `Comparator.comparingInt` ou `compareTo`.

A segunda é a coerência com `equals`. Se `compareTo` devolve 0 para objetos que `equals` considera diferentes, um `TreeSet` ou `TreeMap` vai tratá-los como o mesmo elemento, como o comparador sem distinção de maiúsculas do [episódio de conjuntos](/assistir/pleno-t3-e02).

## Buscando numa lista ordenada

`Collections.binarySearch(lista, chave)` faz uma busca binária, O(log n), numa lista **ordenada**. Se acha, devolve o índice; se não, devolve `-(ponto de inserção) - 1`, um número negativo que também diz onde a chave entraria. Em `[1, 3, 5, 8]`, procurar 5 dá 2, e procurar 4 dá -3: ele entraria na posição 2. Numa lista fora de ordem, o resultado é indefinido.

> [!PROVA]
> Ordem natural de `String`: dígitos, maiúsculas, minúsculas. `reversed()` inverte tudo o que está à esquerda dele. `Collections.sort` com um tipo não comparável não compila; `TreeSet` compila e lança `ClassCastException`. E `binarySearch` sem achar devolve `-(inserção) - 1`.

## Por baixo dos panos

`Collections.sort` e `List.sort` usam o **TimSort**, criado por Tim Peters em 2002 para o Python e adotado pelo Java 7 para ordenar objetos. Ele procura trechos que já estão em ordem, as *runs*, e os intercala como um merge sort, o que o torna muito rápido em dados quase ordenados, o caso mais comum no mundo real. O TimSort é **estável**: elementos que empatam mantêm a ordem em que estavam. Isso permite ordenar em etapas:

```java executar
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Estavel {
    record Pessoa(String nome, int idade) { }

    public static void main(String[] args) {
        List<Pessoa> p = new ArrayList<>(List.of(
            new Pessoa("Caio", 30), new Pessoa("Ana", 25), new Pessoa("Bia", 30), new Pessoa("Davi", 25)));
        p.sort(Comparator.comparingInt(Pessoa::idade));
        System.out.println(p);
    }
}
```

```saida
[Pessoa[nome=Ana, idade=25], Pessoa[nome=Davi, idade=25], Pessoa[nome=Caio, idade=30], Pessoa[nome=Bia, idade=30]]
```

Entre os de 25 anos, Ana continua antes de Davi, e entre os de 30, Caio antes de Bia, exatamente como estavam. O TimSort ainda confere o contrato do comparador enquanto trabalha: um comparador incoerente pode fazê-lo lançar `IllegalArgumentException: Comparison method violates its general contract!`, uma mensagem que assusta muita gente em produção. Para arrays de primitivos, onde estabilidade não faz diferença, `Arrays.sort` usa outro algoritmo, o *dual-pivot quicksort* de Vladimir Yaroslavskiy.

## Resumo para a prova

- `compareTo` e `compare`: negativo antes, zero empate, positivo depois
- `Comparable` define a ordem natural dentro da classe; `Comparator`, ordens de fora
- `comparing`, `thenComparing`, `reversed`, `naturalOrder`, `reverseOrder`, `nullsFirst`
- `reversed()` inverte toda a cadeia à sua esquerda
- Não compare com subtração; use `Integer.compare`
- O TimSort é estável: empates mantêm a ordem anterior
