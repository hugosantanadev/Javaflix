O `for` clássico junta num cabeçalho só as três peças de quase todo laço: o valor inicial, a condição e a atualização. Por ser compacto, ele esconde detalhes que a prova adora: a ordem exata em que as três partes rodam, o escopo da variável do laço, as regras para declarar mais de uma variável e o que acontece quando o corpo mexe no contador.

## As três partes e a ordem de execução

```java
for (inicialização; condição; atualização) {
    corpo
}
```

A ordem é sempre a mesma: a **inicialização** roda uma única vez; depois, a cada volta, **condição**, **corpo**, **atualização**. Quando a condição falha, o laço acaba, e a atualização daquela volta não acontece.

![As quatro partes do for numeradas no cabeçalho e o ciclo condição, corpo, atualização, com a saída quando a condição falha](/figuras/ordem-do-for.svg "A inicialização fica fora do ciclo. A atualização vem depois do corpo, nunca antes.")

Este programa deixa a ordem visível:

```java executar
public class OrdemDoFor {
    static boolean teste(int i) {
        System.out.println("teste " + i);
        return i < 2;
    }

    static int proximo(int i) {
        System.out.println("atualiza " + i);
        return i + 1;
    }

    public static void main(String[] args) {
        for (int i = 0; teste(i); i = proximo(i)) {
            System.out.println("corpo " + i);
        }
    }
}
```

```saida
teste 0
corpo 0
atualiza 0
teste 1
corpo 1
atualiza 1
teste 2
```

O `for` é equivalente a um `while` com a inicialização antes e a atualização no fim do corpo. A diferença é o escopo: a variável declarada no `for` só existe dentro dele.

## Várias variáveis e partes vazias

A inicialização pode declarar várias variáveis, desde que **do mesmo tipo**, e a atualização pode ter várias expressões separadas por vírgula:

```java executar
for (int i = 0, j = 10; i < j; i += 3, j -= 2) { //> Duas variáveis do mesmo tipo e duas atualizações, separadas por vírgula.
    System.out.println(i + " " + j);
}
```

```saida
0 10
3 8
```

Na terceira volta, i vale 6 e j vale 6, e o teste falha. Já tipos diferentes na declaração não compilam, porque a inicialização é **uma** declaração:

```java nao-compila
for (int i = 0, long j = 0; i < 3; i++) {
}
```

Qualquer uma das três partes pode ficar vazia. Sem condição, o laço é infinito, e só um `break` (ou `return`) o encerra:

```java executar
int k = 0;
for (; k < 3; ) {
    k++;
}
System.out.println(k);
for (int p = 1; ; p *= 2) {
    if (p > 100) {
        System.out.println(p);
        break;
    }
}
```

```saida
3
128
```

## Escopo da variável do laço

A variável declarada na inicialização existe só no cabeçalho e no corpo. Depois do laço, o nome fica livre, e pode ser declarado de novo:

```java executar
for (int i = 0; i < 2; i++) {
}
for (int i = 5; i < 6; i++) {
    System.out.println(i);
}
int i = 9;
System.out.println(i);
```

```saida
5
9
```

```java nao-compila
for (int i = 0; i < 3; i++) {
}
System.out.println(i);
```

Se você precisa do valor final do contador, declare a variável antes do `for` e use só a atribuição na inicialização: `int i; for (i = 0; i < 3; i++) { }`.

> [!ANTES]
> Desde o Java 10, a variável do `for` também pode ser declarada com `var`: `for (var i = 0; i < 3; i++)`. O tipo inferido é `int`, pelo literal. Em código anterior, o tipo aparece sempre escrito, e é o estilo que você vai ver na maior parte dos projetos.

> [!ERRO]
> Pôr `;` logo depois do cabeçalho: `for (i = 1; i <= 5; i++);`. O `;` vira o corpo, o laço roda cinco vezes sem fazer nada, e o bloco entre chaves logo abaixo roda **uma** vez, depois do laço, com `i` já valendo 6. Compila sem nenhum aviso do `javac`.

## Mexer no contador dentro do corpo

Nada impede o corpo de alterar a variável do laço, e a atualização do cabeçalho continua acontecendo no fim de cada volta. As duas se somam.

> [!PENSE]
> No laço abaixo, o corpo soma 2 ao `i`, e o cabeçalho soma mais 1. Quais números você acha que aparecem?

```java executar
for (int i = 0; i < 10; i++) {
    System.out.print(i);
    i += 2;
}
System.out.println();
```

```saida
0369
```

Cada volta anda 3 (2 do corpo e 1 do `i++`). Em código real, isso é quase sempre um bug; na prova, é uma armadilha de contagem.

> [!PREVENCAO]
> Não altere o contador de um `for` dentro do corpo. Quem lê o cabeçalho espera que ele conte tudo o que acontece com a variável. Se o passo precisa variar, use um `while`, em que a atualização fica explícita no corpo.

> [!LAPIS]
> Sem rodar, quantas vezes cada laço executa o corpo?
>
> ```java
> for (int i = 3; i < 20; i += 4) { }
> for (int i = 100; i > 0; i /= 2) { }
> for (int i = 0; i <= 9; i += 3) { }
> ```
>
> **Resposta:** O primeiro roda **5** vezes: 3, 7, 11, 15 e 19, ou ⌈(20 - 3) / 4⌉ = ⌈4,25⌉ = 5. O segundo roda **7** vezes: 100, 50, 25, 12, 6, 3 e 1, porque a divisão inteira de 1 por 2 dá 0. O terceiro roda **4** vezes: 0, 3, 6 e 9, porque o `<=` deixa o 9 passar.

> [!MATEMATICA]
> Somar de 1 a n com um `for` faz n voltas. Gauss, ainda menino, achou um atalho: juntar o primeiro com o último, o segundo com o penúltimo, e assim por diante. Cada par soma n + 1, e são n ÷ 2 pares, então a soma é n × (n + 1) ÷ 2. De 1 a 100: 100 × 101 ÷ 2 = **5.050**, numa conta só. Muitos laços têm uma fórmula fechada como essa, e trocá-los por ela leva o custo de O(n) para O(1).

> [!PROVA]
> Para contar as voltas de `for (int i = a; i < b; i += s)`, use ⌈(b − a) / s⌉. Com `<=`, conte uma volta a mais quando o último valor cair exatamente em `b`. `for (int i = 0; i <= 10; i += 2)` roda 6 vezes (0, 2, 4, 6, 8, 10); com `<`, 5. E a atualização pode ser qualquer expressão: `i *= 2` faz o laço rodar cerca de log₂(b) vezes, como você viu no episódio de [Big-O](/assistir/aprendiz-t3-e05).

```imas executar
int soma = 0;
for (int i = 1; i <= 4; i++) {
    soma += i;
    System.out.println("i = " + i + ", soma = " + soma);
}
System.out.println("Total: " + soma);
```

```saida
i = 1, soma = 1
i = 2, soma = 3
i = 3, soma = 6
i = 4, soma = 10
Total: 10
```

> [!IA]
> Ao gerar um laço sobre um array, assistentes de IA às vezes escrevem `i <= v.length`, e a última volta tenta ler uma posição que não existe, com `ArrayIndexOutOfBoundsException`. Os índices de um array de tamanho n vão de 0 a n - 1, então a condição certa é `i < v.length`. Confira essa condição em todo laço que receber pronto.

## Na IDE

- **Escrever o laço em três letras.** Digite `fori` e aperte **Tab**: o IntelliJ escreve `for (int i = 0; i < ; i++) { }` e põe o cursor no lugar do limite. Com `itar`, ele monta o laço que percorre um array pelo índice.
- **Trocar pelo `for` aprimorado.** Num `for` que só usa `v[i]` para ler os elementos, **Alt + Enter** oferece *Replace with enhanced 'for'*, assunto do [próximo episódio](/assistir/estagiario-t4-e03).
- **`for` com corpo vazio.** O `;` depois do cabeçalho é marcado com o aviso de comando com corpo vazio, o mesmo do `if`.

## Por baixo dos panos

O `javac` gera para o `for` exatamente o mesmo bytecode de um `while` com a inicialização antes e a atualização no fim do corpo: o "for" não existe na JVM. O que torna laços rápidos é o [JIT](/assistir/aprendiz-t2-e04). Num `for (int i = 0; i < v.length; i++)`, ele percebe que `i` nunca sai do intervalo do array e **elimina a verificação de limites** de cada `v[i]`, que de outro modo seria feita a cada acesso. Também costuma **desenrolar** o laço, executando várias voltas por iteração para gastar menos tempo com o teste e o salto. Laços simples e previsíveis são os que o JIT otimiza melhor.

## Resumo para a prova

- Ordem: inicialização (uma vez); depois condição, corpo, atualização a cada volta
- Quando a condição falha, a atualização daquela volta não roda
- A inicialização declara variáveis de um único tipo: `int i = 0, j = 10` sim, `int i = 0, long j = 0` não
- Atualização com várias expressões: `i++, j--`
- Partes vazias são permitidas; `for (;;)` é laço infinito
- A variável do `for` não existe depois do laço; o nome pode ser reusado
- Alterar o contador no corpo soma com a atualização do cabeçalho
