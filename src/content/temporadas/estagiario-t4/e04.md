`break` e `continue` mudam o fluxo de um laço no meio de uma volta. Sozinhos, são simples; com laços aninhados e **rótulos**, viram as questões de saída mais trabalhosas da prova. Este episódio mostra o que cada um faz, como os rótulos escolhem o laço afetado, e onde cada comando é permitido.

## `break` e `continue`

| Comando | Efeito |
|---|---|
| `break` | sai do laço (ou do `switch`) mais interno, imediatamente |
| `continue` | pula o resto da volta atual e vai para a próxima |

No `continue`, "ir para a próxima volta" significa: no `while` e no `do-while`, testar a condição de novo; no `for`, executar a **atualização** e depois testar:

```java executar
for (int i = 1; i <= 6; i++) {
    if (i == 5) {
        break; //> Sai do laço na hora: o 5 nem é impresso.
    }
    if (i % 2 == 0) {
        continue; //> Pula o println, mas o i++ do cabeçalho ainda roda.
    }
    System.out.println(i);
}
```

```saida
1
3
```

Os pares são pulados pelo `continue`, e o laço acaba no 5 pelo `break`, antes de imprimir o 5. O `i++` do cabeçalho roda normalmente depois de cada `continue`.

> [!ERRO]
> Num `while`, o `continue` pula também tudo que estiver no fim do corpo, inclusive a atualização da variável, se ela estiver lá. `while (i < 5) { if (i == 2) continue; i++; }` vira um laço infinito quando `i` chega a 2. No `for`, a atualização fica no cabeçalho e não é pulada; no `while`, atualize a variável antes do `continue`.

> [!LAPIS]
> Qual é a saída deste trecho?
>
> ```java
> int i = 0;
> while (i < 5) {
>     i++;
>     if (i == 3) continue;
>     System.out.print(i);
> }
> ```
>
> **Resposta:** `1245`. Aqui o `i++` está no começo do corpo, antes do `continue`, então ele nunca é pulado. O `continue` só pula o `print` da volta em que `i` vale 3.

## Rótulos

Com laços aninhados, `break` e `continue` afetam só o laço mais interno. Para afetar um laço externo, dê um **rótulo** a ele (um nome seguido de dois-pontos) e use o nome no comando:

```java executar
externo: //> O rótulo marca o laço da linha seguinte.
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (j == 2) {
            continue externo; //> Abandona o laço do j e vai para o i++.
        }
        if (i == 3) {
            break externo; //> Sai dos dois laços de uma vez.
        }
        System.out.println(i + "," + j);
    }
}
System.out.println("fim");
```

```saida
1,1
2,1
fim
```

Para i = 1 e i = 2, o laço interno imprime o j = 1 e, no j = 2, o `continue externo` abandona o laço interno e vai para a próxima volta do **externo**. Para i = 3, o `break externo` encerra os dois laços de uma vez.

As setas verdes e azuis voltam para uma atualização; as laranjas e vermelhas saem para baixo.")

> [!ANTES]
> Nos anos 1960, linguagens como Fortran e C ofereciam o `goto`, que salta para qualquer linha marcada. Em 1968, Edsger Dijkstra publicou a carta "Go To Statement Considered Harmful", e a ideia pegou: saltos livres deixam o programa difícil de seguir. O Java, de 1995, reservou a palavra `goto` mas nunca a implementou. No lugar dela, deu o `break` e o `continue` com rótulo, que cobrem o único uso que ainda fazia falta: sair de laços aninhados.

> [!PENSE]
> No próximo exemplo, o número procurado está na linha 1, coluna 1 de uma grade 3 × 3. Quantas vezes o `if` é avaliado com o rótulo? E se o `break` não tivesse rótulo?

O uso mais comum do rótulo é sair de dois laços quando se acha o que se procura:

```java executar
int[][] grade = {{4, 7, 1}, {9, 3, 8}, {2, 6, 5}};
int alvoLinha = -1, alvoColuna = -1;
busca:
for (int l = 0; l < grade.length; l++) {
    for (int c = 0; c < grade[l].length; c++) {
        if (grade[l][c] == 3) {
            alvoLinha = l;
            alvoColuna = c;
            break busca; //> Sem o rótulo, sairia só do laço do c.
        }
    }
}
System.out.println(alvoLinha + " " + alvoColuna);
```

```saida
1 1
```

Sem o rótulo, o `break` sairia só do laço interno, e o externo continuaria procurando nas linhas seguintes.

> [!MATEMATICA]
> Numa grade de L linhas por C colunas, achar o alvo na linha `l`, coluna `c` custa `l × C + c + 1` comparações com o `break busca`: todas as linhas anteriores inteiras, mais as colunas até o alvo. Aqui, 1 × 3 + 1 + 1 = **5**. Sem o rótulo, o `break` corta só o resto da linha do alvo, e as linhas seguintes são percorridas inteiras: 3 + 2 + 3 = **8**. No pior caso, o alvo no fim, os dois dão L × C; o rótulo ajuda quando o alvo aparece cedo.

> [!PERGUNTAS]
> **P:** O rótulo é um `goto` disfarçado?
>
> **R:** Não. O `goto` salta para qualquer lugar; o rótulo só diz **de qual** laço ou bloco o `break` ou o `continue` vale. Não dá para saltar para dentro de um bloco, nem para trás de um laço que já terminou.
>
> **P:** Posso usar o mesmo nome de rótulo duas vezes?
>
> **R:** Em laços separados, um depois do outro, sim. Um dentro do outro, não: o `javac` acusa `label externo already in use`.
>
> **P:** Existe convenção para o nome?
>
> **R:** Não há regra na linguagem, mas o costume é um nome curto em minúsculas que diga o que o laço faz: `busca`, `linhas`, `externo`.
>
> **P:** E o `return`, não resolve também?
>
> **R:** Resolve, e muitas vezes melhor: se a busca estiver num método próprio, um `return` sai de todos os laços e já devolve o resultado. Métodos chegam na próxima temporada.

## Onde cada um é permitido

| Comando | Permitido em |
|---|---|
| `break` sem rótulo | dentro de laço ou `switch` |
| `continue` (com ou sem rótulo) | só dentro de laço |
| `break rótulo` | dentro de qualquer comando rotulado, até de um bloco `{ }` ou de um `if` |

O rótulo de um `continue` precisa marcar um **laço**; o de um `break` pode marcar qualquer comando. Usar `continue` fora de laço, ou com o rótulo de um bloco comum, não compila:

```java nao-compila
int x = 1;
if (x > 0) {
    continue;
}
```

```java executar
bloco: {
    System.out.println("antes");
    if (true) {
        break bloco; //> Sai do bloco rotulado, que nem é um laço.
    }
    System.out.println("nunca");
}
System.out.println("depois");
```

```saida
antes
depois
```

`break bloco` funciona como um "sair deste bloco", um uso raro, mas que aparece em prova. O `if (true)` está ali porque um `break` direto deixaria o `println("nunca")` [inalcançável](/assistir/estagiario-t3-e04), o que não compila.

> [!PROVA]
> Um rótulo só vale para o comando que ele marca, e precisa estar **em volta** do `break` ou do `continue`: não dá para pular para um rótulo de um laço que já terminou ou que está em outro lugar. Rótulos não são `goto` (que, aliás, é palavra reservada em Java, mas não faz nada). E um `break` dentro de um `switch` que está dentro de um laço sai só do `switch`.

> [!ENGENHARIA]
> Rótulos são raros em código de produção, e muitos times só os aceitam no caso clássico de sair de laços aninhados. Se um laço tem vários `continue` e `break` espalhados, é sinal de que faz coisas demais: separe a busca num método e use `return`, ou junte as condições de saída no teste do laço. O leitor do código não deveria precisar de setas, como as da figura, para entender o fluxo.

> [!IA]
> Assistentes costumam resolver "sair de dois laços" com uma variável `boolean achou` testada nos dois laços, o que funciona, mas espalha a lógica. Também é comum trocarem um `for` por um `while` e esquecerem que o `continue` passa a pular o incremento. Peça o rótulo ou um método com `return`, e rode o código com o alvo no começo, no meio e ausente.

## Na IDE

- **Ir para o rótulo.** Com o cursor no nome depois de `break` ou `continue`, **Ctrl + B** leva à linha do rótulo, útil em laços longos.
- **Rótulo inútil.** Se o `break externo` já sairia do laço certo sem o rótulo, o IntelliJ marca o rótulo como desnecessário e oferece removê-lo com **Alt + Enter**.
- **`continue` sobrando.** Um `continue` que é o último comando do laço não muda nada, e a inspeção "Unnecessary 'continue' statement" aponta isso.

## Por baixo dos panos

Para o bytecode, `break` e `continue` são o que sempre foram: um `goto`. O `break` salta para a primeira instrução depois do laço; o `continue`, para o ponto da atualização (no `for`) ou do teste (no `while`). O rótulo só diz ao `javac` qual laço usar para calcular o endereço do salto. Por isso essa liberdade tem limites: o Java só permite saltar "para fora" de comandos que envolvem o `break`, nunca para dentro de outro bloco, e é isso que mantém o fluxo analisável pelas regras de [código inalcançável e atribuição definida](/assistir/estagiario-t3-e04).

## Resumo para a prova

- `break` sai do laço ou `switch` mais interno; `continue` vai para a próxima volta do laço mais interno
- No `for`, o `continue` executa a atualização antes do teste; no `while`, pula o que houver no fim do corpo
- `break rótulo` e `continue rótulo` afetam o comando rotulado, mesmo que seja externo
- `continue` só existe dentro de laço, e o seu rótulo precisa ser de um laço
- `break rótulo` pode sair de qualquer bloco rotulado
- `break` dentro de `switch` dentro de laço sai só do `switch`
