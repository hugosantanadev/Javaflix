Laços são a maior fonte de questões de "qual é a saída?" da prova: quantas vezes o corpo roda, qual é o valor da variável depois do fim, o que acontece com um `++` dentro da condição. Este episódio começa pelos dois laços mais simples, `while` e `do-while`, e por um método para contar iterações sem errar.

## `while`: testa antes

```java
while (condição) {
    // corpo
}
```

A condição é testada **antes** de cada volta. Se for falsa logo de início, o corpo não roda nenhuma vez. Como no `if`, ela precisa ser `boolean`.

## `do-while`: testa depois

```java
do {
    // corpo
} while (condição);
```

O corpo roda **primeiro** e a condição é testada depois, então o `do-while` sempre executa pelo menos uma vez. Repare no `;` depois do `while (condição)`: ele é obrigatório. A diferença aparece quando a condição já começa falsa:

```java executar
int i = 10;
while (i < 5) {
    System.out.println("while " + i);
    i++;
}
int j = 10;
do {
    System.out.println("do " + j);
    j++;
} while (j < 5);
System.out.println(i + " " + j);
```

```saida
do 10
10 11
```

O `do-while` é o laço natural para "faça e depois pergunte se repete": um menu que aparece pelo menos uma vez, uma leitura que precisa ser validada depois de feita.

> [!PROVA]
> A condição do `do-while` fica **fora** do bloco do corpo. Uma variável declarada dentro do `do { }` já deixou de existir quando o `while (...)` é avaliado:

```java nao-compila
do {
    int tentativa = 1;
} while (tentativa < 3);
```

## Contando as voltas

A maioria das questões se resolve montando uma tabela com o valor das variáveis a cada volta. Faça isso no papel até ficar automático:

```java executar
int n = 0, passos = 0;
while (n < 20) {
    n += 3;
    passos++;
}
System.out.println(n + " " + passos);
```

```saida
21 7
```

| Volta | n antes | n < 20? | n depois |
|---|---|---|---|
| 1 | 0 | sim | 3 |
| 2 | 3 | sim | 6 |
| ... | ... | ... | ... |
| 7 | 18 | sim | 21 |
| fim | 21 | não | |

Em geral, um laço que começa em `a`, soma `s` a cada volta e continua enquanto o valor for menor que `b` roda ⌈(b − a) / s⌉ vezes: ⌈20 / 3⌉ = 7. E a variável termina com o **primeiro valor que falha** a condição (21), não com o último que passou.

## Incremento dentro da condição

Quando a condição tem um `++`, ele acontece **a cada teste**, inclusive no último, o que falha:

```java executar
int k = 0;
while (k++ < 3) {
    System.out.print(k + " ");
}
System.out.println("| " + k);
```

```saida
1 2 3 | 4
```

O teste compara o valor antigo (0, 1, 2 passam; 3 falha), mas dentro do corpo `k` já foi incrementado, por isso imprime 1, 2 e 3. O último teste, o que falhou, também incrementou: `k` termina em 4.

## Padrões de uso

Três padrões cobrem a maior parte dos `while` reais. O **contador** conta quantas vezes algo acontece; o **acumulador** soma valores a cada volta; e a **sentinela** é um valor especial que marca o fim dos dados:

```java executar
int[] leituras = {12, 7, 30, -1, 8};
int i = 0, soma = 0;
while (leituras[i] != -1) {
    soma += leituras[i];
    i++;
}
System.out.println(soma + " em " + i + " leituras");
```

```saida
49 em 3 leituras
```

O −1 funciona como sentinela: o laço para ao encontrá-lo, e o 8 depois dele nunca é lido. Se o array não tivesse o −1, o laço passaria do fim e lançaria `ArrayIndexOutOfBoundsException`.

## Laços infinitos

Um laço cuja condição nunca fica falsa roda para sempre. Às vezes é proposital (`while (true)` com `break`, como num servidor que atende pedidos); quase sempre é bug: esquecer de atualizar a variável, atualizar na direção errada, ou usar `!=` com um passo que pula o valor de parada:

```java
int i = 1;
while (i != 10) {   // 1, 4, 7, 10: para
    i += 3;
}
int j = 1;
while (j != 10) {   // 1, 3, 5, 7, 9, 11, 13...: nunca para
    j += 2;
}
```

Com `<` no lugar de `!=`, o segundo laço pararia em 11. Por isso condições de parada com `<` e `>` são mais seguras que com `!=`.

## Por baixo dos panos

Não existe instrução de laço no bytecode, assim como não existe `if`: um laço é um teste com salto para fora e um `goto` de volta para o começo, exatamente o padrão do episódio de [assembly](/assistir/aprendiz-t2-e01). A diferença entre `while` e `do-while` está só em onde o teste fica: antes do corpo, com um salto que pode pular tudo, ou depois do corpo, com um salto que volta para o início. O `javac` não sabe quantas vezes o laço vai rodar; quem descobre os laços "quentes" e os compila para código nativo, às vezes desenrolando várias voltas, é o [JIT](/assistir/aprendiz-t2-e04).

## Resumo para a prova

- `while` testa antes e pode rodar zero vezes; `do-while` testa depois e roda pelo menos uma vez
- `do { } while (condição);` termina com `;`
- Variável declarada dentro do `do { }` não existe na condição
- A variável termina com o primeiro valor que falhou a condição
- `++` na condição acontece a cada teste, inclusive no que falha
- `while (x != fim)` com passo que pula `fim` nunca termina; prefira `<` e `>`
- Monte a tabela volta a volta: é o jeito mais seguro de responder questões de saída
