Laços são a maior fonte de questões de "qual é a saída?" da prova: quantas vezes o corpo roda, qual é o valor da variável depois do fim, o que acontece com um `++` dentro da condição. Este episódio começa pelos dois laços mais simples, `while` e `do-while`, e por um método para contar iterações sem errar.

## `while`: testa antes

```java
while (condição) {
    // corpo
}
```

A condição é testada **antes** de cada volta. Se for falsa logo de início, o corpo não roda nenhuma vez. Como no `if`, ela precisa ser `boolean`.

## `do-while`: testa depois

```java
do {
    // corpo
} while (condição);
```

O corpo roda **primeiro** e a condição é testada depois, então o `do-while` sempre executa pelo menos uma vez. Repare no `;` depois do `while (condição)`: ele é obrigatório.

![Os fluxogramas lado a lado: no while, a condição vem antes do corpo; no do-while, o corpo vem antes da condição](/figuras/while-e-do-while.svg "A única diferença é onde o losango da condição fica. Isso decide se o corpo pode rodar zero vezes.")

A diferença aparece quando a condição já começa falsa:

```java executar
int i = 10;
while (i < 5) {
    System.out.println("while " + i);
    i++;
}
int j = 10;
do {
    System.out.println("do " + j);
    j++;
} while (j < 5);
System.out.println(i + " " + j);
```

```saida
do 10
10 11
```

O `do-while` é o laço natural para "faça e depois pergunte se repete": um menu que aparece pelo menos uma vez, uma leitura que precisa ser validada depois de feita.

> [!PROVA]
> A condição do `do-while` fica **fora** do bloco do corpo. Uma variável declarada dentro do `do { }` já deixou de existir quando o `while (...)` é avaliado:

```java nao-compila
do {
    int tentativa = 1;
} while (tentativa < 3);
```

## Contando as voltas

A maioria das questões se resolve montando uma tabela com o valor das variáveis a cada volta. Faça isso no papel até ficar automático:

```java executar
int n = 0, passos = 0;
while (n < 20) {
    n += 3;
    passos++;
}
System.out.println(n + " " + passos);
```

```saida
21 7
```

| Volta | n antes | n < 20? | n depois |
|---|---|---|---|
| 1 | 0 | sim | 3 |
| 2 | 3 | sim | 6 |
| ... | ... | ... | ... |
| 7 | 18 | sim | 21 |
| fim | 21 | não | |

Em geral, um laço que começa em `a`, soma `s` a cada volta e continua enquanto o valor for menor que `b` roda ⌈(b − a) / s⌉ vezes: ⌈20 / 3⌉ = 7. E a variável termina com o **primeiro valor que falha** a condição (21), não com o último que passou.

> [!MATEMATICA]
> Quando o laço **multiplica** em vez de somar, a conta vira um logaritmo. Começando em 1 e dobrando enquanto o valor for menor que 1.000, o laço roda ⌈log₂ 1.000⌉ = 10 vezes, e a variável termina em 2¹⁰ = 1.024. Compare: somando 2 a cada volta, o mesmo caminho levaria 500 voltas. É a mesma diferença entre a busca linear e a binária da trilha Aprendiz.

> [!PENSE]
> No próximo exemplo, o `++` está dentro da condição. Antes de ver a saída, decida: quantas vezes o `k` é incrementado, e com que valor ele termina?

## Incremento dentro da condição

Quando a condição tem um `++`, ele acontece **a cada teste**, inclusive no último, o que falha:

```java executar
int k = 0;
while (k++ < 3) {
    System.out.print(k + " ");
}
System.out.println("| " + k);
```

```saida
1 2 3 | 4
```

O teste compara o valor antigo (0, 1, 2 passam; 3 falha), mas dentro do corpo `k` já foi incrementado, por isso imprime 1, 2 e 3. O último teste, o que falhou, também incrementou: `k` termina em 4.

> [!PERGUNTAS]
> **P:** Já vi `while (x --> 0)`. Existe um operador `-->`?
>
> **R:** Não. É `x-- > 0` escrito sem espaço: um decremento seguido de uma comparação. A brincadeira de chamar isso de "operador vai para" circula na internet, mas o espaço faz falta para quem lê. Escreva `x-- > 0`.
>
> **P:** Quando usar `while` e quando usar `do-while`?
>
> **R:** Use `do-while` quando o corpo precisa rodar antes de existir algo para testar, como pedir uma senha e depois conferir. Nos outros casos, o `while` é o padrão, e o `for`, do próximo episódio, quando há um contador.

## Padrões de uso

Três padrões cobrem a maior parte dos `while` reais. O **contador** conta quantas vezes algo acontece; o **acumulador** soma valores a cada volta; e a **sentinela** é um valor especial que marca o fim dos dados:

```java executar
int[] leituras = {12, 7, 30, -1, 8};
int i = 0, soma = 0; //> Contador e acumulador começam em zero.
while (leituras[i] != -1) { //> O -1 é a sentinela: marca o fim dos dados.
    soma += leituras[i];
    i++; //> Sem isso, o laço testaria o 12 para sempre.
}
System.out.println(soma + " em " + i + " leituras");
```

```saida
49 em 3 leituras
```

O −1 funciona como sentinela: o laço para ao encontrá-lo, e o 8 depois dele nunca é lido. Se o array não tivesse o −1, o laço passaria do fim e lançaria `ArrayIndexOutOfBoundsException`.

## Laços infinitos

Um laço cuja condição nunca fica falsa roda para sempre. Às vezes é proposital (`while (true)` com `break`, como num servidor que atende pedidos); quase sempre é bug: esquecer de atualizar a variável, atualizar na direção errada, ou usar `!=` com um passo que pula o valor de parada:

```java
int i = 1;
while (i != 10) {   // 1, 4, 7, 10: para
    i += 3;
}
int j = 1;
while (j != 10) {   // 1, 3, 5, 7, 9, 11, 13...: nunca para
    j += 2;
}
```

Com `<` no lugar de `!=`, o segundo laço pararia em 11. Por isso condições de parada com `<` e `>` são mais seguras que com `!=`.

> [!ERRO]
> Pôr `;` depois da condição do `while`: `while (i < 3); { i++; }`. O `;` vira o corpo do laço, um comando vazio que nunca muda `i`, e o programa trava para sempre na mesma linha. O bloco entre chaves nunca chega a rodar. No `do-while` o `;` é obrigatório; no `while`, é um bug.

```imas executar
int tentativas = 0;
int senha;
do {
    tentativas++;
    senha = tentativas * 111;
} while (senha != 333);
System.out.println("Acertou na tentativa " + tentativas);
```

```saida
Acertou na tentativa 3
```

> [!IA]
> Peça um laço que "repita até o usuário acertar" e a IA às vezes escreve um `while` comum, que exige ler a primeira resposta antes do laço e repetir a leitura dentro dele. É o caso clássico do `do-while`: o corpo roda antes do teste. Outro erro frequente é a condição de parada com `!=` e um passo que pula o valor final.

> [!ANTES]
> Antes do Java 5, percorrer uma lista era sempre um `while` com um iterador: `Iterator it = lista.iterator(); while (it.hasNext()) { Object x = it.next(); ... }`. O `for` aprimorado, que você vai ver no [terceiro episódio](/assistir/estagiario-t4-e03), escreve isso numa linha. O padrão do `while` com `hasNext` continua vivo na leitura de dados, como no `Scanner`.

## Na IDE

- **Laço que nunca termina.** O IntelliJ avisa quando percebe que um laço não tem como sair, como um `while (true)` sem `break`.
- **Parar um programa travado.** Se o programa entrar num laço infinito, o botão quadrado vermelho da janela Run, ou **Ctrl + F2**, encerra a execução.
- **Acompanhar as voltas.** Com um breakpoint dentro do laço e o **Debug** (**Shift + F9**), cada **F9** (*Resume*) avança uma volta inteira, e a janela *Variables* mostra a tabela deste episódio sendo preenchida.

## Por baixo dos panos

Não existe instrução de laço no bytecode, assim como não existe `if`: um laço é um teste com salto para fora e um `goto` de volta para o começo, exatamente o padrão do episódio de [assembly](/assistir/aprendiz-t2-e01). A diferença entre `while` e `do-while` está só em onde o teste fica: antes do corpo, com um salto que pode pular tudo, ou depois do corpo, com um salto que volta para o início. O `javac` não sabe quantas vezes o laço vai rodar; quem descobre os laços "quentes" e os compila para código nativo, às vezes desenrolando várias voltas, é o [JIT](/assistir/aprendiz-t2-e04).

## Resumo para a prova

- `while` testa antes e pode rodar zero vezes; `do-while` testa depois e roda pelo menos uma vez
- `do { } while (condição);` termina com `;`
- Variável declarada dentro do `do { }` não existe na condição
- A variável termina com o primeiro valor que falhou a condição
- `++` na condição acontece a cada teste, inclusive no que falha
- `while (x != fim)` com passo que pula `fim` nunca termina; prefira `<` e `>`
- Monte a tabela volta a volta: é o jeito mais seguro de responder questões de saída
