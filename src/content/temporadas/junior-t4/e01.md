Uma classe abstrata diz "o que algo é"; uma **interface** diz "o que algo sabe fazer". Um pato é uma ave, mas sabe voar e nadar, habilidades que também têm aviões e peixes, de hierarquias completamente diferentes. Interfaces são contratos de comportamento que qualquer classe pode assinar, e uma classe pode assinar quantas quiser. Desde o Java 8, elas também podem trazer código pronto, e a prova cobra cada tipo de membro que uma interface aceita.

## Declarar e implementar

```java executar
interface Voador {
    String voar();
}

interface Nadador {
    String nadar();
}

class Pato implements Voador, Nadador {
    public String voar() { return "pato voa"; }
    public String nadar() { return "pato nada"; }
}

Pato p = new Pato();
Voador v = p;
Nadador n = p;
System.out.println(v.voar() + ", " + n.nadar());
System.out.println((v instanceof Nadador) + " " + (n instanceof Pato));
```

```saida
pato voa, pato nada
true true
```

Uma classe estende **uma** classe, mas implementa **várias** interfaces, separadas por vírgula. E uma interface pode estender várias outras com `extends`. A interface é um tipo como outro qualquer: serve para variáveis, parâmetros, arrays, `instanceof` e casts. O que ela não pode é ser instanciada com `new`, nem ter construtores.

## Modificadores implícitos

Tudo numa interface é público, e o compilador acrescenta modificadores que você não escreveu:

| Membro | Implícito | Desde |
|---|---|---|
| Método sem corpo | `public abstract` | sempre |
| Campo | `public static final` (constante) | sempre |
| Método `default` | `public` | Java 8 |
| Método `static` | `public`, se não for `private` | Java 8 |
| Método `private` e `private static` | só usáveis dentro da interface | Java 9 |

Duas consequências caem sempre na prova. Primeira: como o método da interface é `public`, a classe que o implementa **precisa** declará-lo `public`; sem modificador, ela estaria fechando o acesso, como na [sobrescrita](/assistir/junior-t3-e02):

```java nao-compila
interface Forma {
    double area();
}

class Quadrado implements Forma {
    double area() { return 4; }
}
```

Segunda: todo campo de interface é uma constante. Precisa de valor na declaração e não pode ser alterado:

```java executar
interface Config {
    int LIMITE = 3;
    String nome();
}

class App implements Config {
    public String nome() { return "javaflix"; }
}

System.out.println(Config.LIMITE + " " + new App().nome() + " " + App.LIMITE);
```

```saida
3 javaflix 3
```

```java nao-compila
interface Config {
    int LIMITE = 3;
}

class Teste {
    void mudar() {
        Config.LIMITE = 5;
    }
}
```

## Métodos `default`, `static` e `private`

Um método **`default`** tem corpo e é herdado pelas classes que implementam a interface, que podem usá-lo como está ou sobrescrevê-lo. Um método **`static`** pertence à interface e é chamado pelo nome dela. Métodos **`private`** existem para reaproveitar código entre os outros métodos da própria interface:

```java executar
interface Saudacao {
    String nome();

    default String ola() {
        return prefixo() + nome() + "!";
    }

    default String tchau() {
        return "Tchau, " + nome();
    }

    private String prefixo() {
        return "Olá, ";
    }

    static Saudacao de(String nome) {
        return new Saudacao() {
            public String nome() { return nome; }
        };
    }
}

class Formal implements Saudacao {
    public String nome() { return "Sra. Lima"; }
    @Override public String ola() { return "Prezada " + nome(); }
}

Saudacao a = Saudacao.de("Ana");
Saudacao b = new Formal();
System.out.println(a.ola() + " | " + a.tchau());
System.out.println(b.ola() + " | " + b.tchau());
```

```saida
Olá, Ana! | Tchau, Ana
Prezada Sra. Lima | Tchau, Sra. Lima
```

Ao contrário dos métodos `static` de classes, os de interface **não são herdados**: só podem ser chamados pelo nome da interface, nunca pelo da classe que a implementa nem por uma referência.

```java nao-compila
interface Util {
    static int dobro(int x) {
        return x * 2;
    }
}

class Calc implements Util {
}

int a = Util.dobro(2);
int b = Calc.dobro(2);
```

## Interfaces que estendem interfaces

Uma classe abstrata pode implementar uma interface sem implementar os métodos dela, deixando-os para as subclasses concretas, pela mesma regra do [episódio de classes abstratas](/assistir/junior-t3-e05):

```java executar
interface Leitor {
    String ler();
}

interface Escritor {
    void escrever(String s);
}

interface Arquivo extends Leitor, Escritor {
    default String nome() { return "arquivo"; }
}

abstract class ArquivoBase implements Arquivo {
    protected String conteudo = "";
    public String ler() { return conteudo; }
}

class ArquivoTexto extends ArquivoBase {
    public void escrever(String s) { conteudo += s; }
}

Arquivo a = new ArquivoTexto();
a.escrever("abc");
a.escrever("def");
System.out.println(a.nome() + ": " + a.ler());
```

```saida
arquivo: abcdef
```

> [!PROVA]
> Diante de uma interface numa questão, confira: campos têm valor e nunca são reatribuídos; métodos abstratos não têm corpo; `default`, `static` e `private` têm corpo; nada é `protected`; e a classe que implementa declara os métodos como `public`. Cast de uma classe não `final` para uma interface sempre compila, porque alguma subclasse poderia implementá-la; o erro, se houver, aparece na execução.

## Por baixo dos panos

Chamadas por uma referência de interface usam uma instrução própria, `invokeinterface`. A diferença para o `invokevirtual` é que um método de interface não tem posição fixa na tabela virtual: classes diferentes implementam conjuntos diferentes de interfaces, em ordens diferentes. A HotSpot mantém, para cada classe, uma *itable*, uma tabela por interface implementada, e a chamada precisa primeiro achar a tabela certa. Na prática, os caches de chamada do JIT, que você viu no [episódio de polimorfismo](/assistir/junior-t3-e03), deixam o custo igual ao de uma chamada virtual comum.

Os métodos `default` nasceram de um problema concreto. Para o Java 8 acrescentar `stream()` e `forEach` à interface `Collection`, sem quebrar as milhares de classes que já a implementavam, era preciso um jeito de pôr um método com corpo numa interface. As constantes, como qualquer constante de compilação, são copiadas para o código de quem as usa.

## Resumo para a prova

- Uma classe implementa várias interfaces; uma interface estende várias interfaces
- Interfaces não têm construtores e não podem ser instanciadas
- Métodos sem corpo são `public abstract`; campos são `public static final`
- A implementação na classe precisa ser `public`
- `default` tem corpo e é herdado; pode ser sobrescrito
- `static` de interface só é chamado pelo nome da interface e não é herdado
- `private` (Java 9) só serve aos outros métodos da interface
- Classe abstrata pode implementar uma interface sem implementar os métodos dela
