Uma interface com **um único método abstrato** é especial: ela descreve uma função. "Receba dois números e devolva um", "receba um texto e diga se é válido". Essas interfaces se chamam **funcionais**, e são a base das expressões lambda, que transformam um bloco de código num objeto em uma linha. A prova cobra o que conta como interface funcional, a sintaxe básica das lambdas e, principalmente, as interfaces prontas do pacote `java.util.function` e o nome do método de cada uma.

## Um método abstrato, e só um

Uma interface funcional tem exatamente um método abstrato (*SAM*, de *single abstract method*). Ela pode ser implementada por uma classe, por uma classe anônima, como no [episódio de classes aninhadas](/assistir/junior-t2-e05), ou por uma **lambda**:

```java executar
@FunctionalInterface
interface Operacao {
    int aplicar(int a, int b);
}

Operacao soma = new Operacao() {
    @Override
    public int aplicar(int a, int b) {
        return a + b;
    }
};
Operacao multiplicacao = (a, b) -> a * b;
Operacao potencia = (a, b) -> {
    int r = 1;
    for (int i = 0; i < b; i++) r *= a;
    return r;
};
System.out.println(soma.aplicar(3, 4) + " " + multiplicacao.aplicar(3, 4) + " " + potencia.aplicar(3, 4));
```

```saida
7 12 81
```

A lambda `(a, b) -> a * b` é o corpo do único método, sem a cerimônia da classe anônima. Os tipos dos parâmetros vêm da interface. Com uma expressão só, não há chaves nem `return`; com um bloco, as chaves e o `return` são obrigatórios.

## O que conta e o que não conta

Métodos `default`, `static` e `private` têm corpo, então **não contam**. Métodos abstratos que repetem métodos públicos de `Object`, como `equals` e `toString`, também não contam: toda classe já os tem. A anotação `@FunctionalInterface` é opcional, mas faz o compilador conferir a regra:

```java compila
@FunctionalInterface
interface Validador {
    boolean validar(String s);

    default Validador e(Validador outro) {
        return s -> validar(s) && outro.validar(s);
    }

    static Validador naoVazio() {
        return s -> !s.isEmpty();
    }

    boolean equals(Object o);
    String toString();
}
```

```java nao-compila
@FunctionalInterface
interface Conversor {
    double converter(double valor);
    String unidade();
}
```

É por isso que `Comparator`, que declara `equals`, é uma interface funcional.

## As interfaces de `java.util.function`

Quase nunca é preciso criar a sua: o pacote `java.util.function` tem as formas mais comuns, e a prova exige o nome do método de cada uma.

| Interface | Recebe | Devolve | Método |
|---|---|---|---|
| `Supplier<T>` | nada | `T` | `get()` |
| `Consumer<T>` | `T` | nada | `accept(T)` |
| `BiConsumer<T, U>` | `T`, `U` | nada | `accept(T, U)` |
| `Predicate<T>` | `T` | `boolean` | `test(T)` |
| `BiPredicate<T, U>` | `T`, `U` | `boolean` | `test(T, U)` |
| `Function<T, R>` | `T` | `R` | `apply(T)` |
| `BiFunction<T, U, R>` | `T`, `U` | `R` | `apply(T, U)` |
| `UnaryOperator<T>` | `T` | `T` | `apply(T)` |
| `BinaryOperator<T>` | `T`, `T` | `T` | `apply(T, T)` |

```java executar
Supplier<String> saudacao = () -> "olá";
Consumer<String> imprimir = s -> System.out.println("> " + s);
Predicate<String> longa = s -> s.length() > 3;
Function<String, Integer> tamanho = s -> s.length();
UnaryOperator<String> grito = s -> s.toUpperCase();
BinaryOperator<Integer> maior = (a, b) -> a > b ? a : b;
BiFunction<String, Integer, String> repetir = (s, n) -> s.repeat(n);

imprimir.accept(saudacao.get());
System.out.println(longa.test("java") + " " + longa.test("oi"));
System.out.println(tamanho.apply("javaflix") + " " + grito.apply("ok") + " " + maior.apply(3, 9));
System.out.println(repetir.apply("ab", 3));
```

```saida
> olá
true false
8 OK 9
ababab
```

Para evitar o autoboxing, há versões para primitivos: `IntPredicate`, `IntUnaryOperator`, `IntBinaryOperator` e `ToIntFunction`, entre outras, com métodos como `applyAsInt`. A forma `String::length` é uma **referência a método**, um atalho para `s -> s.length()`:

```java executar
IntPredicate par = n -> n % 2 == 0;
IntBinaryOperator soma = (a, b) -> a + b;
ToIntFunction<String> tamanho = String::length;
System.out.println(par.test(4) + " " + soma.applyAsInt(2, 3) + " " + tamanho.applyAsInt("java"));
```

```saida
true 5 4
```

## Combinando funções com métodos `default`

As interfaces prontas trazem métodos `default` para combinar funções: `and`, `or` e `negate` em `Predicate`; `andThen` e `compose` em `Function`; `andThen` em `Consumer`. Repare na ordem: `f.andThen(g)` aplica `f` primeiro; `f.compose(g)` aplica `g` primeiro.

```java executar
Predicate<String> temArroba = s -> s.contains("@");
Predicate<String> curta = s -> s.length() < 6;
Predicate<String> emailLongo = temArroba.and(curta.negate());
Function<Integer, Integer> dobro = x -> x * 2;
Function<Integer, Integer> maisTres = x -> x + 3;
System.out.println(emailLongo.test("ana@x.com") + " " + emailLongo.test("a@b"));
System.out.println(dobro.andThen(maisTres).apply(5) + " " + dobro.compose(maisTres).apply(5));
```

```saida
true false
13 16
```

> [!PROVA]
> Os erros de sintaxe mais cobrados: chaves sem `return` (`x -> { x * 2 }` não compila), `return` sem chaves, parâmetros com e sem tipo misturados, e parênteses omitidos com mais de um parâmetro. Uma lambda só pode ser atribuída a uma interface funcional: `Object o = s -> s.length();` não compila. E, como as classes anônimas, lambdas só capturam variáveis locais efetivamente final.

```java nao-compila
Function<Integer, Integer> f = x -> { x * 2 };
```

As lambdas têm uma temporada própria no cargo Pleno, com referências a métodos, `Comparator` e streams.

## Por baixo dos panos

Uma classe anônima gera um arquivo `.class` na compilação, como o `Loja$1.class`. Uma lambda, não. O `javac` transforma o corpo dela num método privado da própria classe e, no lugar da lambda, coloca uma instrução `invokedynamic`. Na primeira execução, a JVM chama o `LambdaMetafactory`, que gera em memória uma classe *oculta* (*hidden class*, desde o Java 15) implementando a interface. Nas execuções seguintes, o resultado já está ligado.

```java executar
Runnable a = () -> {};
Runnable b = new Runnable() { public void run() { } };
System.out.println(a.getClass().isAnonymousClass() + " " + b.getClass().isAnonymousClass() + " " + a.getClass().isHidden());
```

```saida
false true true
```

Uma lambda que não captura nada é criada uma vez só e reaproveitada em todas as execuções daquela linha; uma que captura variáveis cria um objeto novo a cada vez, com os valores capturados como campos. Essa estratégia deixou o JDK livre para mudar a implementação das lambdas sem recompilar o código de ninguém.

## Resumo para a prova

- Interface funcional: exatamente um método abstrato
- `default`, `static`, `private` e métodos abstratos de `Object` não contam
- `@FunctionalInterface` é opcional e faz o compilador conferir
- Lambda: `(a, b) -> expressão` ou `(a, b) -> { ...; return x; }`
- `Supplier.get`, `Consumer.accept`, `Predicate.test`, `Function.apply`, `UnaryOperator.apply`, `BinaryOperator.apply`
- Versões primitivas usam métodos como `applyAsInt`
- `f.andThen(g)` aplica `f` primeiro; `f.compose(g)` aplica `g` primeiro
- Lambdas só podem ser atribuídas a interfaces funcionais e só capturam variáveis efetivamente final
