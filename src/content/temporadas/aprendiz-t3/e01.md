Todo `if` é uma frase que pode ser verdadeira ou falsa, e toda coleção sem repetição é um conjunto. A lógica proposicional e a teoria dos conjuntos são a matemática por trás dessas duas coisas. Com elas você simplifica condições sem medo de errar, escreve validações que dizem exatamente o que você quer e entende por que `allMatch` numa lista vazia devolve `true`.

## Proposições e conectivos

Uma **proposição** é uma afirmação que é verdadeira ou falsa, sem meio-termo: "o pedido foi pago", "o saldo é maior que zero". Proposições simples se combinam com **conectivos**:

| Conectivo | Símbolo | Lê-se | Em Java |
|---|---|---|---|
| Negação | ¬p | não p | `!p` |
| Conjunção | p ∧ q | p e q | `p && q` |
| Disjunção | p ∨ q | p ou q | `p \|\| q` |
| Ou exclusivo | p ⊕ q | ou p ou q, não os dois | `p ^ q` ou `p != q` |
| Implicação | p → q | se p, então q | `!p \|\| q` |
| Bicondicional | p ↔ q | p se e somente se q | `p == q` |

O Java não tem operador de implicação, mas ela cabe em `!p || q`, como você vai ver.

## A tabela-verdade

Uma **tabela-verdade** lista todas as combinações de valores das proposições. Com n proposições há 2ⁿ linhas, porque cada uma tem 2 valores possíveis.

| p | q | p ∧ q | p ∨ q | p ⊕ q | p → q | p ↔ q |
|---|---|---|---|---|---|---|
| F | F | F | F | F | V | V |
| F | V | F | V | V | V | F |
| V | F | F | V | V | F | F |
| V | V | V | V | F | V | V |

Duas fórmulas são **equivalentes** (≡) quando têm a mesma coluna na tabela. Uma **tautologia** é verdadeira em todas as linhas (p ∨ ¬p). Uma **contradição** é falsa em todas (p ∧ ¬p).

## A implicação, a mais traiçoeira

> [!PENSE]
> Antes de ler: se um cliente comprou R$ 50 e pagou frete, ele pode dizer que a loja quebrou a promessa do frete grátis?

"Se o pedido passa de R$ 200, o frete é grátis." Quando essa regra é quebrada? Só quando o pedido passa de R$ 200 **e** o frete é cobrado. Se o pedido é de R$ 50, a regra não diz nada, e por isso a implicação é verdadeira. É a linha p = F da tabela, chamada **verdade vazia**.

Daí vem a fórmula p → q ≡ ¬p ∨ q: a implicação só falha quando p é verdadeiro e q é falso.

> [!CONVERSA]
> **Implicação:** Eu digo só uma coisa: se p, então q. Sobre o que acontece quando p é falso, eu não prometo nada.
>
> **Recíproca:** E eu sou você ao contrário: se q, então p. Muita gente acha que somos a mesma pessoa.
>
> **Implicação:** Mas não somos. Frete grátis por cupom torna você falsa e me deixa verdadeira.
>
> **Contrapositiva:** Quem é igual a você sou eu: se não q, então não p. Mesma tabela-verdade, linha por linha.

Duas variações aparecem o tempo todo:

- **Contrapositiva**: ¬q → ¬p. É **equivalente** à original. "Se o frete foi cobrado, o pedido não passou de R$ 200."
- **Recíproca**: q → p. **Não** é equivalente. Frete grátis não prova que o pedido passou de R$ 200; pode ter sido um cupom.

Em vez de acreditar, confira por força bruta. Este programa monta a tabela-verdade das três fórmulas:

```java executar
public class Equivalencias {
    static boolean implica(boolean p, boolean q) {
        return !p || q; //> Só é falsa com p verdadeiro e q falso.
    }

    public static void main(String[] args) {
        boolean[] valores = {false, true};
        System.out.println("p     q     p→q   ¬q→¬p q→p");
        for (boolean p : valores) {
            for (boolean q : valores) {
                System.out.printf("%-5b %-5b %-5b %-5b %b%n",
                        p, q, implica(p, q), implica(!q, !p), implica(q, p));
            }
        }
    }
}
```

```saida
p     q     p→q   ¬q→¬p q→p
false false true  true  true
false true  true  true  false
true  false false false true
true  true  true  true  true
```

A terceira e a quarta colunas são iguais: a contrapositiva é equivalente. A recíproca difere em duas linhas.

## Simplificando condições

As leis da álgebra booleana que você viu nas [portas lógicas](/assistir/aprendiz-t1-e02) valem para qualquer condição em Java. As mais úteis no dia a dia:

| Lei | Forma |
|---|---|
| De Morgan | ¬(p ∧ q) ≡ ¬p ∨ ¬q e ¬(p ∨ q) ≡ ¬p ∧ ¬q |
| Dupla negação | ¬¬p ≡ p |
| Absorção | p ∨ (p ∧ q) ≡ p e p ∧ (p ∨ q) ≡ p |
| Distributiva | p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r) |
| Implicação | p → q ≡ ¬p ∨ q |

> [!ERRO]
> Negar uma comparação trocando só o sinal de lado: a negação de `idade >= 18` escrita como `idade <= 18`. O 18 fica dos dois lados, e uma pessoa de 18 anos é recusada e aceita ao mesmo tempo, dependendo do `if`. A negação de `>=` é `<`, e a de `>` é `<=`.

Um exemplo real. Esta condição barra quem não pode se matricular:

```java
if (!(idade >= 18 && (temDocumento || temResponsavel))) { recusar(); }
```

Aplicando De Morgan duas vezes:

```java
if (idade < 18 || (!temDocumento && !temResponsavel)) { recusar(); }
```

Mesma tabela-verdade, mas agora dá para ler em voz alta: "recuse se for menor de idade, ou se não tiver documento nem responsável". Repare que a negação de `>=` é `<`, não `<=`.

> [!ATENCAO]
> Em Java, `&&` e `||` avaliam da esquerda para a direita e param assim que o resultado está decidido (curto-circuito). Logicamente, p ∧ q ≡ q ∧ p. Na prática, `x != null && x.isEmpty()` funciona e `x.isEmpty() && x != null` lança `NullPointerException`. A ordem importa quando um lado tem efeito colateral ou pode falhar.

## Quantificadores

Proposições sobre coleções usam **quantificadores**:

- **Para todo** (∀): ∀x P(x), "todo x satisfaz P"
- **Existe** (∃): ∃x P(x), "algum x satisfaz P"

A negação troca um pelo outro, e é De Morgan de novo: ¬∀x P(x) ≡ ∃x ¬P(x). "Não é verdade que todos passaram" é o mesmo que "alguém não passou". Nas streams do Java, ∀ é `allMatch`, ∃ é `anyMatch` e ¬∃ é `noneMatch`:

```java executar
import java.util.List;

public class Quantificadores {
    public static void main(String[] args) {
        List<Integer> notas = List.of(7, 9, 4, 8);
        System.out.println(!notas.stream().allMatch(n -> n >= 6));
        System.out.println(notas.stream().anyMatch(n -> n < 6));

        List<Integer> vazia = List.of();
        System.out.println(vazia.stream().allMatch(n -> n >= 6));
        System.out.println(vazia.stream().anyMatch(n -> n >= 6));
    }
}
```

```saida
true
true
true
false
```

> [!PERGUNTAS]
> **P:** Não é estranho `allMatch` dar `true` numa lista vazia?
>
> **R:** Parece, mas é o único valor coerente. Se a lista vazia desse `false`, juntar uma lista vazia a uma lista em que todos passam mudaria a resposta, sem nenhum elemento novo reprovado. Com `true`, "todos passaram em A" e "todos passaram em B" implicam "todos passaram em A ∪ B", como deve ser.

As duas primeiras linhas confirmam a negação do quantificador. As duas últimas são a verdade vazia: "todo aluno de uma turma vazia passou" é verdadeiro, porque não há contraexemplo. "Existe aluno que passou" é falso, porque não há exemplo. Um laço que testa "para todo" tem exatamente essa forma: começa com `true` e só muda ao achar um contraexemplo.

## Conjuntos

Um **conjunto** é uma coleção de elementos distintos, sem ordem. A notação básica:

| Notação | Significado | Em `Set<T>` do Java |
|---|---|---|
| x ∈ A | x pertence a A | `a.contains(x)` |
| A ⊆ B | todo elemento de A está em B | `b.containsAll(a)` |
| A ∪ B | união: está em A ou em B | `a.addAll(b)` |
| A ∩ B | interseção: está em A e em B | `a.retainAll(b)` |
| A − B | diferença: está em A e não em B | `a.removeAll(b)` |
| \|A\| | cardinalidade: quantos elementos | `a.size()` |
| ∅ | conjunto vazio | `Set.of()` |

Os métodos `addAll`, `retainAll` e `removeAll` **modificam** o conjunto. Para não estragar o original, faça uma cópia antes:

```java executar
import java.util.Set;
import java.util.TreeSet;

public class Turmas {
    public static void main(String[] args) {
        Set<String> java = new TreeSet<>(Set.of("Ana", "Bruno", "Carla", "Davi"));
        Set<String> sql = new TreeSet<>(Set.of("Carla", "Davi", "Elisa"));

        Set<String> uniao = new TreeSet<>(java);
        uniao.addAll(sql);

        Set<String> intersecao = new TreeSet<>(java);
        intersecao.retainAll(sql); //> Mantém só quem também está em sql; por isso a cópia antes.

        Set<String> soJava = new TreeSet<>(java);
        soJava.removeAll(sql);

        System.out.println("A ∪ B = " + uniao);
        System.out.println("A ∩ B = " + intersecao);
        System.out.println("A − B = " + soJava);
        System.out.println(uniao.size() == java.size() + sql.size() - intersecao.size());
    }
}
```

```saida
A ∪ B = [Ana, Bruno, Carla, Davi, Elisa]
A ∩ B = [Carla, Davi]
A − B = [Ana, Bruno]
true
```

O `TreeSet` mantém os nomes em ordem alfabética; com `HashSet` a ordem de impressão não é garantida.

![Diagrama de Venn das turmas de Java e SQL, com Carla e Davi na interseção; o total é 4 mais 3 menos 2, igual a 5](/figuras/inclusao-exclusao.svg "Quem está nas duas turmas seria contado duas vezes.")

A última linha é o **princípio da inclusão-exclusão**: |A ∪ B| = |A| + |B| − |A ∩ B|. Quem está nas duas turmas seria contado duas vezes, então se desconta uma. Com 4 alunos de Java, 3 de SQL e 2 nas duas, o total é 4 + 3 − 2 = 5.

Lógica e conjuntos são a mesma teoria com roupas diferentes. A ∩ B é o conjunto dos x tais que x ∈ A **∧** x ∈ B; a união usa **∨**; o complemento usa **¬**. Por isso De Morgan também vale para conjuntos: o complemento de A ∪ B é o complemento de A intersectado com o complemento de B.

> [!ANTES]
> George Boole publicou a álgebra da lógica em 1854, e Augustus De Morgan, contemporâneo dele, formulou as leis que levam o seu nome. A teoria dos conjuntos veio depois, com Georg Cantor, nos anos 1870, e os diagramas de John Venn, em 1880. Nas coleções do Java, a interface `Set` existe desde o Java 1.2 (1998); antes, quem precisava de um conjunto usava uma `Hashtable` com valores de enfeite.

## Conjuntos como bits

Se os elementos possíveis são poucos e fixos, um conjunto cabe num número inteiro: o bit i ligado quer dizer "o elemento i está no conjunto". As operações viram operações bit a bit, de um ciclo de CPU cada:

| Conjunto | Bits |
|---|---|
| A ∪ B | `a \| b` |
| A ∩ B | `a & b` |
| A − B | `a & ~b` |
| x ∈ A | `(a & x) != 0` |

É assim que funcionam as permissões de arquivo no Linux (o `chmod 755`):

```java executar
public class Permissoes {
    static final int LER = 1;       // 001
    static final int ESCREVER = 2;  // 010
    static final int EXECUTAR = 4;  // 100

    public static void main(String[] args) {
        int dono = LER | ESCREVER | EXECUTAR;
        int grupo = LER | EXECUTAR;
        int comuns = dono & grupo;
        int soDono = dono & ~grupo;
        System.out.println(dono + " " + grupo + " " + comuns + " " + soDono);
        System.out.println((grupo & ESCREVER) != 0);
    }
}
```

```saida
7 5 5 2
false
```

O 7 do dono é `111` (tudo) e o 5 do grupo é `101` (ler e executar): é o "75" do `chmod 755`.

## O conjunto das partes

Quantos subconjuntos tem um conjunto de n elementos? Cada elemento está ou não está, duas escolhas independentes, então são 2ⁿ. Isso dá um jeito elegante de listar todos: conte de 0 a 2ⁿ − 1 e use os bits do contador como máscara.

```java executar
public class Subconjuntos {
    public static void main(String[] args) {
        String[] itens = {"A", "B", "C"};
        int n = itens.length;
        for (int mascara = 0; mascara < (1 << n); mascara++) {
            StringBuilder sb = new StringBuilder("{");
            for (int i = 0; i < n; i++) {
                if ((mascara & (1 << i)) != 0) {
                    if (sb.length() > 1) sb.append(", ");
                    sb.append(itens[i]);
                }
            }
            String bits = Integer.toBinaryString(mascara | (1 << n)).substring(1);
            System.out.println(bits + " " + sb.append("}"));
        }
    }
}
```

```saida
000 {}
001 {A}
010 {B}
011 {A, B}
100 {C}
101 {A, C}
110 {B, C}
111 {A, B, C}
```

O `mascara | (1 << n)` liga um bit extra à esquerda só para o `toBinaryString` imprimir os zeros à esquerda, e o `substring(1)` o remove. Com 30 elementos já são mais de um bilhão de subconjuntos: algoritmos que testam todas as combinações ficam inviáveis muito rápido, assunto do episódio de [Big-O](/assistir/aprendiz-t3-e05).

> [!MATEMATICA]
> O crescimento de 2ⁿ em números: 10 elementos dão 1.024 subconjuntos, 20 dão 1.048.576 e 30 dão 1.073.741.824. Se testar cada subconjunto levar 1 microssegundo, 20 elementos levam 1 segundo, 30 levam 18 minutos e 40 levam 12,7 dias. Cada elemento a mais **dobra** o tempo. É por isso que "testar todas as combinações" só funciona para entradas muito pequenas.

> [!DICA]
> O `EnumSet` do Java usa exatamente essa técnica por dentro: um conjunto de constantes de um `enum` com até 64 valores é guardado num único `long`. Por isso `EnumSet` é muito mais rápido e econômico que um `HashSet` de enums. Para conjuntos de inteiros grandes, existe o `BitSet`.

> [!IA]
> Ao simplificar condições, a IA às vezes confunde a recíproca com a contrapositiva, ou nega `>=` como `<=`. Peça sempre a tabela-verdade das duas versões, ou rode as duas para todas as combinações, como o programa `Equivalencias` deste episódio. Para conjuntos, confira se ela fez a cópia antes de chamar `retainAll` ou `removeAll`.

## Na IDE

- **Simplificar condições.** Com o cursor num `!(...)`, **Alt + Enter** oferece *Simplify* e *Invert*, que aplicam De Morgan e trocam `>=` por `<` do jeito certo.
- **Condição sempre verdadeira.** A inspeção "Constant conditions" avisa quando uma parte do `if` é sempre verdadeira ou sempre falsa, sinal de uma tautologia ou contradição sem querer.
- **Ver os conjuntos.** No depurador, um `Set` aparece com os elementos e o `size`; *View as*, *Binary* mostra um conjunto guardado em bits.

## Resumo

- Proposição é verdadeira ou falsa; conectivos: ¬, ∧, ∨, ⊕, →, ↔
- Tabela-verdade com n proposições tem 2ⁿ linhas; equivalência é ter a mesma coluna
- p → q ≡ ¬p ∨ q; só falha com p verdadeiro e q falso
- A contrapositiva é equivalente; a recíproca não
- ¬∀ ≡ ∃¬; em lista vazia, `allMatch` dá `true` e `anyMatch` dá `false`
- União, interseção e diferença: `addAll`, `retainAll`, `removeAll`, que modificam o conjunto
- |A ∪ B| = |A| + |B| − |A ∩ B|
- Conjuntos pequenos cabem em bits: `|`, `&`, `& ~`; um conjunto de n elementos tem 2ⁿ subconjuntos
