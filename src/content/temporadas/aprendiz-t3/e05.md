Um programa que responde em um segundo com mil registros pode levar onze dias com um milhão. Outro, que faz a mesma coisa, continua respondendo em um segundo. A diferença não está na linguagem nem no computador, e sim em como o número de operações **cresce** com o tamanho da entrada. Para enxergar isso você precisa de três ferramentas: potências, logaritmos e a notação Big-O.

## Potências de 2

Potências de 2 aparecem em todo lugar porque cada bit dobra as possibilidades. Vale decorar a ponte entre elas e as potências de 10:

| Potência | Valor | Aproximação | Onde aparece |
|---|---|---|---|
| 2¹⁰ | 1.024 | mil (10³) | 1 KiB |
| 2²⁰ | 1.048.576 | milhão (10⁶) | 1 MiB |
| 2³⁰ | 1.073.741.824 | bilhão (10⁹) | 1 GiB |
| 2³¹ | 2.147.483.648 | 2,1 bilhões | limite do `int` |
| 2⁶³ | 9.223.372.036.854.775.808 | 9,2 × 10¹⁸ | limite do `long` |

A regra de bolso: **10 bits valem cerca de 3 dígitos decimais**. As propriedades que você vai usar: 2ᵃ · 2ᵇ = 2ᵃ⁺ᵇ e (2ᵃ)ᵇ = 2ᵃᵇ. Por isso dobrar algo 10 vezes multiplica por mil, e 20 vezes, por um milhão.

## Logaritmo: o inverso da potência

Se 2¹⁰ = 1024, então log₂ 1024 = 10. O logaritmo responde à pergunta "a que potência elevo a base para chegar neste número?". Para programadores, duas leituras do log₂ n são mais úteis que a definição:

- **Quantas vezes dá para dividir n pela metade até chegar a 1.** log₂ 1.000.000 ≈ 20: vinte cortes ao meio reduzem um milhão a um.
- **Quantos bits são necessários para escrever n.** Um número n ≥ 1 tem ⌊log₂ n⌋ + 1 bits; 1.000.000 tem 20.

As propriedades transformam produtos em somas: log(a · b) = log a + log b, e log(aᵏ) = k · log a. E a **mudança de base** diz que logaritmos em bases diferentes só diferem por uma constante:

```text
log_b(n) = ln(n) / ln(b)       log₂ n ≈ 3,32 · log₁₀ n
```

No Java, `Math.log` é o logaritmo natural (base e) e `Math.log10` é o de base 10. Não existe `log2`, e a conta com doubles pode enganar. Para inteiros, a forma exata usa bits:

```java executar
System.out.println(Math.log(1000) / Math.log(10));
System.out.println(Math.log10(1000));
System.out.println(31 - Integer.numberOfLeadingZeros(1_000_000));
System.out.println(Integer.toBinaryString(1_000_000).length());
```

```saida
2.9999999999999996
3.0
19
20
```

A primeira linha é o erro de ponto flutuante do [IEEE 754](/assistir/aprendiz-t3-e03): um `(int)` nesse resultado daria 2. `31 - Integer.numberOfLeadingZeros(n)` é ⌊log₂ n⌋ sem nenhuma conta de ponto flutuante: conta quantos zeros há à esquerda do primeiro bit 1. O processador tem uma instrução para isso (`lzcnt` no x86).

## Dividir pela metade

Todo algoritmo que **descarta metade** do problema a cada passo faz cerca de log₂ n passos. É o caso da busca binária num array ordenado: compare com o elemento do meio e descarte a metade em que o valor não pode estar.

```java executar
int passos = 0;
for (int n = 1_000_000; n > 1; n /= 2) {
    passos++;
}
System.out.println(passos);
```

```saida
19
```

Num milhão de elementos ordenados, a busca binária acha qualquer valor (ou prova que ele não está lá) em no máximo 20 comparações. Num bilhão, 30. A busca linear precisaria de até um bilhão.

## Somas que aparecem nos laços

Dois resultados de matemática do ensino médio explicam o custo de muitos laços.

**Soma de Gauss.** 1 + 2 + ... + n = n(n + 1)/2. Um laço que compara cada par de elementos (o `j` começando depois do `i`) faz 0 + 1 + ... + (n − 1) = n(n − 1)/2 comparações:

```java executar
int n = 1000;
long comparacoes = 0;
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        comparacoes++;
    }
}
System.out.println(comparacoes);
System.out.println((long) n * (n - 1) / 2);
```

```saida
499500
499500
```

Metade de n², mas ainda proporcional a n²: dobrar n quadruplica o trabalho.

**Soma geométrica.** 1 + 2 + 4 + ... + 2ᵏ = 2ᵏ⁺¹ − 1: a soma de todas as potências anteriores é menor que a próxima. É por isso que o `ArrayList` pode crescer copiando tudo para um array maior quando enche. Se cada crescimento dobra a capacidade, o total de cópias para inserir n elementos fica abaixo de 2n, ou seja, um custo médio constante por inserção, o chamado **custo amortizado** O(1). O `ArrayList` real cresce 50% de cada vez (a conta dá menos de 3n cópias) e continua O(1) amortizado.

## Big-O: a definição

A notação Big-O descreve como o custo cresce, ignorando constantes e termos pequenos. A definição formal:

```text
f(n) = O(g(n))  se existem c > 0 e n₀ tais que f(n) ≤ c · g(n) para todo n ≥ n₀
```

Em palavras: a partir de algum tamanho, f nunca passa de um múltiplo fixo de g. Exemplo: f(n) = 3n² + 10n + 5 é O(n²). Para n ≥ 10, vale 10n ≤ n² e 5 ≤ n², então f(n) ≤ 3n² + n² + n² = 5n². Com c = 5 e n₀ = 10, a definição está satisfeita.

As regras práticas saem daí:

- **Descarte constantes**: 5n e n/2 são O(n).
- **Fique com o termo dominante**: n² + n + 1000 é O(n²).
- **Base de logaritmo não importa**: log₂ n e log₁₀ n diferem por um fator constante, então ambos são O(log n).

Big-O é um **limite superior**: n é tecnicamente O(n²), embora isso diga pouco. Quando o limite é justo nos dois sentidos, o nome é Θ (theta), e o limite inferior é Ω (ômega). No dia a dia, as pessoas dizem O querendo dizer Θ.

## As classes mais comuns

| Classe | Nome | Exemplo | n = 1.000 | n = 1.000.000 |
|---|---|---|---|---|
| O(1) | constante | `array[i]`, `ArrayList.get` | 1 | 1 |
| O(log n) | logarítmica | busca binária, `TreeMap.get` | 10 | 20 |
| O(n) | linear | percorrer uma lista, `ArrayList.contains` | 1.000 | 1.000.000 |
| O(n log n) | linearítmica | `Collections.sort`, merge sort | 10.000 | 20.000.000 |
| O(n²) | quadrática | dois laços aninhados sobre os dados | 1.000.000 | 10¹² |
| O(2ⁿ) | exponencial | testar todos os subconjuntos | 10³⁰¹ | impossível |
| O(n!) | fatorial | testar todas as ordens | 10²⁵⁶⁷ | impossível |

Um processador moderno faz algo na casa de 10⁸ a 10⁹ operações simples por segundo. Com essa régua: 10¹² operações (O(n²) com um milhão de itens) levam de 15 minutos a algumas horas, e 10³⁰¹ não terminariam nem se o universo durasse trilhões de vezes mais. É a mesma explosão que você viu no [conjunto das partes](/assistir/aprendiz-t3-e01).

## Contando operações no código

Os padrões que cobrem quase tudo:

```java
for (int i = 0; i < n; i++) { ... }                 // O(n)

for (int i = 0; i < n; i++)                          // O(n²)
    for (int j = 0; j < n; j++) { ... }

for (int i = 1; i < n; i *= 2) { ... }               // O(log n): i dobra a cada volta

for (int i = 0; i < n; i++)                          // O(n log n)
    for (int j = 1; j < n; j *= 2) { ... }
```

Blocos em sequência **somam** (O(n) + O(n²) = O(n²): fica o maior). Blocos aninhados **multiplicam**. E uma recursão que chama a si mesma duas vezes, sem guardar resultados, cresce exponencialmente:

```java executar
public class Fibonacci {
    static long chamadas = 0;

    static long fib(int n) {
        chamadas++;
        return n < 2 ? n : fib(n - 1) + fib(n - 2);
    }

    public static void main(String[] args) {
        System.out.println(fib(20) + " em " + chamadas + " chamadas");
        chamadas = 0;
        System.out.println(fib(30) + " em " + chamadas + " chamadas");
    }
}
```

```saida
6765 em 21891 chamadas
832040 em 2692537 chamadas
```

Dez a mais no n multiplicaram as chamadas por 123: o crescimento é de cerca de 1,618ⁿ (a razão áurea). Um laço que guarda os dois últimos valores calcula o mesmo em n passos, O(n).

## O custo das coleções do Java

| Operação | `ArrayList` | `LinkedList` | `HashMap` / `HashSet` | `TreeMap` / `TreeSet` |
|---|---|---|---|---|
| Acessar por índice | O(1) | O(n) | não tem | não tem |
| Inserir no fim | O(1) amortizado | O(1) | O(1) em média | O(log n) |
| Inserir no começo | O(n) | O(1) | não tem | não tem |
| Buscar um valor | O(n) | O(n) | O(1) em média | O(log n) |

A armadilha mais comum em código real é um `contains` em lista dentro de um laço:

```java
for (Pedido p : pedidos) {                 // n pedidos
    if (cancelados.contains(p.id())) { ... }  // ArrayList: O(m) por busca
}
```

Com 100 mil pedidos e 100 mil cancelados, são 10¹⁰ comparações. Trocar `cancelados` por um `HashSet` torna cada busca O(1) em média, e o laço inteiro, O(n): de minutos para milissegundos, com uma linha alterada.

## Big-O não é tudo

- **Constantes importam para n pequeno.** Para ordenar 10 elementos, um algoritmo O(n²) simples pode ganhar de um O(n log n) sofisticado. O `Arrays.sort` do Java usa ordenação por inserção, que é O(n²), em pedaços pequenos.
- **Memória e cache importam.** A `LinkedList` tem inserção O(1) no meio, mas seus nós ficam espalhados na memória, e percorrer a lista causa falhas de cache (lembre da [hierarquia de memória](/assistir/aprendiz-t1-e04)). Na prática, `ArrayList` costuma ganhar quase sempre.
- **Caso médio não é pior caso.** O `HashMap` é O(1) em média, mas se todas as chaves colidirem, vira O(n). Desde o Java 8, um balde com muitas colisões é convertido numa árvore, e o pior caso cai para O(log n).
- **Espaço também é complexidade.** Uma recursão de profundidade n usa O(n) de pilha, e é assim que nasce o `StackOverflowError`.

## Resumo

- 2¹⁰ ≈ mil, 2²⁰ ≈ milhão, 2³⁰ ≈ bilhão; 10 bits ≈ 3 dígitos
- log₂ n = quantas vezes dá para dividir n ao meio = quantos bits n tem (menos um)
- Para ⌊log₂ n⌋ exato em inteiros: `31 - Integer.numberOfLeadingZeros(n)`
- 1 + 2 + ... + n = n(n + 1)/2 → pares de elementos são O(n²)
- 1 + 2 + 4 + ... + 2ᵏ = 2ᵏ⁺¹ − 1 → crescer dobrando dá O(1) amortizado
- f = O(g): a partir de n₀, f ≤ c · g. Descarte constantes e termos menores
- Laços em sequência somam, aninhados multiplicam; dividir ao meio dá log n
- `contains` em `ArrayList` é O(n); em `HashSet`, O(1) em média
