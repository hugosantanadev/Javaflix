O `toString` das classes de data usa o formato ISO, ótimo para máquinas e estranho para pessoas: ninguém escreve `2024-03-05` num boleto brasileiro. Este episódio fecha a temporada com o `DateTimeFormatter`, que transforma datas em texto e texto em datas, e com as pontes para a API antiga, que todo sistema real ainda tem.

## Formatar e interpretar

Um `DateTimeFormatter` é criado a partir de um padrão de letras e serve nos dois sentidos: `format` transforma uma data em texto, e `parse` faz o caminho inverso. Os dois estilos de chamada são equivalentes: `data.format(f)` e `f.format(data)`.

```java executar
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.util.Locale;

public class Formatos {
    public static void main(String[] args) {
        LocalDateTime t = LocalDateTime.of(2024, 3, 5, 14, 7, 9);
        DateTimeFormatter br = DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm");
        System.out.println(t.format(br) + " | " + br.format(t));
        System.out.println(t.format(DateTimeFormatter.ofPattern("d/M/yy h:mm a", Locale.US)));

        DateTimeFormatter extenso = DateTimeFormatter.ofPattern("EEEE, d 'de' MMMM 'de' yyyy", Locale.forLanguageTag("pt-BR"));
        System.out.println(t.format(extenso));

        LocalDate lida = LocalDate.parse("05/03/2024", DateTimeFormatter.ofPattern("dd/MM/yyyy"));
        System.out.println(lida + " " + lida.getMonth());
    }
}
```

```saida
05/03/2024 14:07 | 05/03/2024 14:07
5/3/24 2:07 PM
terça-feira, 5 de março de 2024
2024-03-05 MARCH
```

## As letras do padrão

| Letra | Significado | Exemplos |
|---|---|---|
| `y` / `u` | Ano | `yy` = 24, `yyyy` = 2024 |
| `M` | Mês | `M` = 3, `MM` = 03, `MMM` = abreviado, `MMMM` = março |
| `d` | Dia do mês | `d` = 5, `dd` = 05 |
| `E` | Dia da semana | `EEEE` = terça-feira |
| `H` | Hora de 0 a 23 | `HH` = 14 |
| `h` e `a` | Hora de 1 a 12 e AM/PM | `h:mm a` = 2:07 PM |
| `m` | **Minuto** | `mm` = 07 |
| `s` / `S` | Segundo e fração | `ss` = 09 |
| `XXX` / `VV` | Deslocamento e fuso | `-03:00`, `America/Sao_Paulo` |
| `'texto'` | Texto literal | `'de'`, e `''` para um apóstrofo |

Repetir a letra muda a forma: uma letra não preenche com zeros, duas preenchem, três e quatro passam a texto (nos campos que têm nome). Nomes de meses e dias dependem do `Locale`; sem ele, o formatador usa o idioma da máquina, e o mesmo programa imprime "March" num servidor e "março" em outro.

## As quatro armadilhas clássicas

```java executar
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

public class Armadilhas {
    public static void main(String[] args) {
        LocalDateTime t = LocalDateTime.of(2024, 3, 5, 14, 7);
        System.out.println(t.format(DateTimeFormatter.ofPattern("dd/mm/yyyy")));

        LocalDate fimDeAno = LocalDate.of(2024, 12, 30);
        System.out.println(fimDeAno.format(DateTimeFormatter.ofPattern("dd/MM/YYYY")) + " " + fimDeAno.format(DateTimeFormatter.ofPattern("dd/MM/yyyy")));

        System.out.println(LocalDate.parse("31/02/2023", DateTimeFormatter.ofPattern("dd/MM/yyyy")));
    }
}
```

```saida
05/07/2024
30/12/2025 30/12/2024
2023-02-28
```

1. **`mm` é minuto**, `MM` é mês. O primeiro resultado trocou o mês pelos 7 minutos.
2. **`YYYY` é o ano da semana**, não o ano do calendário. A semana que contém 30 de dezembro de 2024 já pertence a 2025, e o ano "pulou". Esse erro já derrubou sistemas de empresas grandes em dias de fim de ano.
3. **O modo padrão de interpretação, `SMART`, corrige datas impossíveis** de dias 29 a 31: "31/02/2023" vira 28 de fevereiro, sem erro. Para recusar, use `.withResolverStyle(ResolverStyle.STRICT)` com `uuuu` no lugar de `yyyy` (no modo estrito, `yyyy` exigiria também a era).
4. **O padrão precisa combinar com o tipo.** Formatar um `LocalDate` com `HH` lança `UnsupportedTemporalTypeException`, porque a data não tem hora. Interpretar "05/03/2024" como `LocalDateTime` lança `DateTimeParseException`, porque o texto não tem hora.

> [!PROVA]
> Os erros de formatação acontecem **na execução**: o padrão é só uma `String`, e o compilador não o confere. Uma letra inválida no padrão lança `IllegalArgumentException` em `ofPattern`; um campo ausente no objeto lança `UnsupportedTemporalTypeException` em `format`; um texto que não combina lança `DateTimeParseException` em `parse`.

## Formatadores prontos

A classe traz constantes para os formatos ISO e estilos localizados, que se adaptam ao idioma:

```java executar
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.time.format.FormatStyle;
import java.util.Locale;

public class Prontos {
    public static void main(String[] args) {
        LocalDateTime t = LocalDateTime.of(2024, 3, 5, 14, 7, 9);
        System.out.println(t.format(DateTimeFormatter.ISO_LOCAL_DATE) + " " + t.format(DateTimeFormatter.BASIC_ISO_DATE) + " " + t.format(DateTimeFormatter.ISO_LOCAL_DATE_TIME));
        System.out.println(LocalDate.parse("20240305", DateTimeFormatter.BASIC_ISO_DATE));

        DateTimeFormatter longo = DateTimeFormatter.ofLocalizedDate(FormatStyle.LONG).withLocale(Locale.forLanguageTag("pt-BR"));
        System.out.println(longo.format(t));
    }
}
```

```saida
2024-03-05 20240305 2024-03-05T14:07:09
2024-03-05
5 de março de 2024
```

## Pontes com a API antiga

Bibliotecas antigas, frameworks e o JDBC ainda usam `java.util.Date` e as classes de `java.sql`. Cada uma ganhou métodos de conversão no Java 8:

| De | Para | Como |
|---|---|---|
| `Instant` | `java.util.Date` | `Date.from(instant)` |
| `java.util.Date` | `Instant` | `data.toInstant()` |
| `LocalDate` | `java.sql.Date` | `java.sql.Date.valueOf(localDate)` |
| `java.sql.Date` | `LocalDate` | `sqlDate.toLocalDate()` |
| `LocalDateTime` | `java.sql.Timestamp` | `Timestamp.valueOf(ldt)` |

`java.util.Date`, apesar do nome, representa um **instante**, e por isso converte para `Instant`, não para `LocalDate`. Para chegar a uma data, é preciso escolher o fuso: `data.toInstant().atZone(fuso).toLocalDate()`.

## Por baixo dos panos

O `SimpleDateFormat` antigo guardava um `Calendar` num campo e o alterava a cada chamada de `format` e `parse`. Duas threads usando o mesmo formatador sobrescreviam o estado uma da outra e produziam datas trocadas, sem exceção nenhuma. O `DateTimeFormatter` é **imutável** e seguro entre threads: pode ser guardado numa constante `static final` e compartilhado por toda a aplicação.

A interpretação acontece em duas fases. Primeiro, o texto é quebrado em campos soltos (dia 31, mês 2, ano 2023), guardados num objeto intermediário. Depois, a fase de **resolução** combina os campos num objeto de data, e é nela que o `ResolverStyle` age: `STRICT` recusa o dia 31 de fevereiro, `SMART` o ajusta para o último dia válido, e `LENIENT` deixaria transbordar para 3 de março. A mensagem `Unable to obtain LocalDateTime from TemporalAccessor` vem exatamente dessa fase: os campos foram lidos, mas não bastam para montar o tipo pedido.

## Resumo para a prova

- `DateTimeFormatter.ofPattern` cria o formatador; `format` e `parse` usam o mesmo objeto
- `MM` é mês, `mm` é minuto; `HH` vai de 0 a 23, `hh` de 1 a 12; `yyyy` é ano, `YYYY` é ano da semana
- Texto literal entre aspas simples; `''` para um apóstrofo
- O padrão só é conferido na execução: `IllegalArgumentException`, `UnsupportedTemporalTypeException` ou `DateTimeParseException`
- O modo `SMART` ajusta dias 29 a 31 inexistentes; `STRICT` com `uuuu` recusa
- `Date.from(instant)` e `date.toInstant()`; `java.sql.Date.valueOf(localDate)` e `toLocalDate()`
