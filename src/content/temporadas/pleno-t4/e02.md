Uma data diz **quando**; uma quantidade de tempo diz **quanto**. O `java.time` tem duas classes para quantidades, e a diferença entre elas é o centro de muitas questões: `Period` mede em anos, meses e dias, como um calendário; `Duration` mede em segundos e nanossegundos, como um cronômetro.

## Period: quantidades de calendário

Um `Period` guarda três números independentes: anos, meses e dias. O `toString` usa o formato ISO 8601, que começa com `P` (*period*):

```java executar
import java.time.LocalDate;
import java.time.Period;

public class Periodos {
    public static void main(String[] args) {
        System.out.println(Period.of(1, 2, 3) + " " + Period.ofWeeks(2) + " " + Period.ofDays(45) + " " + Period.ofDays(0));
        System.out.println(Period.ofMonths(14) + " " + Period.ofMonths(14).normalized());

        Period errado = Period.ofYears(1).ofMonths(2);
        System.out.println(errado);

        LocalDate contrato = LocalDate.of(2024, 1, 31);
        System.out.println(contrato.plus(Period.ofMonths(1)) + " " + contrato.plus(Period.of(0, 1, 1)));
    }
}
```

```saida
P1Y2M3D P14D P45D P0D
P14M P1Y2M
P2M
2024-02-29 2024-03-01
```

Três detalhes. `ofWeeks(2)` vira 14 **dias**: `Period` não guarda semanas. Os campos não são normalizados sozinhos: 45 dias continuam 45 dias, e 14 meses só viram 1 ano e 2 meses com `normalized()`. E a pegadinha clássica da terceira linha: `ofYears` e `ofMonths` são métodos **estáticos**, então `Period.ofYears(1).ofMonths(2)` descarta o primeiro período e cria só `P2M`. Para combinar, use `Period.of(1, 2, 0)` ou `Period.ofYears(1).plusMonths(2)`.

## Duration: quantidades de relógio

`Duration` guarda segundos e nanossegundos. O `toString` começa com `PT` (*period of time*) e mostra horas, minutos e segundos, nunca dias:

```java executar
import java.time.Duration;
import java.time.LocalTime;

public class Duracoes {
    public static void main(String[] args) {
        System.out.println(Duration.ofHours(2) + " " + Duration.ofMinutes(90) + " " + Duration.ofDays(1) + " " + Duration.ofMillis(1500));
        System.out.println(Duration.ofSeconds(3661) + " " + Duration.ZERO + " " + Duration.ofMinutes(-90));

        Duration expediente = Duration.between(LocalTime.of(9, 15), LocalTime.of(17, 50));
        System.out.println(expediente + " " + expediente.toMinutes() + " " + expediente.toHoursPart() + "h" + expediente.toMinutesPart());
        System.out.println(Duration.between(LocalTime.of(17, 0), LocalTime.of(9, 0)));
    }
}
```

```saida
PT2H PT1H30M PT24H PT1.5S
PT1H1M1S PT0S PT-1H-30M
PT8H35M 515 8h35
PT-8H
```

`Duration.ofDays(1)` imprime `PT24H`: para uma duração, um dia é exatamente 86.400 segundos. `toMinutes()` dá o **total** em minutos; `toHoursPart()` e `toMinutesPart()` (Java 9) dão as partes, como num relógio. E `between` com o fim antes do início dá uma duração negativa.

## Qual combina com qual

| | `LocalDate` | `LocalTime` | `LocalDateTime` |
|---|---|---|---|
| `plus(Period)` | Sim | `UnsupportedTemporalTypeException` | Sim |
| `plus(Duration)` | `UnsupportedTemporalTypeException` | Sim | Sim |

Os erros acontecem **na execução**, não na compilação, porque `plus` recebe a interface `TemporalAmount`. Uma data não sabe somar segundos, e uma hora não sabe somar dias.

```java executar
import java.time.Duration;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.Period;
import java.time.temporal.UnsupportedTemporalTypeException;

public class Combinacoes {
    public static void main(String[] args) {
        LocalDateTime inicio = LocalDateTime.of(2024, 1, 1, 10, 0);
        System.out.println(inicio.plus(Period.ofDays(1)) + " " + inicio.plus(Duration.ofHours(36)));
        try {
            LocalDate.of(2024, 1, 1).plus(Duration.ofDays(1));
        } catch (UnsupportedTemporalTypeException e) {
            System.out.println("LocalDate com Duration: " + e.getMessage());
        }
    }
}
```

```saida
2024-01-02T10:00 2024-01-02T22:00
LocalDate com Duration: Unsupported unit: Seconds
```

## Medindo a distância entre datas

Há três formas, com respostas diferentes:

```java executar
import java.time.LocalDate;
import java.time.Period;
import java.time.temporal.ChronoUnit;

public class Distancias {
    public static void main(String[] args) {
        LocalDate a = LocalDate.of(2024, 1, 15);
        LocalDate b = LocalDate.of(2024, 3, 20);
        Period p = Period.between(a, b);
        System.out.println(p + " " + p.getDays() + " " + p.getMonths());
        System.out.println(ChronoUnit.DAYS.between(a, b) + " " + ChronoUnit.WEEKS.between(a, b) + " " + a.until(b, ChronoUnit.MONTHS));
        System.out.println(Period.between(b, a) + " " + Period.between(LocalDate.of(2024, 1, 31), LocalDate.of(2024, 3, 1)));
    }
}
```

```saida
P2M5D 5 2
65 9 2
P-2M-5D P1M1D
```

`Period.between` decompõe a distância em meses e dias: `getDays()` devolve só a **parte** dos dias, 5, e não os 65 dias totais. Para o total numa unidade, use `ChronoUnit.X.between(a, b)` ou `a.until(b, unidade)`, que devolvem `long` e descartam a fração: 65 dias são 9 semanas completas.

> [!PROVA]
> `Period.ofWeeks(2)` imprime `P14D`. `Duration.ofDays(1)` imprime `PT24H`. Encadear fábricas estáticas (`Period.ofYears(1).ofMonths(2)`) fica só com a última. `Period` em `LocalTime` e `Duration` em `LocalDate` lançam `UnsupportedTemporalTypeException` na execução.

## Por baixo dos panos

A separação não é capricho: "um dia" de calendário e "24 horas" de relógio são coisas diferentes. Num dia de horário de verão, a distância de meio-dia a meio-dia do dia seguinte pode ser 23 ou 25 horas. Somar `Period.ofDays(1)` mantém o meio-dia; somar `Duration.ofHours(24)` mantém as 24 horas e muda o horário de parede. O [episódio 4](/assistir/pleno-t4-e04) mostra isso com fusos de verdade.

Internamente, `Duration` guarda um `long` de segundos e um `int` de nanossegundos, de 0 a 999.999.999. Uma duração negativa como `PT-1.5S` é guardada como -2 segundos mais 500 milhões de nanos, para que o campo de nanos nunca seja negativo. `Period` guarda três `int` sem relação entre si, e por isso `P1M` somado a 31 de janeiro dá um resultado diferente de `P30D`.

O formato dos dois `toString` vem da norma ISO 8601, a mesma que define `2024-03-15` e `14:30`. Ela é o idioma comum das APIs: um JSON com `"PT1H30M"` é lido por `Duration.parse` sem formatador.

## Resumo para a prova

- `Period`: anos, meses e dias, `toString` com `P`; `Duration`: segundos e nanos, `toString` com `PT`
- `ofWeeks` vira dias; `normalized()` converte 12 meses em 1 ano; `Duration.ofDays(1)` é `PT24H`
- Fábricas encadeadas: só a última vale
- `Period` não serve para `LocalTime`; `Duration` não serve para `LocalDate`: `UnsupportedTemporalTypeException`
- `Period.between(...).getDays()` é só a parte dos dias; o total vem de `ChronoUnit.DAYS.between`
- `toMinutes()` é total; `toMinutesPart()` é a parte
