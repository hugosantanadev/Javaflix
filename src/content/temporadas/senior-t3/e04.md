Os episódios anteriores abriram arquivos pelo nome, com `new FileReader("dados.txt")` e `File.createTempFile`. Para trabalhar de verdade com o sistema de arquivos, como montar caminhos, descobrir a pasta de um arquivo ou comparar duas localizações, o Java 7 trouxe o pacote **NIO.2**, `java.nio.file`, com a interface `Path` no centro. Este episódio trata só de caminhos: manipulá-los **não toca o disco**. Ler, escrever e copiar ficam para o [próximo episódio](/assistir/senior-t3-e05).

## Criando um Path

Um `Path` representa um caminho no sistema de arquivos, que pode ou não existir. As formas de criar um:

| Forma | Desde |
|---|---|
| `Path.of("a", "b", "c")` | Java 11 |
| `Paths.get("a", "b", "c")` | Java 7, equivalente |
| `FileSystems.getDefault().getPath("a/b")` | Java 7 |
| `arquivo.toPath()`, a partir de um `java.io.File` | Java 7 |

Os vários argumentos são unidos com o separador do sistema. O caminho de volta também existe: `path.toFile()` devolve um `java.io.File`, a classe antiga, que mistura caminho e operações de disco num objeto só, com métodos como `exists()`, `mkdir()` e `listFiles()`. Código novo usa `Path` e a classe `Files`.

Um detalhe de portabilidade: o separador é `/` no Linux e no macOS e `\` no Windows, e o `toString()` de um `Path` usa o do sistema. Para que a saída dos exemplos seja a mesma em qualquer máquina, eles imprimem os caminhos com um método `txt`, que troca o separador por `/`. A lógica dos caminhos é a mesma nos dois sistemas.

## As partes de um caminho

Um caminho tem uma **raiz** opcional (`/` no Linux, algo como `C:\` no Windows) e uma sequência de **nomes**. Os nomes são numerados a partir de 0, **sem contar a raiz**.

| Método | Devolve |
|---|---|
| `getNameCount()` | Quantidade de nomes |
| `getName(i)` | O nome na posição `i`, como `Path` |
| `subpath(inicio, fim)` | Os nomes de `inicio` até `fim - 1`, sem raiz |
| `getFileName()` | O último nome |
| `getParent()` | Tudo menos o último nome; `null` se não houver |
| `getRoot()` | A raiz; `null` num caminho relativo |

```java executar
import java.io.File;
import java.nio.file.Path;

public class Partes {
    static String txt(Path p) {
        return p == null ? "null" : p.toString().replace(File.separatorChar, '/');
    }

    public static void main(String[] args) {
        Path p = Path.of("/zoo/animais/urso/comida.txt");
        System.out.println(txt(p) + " " + p.getNameCount());
        System.out.println(txt(p.getName(0)) + " " + txt(p.getName(3)) + " " + txt(p.subpath(1, 3)));
        System.out.println(txt(p.getFileName()) + " " + txt(p.getParent()) + " " + txt(p.getRoot()));
        Path r = Path.of("animais", "urso");
        System.out.println(txt(r) + " " + txt(r.getRoot()) + " " + txt(Path.of("a").getParent()));
        for (Path parte : p) {
            System.out.print(txt(parte) + "|");
        }
        System.out.println();
    }
}
```

```saida
/zoo/animais/urso/comida.txt 4
zoo comida.txt animais/urso
comida.txt /zoo/animais/urso /
animais/urso null null
zoo|animais|urso|comida.txt|
```

Quatro nomes, `zoo` no índice 0, e a raiz fora da contagem. `subpath(1, 3)` pega os índices 1 e 2, e o resultado nunca tem raiz. Um índice inválido, como `getName(4)` ou `subpath(2, 2)`, lança `IllegalArgumentException`. E um `Path` é `Iterable<Path>`: o for-each percorre os nomes.

## Absoluto ou relativo

Um caminho **absoluto** começa da raiz e aponta para o mesmo lugar não importa de onde o programa rode. Um **relativo** é resolvido a partir da pasta atual do programa. `isAbsolute()` informa, e `toAbsolutePath()` junta a pasta atual a um caminho relativo.

Aqui está a única diferença real entre os sistemas: no Windows, um caminho absoluto exige a **unidade**, como `C:\dados`. O caminho `/zoo` tem raiz, mas sem unidade: `isAbsolute()` devolve `true` no Linux e `false` no Windows. A prova segue o estilo do Linux, em que todo caminho que começa com `/` é absoluto.

## normalize: tirando os pontos

Os nomes especiais `.` (a pasta atual) e `..` (a pasta de cima) podem aparecer no meio de um caminho. `normalize()` os elimina **só olhando o texto**, sem consultar o disco: cada `..` apaga o nome anterior, e cada `.` some. Um `..` sem nome antes, num caminho relativo, é mantido; logo depois da raiz, é descartado, porque não há nada acima dela.

## resolve e relativize

`resolve` **junta** dois caminhos: `base.resolve(outro)` acrescenta `outro` ao fim de `base`. Se `outro` for absoluto, o resultado é simplesmente `outro`. Nenhum dos dois métodos normaliza nada.

`relativize` faz o contrário: `a.relativize(b)` devolve o caminho que leva **de `a` até `b`**. Os dois precisam ser do mesmo tipo, ambos absolutos ou ambos relativos; misturar lança `IllegalArgumentException`. Para caminhos relativos, os dois são considerados a partir da mesma pasta.

```java executar
import java.io.File;
import java.nio.file.Path;

public class Combinando {
    static String txt(Path p) {
        return p.toString().replace(File.separatorChar, '/');
    }

    public static void main(String[] args) {
        System.out.println(txt(Path.of("/zoo/../casa/./ana").normalize()) + " " + txt(Path.of("../a/./b/..").normalize()) + " " + txt(Path.of("/..").normalize()));
        System.out.println(txt(Path.of("/gatos/../pantera").resolve("comida")) + " " + txt(Path.of("/gatos").resolve("/onça")));
        System.out.println(txt(Path.of("peixe.txt").relativize(Path.of("amigos/aves.txt"))) + " " + txt(Path.of("/habitat").relativize(Path.of("/santuario/corvo/poe.txt"))));
        System.out.println("[" + txt(Path.of("/a/b").relativize(Path.of("/a/b"))) + "] " + txt(Path.of("/a/b").relativize(Path.of("/a"))));
        try {
            Path.of("/a").relativize(Path.of("b"));
        } catch (IllegalArgumentException e) {
            System.out.println("absoluto com relativo: IllegalArgumentException");
        }
        System.out.println(txt(Path.of("a", "b").resolveSibling("c")));
    }
}
```

```saida
/casa/ana ../a /
/gatos/../pantera/comida /onça
../amigos/aves.txt ../santuario/corvo/poe.txt
[] ..
absoluto com relativo: IllegalArgumentException
a/c
```

Repare no `resolve` da segunda linha: o `..` continua lá, porque `resolve` só concatena. E em `peixe.txt` para `amigos/aves.txt`, o caminho começa com `..`: `peixe.txt` é tratado como uma pasta, e é preciso subir um nível para sair dela. Relativizar um caminho com ele mesmo dá um caminho vazio. `resolveSibling` resolve a partir do pai: troca o último nome.

## Comparando caminhos

`equals` compara o **texto** dos caminhos, sem normalizar: `a/./b` e `a/b` são diferentes. `startsWith` e `endsWith` comparam **nomes inteiros**, não letras: `/zoo/urso/comida.txt` termina com `comida.txt` e com `urso/comida.txt`, mas não com `.txt`. Um caminho absoluto não começa com um relativo, mesmo que os nomes coincidam.

Para saber se dois caminhos apontam para o **mesmo arquivo** no disco, resolvendo pontos e atalhos, há `Files.isSameFile` e `toRealPath()`, que consultam o sistema de arquivos e lançam `NoSuchFileException` se o arquivo não existir.

```java executar
import java.nio.file.Path;

public class Comparando {
    public static void main(String[] args) {
        Path p = Path.of("/zoo/urso/comida.txt");
        System.out.println(p.startsWith("/zoo") + " " + p.startsWith("zoo") + " " + p.endsWith("comida.txt") + " " + p.endsWith("urso/comida.txt") + " " + p.endsWith(".txt"));
        System.out.println(Path.of("a/b/../c").normalize().equals(Path.of("a/c")) + " " + Path.of("a/./b").equals(Path.of("a/b")));
        Path relativo = Path.of("dados/notas.txt");
        Path absoluto = relativo.toAbsolutePath();
        System.out.println(relativo.isAbsolute() + " " + absoluto.isAbsolute() + " " + absoluto.endsWith(relativo));
    }
}
```

```saida
true false true true false
true false
false true true
```

O `toAbsolutePath` não confere se o arquivo existe: só junta a pasta atual ao caminho.

> [!PROVA]
> Os índices de `getName` e `subpath` começam em 0 e ignoram a raiz; `subpath` exclui o fim. `getParent()` e `getRoot()` podem devolver `null`. `normalize` só olha o texto. `resolve` com caminho absoluto devolve o próprio argumento. `relativize` exige dois absolutos ou dois relativos. `equals` não normaliza, e `endsWith(".txt")` compara nomes inteiros. Nada disso acessa o disco, exceto `toRealPath`.

## Por baixo dos panos

`Path` é uma interface. A implementação vem de um **provedor de sistema de arquivos**, um `FileSystemProvider`: `UnixPath` no Linux e no macOS, `WindowsPath` no Windows, e cada uma sabe interpretar a sintaxe do seu sistema. Por baixo, um `UnixPath` guarda os bytes do caminho e um array com a posição em que cada nome começa, calculado uma vez; `getName`, `subpath` e `getNameCount` só consultam esse array. Um `Path` é **imutável**: `normalize`, `resolve` e os outros sempre devolvem um objeto novo.

O mecanismo de provedores permite outros sistemas de arquivos com a mesma API. O JDK traz um para arquivos ZIP: `FileSystems.newFileSystem(caminhoDoZip)` devolve um `FileSystem` cujos `Path` apontam para dentro do ZIP, e as mesmas operações de `Files` leem e escrevem lá dentro. Há também o `jrt:/`, que expõe as classes do próprio JDK, e bibliotecas que criam sistemas de arquivos inteiros na memória, úteis em testes.

## Resumo para a prova

- `Path.of(...)` (Java 11) ou `Paths.get(...)`; `toFile()` e `toPath()` convertem de e para `java.io.File`
- Nomes indexados a partir de 0, sem a raiz; `subpath(a, b)` exclui `b`; índice inválido lança `IllegalArgumentException`
- `getFileName`, `getParent` (pode ser `null`), `getRoot` (`null` em relativos)
- `normalize` remove `.` e `..` pelo texto; `resolve` concatena, ou devolve o argumento se ele for absoluto
- `relativize` vai de um caminho ao outro; misturar absoluto e relativo lança `IllegalArgumentException`
- `equals` compara texto; `startsWith`/`endsWith` comparam nomes inteiros; `toRealPath` exige que o arquivo exista
