O [episódio anterior](/assistir/senior-t3-e05) trabalhou com um arquivo de cada vez. Muitas tarefas reais olham para **árvores** inteiras: procurar todos os `.java` de um projeto, somar o tamanho de uma pasta, apagar um diretório com tudo dentro, copiar um backup. Este episódio fecha a temporada com as ferramentas para percorrer diretórios e com os **atributos** de arquivos: tamanho, datas e tipo.

## list, walk e find

Os três devolvem um `Stream<Path>` preguiçoso, que mantém pastas abertas e, por isso, precisa ser fechado com try-with-resources.

| Método | Percorre |
|---|---|
| `Files.list(pasta)` | Só os filhos diretos da pasta |
| `Files.walk(inicio)` | A árvore inteira, em profundidade, **incluindo o próprio início** |
| `Files.walk(inicio, profundidade)` | Até a profundidade dada: 0 é só o início, 1 inclui os filhos |
| `Files.find(inicio, profundidade, filtro)` | Como `walk`, mas com um filtro que recebe o caminho **e os atributos** |

A ordem dos itens **não é garantida**: depende do sistema de arquivos. Os exemplos ordenam os nomes antes de imprimir, para a saída ser a mesma em qualquer máquina, e mostram os caminhos relativos à pasta inicial, com `/`.

```java executar
import java.io.File;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Comparator;
import java.util.stream.Stream;

public class Arvore {
    static String nome(Path raiz, Path p) {
        String relativo = raiz.relativize(p).toString().replace(File.separatorChar, '/');
        return relativo.isEmpty() ? "." : relativo;
    }

    public static void main(String[] args) throws IOException {
        Path raiz = Files.createTempDirectory("projeto");
        Files.createDirectories(raiz.resolve("src/util"));
        Files.createDirectories(raiz.resolve("docs"));
        Files.writeString(raiz.resolve("README.md"), "# Projeto");
        Files.writeString(raiz.resolve("src/Main.java"), "class Main {}");
        Files.writeString(raiz.resolve("src/util/Texto.java"), "class Texto { /* utilitários de texto */ }");
        Files.writeString(raiz.resolve("docs/guia.md"), "Guia");

        try (Stream<Path> filhos = Files.list(raiz)) {
            System.out.println("list: " + filhos.map(p -> nome(raiz, p)).sorted().toList());
        }
        try (Stream<Path> todos = Files.walk(raiz)) {
            System.out.println("walk: " + todos.map(p -> nome(raiz, p)).sorted().toList());
        }
        try (Stream<Path> rasos = Files.walk(raiz, 1)) {
            System.out.println("walk até 1: " + rasos.count() + " caminhos");
        }
        try (Stream<Path> java = Files.find(raiz, 10, (p, atributos) -> atributos.isRegularFile() && p.toString().endsWith(".java") && atributos.size() > 20)) {
            System.out.println("find: " + java.map(p -> p.getFileName().toString()).toList());
        }

        try (Stream<Path> todos = Files.walk(raiz)) {
            todos.sorted(Comparator.reverseOrder()).forEach(p -> p.toFile().delete());
        }
        System.out.println("apagado: " + Files.notExists(raiz));
    }
}
```

```saida
list: [README.md, docs, src]
walk: [., README.md, docs, docs/guia.md, src, src/Main.java, src/util, src/util/Texto.java]
walk até 1: 4 caminhos
find: [Texto.java]
apagado: true
```

O `list` não entra nas subpastas; o `walk` entra em todas e inclui a própria raiz, o `.`. Com profundidade 1, são a raiz e seus três filhos. O `find` recebe os atributos de graça, sem uma segunda consulta ao disco: aqui, pede arquivos `.java` com mais de 20 bytes. O final mostra um truque comum para apagar uma árvore: ordenar os caminhos em ordem **reversa** coloca cada arquivo antes da pasta que o contém, e cada pasta é apagada já vazia.

Por padrão, `walk` e `find` **não seguem** atalhos simbólicos. Com a opção `FileVisitOption.FOLLOW_LINKS`, seguem, e um atalho que aponte para uma pasta acima cria um ciclo, detectado com `FileSystemLoopException`.

## Filtrando por padrão: glob

Um **glob** é um padrão simples de nomes, o mesmo dos terminais. `Files.newDirectoryStream(pasta, "*.txt")` lista os filhos que casam com o padrão, e um `PathMatcher` testa qualquer caminho:

| Glob | Casa com |
|---|---|
| `*` | Qualquer sequência de caracteres, **sem atravessar** pastas |
| `**` | Qualquer sequência, atravessando pastas |
| `?` | Exatamente um caractere |
| `{jpg,png}` | Qualquer uma das alternativas |
| `[abc]` | Um caractere do conjunto |

```java executar
import java.io.IOException;
import java.nio.file.DirectoryStream;
import java.nio.file.FileSystems;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.PathMatcher;
import java.util.ArrayList;
import java.util.List;

public class Padroes {
    public static void main(String[] args) throws IOException {
        PathMatcher java = FileSystems.getDefault().getPathMatcher("glob:*.java");
        PathMatcher qualquerJava = FileSystems.getDefault().getPathMatcher("glob:**.java");
        PathMatcher fotos = FileSystems.getDefault().getPathMatcher("glob:*.{jpg,png}");
        PathMatcher versao = FileSystems.getDefault().getPathMatcher("glob:v?.txt");
        System.out.println(java.matches(Path.of("Main.java")) + " " + java.matches(Path.of("src", "Main.java")));
        System.out.println(qualquerJava.matches(Path.of("src", "util", "Texto.java")));
        System.out.println(fotos.matches(Path.of("ferias.png")) + " " + fotos.matches(Path.of("ferias.gif")));
        System.out.println(versao.matches(Path.of("v2.txt")) + " " + versao.matches(Path.of("v10.txt")));

        Path pasta = Files.createTempDirectory("fotos");
        for (String nome : List.of("a.jpg", "b.png", "c.gif", "notas.txt")) {
            Files.createFile(pasta.resolve(nome));
        }
        List<String> imagens = new ArrayList<>();
        try (DirectoryStream<Path> conteudo = Files.newDirectoryStream(pasta, "*.{jpg,png}")) {
            for (Path p : conteudo) {
                imagens.add(p.getFileName().toString());
            }
        }
        imagens.sort(null);
        System.out.println(imagens);
        for (String nome : List.of("a.jpg", "b.png", "c.gif", "notas.txt")) {
            Files.delete(pasta.resolve(nome));
        }
        Files.delete(pasta);
    }
}
```

```saida
true false
true
true false
true false
[a.jpg, b.png]
```

O `*.java` não casa com `src/Main.java`, porque `*` não atravessa a barra; o `**.java` casa. Além de `glob:`, o `PathMatcher` aceita `regex:`, com expressões regulares completas.

## Atributos

Os métodos diretos cobrem o básico: `Files.size`, `Files.getLastModifiedTime`, `Files.setLastModifiedTime`, `Files.isHidden`, `Files.isSymbolicLink`, `Files.getOwner`. Para ler vários atributos de uma vez, numa única consulta ao disco, há duas formas:

- `Files.readAttributes(p, BasicFileAttributes.class)`: um retrato **somente leitura**, com `size()`, `isRegularFile()`, `isDirectory()`, `isSymbolicLink()`, `creationTime()`, `lastModifiedTime()` e `lastAccessTime()`.
- `Files.getFileAttributeView(p, BasicFileAttributeView.class)`: uma **visão** que permite alterar, com `setTimes(modificacao, acesso, criacao)`; `null` mantém o valor atual.

As datas são do tipo `FileTime`, que converte de e para `Instant`. Além dos básicos, há atributos específicos de cada sistema: `PosixFileAttributes`, com dono, grupo e permissões no estilo `rwxr-x---`, no Linux e no macOS; e `DosFileAttributes`, com as marcas de oculto e somente leitura, no Windows. Pedir a visão de outro sistema devolve `null` ou lança `UnsupportedOperationException`.

## FileVisitor: controle total do percurso

`Files.walkFileTree(inicio, visitante)` percorre a árvore chamando métodos de um `FileVisitor`, em geral uma subclasse de `SimpleFileVisitor`, que já traz implementações que só continuam:

| Método | Chamado |
|---|---|
| `preVisitDirectory(pasta, atributos)` | Antes de entrar numa pasta |
| `visitFile(arquivo, atributos)` | Para cada arquivo |
| `visitFileFailed(arquivo, erro)` | Quando um arquivo não pôde ser lido |
| `postVisitDirectory(pasta, erro)` | Depois de visitar todo o conteúdo da pasta |

Cada um devolve um `FileVisitResult`: `CONTINUE` segue; `SKIP_SUBTREE`, em `preVisitDirectory`, pula a pasta; `SKIP_SIBLINGS` pula os irmãos; `TERMINATE` para tudo. O `postVisitDirectory` é o lugar natural para apagar uma pasta, porque ele roda quando o conteúdo já foi tratado:

```java executar
import java.io.IOException;
import java.nio.file.FileVisitResult;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.SimpleFileVisitor;
import java.nio.file.attribute.BasicFileAttributeView;
import java.nio.file.attribute.BasicFileAttributes;
import java.nio.file.attribute.FileTime;
import java.time.Instant;

public class Atributos {
    public static void main(String[] args) throws IOException {
        Path raiz = Files.createTempDirectory("atributos");
        Path relatorio = Files.writeString(raiz.resolve("relatorio.txt"), "12345");
        Path dentro = Files.createDirectories(raiz.resolve("a/b"));
        Files.writeString(dentro.resolve("x.txt"), "abc");

        FileTime virada = FileTime.from(Instant.parse("2024-01-01T00:00:00Z"));
        Files.setLastModifiedTime(relatorio, virada);
        BasicFileAttributes atributos = Files.readAttributes(relatorio, BasicFileAttributes.class);
        System.out.println(atributos.isRegularFile() + " " + atributos.isDirectory() + " " + atributos.size() + " " + atributos.lastModifiedTime());

        BasicFileAttributeView visao = Files.getFileAttributeView(relatorio, BasicFileAttributeView.class);
        visao.setTimes(FileTime.from(Instant.parse("2025-06-30T12:00:00Z")), null, null);
        System.out.println(Files.getLastModifiedTime(relatorio) + " " + Files.size(relatorio));

        int[] contagem = new int[2];
        Files.walkFileTree(raiz, new SimpleFileVisitor<>() {
            @Override
            public FileVisitResult visitFile(Path arquivo, BasicFileAttributes attrs) throws IOException {
                contagem[0]++;
                Files.delete(arquivo);
                return FileVisitResult.CONTINUE;
            }

            @Override
            public FileVisitResult postVisitDirectory(Path pasta, IOException erro) throws IOException {
                contagem[1]++;
                Files.delete(pasta);
                return FileVisitResult.CONTINUE;
            }
        });
        System.out.println(contagem[0] + " arquivos e " + contagem[1] + " pastas apagados; existe? " + Files.exists(raiz));
    }
}
```

```saida
true false 5 2024-01-01T00:00:00Z
2025-06-30T12:00:00Z 5
2 arquivos e 3 pastas apagados; existe? false
```

> [!PROVA]
> `list` só vê os filhos; `walk` desce em profundidade e inclui o início; `walk(inicio, 0)` devolve só o início. `find` recebe um `BiPredicate<Path, BasicFileAttributes>`. Os três precisam ser fechados. Por padrão, atalhos simbólicos não são seguidos. No glob, `*` não atravessa pastas e `**` atravessa. `readAttributes` é somente leitura; a `AttributeView` permite alterar. `postVisitDirectory` roda depois do conteúdo da pasta.

## Por baixo dos panos

`Files.walk` é construído sobre um iterador que mantém uma **pilha** de `DirectoryStream` abertos, um para cada nível da descida. Quando o stream pede o próximo item, o iterador lê a próxima entrada da pasta do topo; se for uma pasta e a profundidade permitir, abre um novo `DirectoryStream` e o empilha. Por isso o percurso é em profundidade, e por isso o stream segura descritores abertos até ser fechado. A ordem das entradas é a que o sistema operacional devolve: no Linux, a ordem interna do diretório no sistema de arquivos, que não tem relação com a ordem alfabética.

Os atributos vêm de uma única chamada de sistema, `stat` no Linux, que preenche de uma vez tamanho, datas, tipo e permissões. Por isso `readAttributes` é mais eficiente que chamar `size`, `isDirectory` e `getLastModifiedTime` separadamente, e por isso o `find` e o `walkFileTree` entregam os atributos junto: eles já precisaram fazer o `stat` para saber se cada caminho era uma pasta.

## Resumo para a prova

- `Files.list` (filhos), `Files.walk` (árvore, com o início), `Files.find` (árvore com filtro de caminho e atributos); feche todos
- Profundidade: 0 é só o início; `FOLLOW_LINKS` segue atalhos e pode lançar `FileSystemLoopException`
- Glob: `*` (sem atravessar pastas), `**` (atravessando), `?`, `{a,b}`, `[abc]`; `PathMatcher` aceita `glob:` e `regex:`
- `readAttributes(p, BasicFileAttributes.class)` lê de uma vez; `BasicFileAttributeView` permite alterar datas
- `walkFileTree` com `SimpleFileVisitor`: `preVisitDirectory`, `visitFile`, `visitFileFailed`, `postVisitDirectory`
- `FileVisitResult`: `CONTINUE`, `SKIP_SUBTREE`, `SKIP_SIBLINGS`, `TERMINATE`
