O [episódio anterior](/assistir/senior-t3-e01) leu arquivos byte a byte e caractere a caractere, e terminou com um alerta: cada `read()` direto num arquivo é uma chamada ao sistema operacional, e isso é lento. Este episódio resolve o problema com as classes **bufferizadas**, mostra como ler texto linha a linha, formatar a saída e interagir com quem está no terminal, pelo `System.in`, pelo `Scanner` e pelo `Console`.

## Buffers: ler e escrever em lotes

As classes `BufferedInputStream`, `BufferedOutputStream`, `BufferedReader` e `BufferedWriter` envolvem outro stream e guardam um bloco de dados na memória, 8 KB por padrão. Quando o programa pede um caractere, o `BufferedReader` lê um bloco inteiro do arquivo de uma vez e entrega os próximos pedidos a partir da memória. Na escrita, o `BufferedWriter` acumula o texto e só o envia ao arquivo quando o buffer enche, quando se chama `flush()` ou quando o stream é fechado.

Além do desempenho, as versões de caracteres trazem métodos para **linhas**:

| Método | Faz |
|---|---|
| `BufferedReader.readLine()` | Lê uma linha **sem** o terminador; devolve `null` no fim |
| `BufferedReader.lines()` | Um `Stream<String>` com as linhas restantes |
| `BufferedWriter.newLine()` | Escreve o separador de linha do sistema |

```java executar
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.File;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;

public class Linhas {
    public static void main(String[] args) throws IOException {
        File arquivo = File.createTempFile("linhas", ".txt");
        arquivo.deleteOnExit();
        try (BufferedWriter w = new BufferedWriter(new FileWriter(arquivo, StandardCharsets.UTF_8))) {
            w.write("um");
            w.newLine();
            w.write("dois");
            w.newLine();
            w.write("três");
        }
        try (BufferedReader r = new BufferedReader(new FileReader(arquivo, StandardCharsets.UTF_8))) {
            String linha;
            int n = 0;
            while ((linha = r.readLine()) != null) {
                System.out.println(++n + ": " + linha);
            }
            System.out.println("depois do fim: " + r.readLine());
        }
        try (BufferedReader r = new BufferedReader(new FileReader(arquivo, StandardCharsets.UTF_8))) {
            System.out.println(r.lines().filter(l -> l.length() > 2).toList());
        }
    }
}
```

```saida
1: um
2: dois
3: três
depois do fim: null
[dois, três]
```

O fim é marcado por `null`, e não por -1, porque `readLine()` devolve `String`. O `newLine()` escreve `\r\n` no Windows e `\n` nos outros sistemas; o `readLine()` reconhece os dois, e também o `\r` sozinho.

## Marcar, voltar e pular

Alguns streams permitem **marcar** uma posição e **voltar** a ela depois, útil para espiar os próximos dados antes de decidir como lê-los. `mark(limite)` marca a posição atual, e o limite diz quantos caracteres podem ser lidos antes de a marca se perder. `reset()` volta à marca. `skip(n)` pula `n` posições. Nem todo stream suporta marca: `markSupported()` informa, e um `mark` ou `reset` sem suporte lança `IOException`.

```java executar
import java.io.BufferedInputStream;
import java.io.BufferedReader;
import java.io.ByteArrayInputStream;
import java.io.File;
import java.io.FileInputStream;
import java.io.FileReader;
import java.io.IOException;
import java.io.InputStream;
import java.io.Reader;
import java.io.StringReader;

public class Marca {
    public static void main(String[] args) throws IOException {
        try (BufferedReader r = new BufferedReader(new StringReader("abcdef"))) {
            System.out.print((char) r.read());
            r.mark(10);
            System.out.print((char) r.read());
            System.out.print((char) r.read());
            r.reset();
            System.out.print((char) r.read());
            r.skip(2);
            System.out.println((char) r.read());
            System.out.println(r.markSupported());
        }
        File f = File.createTempFile("marca", ".txt");
        f.deleteOnExit();
        try (Reader fr = new FileReader(f); InputStream fis = new FileInputStream(f);
             InputStream bis = new BufferedInputStream(new FileInputStream(f))) {
            System.out.println(fr.markSupported() + " " + fis.markSupported() + " " + bis.markSupported() + " " + new ByteArrayInputStream(new byte[0]).markSupported());
        }
        try (Reader fr = new FileReader(f)) {
            fr.mark(1);
        } catch (IOException e) {
            System.out.println("mark não suportado: " + e.getClass().getSimpleName());
        }
    }
}
```

```saida
abcbe
true
false false true true
mark não suportado: IOException
```

Siga a primeira linha: lê `a`, marca, lê `b` e `c`, volta à marca, lê `b` de novo, pula `c` e `d`, lê `e`. As classes de arquivo não suportam marca; as bufferizadas e as de memória, sim.

## PrintStream e PrintWriter

`PrintStream` (bytes) e `PrintWriter` (caracteres) têm os métodos de texto conhecidos: `print`, `println`, `printf` e `format`, que é o mesmo que `printf`. O `System.out` e o `System.err` são `PrintStream`. Uma diferença importante: os métodos dessas classes **não lançam `IOException`**. Se a escrita falhar, eles registram o erro em silêncio, e quem quiser saber chama `checkError()`.

A formatação do `printf` usa a **localidade** padrão: `%.2f` escreve `3,14` no Brasil e `3.14` nos Estados Unidos. Para uma saída que não muda de máquina para máquina, informe a localidade no primeiro argumento:

```java executar
import java.io.PrintWriter;
import java.io.StringWriter;
import java.util.IllegalFormatException;
import java.util.Locale;

public class Formato {
    public static void main(String[] args) {
        StringWriter texto = new StringWriter();
        try (PrintWriter pw = new PrintWriter(texto)) {
            pw.printf(Locale.US, "%-6s|%5.2f|%04d%n", "café", 3.14159, 42);
            pw.format(Locale.GERMANY, "%,.2f%n", 1234567.891);
            pw.println(true);
            pw.print('x');
            System.out.println(pw.checkError());
        }
        System.out.println(texto);
        try {
            System.out.printf("%d%n", 3.5);
        } catch (IllegalFormatException e) {
            System.out.println(e.getClass().getSimpleName());
        }
    }
}
```

```saida
false
café  | 3.14|0042
1.234.567,89
true
x
IllegalFormatConversionException
```

`%-6s` alinha o texto à esquerda em 6 posições, `%5.2f` usa 5 posições com 2 casas, `%04d` completa com zeros, e `%n` é a quebra de linha do sistema. Um formato incompatível com o argumento, como `%d` para um `double`, lança `IllegalFormatConversionException` em tempo de execução.

## Entrada pelo terminal

O `System.in` é um `InputStream` cru. Para ler linhas digitadas, há três caminhos:

- `new BufferedReader(new InputStreamReader(System.in))` e `readLine()`.
- `new Scanner(System.in)`, que além de linhas lê números e palavras com `nextInt`, `nextDouble`, `next` e `nextLine`.
- `System.console()`, que devolve um `Console` com `readLine(formato, args)` e `readPassword(formato, args)`. A senha volta como `char[]`, e não como `String`, para que o programa possa apagá-la da memória depois de usar, e os caracteres não aparecem na tela enquanto são digitados.

Dois cuidados. Primeiro, `System.console()` devolve **`null`** quando o programa não está ligado a um terminal interativo, como ao rodar dentro de algumas IDEs ou com a entrada redirecionada de um arquivo; o código precisa testar. Segundo, o `Scanner` tem uma pegadinha clássica com `nextInt` seguido de `nextLine`:

```java executar
import java.util.Scanner;

public class Scan {
    public static void main(String[] args) {
        Scanner sc = new Scanner("42\nAna Lima\n7 8 9\n");
        int idade = sc.nextInt();
        String resto = sc.nextLine();
        String nome = sc.nextLine();
        int soma = 0;
        while (sc.hasNextInt()) {
            soma += sc.nextInt();
        }
        System.out.println(idade + " [" + resto + "] " + nome + " " + soma);
    }
}
```

```saida
42 [] Ana Lima 24
```

O `nextInt` lê o 42 e **para antes** da quebra de linha. O primeiro `nextLine` devolve o que sobrou da linha: nada. Só o segundo lê o nome. O exemplo usa um `Scanner` sobre um texto para ter sempre a mesma entrada; com `System.in`, o comportamento é idêntico.

> [!PROVA]
> `readLine()` devolve `null` no fim. `newLine()` usa o separador do sistema. `mark`/`reset` só funcionam se `markSupported()` for `true`; senão, `IOException`. `PrintWriter` e `PrintStream` não lançam `IOException`. `System.console()` pode devolver `null`. `readPassword` devolve `char[]`. `printf` com tipo incompatível lança `IllegalFormatConversionException`.

## Por baixo dos panos

O `BufferedReader` guarda um `char[]` de 8192 posições e dois índices: até onde o array está preenchido e qual a próxima posição a entregar. Um `read()` só toca o arquivo quando os índices se encontram; aí chama `read(char[], ...)` no leitor de baixo para encher o array de novo. O `mark` é implementado com esse mesmo array: marcar guarda o índice atual, e o limite garante que o array não descarte aquela parte antes do `reset`. Por isso `mark` só existe em classes que guardam dados na memória.

O `System.out` é um `PrintStream` sobre um `BufferedOutputStream` sobre o descritor de arquivo 1, a saída padrão do processo. Ele é criado com **descarga automática**: cada `println` descarrega o buffer, para o texto aparecer na hora no terminal. O `System.err`, no descritor 2, é um `PrintStream` separado, com o próprio buffer. Como o terminal recebe os dois por canais diferentes, mensagens de erro e de saída podem aparecer numa ordem diferente da que o programa as escreveu, sobretudo quando a saída é redirecionada para um arquivo.

## Resumo para a prova

- Classes `Buffered*` leem e escrevem em blocos; `flush()` ou `close()` descarregam a escrita
- `readLine()` sem o terminador, `null` no fim; `lines()` devolve um stream; `newLine()` escreve o separador do sistema
- `mark(limite)`, `reset()` e `skip(n)`; confira `markSupported()`; sem suporte, `IOException`
- `PrintWriter`/`PrintStream`: `print`, `println`, `printf`, `format`; não lançam `IOException`, use `checkError()`
- `printf` usa a localidade padrão; informe uma `Locale` para saída estável
- `System.console()` pode ser `null`; `readPassword` devolve `char[]`; `Scanner.nextInt` deixa a quebra de linha para o próximo `nextLine`
