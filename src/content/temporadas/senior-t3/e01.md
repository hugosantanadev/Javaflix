Todo programa útil conversa com o mundo de fora: lê arquivos de configuração, grava relatórios, recebe dados pela rede. Em Java, essa conversa passa pelo pacote `java.io`, o mais antigo da plataforma, e pelo `java.nio.file`, que os episódios 4 a 6 desta temporada cobrem. Aqui começa a base de tudo: os **streams de entrada e saída**. Apesar do nome, eles não têm relação com os streams de coleções do Pleno: são canais por onde os dados passam em sequência, um pedaço de cada vez.

## Bytes e caracteres

O `java.io` tem duas famílias paralelas:

| | Bytes (dados binários) | Caracteres (texto) |
|---|---|---|
| Entrada | `InputStream` | `Reader` |
| Saída | `OutputStream` | `Writer` |
| Arquivo | `FileInputStream`, `FileOutputStream` | `FileReader`, `FileWriter` |
| Memória | `ByteArrayInputStream`, `ByteArrayOutputStream` | `StringReader`, `StringWriter`, `CharArrayReader` |
| Com buffer | `BufferedInputStream`, `BufferedOutputStream` | `BufferedReader`, `BufferedWriter` |
| Formatação | `PrintStream` | `PrintWriter` |
| Objetos | `ObjectInputStream`, `ObjectOutputStream` | |

A regra para não errar na prova: classes com **Stream** no nome trabalham com **bytes**; com **Reader** ou **Writer**, com **caracteres**. As exceções são as pontes `InputStreamReader` e `OutputStreamWriter`, que convertem uma família na outra, e o `PrintStream`, que é de bytes mas tem métodos para texto, como o `System.out`.

Um byte é um número de 0 a 255. Um caractere é uma letra, que pode ocupar **vários** bytes, dependendo da **codificação**. Em UTF-8, `o` e `l` ocupam um byte cada, e `á` ocupa dois:

```java executar
import java.io.File;
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.nio.charset.StandardCharsets;

public class Bytes {
    public static void main(String[] args) throws IOException {
        File arquivo = File.createTempFile("bytes", ".txt");
        arquivo.deleteOnExit();
        try (OutputStream saida = new FileOutputStream(arquivo)) {
            saida.write("olá".getBytes(StandardCharsets.UTF_8));
        }
        try (InputStream entrada = new FileInputStream(arquivo)) {
            int b;
            while ((b = entrada.read()) != -1) {
                System.out.print(b + " ");
            }
        }
        System.out.println("| " + arquivo.length() + " bytes");
    }
}
```

```saida
111 108 195 161 | 4 bytes
```

Repare no tipo de `read()`: ele devolve um **`int`**, não um `byte`. Os valores de 0 a 255 representam o byte lido, e **-1** sinaliza o fim do stream. Se devolvesse `byte`, não haveria como distinguir o byte 255 do fim. O `Reader.read()` segue a mesma ideia: devolve o código do caractere como `int`, ou -1 no fim.

## A codificação importa

`FileReader` e `FileWriter` aceitam a codificação no construtor desde o Java 11. A ponte `InputStreamReader` também. Ler com uma codificação diferente da usada para gravar produz o famoso texto embaralhado:

```java executar
import java.io.File;
import java.io.FileInputStream;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.Reader;
import java.io.Writer;
import java.nio.charset.StandardCharsets;

public class Caracteres {
    public static void main(String[] args) throws IOException {
        File arquivo = File.createTempFile("chars", ".txt");
        arquivo.deleteOnExit();
        try (Writer w = new FileWriter(arquivo, StandardCharsets.UTF_8)) {
            w.write("olá");
        }
        try (Reader r = new FileReader(arquivo, StandardCharsets.UTF_8)) {
            int c;
            int lidos = 0;
            while ((c = r.read()) != -1) {
                System.out.print((char) c);
                lidos++;
            }
            System.out.println(" (" + lidos + " caracteres)");
        }
        try (Reader r = new InputStreamReader(new FileInputStream(arquivo), StandardCharsets.ISO_8859_1)) {
            char[] buffer = new char[10];
            int n = r.read(buffer);
            System.out.println(new String(buffer, 0, n) + " (" + n + " caracteres)");
        }
    }
}
```

```saida
olá (3 caracteres)
olÃ¡ (4 caracteres)
```

Em ISO-8859-1, cada byte é um caractere, e os dois bytes do `á` viram `Ã` e `¡`.

> [!VERSAO]
> Até o Java 17, a codificação padrão, usada quando nenhuma é informada, dependia do sistema operacional: UTF-8 no Linux e no macOS, mas em geral windows-1252 no Windows. Desde o Java 18 (JEP 400), o padrão é UTF-8 em todo lugar. Código que precisa rodar em versões antigas deve sempre informar a codificação.

## Lendo em blocos e copiando

Ler um byte de cada vez é lento. `read(byte[] buffer)` lê **até** o tamanho do buffer e devolve quantos bytes leu de fato, ou -1 no fim. O valor devolvido importa: a última leitura quase nunca enche o buffer, e o que sobrou nele da leitura anterior é lixo. Por isso a escrita usa `write(buffer, 0, n)`, nunca `write(buffer)`.

```java executar
import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.io.InputStream;
import java.util.Arrays;

public class Copia {
    public static void main(String[] args) throws IOException {
        byte[] dados = new byte[10_000];
        for (int i = 0; i < dados.length; i++) {
            dados[i] = (byte) i;
        }
        ByteArrayOutputStream destino = new ByteArrayOutputStream();
        int leituras = 0;
        try (InputStream origem = new ByteArrayInputStream(dados)) {
            byte[] buffer = new byte[4096];
            int n;
            while ((n = origem.read(buffer)) != -1) {
                destino.write(buffer, 0, n);
                leituras++;
                System.out.print(n + " ");
            }
        }
        System.out.println("| " + leituras + " leituras, " + destino.size() + " bytes");
        ByteArrayOutputStream outra = new ByteArrayOutputStream();
        long copiados = new ByteArrayInputStream(dados).transferTo(outra);
        System.out.println(copiados + " " + Arrays.equals(dados, outra.toByteArray()));
        InputStream in = new ByteArrayInputStream(new byte[] {(byte) 200, -1, 65});
        System.out.println(in.read() + " " + in.read() + " " + in.read() + " " + in.read());
    }
}
```

```saida
4096 4096 1808 | 3 leituras, 10000 bytes
10000 true
200 255 65 -1
```

O `transferTo`, do Java 9, faz o laço de cópia numa linha. A última linha mostra a conversão: o byte `-1`, que em Java é um `byte` com sinal, sai de `read()` como 255, e só o fim do stream devolve -1 de verdade.

## Fechar e acrescentar

Streams seguram recursos do sistema operacional, como descritores de arquivo, e precisam ser fechados. O try-with-resources faz isso mesmo com exceção. Quando um stream envolve outro, como um `BufferedReader` em volta de um `FileReader`, fechar o de fora **fecha também o de dentro**.

Por padrão, `FileOutputStream` e `FileWriter` **substituem** o conteúdo do arquivo. Para acrescentar ao final, passe `true` no construtor: `new FileWriter(arquivo, true)` ou `new FileOutputStream(arquivo, true)`. Se o arquivo não existir, os dois o criam; a pasta, não.

> [!PROVA]
> Classes com `Stream` no nome lidam com bytes; com `Reader`/`Writer`, com caracteres. `read()` devolve `int`, e -1 no fim. `read(buffer)` devolve quantos leu, que pode ser menos que o tamanho do buffer. Escritores de arquivo sobrescrevem por padrão; `true` no construtor acrescenta. Fechar o stream externo fecha o interno.

## Por baixo dos panos

Um `FileInputStream` guarda um descritor de arquivo, um número que o sistema operacional entrega quando o arquivo é aberto. Cada `read()` sem buffer vira uma **chamada de sistema** (`read` no Linux, `ReadFile` no Windows), que passa do modo usuário para o modo núcleo, e isso custa centenas de nanossegundos. Ler um arquivo de 1 MB byte a byte faz um milhão dessas chamadas; com um buffer de 8 KB, faz 128. É por isso que existem as classes com buffer do [próximo episódio](/assistir/senior-t3-e02).

As classes do `java.io` usam o padrão de projeto **Decorator**: um `BufferedInputStream` é um `InputStream` que recebe outro `InputStream` e acrescenta um comportamento, o buffer. Um `ObjectInputStream` acrescenta a leitura de objetos, e assim por diante. Por isso dá para empilhar: `new ObjectInputStream(new BufferedInputStream(new FileInputStream(arquivo)))`. Cada camada só conhece a de baixo pela interface comum. A conversão de bytes em caracteres, nas pontes, fica a cargo de um `CharsetDecoder`, que lê bytes até completar cada caractere da codificação escolhida.

## Resumo para a prova

- Bytes: `InputStream`/`OutputStream`; caracteres: `Reader`/`Writer`; pontes: `InputStreamReader`/`OutputStreamWriter`
- `read()` devolve um `int` de 0 a 255 (ou o código do caractere), e -1 no fim
- `read(byte[])` devolve a quantidade lida; escreva com `write(buffer, 0, n)`
- Informe a codificação; desde o Java 18, o padrão é UTF-8
- `new FileWriter(arquivo, true)` acrescenta; sem o `true`, substitui
- try-with-resources fecha; fechar o envoltório fecha o stream de dentro
