Quando um programa roda, muita coisa acontece antes da primeira linha do construtor: a classe é carregada, os campos `static` recebem valores, blocos especiais são executados, e só então o objeto ganha forma. A prova adora questões em que um programa imprime de vários lugares e você precisa dizer a ordem exata. A boa notícia é que a ordem é fixa e cabe em poucas regras.

## Blocos de inicialização

Além de campos, métodos e construtores, uma classe pode ter blocos de código soltos entre chaves. Um **bloco de instância** (`{ ... }`) roda a cada objeto criado. Um **bloco `static`** (`static { ... }`) roda uma única vez, quando a classe é inicializada:

```java executar
public class Ordem {
    static {
        System.out.println("1. bloco static");
    }

    int x = valor("3. campo x");

    {
        System.out.println("4. bloco de instância");
    }

    Ordem() {
        System.out.println("5. construtor");
    }

    static int valor(String msg) {
        System.out.println(msg);
        return 1;
    }

    public static void main(String[] args) {
        System.out.println("2. main");
        new Ordem();
        System.out.println("---");
        new Ordem();
    }
}
```

```saida
1. bloco static
2. main
3. campo x
4. bloco de instância
5. construtor
---
3. campo x
4. bloco de instância
5. construtor
```

O bloco `static` rodou antes do `main`, porque o `main` pertence a `Ordem` e a classe precisa estar inicializada para que ele seja chamado. Depois, cada `new` repete a parte de instância.

## A ordem, em regras

**Uma vez por classe**, no primeiro uso: os inicializadores de campos `static` e os blocos `static`, **na ordem em que aparecem no código**. Se a classe tem uma superclasse, ela é inicializada antes.

**A cada `new`**: primeiro o construtor da superclasse; depois os inicializadores de campos de instância e os blocos de instância, **na ordem do código**; por último, o resto do corpo do construtor.

A ordem do código é literal. Um bloco escrito depois do construtor ainda roda antes do corpo dele, e um campo declarado depois de um bloco recebe o valor depois:

```java executar
public class Sequencia {
    int a = 1;

    {
        a = a * 10;
    }

    int b = a + 5;

    {
        b *= 2;
    }

    public static void main(String[] args) {
        Sequencia s = new Sequencia();
        System.out.println(s.a + " " + s.b);
    }
}
```

```saida
10 30
```

## Quando a classe é inicializada

Não é quando o programa começa: é no primeiro **uso ativo**. Criar um objeto, chamar um método `static` e ler ou escrever um campo `static` disparam a inicialização. Declarar uma variável do tipo, criar um array dele ou ler uma **constante de compilação** (um `static final` primitivo ou `String` inicializado com um valor constante) não disparam:

```java executar
class Config {
    static final int VERSAO = 3;
    static final String NOME = "app";
    static int acessos = 0;

    static {
        System.out.println("Config inicializada");
    }
}

public class Gatilhos {
    public static void main(String[] args) {
        System.out.println(Config.VERSAO + " " + Config.NOME);
        Config[] varias = new Config[2];
        System.out.println("antes do acesso");
        System.out.println(Config.acessos);
    }
}
```

```saida
3 app
antes do acesso
Config inicializada
0
```

As constantes nem chegam a consultar a classe: o compilador copia o valor delas para o código de quem as usa, como você viu no [pool de strings](/assistir/estagiario-t5-e05).

## Campos `final`

Um campo `final` precisa receber valor **exatamente uma vez**, e o compilador confere. Um `final` de instância pode ser inicializado na declaração, num bloco de instância ou no construtor, e, nesse caso, em **todos** os construtores. Um `static final` só na declaração ou num bloco `static`:

```java executar
public class Limites {
    static final int MAXIMO;
    final int minimo;

    static {
        MAXIMO = Integer.parseInt("100");
    }

    {
        minimo = 1;
    }

    public static void main(String[] args) {
        Limites l = new Limites();
        System.out.println(l.minimo + " a " + MAXIMO);
    }
}
```

```saida
1 a 100
```

Se algum caminho deixar o campo sem valor, não compila:

```java nao-compila
public class Ingresso {
    final int numero;
    final String evento;

    Ingresso(int numero) {
        this.numero = numero;
    }
}
```

> [!PROVA]
> `final` impede uma **nova atribuição**, não mudanças no objeto: um `final StringBuilder sb` aceita `sb.append("x")`, só não aceita `sb = new StringBuilder()`. E `static final` não pode ser atribuído no construtor, que roda a cada objeto: o compilador só aceita a declaração ou um bloco `static`.

## Referências adiantadas

Um inicializador não pode ler, pelo nome simples, um campo declarado **mais abaixo**. É a regra da *referência adiantada ilegal*:

```java nao-compila
public class Frente {
    static int a = b + 1;
    static int b = 2;
}
```

A regra é só do compilador, e só para o nome simples. Escrito como `Frente.b`, compila, e revela o que a JVM faz por baixo: o campo já existe, com o valor padrão, antes de o inicializador dele rodar:

```java executar
public class Frente {
    static int a = Frente.b + 1;
    static int b = 2;

    public static void main(String[] args) {
        System.out.println(a + " " + b);
    }
}
```

```saida
1 2
```

## Por baixo dos panos

O `javac` reúne todos os inicializadores `static` e os blocos `static` de uma classe, na ordem do código, num único método especial chamado `<clinit>`. A JVM garante que ele rode **uma única vez**, mesmo que várias threads usem a classe ao mesmo tempo: cada classe tem uma trava de inicialização, e as outras threads esperam. Esse comportamento é a base de um idioma conhecido, o *holder* preguiçoso, em que um objeto caro só é criado no primeiro uso, sem nenhum `synchronized` escrito à mão.

Se o `<clinit>` lança uma exceção, a JVM a embrulha num `ExceptionInInitializerError`, e a classe fica marcada como com defeito: qualquer tentativa posterior de usá-la lança `NoClassDefFoundError`, uma mensagem que costuma confundir porque o arquivo `.class` está lá. Já os inicializadores de instância, como você viu no [episódio 2](/assistir/junior-t1-e02), são copiados para dentro de cada construtor `<init>` que chama `super(...)`.

## Resumo para a prova

- Bloco `static`: uma vez, no primeiro uso ativo da classe; bloco de instância: a cada `new`
- Classe: campos e blocos `static` na ordem do código, superclasse primeiro
- Objeto: construtor da superclasse, depois campos e blocos de instância na ordem do código, depois o corpo do construtor
- Constantes de compilação, arrays e declarações de variável não inicializam a classe
- `final` de instância: uma vez, na declaração, num bloco ou em todos os construtores
- `static final`: na declaração ou num bloco `static`, nunca no construtor
- Ler pelo nome simples um campo declarado abaixo não compila
- Exceção no `<clinit>` vira `ExceptionInInitializerError`
