O `switch` clássico tem dois problemas: o fall-through, que causa bugs quando alguém esquece um `break`, e o fato de ser só um comando, que obriga a declarar uma variável antes e atribuí-la em cada `case`. O Java 14 resolveu os dois com a forma **arrow** (`->`) e com o `switch` como **expressão**, que produz um valor. Este episódio cobre as duas formas, o `yield` e a regra que mais derruba candidatos: a expressão precisa cobrir todos os valores possíveis.

## A forma arrow

Com `->` no lugar de `:`, cada `case` executa só o que está à direita da seta, **sem fall-through** e sem `break`. Do lado direito vai uma expressão, um bloco `{ }` ou um `throw`:

```java executar
int dia = 6;
switch (dia) {
    case 1, 2, 3, 4, 5 -> System.out.println("dia útil");
    case 6, 7 -> {
        System.out.println("fim de semana");
        System.out.println("descanso");
    }
    default -> System.out.println("inválido");
}
```

```saida
fim de semana
descanso
```

Num mesmo `switch`, ou todos os `case` usam `:`, ou todos usam `->`. Misturar não compila.

![O mesmo switch de dias do mês na forma clássica, com break em cada case, e na forma de expressão com setas, com metade das linhas](/figuras/switch-antes-e-depois.svg "À esquerda, cada break esquecido é um bug esperando; à direita, não há break para esquecer.")

> [!CONVERSA]
> **switch de dois-pontos:** Eu estou aqui desde o primeiro Java. Herdei tudo do C, inclusive a mania de continuar descendo.
>
> **switch de setas:** E eu cheguei no Java 14 para acabar com essa mania. Cada `case` meu roda o que está à direita da seta, e pronto.
>
> **switch de dois-pontos:** Às vezes descer é útil: vários valores caindo no mesmo código.
>
> **switch de setas:** Para isso eu tenho vírgula: `case 4, 6, 9, 11 ->`. Sem nenhum `break` para esquecer.
>
> **switch de dois-pontos:** E você ainda devolve valor, o que eu nunca soube fazer.
>
> **switch de setas:** Devolvo, e o compilador confere se existe um valor para todo caso. Quem me usa ganha um revisor de graça.

## `switch` como expressão

Um `switch` pode estar do lado direito de uma atribuição, num `return` ou como argumento de um método. O valor de cada `case` é o resultado da expressão inteira, e a instrução termina com `;` depois da chave:

```java executar
int mes = 4;
int dias = switch (mes) { //> O switch inteiro vale um número, guardado em dias.
    case 2 -> 28;
    case 4, 6, 9, 11 -> 30;
    default -> 31;
}; //> O ; fecha a atribuição, não o switch.
System.out.println(dias);
String nome = "Ana";
String saudacao = switch (nome.length()) {
    case 0 -> "anônimo";
    case 1, 2, 3 -> {
        String curto = nome.toUpperCase();
        yield "Oi, " + curto;
    }
    default -> "Olá, " + nome;
};
System.out.println(saudacao);
```

```saida
30
Oi, ANA
```

Quando o lado direito é um bloco, o valor sai com **`yield`**. Não é `return`, que sairia do método inteiro (e não é permitido dentro de uma expressão `switch`), nem `break`, que não carrega valor.

> [!ANTES]
> O `switch` expressão passou por duas prévias antes de ficar pronto. No Java 12, o valor de um bloco saía com `break valor;`. No Java 13, a palavra virou `yield`, para não confundir com o `break` dos laços. A forma final chegou no Java 14. Se você encontrar `break "texto";` num tutorial antigo, é dessa época.

> [!IA]
> Assistentes de IA às vezes escrevem `return` dentro do bloco de uma expressão `switch`, ou `break valor;`, a sintaxe da prévia do Java 12, que não compila em nenhuma versão final. O certo, em bloco, é sempre `yield`.

A forma com `:` também funciona numa expressão, mas aí o fall-through volta, e cada caminho termina num `yield`:

```java executar
int n = 1;
String r = switch (n) {
    case 1:
    case 2:
        yield "pequeno";
    case 3:
        System.out.println("três");
    default:
        yield "grande";
};
System.out.println(r);
```

```saida
pequeno
```

## A expressão precisa ser exaustiva

> [!PENSE]
> Um `switch` que devolve um valor recebe um `int` que ninguém previu, digamos 37. O que a expressão deveria produzir? Que regra você criaria no compilador para isso nunca acontecer?

Uma expressão sempre produz um valor, então o `switch` precisa cobrir **todos** os valores possíveis do seletor. Para `int` e `String`, isso exige um `default`:

```java nao-compila
int x = 5;
String s = switch (x) {
    case 1 -> "um";
    case 2 -> "dois";
};
```

Com `enum`, basta listar todas as constantes, e o `default` pode ficar de fora:

```java executar
public class Semaforo {
    enum Cor { VERDE, AMARELO, VERMELHO }

    static String acao(Cor c) {
        return switch (c) {
            case VERDE -> "siga";
            case AMARELO -> "atenção";
            case VERMELHO -> "pare";
        };
    }

    public static void main(String[] args) {
        System.out.println(acao(Cor.AMARELO));
    }
}
```

```saida
atenção
```

Sem o `default`, o compilador passa a ajudar: se alguém acrescentar `PISCANDO` ao `enum`, esse `switch` deixa de compilar até tratar a constante nova.

> [!MATEMATICA]
> Um `switch` expressão é uma **função total**: precisa dar um resultado para cada valor do domínio. O domínio de um `int` tem 2³² = 4.294.967.296 valores, e ninguém escreve tantos `case`: daí o `default` obrigatório. O domínio do `enum Cor` tem só 3 valores, e 3 `case` já cobrem tudo. Com `String`, o domínio é infinito, e de novo só o `default` fecha a conta.

> [!PREVENCAO]
> Num `switch` sobre `enum`, resista à vontade de pôr um `default` "por segurança". Sem ele, cada constante nova no `enum` faz o compilador apontar todos os `switch` que precisam tratá-la. Com ele, a constante nova cai em silêncio no `default`, e o bug só aparece em produção.

> [!LAPIS]
> Reescreva como expressão `switch`, com setas, sem nenhum `break`:
>
> ```java
> String preco;
> switch (tamanho) {
>     case "P": preco = "R$ 20"; break;
>     case "M": preco = "R$ 25"; break;
>     default: preco = "R$ 30";
> }
> ```
>
> **Resposta:**
>
> ```java
> String preco = switch (tamanho) {
>     case "P" -> "R$ 20";
>     case "M" -> "R$ 25";
>     default -> "R$ 30";
> };
> ```
>
> A variável nasce com valor, os `break` somem, e o `default` continua obrigatório, porque `tamanho` é uma `String`. O `switch` **comando** (sem valor) não precisa ser exaustivo, exceto quando usa padrões, como você vai ver na caixa de versão.

> [!PROVA]
> Pegadinhas de sintaxe que a prova usa: esquecer o `;` depois da `}` de uma expressão `switch`; um bloco `{ }` sem `yield`; `return` dentro do `switch` expressão; e misturar `:` com `->`. Todos são erros de compilação.

## O tipo do resultado

Se os `case` produzem tipos diferentes, o tipo da expressão segue as mesmas regras do [ternário](/assistir/estagiario-t2-e05): números são promovidos para o maior tipo:

```java executar
int k = 2;
var v = switch (k) {
    case 1 -> 1;
    case 2 -> 'A';
    default -> 2.5;
};
System.out.println(v);
```

```saida
65.0
```

Os ramos produzem `int`, `char` e `double`, então a expressão é `double`, e o `'A'` escolhido vira 65.0.

> [!VERSAO]
> **Java 21 (1Z0-830 e 1Z0-831).** O `switch` aceita **padrões de tipo**, com condição extra em `when`, e um `case null`. O seletor pode ser qualquer objeto, e o `switch` com padrões precisa ser exaustivo, mesmo como comando:

```java executar java21
Object o = 42;
String desc = switch (o) {
    case null -> "nulo";
    case Integer i when i > 10 -> "inteiro grande: " + i;
    case Integer i -> "inteiro: " + i;
    case String s -> "texto de " + s.length() + " letras";
    default -> "outra coisa";
};
System.out.println(desc);
```

```saida
inteiro grande: 42
```

A ordem importa: `case Integer i` antes de `case Integer i when i > 10` não compila, porque o primeiro já "domina" o segundo. O assunto completo, com *record patterns*, está na temporada de [Java moderno](/assistir/junior-t5-e05).

## Na IDE

- **Modernizar com uma tecla.** Num `switch` clássico que só atribui valores a uma variável, **Alt + Enter** na palavra `switch` oferece *Replace with 'switch' expression*: a IDE escreve a expressão com setas e apaga os `break`.
- **Os `case` que faltam.** Num `switch` sobre `enum` incompleto, a mesma tecla oferece criar os ramos que faltam, um para cada constante.
- **O tipo do resultado.** Selecione o `switch` inteiro e use **Ctrl + Shift + P** para ver o tipo da expressão, útil quando os ramos misturam `int`, `char` e `double`.

## Por baixo dos panos

A forma arrow e o `switch` expressão são, em grande parte, açúcar sintático: o `javac` gera o mesmo `tableswitch` ou `lookupswitch` do [episódio anterior](/assistir/estagiario-t3-e02), e cada `yield` vira um salto para o fim do `switch` com o valor deixado na pilha. A exaustividade é verificada só pelo compilador. Para o caso de um `enum` ganhar uma constante depois que o código foi compilado, o `javac` acrescenta um `default` escondido que lança um erro em tempo de execução (`MatchException` a partir do Java 21).

O `switch` com padrões do Java 21 usa outra técnica: um `invokedynamic` que chama `SwitchBootstraps.typeSwitch`, um método do JDK que testa os tipos em ordem e devolve o índice do `case` que casou. É a mesma ideia de deixar a JVM escolher a melhor implementação que você viu na concatenação de strings.

## Resumo para a prova

- `case X ->` não tem fall-through nem `break`; o lado direito é expressão, bloco ou `throw`
- Não se mistura `:` com `->` no mesmo `switch`
- Expressão `switch` produz valor e termina com `;` depois da `}`
- Em bloco, o valor sai com `yield`; `return` e `break` não servem
- Expressão precisa ser exaustiva: `default` para `int` e `String`; todas as constantes para `enum`
- Com `:` numa expressão, o fall-through volta e cada caminho precisa de `yield`
- Tipos diferentes nos ramos são promovidos como no ternário
- Java 21: padrões de tipo, `when` e `case null`
