O `switch` clássico, herdado do C, compara um valor com uma lista de constantes e pula para a correspondente. A pegadinha está no que acontece depois do pulo: sem `break`, a execução **continua** pelos próximos `case`, o famoso *fall-through*. Este episódio cobre os tipos aceitos, as regras dos rótulos, o fall-through e como a JVM transforma um `switch` numa tabela de saltos.

## Estrutura

```java
switch (seletor) {
    case CONSTANTE_1:
        // comandos
        break;
    case CONSTANTE_2, CONSTANTE_3:   // vários rótulos num case (Java 14+)
        // comandos
        break;
    default:
        // se nenhum case casar
}
```

O seletor é avaliado **uma vez**. Se algum `case` casa, a execução começa ali; senão, começa no `default` (se existir). Daí em diante, os comandos rodam em sequência até um `break`, o fim do `switch` ou um `return`.

## Tipos aceitos no seletor

| Aceitos | Não aceitos |
|---|---|
| `int`, `short`, `byte`, `char` | `long` |
| `Integer`, `Short`, `Byte`, `Character` | `boolean` |
| `String` | `float`, `double` |
| `enum` | outros objetos (sem pattern matching) |

```java nao-compila
long id = 1;
switch (id) {
    case 1:
        break;
}
```

> [!VERSAO]
> **Java 21 (1Z0-830 e 1Z0-831).** Com o pattern matching para `switch` (JEP 441), o seletor pode ser de qualquer tipo de referência, e os `case` podem testar tipos (`case String s ->`) e até `null` (`case null ->`). `long`, `boolean`, `float` e `double` continuam proibidos no Java 21 e no 25 (o suporte a primitivos ainda está em *preview*). Os padrões ficam para a temporada de [Java moderno](/assistir/junior-t5-e05).

## Regras dos rótulos

Cada `case` precisa de um valor que o compilador conheça: um literal, uma constante `final` inicializada com constante, ou uma constante de `enum`. Além disso, o valor precisa caber no tipo do seletor, e não pode haver rótulos repetidos.

```java nao-compila
int a = 1, x = 1;
switch (x) {
    case a:
        break;
}
```

```java compila
final int A = 1;
int x = 1;
switch (x) {
    case A:
        break;
}
```

Com `byte b`, `case 200:` não compila, porque 200 não cabe num `byte`. Com `char c`, `case 98:` compila (98 é um `char` válido, o 'b'), e por isso `case 'b':` e `case 98:` no mesmo `switch` são rótulos **repetidos**.

## Fall-through

Sem `break`, a execução atravessa os rótulos seguintes, que não são testados de novo:

```java executar
int dia = 3;
switch (dia) {
    case 1:
        System.out.println("segunda");
    case 2:
        System.out.println("terça");
    case 3:
        System.out.println("quarta");
    case 4:
        System.out.println("quinta");
        break;
    case 5:
        System.out.println("sexta");
    default:
        System.out.println("fim de semana");
}
```

```saida
quarta
quinta
```

A execução entra no `case 3`, passa pelo `case 4` sem testar nada e para no `break`. O `default` não precisa ser o último, e o fall-through também passa por ele:

```java executar
int x = 9;
switch (x) {
    case 1:
        System.out.println("um");
    default:
        System.out.println("outro");
    case 2:
        System.out.println("dois");
        break;
    case 3:
        System.out.println("três");
}
```

```saida
outro
dois
```

Nenhum `case` casou com 9, então a execução começa no `default`, que está no meio, e cai no `case 2` até o `break`.

O fall-through é útil quando vários valores levam ao mesmo código. Desde o Java 14, dá para escrever vários rótulos num `case` só, separados por vírgula:

```java executar
String mes = "fev";
int dias;
switch (mes) {
    case "abr", "jun", "set", "nov":
        dias = 30;
        break;
    case "fev":
        dias = 28;
        break;
    default:
        dias = 31;
}
System.out.println(dias);
```

```saida
28
```

## `String` no `switch`

O `switch` com `String` compara com `equals`, ou seja, pelo conteúdo, e diferencia maiúsculas de minúsculas. Um seletor `null` lança `NullPointerException`, porque o `switch` precisa chamar métodos do objeto:

```java executar
String comando = null;
try {
    switch (comando) {
        case "sair":
            System.out.println("tchau");
            break;
        default:
            System.out.println("?");
    }
} catch (NullPointerException e) {
    System.out.println("NullPointerException");
}
```

```saida
NullPointerException
```

## Por baixo dos panos

O `javac` compila o `switch` para uma de duas instruções. Quando os valores dos `case` são próximos (1, 2, 3, 4...), usa `tableswitch`: uma **tabela de endereços** indexada pelo valor, que pula direto para o `case` certo em tempo constante, como um acesso a array. Quando os valores são espalhados (1, 50, 1000), usa `lookupswitch`: uma lista ordenada de pares (valor, endereço) em que a JVM faz uma [busca binária](/assistir/aprendiz-t4-e02). Em ambos os casos, é mais rápido que uma cadeia de `if` testando um por um.

O `switch` com `String` é traduzido em dois `switch`: o primeiro faz `lookupswitch` sobre o `hashCode()` da string, e dentro de cada `case` um `equals` confirma (porque strings diferentes podem ter o mesmo hash). É por isso que um seletor nulo lança exceção: a primeira coisa que o código gerado faz é chamar `hashCode()`.

## Resumo para a prova

- Seletor: `int` e menores, os wrappers deles, `String` e `enum`; nunca `long`, `boolean`, `float` ou `double`
- Rótulos: constantes de compilação, únicas, que caibam no tipo do seletor
- Sem `break`, a execução cai nos `case` seguintes sem testá-los
- `default` pode ficar em qualquer posição e também participa do fall-through
- Vários valores num `case`: `case 1, 2, 3:` (Java 14+)
- `switch` de `String` usa `equals` e lança `NullPointerException` com seletor nulo
- `char` e `int` se misturam: `case 'b'` e `case 98` são o mesmo rótulo
