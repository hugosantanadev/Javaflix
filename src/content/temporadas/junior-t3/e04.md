O polimorfismo deixa guardar um `Cachorro` numa variável `Animal`. Mas, de vez em quando, o código precisa do cachorro de volta, para chamar um método que só ele tem. É aí que entram o **cast** de referência, que muda o tipo pelo qual se enxerga o objeto, e o `instanceof`, que pergunta antes se a conversão é segura. A prova cobra o que compila, o que falha na execução e a diferença entre as duas coisas.

## Subir é automático, descer exige cast

Converter para um tipo mais **geral** (*upcast*) é sempre seguro e acontece sozinho: todo cachorro é um animal. Converter para um tipo mais **específico** (*downcast*) exige um cast explícito, porque nem todo animal é um cachorro:

```java executar
class Animal {
    String nome() { return "animal"; }
}

class Cachorro extends Animal {
    @Override String nome() { return "cachorro"; }
    String buscar() { return "buscou a bolinha"; }
}

Animal a = new Cachorro();
Cachorro c = (Cachorro) a;
System.out.println(c.buscar());
System.out.println(a == c);
```

```saida
buscou a bolinha
true
```

O cast **não muda o objeto** nem cria outro: `a` e `c` apontam para o mesmo cachorro. Ele só muda o tipo da referência, e com isso o que o compilador deixa chamar.

## Dois momentos de conferência

O compilador confere se o cast é **possível**: os dois tipos precisam estar na mesma linha de herança. Um `Animal` nunca poderia ser um `Carro`, então nem compila:

```java nao-compila
class Animal { }
class Carro { }

Animal a = new Animal();
Carro c = (Carro) a;
```

Se o cast é possível, a JVM confere na execução se ele é **verdadeiro** para aquele objeto. Se não for, lança `ClassCastException`:

```java executar
class Animal { }
class Cachorro extends Animal { }
class Gato extends Animal { }

Animal a = new Gato();
try {
    Cachorro c = (Cachorro) a;
} catch (ClassCastException e) {
    System.out.println("ClassCastException");
}
```

```saida
ClassCastException
```

O compilador aceitou, porque um `Animal` poderia ser um `Cachorro`. Na execução, o objeto era um `Gato`. Um detalhe que a prova usa: o cast de `null` sempre funciona, porque não há objeto para conferir. O resultado é simplesmente `null`.

## `instanceof`

O operador `instanceof` responde se um objeto é do tipo indicado **ou de algum subtipo dele**. Com `null`, a resposta é sempre `false`:

```java executar
class Animal { }
class Cachorro extends Animal { }
class Gato extends Animal { }

Animal[] bichos = {new Cachorro(), new Gato(), null};
for (Animal b : bichos) {
    System.out.println((b instanceof Animal) + " " + (b instanceof Cachorro) + " " + (b instanceof Gato));
}
```

```saida
true true false
true false true
false false false
```

Como no cast, o compilador recusa testes impossíveis. Uma `String` nunca poderia ser um `Integer`:

```java nao-compila
String s = "texto";
System.out.println(s instanceof Integer);
```

## O padrão seguro: testar, depois converter

Juntos, os dois formam o padrão clássico: testar com `instanceof` e só então fazer o cast. Desde o Java 16, a forma com **padrão** faz as duas coisas numa só, declarando a variável já convertida; os detalhes ficam para o episódio de [pattern matching](/assistir/junior-t5-e04):

```java executar
class Animal {
    String nome;
    Animal(String nome) { this.nome = nome; }
}

class Cachorro extends Animal {
    Cachorro(String nome) { super(nome); }
    String buscar() { return nome + " buscou"; }
}

class Gato extends Animal {
    Gato(String nome) { super(nome); }
    String ronronar() { return nome + " ronronou"; }
}

Animal[] bichos = {new Cachorro("Rex"), new Gato("Mia")};
for (Animal b : bichos) {
    if (b instanceof Cachorro) {
        Cachorro c = (Cachorro) b;
        System.out.println(c.buscar());
    } else if (b instanceof Gato g) {
        System.out.println(g.ronronar());
    }
}
```

```saida
Rex buscou
Mia ronronou
```

`instanceof` olha a hierarquia inteira. Para saber a classe **exata**, compara-se `getClass()`:

```java executar
class Animal { }
class Cachorro extends Animal { }

Animal a = new Cachorro();
System.out.println((a instanceof Animal) + " " + (a.getClass() == Animal.class) + " " + (a.getClass() == Cachorro.class));
System.out.println(a.getClass().getSimpleName());
```

```saida
true false true
Cachorro
```

> [!PROVA]
> Três perguntas para cada cast numa questão: os tipos estão na mesma linha de herança? (se não, não compila); o objeto real é do tipo do cast ou de um subtipo dele? (se não, `ClassCastException`); a referência é `null`? (então o cast funciona e o resultado é `null`). E repare nos parênteses: `(Cachorro) a.buscar()` aplica o cast ao resultado de `buscar()`; o certo é `((Cachorro) a).buscar()`.

Muitos `instanceof` seguidos costumam indicar que o comportamento deveria estar num método sobrescrito, como no [episódio de polimorfismo](/assistir/junior-t3-e03). O cast é a exceção, não a regra.

## Por baixo dos panos

O cast vira a instrução `checkcast`, e o teste, a instrução `instanceof`. As duas fazem a mesma pergunta, "a classe deste objeto é subtipo daquela?", e diferem só na reação: uma lança `ClassCastException`, a outra empurra 0 ou 1 na pilha.

A HotSpot responde a essa pergunta em tempo constante, sem subir a hierarquia. Cada classe guarda um pequeno vetor com seus ancestrais por profundidade: `Object` na posição 0, `Animal` na 1, `Cachorro` na 2. Para saber se um objeto é `Animal`, basta olhar a posição 1 do vetor da classe dele e comparar. Interfaces, que não têm profundidade fixa, usam uma lista à parte com um cache do último resultado. E como o JIT sabe muitas vezes o tipo exato de um objeto, ele elimina boa parte dos `checkcast` do código compilado.

## Resumo para a prova

- Upcast é automático; downcast exige cast explícito
- O cast não muda nem copia o objeto: muda só o tipo da referência
- Tipos fora da mesma linha de herança: o cast não compila
- Tipo errado na execução: `ClassCastException`
- Cast de `null` funciona e dá `null`; `null instanceof X` é `false`
- `instanceof` é verdadeiro para o tipo e todos os subtipos; `getClass()` dá a classe exata
- `instanceof` entre tipos incompatíveis não compila
- Cast se aplica antes da chamada só com parênteses: `((Tipo) x).metodo()`
