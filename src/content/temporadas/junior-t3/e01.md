Gerentes são funcionários; contas-poupança são contas; cachorros são animais. Quando um tipo **é um** caso particular de outro, a **herança** permite escrever só o que muda: a subclasse recebe os campos e métodos da superclasse e acrescenta os seus. Neste episódio, a mecânica: o `extends`, o que é e o que não é herdado, e a ordem exata em que os construtores rodam, que a prova cobra sem dó.

## `extends`

```java executar
class Animal {
    protected String nome;

    Animal(String nome) {
        this.nome = nome;
    }

    String apresentar() {
        return "Sou " + nome;
    }
}

class Cachorro extends Animal {
    Cachorro(String nome) {
        super(nome);
    }

    String latir() {
        return nome + ": au!";
    }
}

Cachorro rex = new Cachorro("Rex");
System.out.println(rex.apresentar());
System.out.println(rex.latir());
System.out.println(rex instanceof Animal);
```

```saida
Sou Rex
Rex: au!
true
```

`Cachorro` herdou o campo `nome` e o método `apresentar`, e acrescentou `latir`. Um objeto `Cachorro` **é um** `Animal`, e pode ser usado em qualquer lugar que espere um animal, ideia que o episódio de [polimorfismo](/assistir/junior-t3-e03) explora.

Java tem herança **simples** de classes: cada classe estende exatamente uma outra. Quem não escreve `extends` estende `Object`, a raiz de toda a hierarquia, e é de lá que vêm o `toString`, o `equals` e o `hashCode` de qualquer objeto. Estender duas classes não compila:

```java nao-compila
class A { }
class B { }
class C extends A, B { }
```

## O que é herdado

A subclasse herda os membros que consegue **acessar**: os `public` e `protected` sempre, e os de pacote se estiver no mesmo pacote, pelas regras do [episódio de acesso](/assistir/junior-t1-e06). Os campos `private` continuam existindo dentro do objeto, ocupando memória, mas o código da subclasse não pode usá-los pelo nome:

```java nao-compila
class Cofre {
    private String segredo = "1234";
}

class CofreDigital extends Cofre {
    String revelar() {
        return segredo;
    }
}
```

**Construtores não são herdados**: cada classe declara os seus. E uma classe `final` não pode ser estendida, como `String`:

```java nao-compila
class MinhaString extends String {
}
```

## `super(...)`: o construtor da superclasse vem primeiro

Todo construtor começa chamando um construtor da superclasse. Se você não escrever `super(...)` nem `this(...)`, o compilador insere `super();`, sem argumentos. Por isso, a construção de um objeto sempre sobe a hierarquia até `Object` e depois desce, executando de cima para baixo:

```java executar
class Base {
    static {
        System.out.println("1. static Base");
    }

    {
        System.out.println("3. instância Base");
    }

    Base() {
        System.out.println("4. construtor Base");
    }
}

class Derivada extends Base {
    static {
        System.out.println("2. static Derivada");
    }

    {
        System.out.println("5. instância Derivada");
    }

    Derivada() {
        System.out.println("6. construtor Derivada");
    }
}

public class Ordem {
    public static void main(String[] args) {
        new Derivada();
    }
}
```

```saida
1. static Base
2. static Derivada
3. instância Base
4. construtor Base
5. instância Derivada
6. construtor Derivada
```

É a ordem do [episódio de inicialização](/assistir/junior-t1-e05), aplicada a cada nível: primeiro as classes, da superclasse para a subclasse; depois, para cada nível do objeto, os inicializadores e o construtor.

O `super();` automático é a origem de um erro clássico. Se a superclasse não tem construtor sem parâmetros, a subclasse **precisa** chamar outro explicitamente:

```java nao-compila
class Veiculo {
    String placa;

    Veiculo(String placa) {
        this.placa = placa;
    }
}

class Moto extends Veiculo {
    Moto() {
        System.out.println("moto nova");
    }
}
```

O mesmo erro aparece se `Moto` não declarar construtor nenhum: o construtor padrão gerado também chama `super()`. A correção é `Moto(String placa) { super(placa); }`.

> [!PROVA]
> Como o `this(...)`, o `super(...)` precisa ser o primeiro comando do construtor até o Java 21 (o Java 25 aceita validações antes, desde que não usem o objeto). Um construtor tem no máximo uma chamada explícita: `this(...)` **ou** `super(...)`, nunca os dois. E quando a questão mostra uma subclasse sem construtor, procure o construtor sem parâmetros na superclasse.

## `super.` para membros

Além de chamar o construtor, `super` dá acesso à versão da superclasse de um método ou campo. É o jeito de **estender** um comportamento em vez de reescrevê-lo do zero:

```java executar
class Conta {
    double saldo = 100;

    String extrato() {
        return "Saldo: " + saldo;
    }
}

class ContaPremium extends Conta {
    double limite = 500;

    String extrato() {
        return super.extrato() + " | Limite: " + limite;
    }
}

System.out.println(new ContaPremium().extrato());
```

```saida
Saldo: 100.0 | Limite: 500.0
```

Redeclarar na subclasse um método herdado, como esse `extrato`, é a **sobrescrita**, com regras próprias que o [próximo episódio](/assistir/junior-t3-e02) detalha.

## Por baixo dos panos

Um objeto `Cachorro` é **um único objeto** no heap, não dois: o cabeçalho, depois os campos de `Animal` e, em seguida, os de `Cachorro`. Como cada classe tem só uma superclasse, os campos herdados ficam sempre nas mesmas posições (*offsets*), em qualquer subclasse. Por isso o código compilado de `Animal.apresentar`, que lê `nome` numa posição fixa, funciona igualmente num `Cachorro`, num `Gato` ou em qualquer descendente. Em C++, com herança múltipla, essa conta fica bem mais complicada, e é uma das razões de Java ter ficado com herança simples de classes.

No bytecode, o `super(nome)` é um `invokespecial` do `<init>` de `Animal`, e o verificador da JVM exige que todo construtor chame o da superclasse (ou outro da mesma classe) antes de usar o objeto. A cadeia sempre termina no `<init>` de `Object`. Na carga, acontece o mesmo: inicializar `Cachorro` exige inicializar `Animal` antes, o que explica a ordem dos blocos `static` acima.

## Resumo para a prova

- `extends` estende uma única classe; sem `extends`, a classe estende `Object`
- A subclasse herda o que pode acessar; `private` existe no objeto, mas não é acessível
- Construtores não são herdados; classes `final` não podem ser estendidas
- Todo construtor chama um da superclasse; sem `super(...)` explícito, o compilador insere `super()`
- Superclasse sem construtor sem parâmetros obriga a subclasse a chamar `super(args)`
- Ordem: `static` de cima para baixo; depois, por nível, inicializadores e construtor
- `super.metodo()` chama a versão da superclasse
