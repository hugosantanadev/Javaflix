Na folha de pagamento do episódio de polimorfismo, a classe `Funcionario` tinha um salário "padrão" que não fazia muito sentido: todo funcionário real era de algum tipo específico. Quando uma superclasse existe só para ser estendida, e algum comportamento só faz sentido nas subclasses, ela deve ser **abstrata**. Uma classe abstrata pode ter campos, construtores e métodos prontos, mas também **métodos abstratos**, sem corpo, que as subclasses são obrigadas a implementar.

## Classe e método abstratos

```java executar
abstract class Forma {
    private final String nome;

    Forma(String nome) {
        this.nome = nome;
    }

    abstract double area(); //> Sem corpo: toda forma tem área, cada uma calcula a sua.

    String descrever() {
        return nome + " com área " + area(); //> Usa area() sem saber como é calculada.
    }
}

class Quadrado extends Forma {
    private final double lado;

    Quadrado(double lado) {
        super("quadrado");
        this.lado = lado;
    }

    @Override
    double area() {
        return lado * lado;
    }
}

Forma f = new Quadrado(3);
System.out.println(f.descrever());
```

```saida
quadrado com área 9.0
```

O método abstrato termina com `;`, sem chaves: ele só declara que toda forma **tem** uma área. `descrever` é concreto e usa `area()` sem saber como ela é calculada; na execução, o polimorfismo escolhe a versão do objeto real. Variáveis do tipo abstrato são normais, e é assim que se usa uma classe abstrata. O que não se pode é criar um objeto dela:

```java nao-compila
abstract class Veiculo {
    abstract int rodas();
}

Veiculo v = new Veiculo(); //> Não existe "um veículo qualquer".
```

## A primeira classe concreta paga a conta

Uma subclasse **concreta** (não abstrata) precisa implementar todos os métodos abstratos que herdou, senão não compila:

```java nao-compila
abstract class Animal {
    abstract String som();
    abstract int patas();
}

class Cobra extends Animal {
    String som() { return "sss"; }
}
```

> [!PENSE]
> `Cobra` implementa `som()`, mas não `patas()`. Se o compilador deixasse passar, o que aconteceria num `new Cobra().patas()`?

> [!ERRO]
> A mensagem aponta a declaração da classe, não um método: `error: Cobra is not abstract and does not override abstract method patas() in Animal`. Ela cita só **um** dos métodos que faltam; implemente esse, compile de novo, e o próximo aparece. A IDE lista todos de uma vez.

Uma subclasse **abstrata** pode implementar só parte e deixar o resto para as de baixo. A regra vale para a primeira classe concreta da hierarquia:

```java executar
abstract class Animal {
    abstract String som();
    abstract int patas();
}

abstract class Mamifero extends Animal {
    int patas() { return 4; }
}

class Vaca extends Mamifero {
    String som() { return "muu"; }
}

Animal a = new Vaca();
System.out.println(a.som() + " " + a.patas());
```

```saida
muu 4
```

## As combinações proibidas

As regras saem de uma ideia só: um método abstrato **existe para ser sobrescrito**. Por isso ele não pode ser `private` (a subclasse não o enxergaria), nem `final` (a subclasse não poderia sobrescrevê-lo), nem `static` (métodos `static` não são sobrescritos). E uma classe abstrata existe para ser estendida, então não pode ser `final`:

```java nao-compila
final abstract class Impossivel {
}
```

Um método abstrato não pode ter corpo, nem vazio, e só pode existir numa classe abstrata (ou numa interface, como você verá na próxima temporada):

```java nao-compila
abstract class Regras {
    abstract void validar() { }
}
```

O contrário é livre: uma classe abstrata pode não ter nenhum método abstrato, só para impedir que alguém a instancie.

> [!COMPILADOR]
> Você é o javac. Este código compila?
>
> ```java nao-compila
> abstract class Relatorio {
>     abstract String titulo();
>     static abstract String rodape();
> }
> ```
>
> **Resposta:** Não compila. `rodape` é `abstract` e `static` ao mesmo tempo: um método abstrato existe para ser sobrescrito, e métodos `static` não são sobrescritos, só escondidos.

> [!PERGUNTAS]
> **P:** Para que uma classe abstrata sem nenhum método abstrato?
>
> **R:** Para deixar claro que ela é só uma base: tem o código comum, mas não faz sentido sozinha. O `abstract` impede o `new` por engano, e o leitor entende que deve estender.

> [!PROVA]
> Nas questões de classes abstratas, confira: a classe com método abstrato é `abstract`? Algum método abstrato tem corpo, ou é `private`, `final` ou `static`? A primeira subclasse concreta implementa **todos** os métodos abstratos herdados, inclusive os de níveis acima? E há algum `new` de classe abstrata? Classes abstratas podem ter construtores, e eles rodam quando a subclasse chama `super(...)`.

## Construtores e classes anônimas

Classes abstratas têm construtores, que inicializam a parte comum e rodam pela cadeia de `super(...)`. E uma classe anônima pode estender uma classe abstrata, implementando os métodos que faltam ali mesmo:

```java executar
abstract class Tarefa {
    private final String nome;

    Tarefa(String nome) {
        this.nome = nome;
        System.out.println("criando " + nome);
    }

    abstract void executar();

    void rodar() {
        System.out.print(nome + ": ");
        executar();
    }
}

Tarefa backup = new Tarefa("backup") {
    @Override
    void executar() {
        System.out.println("copiando arquivos");
    }
};
backup.rodar();
```

```saida
criando backup
backup: copiando arquivos
```

O `rodar` é um exemplo do padrão **Template Method**: a classe abstrata fixa o roteiro e deixa os passos variáveis para as subclasses. A biblioteca padrão está cheia dele: `AbstractList` implementa quase toda a interface `List` a partir de dois métodos abstratos, `get` e `size`.

![A classe abstrata Tarefa fixa o roteiro de rodar, com um passo pronto e um passo abstrato, executar, que cada subclasse preenche](/figuras/template-method.svg "O roteiro fica na classe abstrata; o passo variável, nas subclasses.")

> [!ANTES]
> As classes abstratas existem desde o Java 1.0 e, até o Java 7, eram o único jeito de entregar uma base com código pronto: interfaces só tinham assinaturas. Por isso a biblioteca padrão tem pares como `List` e `AbstractList`. Desde o Java 8, com os métodos `default` nas interfaces, muita base que seria abstrata virou interface, como você verá na próxima temporada.

> [!MATEMATICA]
> O ganho do `AbstractList` é de contagem simples. A interface `List` tem cerca de 30 métodos abstratos para implementar. Estendendo `AbstractList`, uma lista só de leitura precisa de 2: `get` e `size`. Os outros 28, como `contains`, `indexOf` e `iterator`, já vêm prontos, escritos em cima desses dois. São 93% menos métodos para escrever e testar.

> [!IA]
> Pedindo uma "hierarquia de formas", a IA costuma dar à superclasse um `area()` concreto que devolve `0`, "para não quebrar". Isso esconde o erro de uma subclasse que esqueceu de implementar o método: a área sai 0 em vez de não compilar. Peça o método `abstract`, e o compilador passa a cobrar.

## Na IDE

- **Implementar o que falta.** Com o cursor na classe sublinhada, **Alt + Enter**, *Implement methods* (ou **Ctrl + I**), lista todos os métodos abstratos pendentes e gera as assinaturas.
- **Ver a classe como abstrata.** O ícone da classe na árvore do projeto ganha um traço diferente para `abstract`, e os métodos abstratos aparecem em itálico na janela *Structure* (**Alt + 7**).
- **Ir para as implementações.** **Ctrl + Alt + B** num método abstrato lista as subclasses que o implementam.

## Por baixo dos panos

No arquivo `.class`, uma classe abstrata é marcada com a flag `ACC_ABSTRACT`, e os métodos abstratos também, sem o atributo `Code`, que guardaria o bytecode do corpo. A proibição do `new` é conferida duas vezes: pelo compilador e pela JVM, que lança `InstantiationError` se algum bytecode, gerado por outra ferramenta, tentar instanciar uma classe abstrata.

Na tabela de métodos virtuais, o método abstrato ocupa uma posição como qualquer outro; cada subclasse concreta preenche essa posição com a sua implementação. Se, por uma recompilação parcial, uma classe concreta chegar à JVM sem implementar um método abstrato e alguém chamá-lo, o resultado é `AbstractMethodError`, um erro que só aparece quando versões diferentes de bibliotecas se misturam.

## Resumo para a prova

- Classe abstrata não pode ser instanciada, mas pode ser usada como tipo de variável
- Pode ter campos, construtores, métodos concretos, `static` e nenhum método abstrato
- Método abstrato: sem corpo, terminado em `;`, só em classe abstrata ou interface
- Método abstrato não pode ser `private`, `final` nem `static`; classe abstrata não pode ser `final`
- A primeira subclasse concreta implementa todos os métodos abstratos herdados
- Subclasses abstratas podem implementar só parte
- Uma classe anônima pode estender uma classe abstrata
