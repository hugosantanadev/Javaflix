Tudo o que um computador guarda é número, e todo número é guardado como uma fileira de zeros e uns. Texto, cor, imagem, o seu programa Java: no fundo, bits. Este episódio ensina a ler e escrever números do jeito que a máquina lê, e isso explica metade das pegadinhas de tipos que você vai ver no cargo de Estagiário.

## Por que binário

Um computador é feito de bilhões de **transistores**, chaves microscópicas que deixam ou não a corrente passar. Cada fio do circuito está numa tensão alta ou baixa. Daria para usar dez níveis de tensão e trabalhar em base 10, mas o ruído elétrico tornaria impossível saber se um fio está no nível 6 ou no 7. Com só dois níveis, a margem de erro é enorme: qualquer coisa perto de 0 V é 0, qualquer coisa perto da tensão máxima é 1.

Esse dígito de dois valores é o **bit** (*binary digit*). Agrupando bits, dá para representar qualquer coisa:

| Bits | Nome | Combinações possíveis |
|---|---|---|
| 1 | bit | 2 |
| 4 | nibble | 2⁴ = 16 |
| 8 | byte | 2⁸ = 256 |
| 16 | | 2¹⁶ = 65.536 |
| 32 | | 2³² ≈ 4,29 bilhões |
| 64 | | 2⁶⁴ ≈ 1,8 × 10¹⁹ |

A regra que você vai usar a vida inteira: **com n bits existem 2ⁿ combinações**. É por isso que um `byte` do Java tem 256 valores possíveis e um `char`, com 16 bits, tem 65.536.

## Sistema posicional

Você já usa um sistema posicional todo dia. Em base 10, cada posição vale dez vezes a da direita:

```text
472 = 4 × 10² + 7 × 10¹ + 2 × 10⁰
    = 400     + 70      + 2
```

Em base 2 é igual, mas cada posição vale **duas** vezes a da direita:

```text
1011₂ = 1 × 2³ + 0 × 2² + 1 × 2¹ + 1 × 2⁰
      = 8      + 0      + 2      + 1
      = 11
```

Vale decorar as primeiras potências de 2, porque elas aparecem em todo lugar: 1, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024. Repare que 2¹⁰ = 1024 fica perto de 10³ = 1000: é daí que vem a confusão entre "quilo" de 1000 e de 1024.

## De decimal para binário

O método mais confiável é dividir por 2 até chegar a zero e ler os restos **de baixo para cima**:

| Divisão | Quociente | Resto |
|---|---|---|
| 13 ÷ 2 | 6 | **1** |
| 6 ÷ 2 | 3 | **0** |
| 3 ÷ 2 | 1 | **1** |
| 1 ÷ 2 | 0 | **1** |

Lendo os restos de baixo para cima: 13 = `1101`₂. Confira pelo outro lado: 8 + 4 + 0 + 1 = 13.

Outro jeito, mais rápido de cabeça: pegue a maior potência de 2 que cabe no número, subtraia e repita. 13 = 8 + 4 + 1, então os bits das posições 3, 2 e 0 ficam ligados: `1101`.

## Hexadecimal

Binário é ótimo para a máquina e péssimo para ler: `11111101010` é fácil de errar. A solução é a base 16, o **hexadecimal**, com os dígitos 0 a 9 e A a F (A = 10, B = 11, ..., F = 15). A mágica é que **um dígito hexadecimal corresponde a exatamente 4 bits**, então a conversão é feita em grupos:

```text
binário:      1010  1111
hexadecimal:    A     F      → 0xAF = 10 × 16 + 15 = 175
```

Você vê hexadecimal o tempo todo, mesmo sem perceber. A cor laranja deste site é `#FF7A1A`: são três bytes, um para cada canal de cor. `FF` = 255 de vermelho, `7A` = 122 de verde e `1A` = 26 de azul. Endereços de memória, hashes do Git e códigos de erro também costumam aparecer em hexadecimal.

Existe ainda o **octal** (base 8, 3 bits por dígito), herança de computadores antigos de 12 e 36 bits. Ele sobrevive em permissões de arquivo no Linux (`chmod 755`) e numa pegadinha famosa do Java: o literal `010` é octal e vale 8.

## Texto também é número

Para o computador, uma letra é só um número combinado. A tabela **ASCII** (1963) usa 7 bits e define, por exemplo:

| Caractere | Decimal | Hexadecimal | Binário |
|---|---|---|---|
| `0` | 48 | 0x30 | `0110000` |
| `A` | 65 | 0x41 | `1000001` |
| `a` | 97 | 0x61 | `1100001` |

Repare que `a` − `A` = 32, que é exatamente um bit (o de valor 32). Trocar maiúscula por minúscula é ligar ou desligar um bit.

ASCII só cobre o inglês. O **Unicode** dá um número (*code point*) para todo caractere de toda escrita, inclusive emoji, e a codificação mais usada, o **UTF-8**, guarda cada caractere em 1 a 4 bytes: letras ASCII continuam com 1 byte, `ã` usa 2, a maioria dos emoji usa 4. O `char` do Java tem 16 bits e guarda uma unidade de UTF-16, outra codificação do Unicode.

## Quilo de 1000 ou de 1024?

Para fabricantes de disco, 1 KB = 1000 bytes. Para a memória, o natural é 1024. A norma resolveu com prefixos binários: **KiB** (kibibyte) = 1024 bytes, MiB = 1024² e GiB = 1024³. É por isso que um SSD de 1 TB (10¹² bytes) aparece como uns 931 GiB no sistema operacional: ninguém roubou espaço, as unidades é que são diferentes.

## Em Java

O Java tem literais e métodos prontos para tudo isso:

```java executar
public class Bases {
    public static void main(String[] args) {
        int n = 2026;
        System.out.println(Integer.toBinaryString(n));
        System.out.println(Integer.toHexString(n));
        System.out.println(Integer.toOctalString(n));
        System.out.println(Integer.parseInt("11111101010", 2));
        System.out.println(Integer.parseInt("7EA", 16));
        System.out.println((int) 'A' + " " + (char) 97);
    }
}
```

```saida
11111101010
7ea
3752
2026
2026
65 a
```

`Integer.parseInt(texto, base)` faz o caminho de volta: lê um número escrito em qualquer base de 2 a 36. E os literais `0b` (binário) e `0x` (hexadecimal) deixam você escrever direto no código: `0b1011` e `0xB` são o mesmo `int` 11.

## Resumo

- Com n bits existem 2ⁿ combinações; um byte tem 8 bits e 256 valores
- Base 2 é posicional: cada posição vale o dobro da anterior
- Decimal para binário: divida por 2 e leia os restos de baixo para cima
- Um dígito hexadecimal são exatamente 4 bits; `0xFF` = 255
- Letras são números: `A` = 65, `a` = 97, e UTF-8 usa de 1 a 4 bytes por caractere
- KB = 1000 bytes, KiB = 1024 bytes
