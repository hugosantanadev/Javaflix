Metade das questões da prova pede a saída de um trecho de código, e quase todas passam por uma conta. Errar a ordem em que o Java resolve uma expressão é o jeito mais comum de perder pontos. Este episódio cobre os operadores aritméticos, a tabela de precedência, a diferença entre **precedência** e **ordem de avaliação**, e o `+` que às vezes soma e às vezes concatena.

## A tabela de precedência

Quanto mais alto na tabela, mais cedo o operador é aplicado. Operadores na mesma linha têm a mesma precedência e são resolvidos pela associatividade.

| Grupo | Operadores | Associatividade |
|---|---|---|
| Pós-fixos | `x++` `x--` | |
| Unários | `++x` `--x` `+x` `-x` `~` `!` `(tipo)` | da direita para a esquerda |
| Multiplicativos | `*` `/` `%` | da esquerda para a direita |
| Aditivos | `+` `-` | da esquerda para a direita |
| Deslocamento | `<<` `>>` `>>>` | da esquerda para a direita |
| Relacionais | `<` `>` `<=` `>=` `instanceof` | da esquerda para a direita |
| Igualdade | `==` `!=` | da esquerda para a direita |
| E bit a bit | `&` | |
| OU exclusivo | `^` | |
| OU bit a bit | `\|` | |
| E condicional | `&&` | |
| OU condicional | `\|\|` | |
| Ternário | `? :` | da direita para a esquerda |
| Atribuição | `=` `+=` `-=` `*=` `/=` `%=` e os outros | da direita para a esquerda |

Não precisa decorar tudo de uma vez. O essencial para este episódio: unários antes de `* / %`, que vêm antes de `+ -`, e operadores do mesmo nível são resolvidos da esquerda para a direita.

```java executar
System.out.println(2 + 3 * 4); //> `*` antes de `+`: 2 + 12.
System.out.println(10 - 4 - 3); //> Mesmo nível: da esquerda para a direita, (10 - 4) - 3.
System.out.println(100 / 10 / 5);
System.out.println(2 * 3 % 4); //> `*` e `%` no mesmo nível: 6 % 4.
System.out.println(20 % 6 * 2);
System.out.println(- -5); //> Dois menos unários, com espaço entre eles.
```

```saida
14
3
2
2
4
5
```

`10 - 4 - 3` é `(10 - 4) - 3`, e não `10 - (4 - 3)`. `2 * 3 % 4` é `6 % 4`, porque `*` e `%` estão no mesmo nível. E `- -5` são dois menos unários (o espaço é obrigatório: `--5` seria um decremento, que não compila num literal).

O jeito mais seguro de ler uma expressão é desenhar a árvore que o compilador monta. Quem tem precedência maior fica mais fundo, e o que está mais fundo é calculado primeiro:

![Duas árvores de expressão: em 2 + 3 * 4 o * fica embaixo e dá 12 antes da soma; em 10 - 4 - 3 a subtração da esquerda fica embaixo](/figuras/arvore-de-expressao.svg "Leia de baixo para cima: cada nó é calculado depois dos seus filhos.")

> [!PERGUNTAS]
> **P:** Parênteses "a mais", que não mudam o resultado, deixam o programa mais lento?
>
> **R:** Não. Os parênteses só dizem ao compilador como montar a árvore; no bytecode eles nem existem. Use à vontade quando deixarem a conta mais clara.
>
> **P:** Preciso decorar a tabela inteira para a prova?
>
> **R:** Não de uma vez. Comece pelo essencial deste episódio e volte à tabela a cada temporada: os relacionais, os lógicos e o ternário aparecem nos próximos episódios.

## Divisão inteira e resto

Com dois inteiros, `/` descarta a parte fracionária, arredondando em direção a zero. O `%` devolve o resto, com o **sinal do dividendo**, como você viu no episódio de [aritmética modular](/assistir/aprendiz-t3-e04). Basta um operando de ponto flutuante para a conta inteira ser feita em ponto flutuante:

```java executar
System.out.println(7 / 2);
System.out.println(-7 / 2);
System.out.println(7 % 3 + " " + -7 % 3 + " " + 7 % -3);
System.out.println(7 / 2.0);
System.out.println(5.5 % 2);
System.out.println(1.0 / 0);
```

```saida
3
-3
1 -1 1
3.5
1.5
Infinity
```

> [!MATEMATICA]
> Divisão e resto sempre fecham a conta: `(a / b) * b + a % b` é igual a `a`, para qualquer `a` e qualquer `b` diferente de zero (JLS 15.17.3). Com `a = -7` e `b = 2`: `-7 / 2` dá **-3**, porque o Java corta em direção a zero; então o resto precisa ser -7 - (-3 × 2) = -7 + 6 = **-1**. É por isso que o resto tem o sinal do dividendo: ele é o que sobra para a identidade fechar.

> [!IA]
> Quem aprendeu Python confunde, e a IA também: lá, `-7 // 2` dá **-4**, porque o Python arredonda para baixo, e `-7 % 2` dá **1**. Em Java, `-7 / 2` dá -3 e `-7 % 2` dá -1. Respostas de IA sobre divisão com negativos às vezes misturam as duas regras; rode a conta no `jshell` antes de confiar.

> [!ERRO]
> Esperar que `1 / 2` dê `0.5`. Com dois inteiros, a divisão é inteira e dá `0`, e `double metade = 1 / 2;` guarda `0.0`: a conversão para `double` só acontece **depois** da divisão. Escreva `1.0 / 2` ou `(double) 1 / 2`.

> [!PROVA]
> Divisão **inteira** por zero (`/` ou `%`) lança `ArithmeticException` em tempo de execução. Divisão de ponto flutuante por zero não lança nada: dá `Infinity`, `-Infinity` ou `NaN`. E o compilador não reclama de `10 / 0`: o erro só aparece quando a linha roda.

## Precedência não é ordem de avaliação

> [!PENSE]
> Em `a() + b() * c()`, a multiplicação acontece antes da soma. Então qual dos três métodos é chamado primeiro?

A precedência diz **como agrupar** os operandos. A **ordem de avaliação** diz em que ordem cada operando é calculado, e no Java ela é sempre da esquerda para a direita (JLS 15.7). Em `a() + b() * c()`, a multiplicação acontece antes da soma, mas os três métodos são chamados na ordem em que aparecem:

```java executar
public class Ordem {
    static int valor(String nome, int v) {
        System.out.print(nome + " ");
        return v;
    }

    public static void main(String[] args) {
        int r = valor("a", 1) + valor("b", 2) * valor("c", 3);
        System.out.println("= " + r);
    }
}
```

```saida
a b c = 7
```

Isso importa sempre que um operando tem efeito colateral: imprimir, chamar um método que altera estado, ou um `++`, assunto do próximo episódio.

## O `+` que concatena

Se **um** dos lados do `+` é uma `String`, o `+` vira concatenação. Como `+` é associativo à esquerda, o momento em que a primeira `String` aparece decide o resultado:

```java executar
System.out.println(1 + 2 + "3");
System.out.println("1" + 2 + 3);
System.out.println("1" + (2 + 3));
System.out.println('a' + 'b' + "c");
System.out.println("" + 'a' + 'b');
String s = null;
System.out.println(s + "!");
```

```saida
33
123
15
195c
ab
null!
```

![As expressões 1 + 2 + "3" e "1" + 2 + 3 resolvidas par a par, da esquerda para a direita, com o tipo de cada resultado](/figuras/concatenacao-passo-a-passo.svg "Na primeira, o 1 + 2 ainda é conta de inteiros; na segunda, o texto aparece no primeiro par e contamina o resto.")

Em `1 + 2 + "3"`, a soma `1 + 2` acontece primeiro, e só depois o 3 é concatenado. Em `'a' + 'b' + "c"`, os dois `char` são números (97 + 98 = 195) até a `String` aparecer. Concatenar `null` não lança exceção: vira o texto `"null"`. Só o `+` (e o `+=`) concatena; `-`, `*` e os outros não aceitam `String`:

```java nao-compila
String s = "abc" - "c";
```

> [!LAPIS]
> Sem rodar, qual é a saída de cada linha?
>
> ```java
> System.out.println(7 + 3 / 2 * 2);
> System.out.println("" + 7 + 3);
> System.out.println(7 + 3 + "");
> System.out.println('1' + 1);
> ```
>
> **Resposta:** `9`, porque `3 / 2` é 1, vezes 2 dá 2, e 7 + 2 = 9. Depois `73`, porque a String vazia aparece antes e transforma tudo em texto. Depois `10`, porque a soma acontece antes de o texto aparecer. E `50`: o `char` `'1'` tem código 49, e 49 + 1 = 50.

> [!DESEMPENHO]
> Montar uma String com `+` dentro de um laço cria um objeto novo a cada volta. Para algumas voltas, tanto faz; para milhares, use um `StringBuilder`, que você vai ver na temporada [Texto](/?t=estagiario-t5). Fora de laços, o `+` é o jeito certo: desde o Java 9 ele é otimizado pela JVM, como mostra a seção abaixo.

> [!ANTES]
> Até o Java 8, o `javac` traduzia cada concatenação para uma cadeia de `StringBuilder.append`. Muitos guias antigos mandam usar `StringBuilder` em qualquer concatenação por causa disso. Desde o Java 9, o `+` fora de laços é otimizado pela própria JVM, e o conselho só continua valendo para concatenar dentro de laços.

## Na IDE

O IntelliJ ajuda a ler e a corrigir expressões:

- **O tipo de uma expressão.** Selecione `'A' + 1` e aperte **Ctrl + Shift + P**: aparece `int`, e a dúvida "isso é letra ou número?" acaba.
- **Divisão inteira suspeita.** Em `double b = a / 2;`, com `a` inteiro, o IntelliJ marca a linha com o aviso *Integer division in floating-point context*: é exatamente o erro do quadro acima.
- **Parênteses que esclarecem.** Com o cursor numa expressão com operadores de níveis diferentes, **Alt + Enter** oferece *Add clarifying parentheses*, que escreve os parênteses implícitos, sem mudar o resultado.
- **Testar uma conta.** **Tools > JShell Console** abre o `jshell` dentro da IDE, para conferir uma expressão sem criar classe.

## Por baixo dos panos

Contas só com constantes nem chegam à execução: o `javac` as calcula na compilação (o *constant folding* do episódio sobre [compiladores](/assistir/aprendiz-t2-e03)), e `2 + 3 * 4` vira o número 14 no bytecode.

A concatenação mudou de implementação no Java 9 (JEP 280). Antes, `"a" + x + "b"` era traduzido para uma cadeia de `new StringBuilder().append("a").append(x).append("b").toString()`. Hoje o `javac` emite uma única instrução `invokedynamic` com uma "receita" (o texto fixo e os pontos onde entram os valores), e a JVM escolhe na primeira execução a forma mais rápida de montar a `String`. Para você, o resultado é o mesmo; a diferença é que a JVM pode otimizar sem que o código precise ser recompilado.

A divisão inteira vira a instrução `idiv` (ou `ldiv` para `long`). Como dividir por zero não tem resultado definido no processador, a JVM verifica o divisor antes e lança `ArithmeticException` no lugar.

## Resumo para a prova

- Unários, depois `* / %`, depois `+ -`; mesmo nível, da esquerda para a direita
- `int / int` descarta a fração em direção a zero; `%` tem o sinal do dividendo
- Divisão inteira por zero lança `ArithmeticException`; com `double`, dá `Infinity` ou `NaN`
- Os operandos são avaliados da esquerda para a direita, independentemente da precedência
- Basta um lado ser `String` para o `+` concatenar; até lá, `char` é número
- `null + "x"` dá `"nullx"`; só `+` e `+=` funcionam com `String`
