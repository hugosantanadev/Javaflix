`x++` parece a coisa mais simples do Java, até aparecer dentro de uma expressão maior. A prova adora `i++ + ++i`, `x = x++` e `b += 300` num `byte`. Este episódio mostra a diferença entre prefixo e sufixo, como resolver qualquer expressão com incrementos de forma mecânica, e o cast escondido nas atribuições compostas.

## Prefixo e sufixo

Os dois incrementam a variável. A diferença está no **valor da expressão**:

| Forma | Efeito na variável | Valor da expressão |
|---|---|---|
| `++x` (prefixo) | soma 1 | o valor **novo** |
| `x++` (sufixo) | soma 1 | o valor **antigo** |
| `--x` / `x--` | subtrai 1 | novo / antigo |

Sozinhos numa linha (`x++;` ou `++x;`), dão no mesmo. Dentro de uma expressão, não.

> [!PENSE]
> Antes de ler a saída abaixo: começando em 10, quanto vale `x` depois de `x = x++`? 10, 11 ou outra coisa?

```java executar
int a = 5;
int b = a++; //> b recebe o 5 antigo; só depois a vira 6.
int c = ++a; //> a vira 7 primeiro; c recebe o 7.
System.out.println(a + " " + b + " " + c);
int x = 10;
x = x++; //> A pegadinha: o 10 antigo é gravado de volta.
System.out.println(x);
```

```saida
7 5 7
10
```

`b = a++` guarda o valor antigo (5) e só então `a` vira 6. `c = ++a` faz `a` virar 7 e guarda o 7. E `x = x++` é a pegadinha clássica: o lado direito vale 10 (o valor antigo), `x` vira 11 por um instante, e a atribuição grava o 10 de volta. O incremento se perde.

![x = x++ em três passos: o 10 sobe para a pilha, a variável vira 11, e o 10 da pilha é gravado de volta](/figuras/x-igual-x-mais-mais.svg "O que se perde é o 11: ele existiu, mas foi sobrescrito pelo 10 que já estava esperando na pilha.")

> [!CONVERSA]
> **++x:** Eu sou direto. Somo 1 e mostro o resultado. Quem me usa recebe o valor novo.
>
> **x++:** Eu sou educado. Primeiro entrego o valor que você tinha, depois somo 1.
>
> **++x:** Educado demais. Em `x = x++`, a sua educação apaga o próprio trabalho.
>
> **x++:** Culpa de quem me escreveu ali. Sozinho numa linha, eu e você fazemos exatamente a mesma coisa.
>
> **++x:** Verdade. Em `for (int i = 0; i < 10; i++)`, ninguém nota diferença entre nós dois.
>
> **x++:** E é por isso que eu apareço muito mais: todo mundo aprendeu o `for` comigo.

> [!ANTES]
> O `++` veio do C, dos anos 1970, passando pelo C++. Em C, uma linha como `i = i++` é **comportamento indefinido**: cada compilador pode dar um resultado diferente. O Java decidiu fixar a ordem de avaliação na especificação (JLS 15.7) exatamente para que o mesmo código dê o mesmo resultado em qualquer JVM.

## O método para qualquer expressão

Como os operandos são avaliados **da esquerda para a direita** (você viu isso no [episódio anterior](/assistir/estagiario-t2-e01)), dá para resolver qualquer expressão com incrementos substituindo cada um pelo seu valor, na ordem em que aparece, e anotando o novo valor da variável:

```java executar
int i = 3;
int r = i++ + ++i * i--;
System.out.println(r + " " + i);
```

```saida
28 4
```

| Pedaço | Valor usado | `i` depois |
|---|---|---|
| `i++` | 3 | 4 |
| `++i` | 5 | 5 |
| `i--` | 5 | 4 |

Com os valores no lugar, a expressão vira `3 + 5 * 5`, e só agora a precedência entra: 3 + 25 = 28. Primeiro avalie os operandos da esquerda para a direita; depois aplique os operadores.

> [!LAPIS]
> Com `int i = 0;`, quanto vale `i` depois de `i = i++ + i++;`? Use o método da tabela.
>
> **Resposta:** **1**. O primeiro `i++` vale 0 e deixa `i` em 1; o segundo vale 1 e deixa `i` em 2. A soma é 0 + 1 = 1, e a atribuição grava esse 1 por cima do 2.

> [!IA]
> Pergunte a um assistente de IA sobre `i++ + ++i` e é comum ouvir que é "comportamento indefinido". Isso vale para C e C++, não para Java: aqui a ordem é definida pela especificação, e a resposta é sempre a mesma. Quando a explicação citar "undefined behavior", desconfie de que a IA misturou as linguagens.

> [!PROVA]
> Incremento e decremento só funcionam em **variáveis**. `5++`, `++(a + 1)` e `(x++)++` não compilam: o resultado de `x++` é um valor, não uma variável que possa ser alterada.

## Atribuição composta e o cast escondido

`x op= y` é quase `x = x op y`. O "quase" é a parte importante: a JLS 15.26.2 define que o resultado é **convertido de volta para o tipo de x** automaticamente, como se houvesse um cast:

```text
x op= y   é equivalente a   x = (T) (x op y), onde T é o tipo de x
```

Por isso estas linhas compilam, com resultados que surpreendem:

```java executar
byte b = 10;
b += 5;
b *= 20;
System.out.println(b);
int x = 5;
x *= 2.5;
System.out.println(x);
char c = 'a';
c += 2;
System.out.println(c);
long total = 0;
total += 0.7;
System.out.println(total);
```

```saida
44
12
c
0
```

15 × 20 = 300, que não cabe num `byte`: o cast implícito fica com os 8 bits de baixo, e 300 − 256 = 44 (é o [complemento de dois](/assistir/aprendiz-t3-e02) de novo).

![O int 300 em binário, com os 8 bits da direita destacados: 0010 1100, que valem 44](/figuras/corte-para-byte.svg "O cast para byte guarda só o último byte. O bit que valia 256 vai embora.")

> [!MATEMATICA]
> Para saber o resultado de um cast para `byte` sem desenhar os bits, use resto: some 128, tire o resto por 256 e subtraia 128. Para 300: (300 + 128) mod 256 = 428 - 256 = 172, e 172 - 128 = **44**. Para 200: (200 + 128) mod 256 = 72, e 72 - 128 = **-56**. Somar e subtrair 128 é só para levar a faixa de 0 a 255 para a faixa do byte, de -128 a 127. `x *= 2.5` calcula 12.5 em `double` e trunca para 12. `c += 2` anda duas letras. E `total += 0.7` dá 0, porque 0.7 é truncado para `long`.

A forma longa, sem o operador composto, não tem esse cast e não compila:

```java nao-compila
byte b = 10;
b = b + 5;
```

`b + 5` é um `int` (a [promoção numérica](/assistir/estagiario-t2-e03) do próximo episódio), e `int` não cabe em `byte` sem cast explícito. Os operadores `++` e `--` também têm o cast embutido: `b++` num `byte` compila.

Num operador composto, o valor antigo do lado esquerdo é guardado **antes** de o lado direito ser avaliado:

```java executar
int k = 2;
k += k++ * 3;
System.out.println(k);
```

```saida
8
```

O Java guarda k = 2, depois avalia `k++ * 3` = 2 × 3 = 6 (e k vira 3 nesse meio-tempo), soma 2 + 6 = 8 e grava 8, apagando o incremento.

## Atribuição também é expressão

Uma atribuição tem um valor: o valor atribuído. Daí vêm três padrões que aparecem na prova:

```java executar
int a, b, c;
a = b = c = 7;
System.out.println(a + b + c);
boolean ligado = false;
if (ligado = true) {
    System.out.println("entrou");
}
int y = (a = 2) * 3;
System.out.println(a + " " + y);
```

```saida
21
entrou
2 6
```

`a = b = c = 7` funciona porque `=` é associativo à **direita**: `c = 7` vale 7, que vai para `b`, que vai para `a`. O `if (ligado = true)` compila (é uma atribuição de `boolean`, que vale `true`) e sempre entra: um erro de digitação real que só existe com `boolean`. Com `int`, `if (x = 5)` não compila, porque `int` não é condição.

> [!ERRO]
> Escrever `=` no lugar de `==` numa condição com `boolean`. `if (aprovado = false)` compila, apaga o valor de `aprovado` e nunca entra no `if`. O compilador não reclama, porque a atribuição também é uma expressão `boolean`.

> [!PREVENCAO]
> Não compare `boolean` com `true` ou `false`: escreva `if (aprovado)` e `if (!aprovado)`. Além de mais curto, não sobra nenhum `=` para errar.

## Na IDE

Expressões com `++` ficam claras quando você vê os valores mudando, um passo de cada vez, no **depurador** do IntelliJ:

1. Clique na margem, ao lado do número de uma linha, para marcar um **breakpoint** (aparece um círculo vermelho).
2. Rode com **Debug** (**Shift + F9**) em vez de Run. O programa para na linha marcada.
3. Aperte **F8** (*Step Over*) para executar uma linha por vez. A janela *Variables* mostra o valor de cada variável a cada passo.

Faça isso com o `x = x++` e com o exemplo da tabela: você vê o `i` subir e descer na ordem em que os operandos são avaliados.

## Por baixo dos panos

A JVM tem uma instrução só para incrementar variáveis locais `int`: `iinc`, que soma uma constante diretamente no slot da variável, sem passar pela pilha de operandos. O `javap -c` de `x = x++` mostra por que o incremento se perde:

```text
iload_1        // empilha o valor atual de x (10)
iinc 1, 1      // incrementa o slot de x: agora vale 11
istore_1       // desempilha o 10 e grava em x
```

O 10 já estava na pilha antes do incremento, e é ele que volta para a variável. Para `++x`, a ordem das duas primeiras instruções se inverte, e o 11 é empilhado. Já o cast dos operadores compostos aparece como instruções de conversão: `b += 5` num `byte` vira `iadd` seguido de `i2b`, que corta o resultado para 8 bits.

## Resumo para a prova

- `x++` vale o valor antigo; `++x` vale o novo; os dois alteram a variável
- `x = x++` não altera `x`
- Resolva expressões trocando cada `++`/`--` pelo valor, da esquerda para a direita; depois aplique a precedência
- `++` e `--` só em variáveis: `5++` e `++(a + 1)` não compilam
- `x op= y` tem cast implícito para o tipo de `x`: `b += 5` compila num `byte`; `b = b + 5` não
- No operador composto, o valor antigo de `x` é guardado antes de avaliar o lado direito
- Atribuição é expressão: `a = b = 7` funciona; `if (flag = true)` compila e sempre entra
