Toda decisão de um programa passa por uma expressão `boolean`, e a prova cobra três coisas nelas: o que pode ser comparado com o quê, a precedência entre `&&`, `||` e `!`, e, principalmente, o **curto-circuito**, que decide se o lado direito de uma expressão chega a ser executado. Quando esse lado tem um `++` ou uma chamada de método, a saída do programa depende disso.

## Operadores relacionais e de igualdade

| Operador | Significa | Aceita |
|---|---|---|
| `<` `>` `<=` `>=` | menor, maior, menor ou igual, maior ou igual | só tipos numéricos (incluindo `char`) |
| `==` `!=` | igual, diferente | números entre si, `boolean` entre si, referências entre si |

Antes de comparar números, o Java aplica a mesma [promoção numérica](/assistir/estagiario-t2-e03) das contas. E os relacionais têm precedência maior que a igualdade:

```java executar
System.out.println(5 == 5.0);
System.out.println('a' == 97);
System.out.println(10 / 4 == 2.5);
System.out.println(0.1 + 0.2 == 0.3);
System.out.println(Double.NaN == Double.NaN);
System.out.println(3 > 2 == true);
```

```saida
true
true
false
false
false
true
```

`10 / 4` é a divisão inteira 2, que não é 2.5. As linhas com `0.1 + 0.2` e `NaN` são o [ponto flutuante](/assistir/aprendiz-t3-e03) mostrando os dentes. E `3 > 2 == true` funciona porque `3 > 2` é calculado antes do `==`.

Comparações não se encadeiam como na matemática. `1 < x < 10` vira `(1 < x) < 10`, que compara um `boolean` com um `int`:

```java nao-compila
int x = 5;
boolean dentro = 1 < x < 10;
```

O certo é `1 < x && x < 10`. Também não dá para comparar `boolean` com número (`x == true` com `x` inteiro não compila): em Java, `boolean` não é um número disfarçado, como em C.

> [!ATENCAO]
> Com objetos, `==` compara **referências** (se são o mesmo objeto), não o conteúdo. Para `String` e para objetos em geral, o conteúdo se compara com `equals`. O assunto volta com força na temporada de [texto](/assistir/estagiario-t5-e05).

## Operadores lógicos

| Operador | Nome | Avalia o lado direito |
|---|---|---|
| `!` | NÃO | (unário) |
| `&&` | E condicional | só se o esquerdo for `true` |
| `\|\|` | OU condicional | só se o esquerdo for `false` |
| `&` | E lógico | sempre |
| `\|` | OU lógico | sempre |
| `^` | OU exclusivo | sempre |

A precedência, do mais forte para o mais fraco: `!`, depois `&`, `^`, `|`, depois `&&`, e por último `||`. Assim como `*` vem antes de `+`, `&&` vem antes de `||`:

```java executar
boolean t = true, f = false;
System.out.println(t || f && f);
System.out.println((t || f) && f);
System.out.println(!t || t);
System.out.println(!(t || t));
System.out.println(t ^ t ^ t);
```

```saida
true
false
true
false
true
```

`t || f && f` é `t || (f && f)`, que dá `true`. Com parênteses forçando o `||` primeiro, o resultado muda. Para simplificar ou negar condições, as leis de De Morgan do episódio de [lógica](/assistir/aprendiz-t3-e01) valem aqui: `!(a && b)` é `!a || !b`.

## Curto-circuito

`&&` e `||` param assim que o resultado está decidido: em `false && qualquer`, o resultado já é `false`; em `true || qualquer`, já é `true`. O lado direito **nem é executado**. Já `&` e `|` com `boolean` sempre avaliam os dois lados:

```java executar
int a = 0;
boolean r1 = (a > 0) && (++a > 0);
System.out.println(r1 + " " + a);
boolean r2 = (a > 0) & (++a > 0);
System.out.println(r2 + " " + a);
boolean r3 = (a > 0) || (++a > 0);
System.out.println(r3 + " " + a);
boolean r4 = true | (++a > 0);
System.out.println(r4 + " " + a);
```

```saida
false 0
false 1
true 1
true 2
```

Linha por linha: em `r1`, o lado esquerdo é falso e o `++a` não roda. Em `r2`, o `&` avalia os dois lados, e `a` vira 1. Em `r3`, como `a` já é 1, o lado esquerdo é verdadeiro e o `++a` é pulado. Em `r4`, o `|` avalia tudo mesmo com `true` na esquerda.

O curto-circuito é o que torna seguro o padrão "teste antes de usar":

```java executar
String s = null;
System.out.println(s != null && s.length() > 3);
try {
    System.out.println(s != null & s.length() > 3);
} catch (NullPointerException e) {
    System.out.println("NullPointerException");
}
```

```saida
false
NullPointerException
```

Com `&&`, o `s.length()` nunca roda quando `s` é `null`. Com `&`, ele roda e lança a exceção. A ordem também importa: `s.length() > 3 && s != null` lança a exceção do mesmo jeito, porque o teste de nulo veio tarde demais.

> [!PROVA]
> `&`, `|` e `^` funcionam com `boolean` e com inteiros. Com `boolean`, são operadores lógicos **sem** curto-circuito. Com inteiros, operam bit a bit, assunto do [próximo episódio](/assistir/estagiario-t2-e05). Quando a questão mostra um `&` sozinho entre duas condições, procure o efeito colateral do lado direito.

## Por baixo dos panos

Não existe instrução de "E condicional" no bytecode. O `javac` transforma `&&` e `||` em **saltos**: `if (a > 0 && ++a > 0)` vira "compare `a` com 0; se não for maior, pule para o `else`; senão, incremente e compare de novo". O curto-circuito é, literalmente, um desvio que pula o código do lado direito.

Já `a & b` com `boolean` vira a instrução `iand`, que precisa dos dois valores prontos na pilha, e por isso os dois lados são sempre calculados. Na JVM, um `boolean` numa expressão é só um `int` que vale 0 ou 1, e `iand` é o mesmo E bit a bit que você viu nas [portas lógicas](/assistir/aprendiz-t1-e02).

## Resumo para a prova

- Relacionais (`<`, `>`, `<=`, `>=`) só com números e `char`; vêm antes de `==` e `!=`
- Números de tipos diferentes são promovidos antes da comparação: `5 == 5.0` é `true`
- `1 < x < 10` não compila; use `1 < x && x < 10`
- `boolean` não se compara com número
- Precedência: `!`, depois `&`, `^`, `|`, depois `&&`, depois `||`
- `&&` e `||` fazem curto-circuito; `&`, `|` e `^` avaliam os dois lados
- Procure efeitos colaterais (`++`, chamadas) no lado direito: o curto-circuito decide se eles acontecem
- `x != null && x.metodo()` é seguro; trocar a ordem ou usar `&` não é
