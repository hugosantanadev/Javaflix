O operador ternário é o único do Java com três operandos, e a prova o usa de dois jeitos: aninhado, para testar a leitura, e com tipos diferentes nos dois ramos, para testar as regras de tipo. Os operadores bit a bit aparecem menos, mas quando aparecem são questões de conta pura, com uma regra que quase ninguém conhece: o deslocamento de 32 posições num `int` não faz nada.

## O ternário

`condição ? valorSeVerdadeiro : valorSeFalso` é uma **expressão**: produz um valor, ao contrário do `if`, que é um comando. Só um dos dois ramos é avaliado.

```java executar
int nota = 7;
String r = nota >= 7 ? "aprovado" : nota >= 5 ? "recuperação" : "reprovado";
System.out.println(r);
int x = 5;
int y = x > 3 ? x++ : x--;
System.out.println(x + " " + y);
```

```saida
aprovado
6 5
```

O ternário é associativo à **direita**: `a ? b : c ? d : e` é `a ? b : (c ? d : e)`, o que permite encadear faixas como um `else if`. No segundo exemplo, só o `x++` roda: `y` recebe o valor antigo (5), e o `x--` nunca acontece.

Por ser expressão, o ternário não pode ser um comando sozinho, e os dois ramos precisam produzir valores:

```java nao-compila
int x = 5;
x > 3 ? System.out.println("sim") : System.out.println("não");
```

> [!ANTES]
> Até o Java 13, o ternário era o único jeito de escolher um valor no meio de uma expressão, e código antigo tem cadeias de ternários aninhados difíceis de ler. Desde o Java 14, o `switch` com `->` também é uma expressão, assunto da temporada [Decisões](/?t=estagiario-t3), e é ele que se usa hoje quando há mais de duas opções.

## O tipo do resultado

> [!PENSE]
> `true ? 1 : 2.0` escolhe o ramo do `1`. O que você acha que o `println` mostra: `1` ou `1.0`?

Quando os dois ramos têm tipos diferentes, o tipo do ternário segue regras (JLS 15.25). As que caem na prova:

| Ramos | Tipo do resultado |
|---|---|
| dois números de tipos diferentes | a [promoção numérica](/assistir/estagiario-t2-e03): `true ? 1 : 2.0` é `double` |
| `char` e uma constante `int` que cabe em `char` | `char` |
| `char` e uma variável `int` | `int` |
| um primitivo e o seu wrapper (`int` e `Integer`) | o primitivo, com *unboxing* |
| tipos sem relação (`int` e `String`) | um tipo comum de referência, como `Object` |

```java executar
System.out.println(true ? 1 : 2.0);
System.out.println(false ? 1 : 'a');
System.out.println(true ? 'a' : 0);
int i = 0;
System.out.println(true ? 'a' : i);
Object o = true ? 1 : "um";
System.out.println(o);
```

```saida
1.0
a
a
97
1
```

A primeira linha imprime `1.0`, mesmo escolhendo o ramo do `1`: o tipo do ternário inteiro é `double`. Na segunda e na terceira, a constante cabe em `char`, e o resultado é um `char`. Na quarta, `i` é uma variável, e o resultado vira `int`: 97.

A linha do *unboxing* esconde uma armadilha: se o ramo escolhido for um `Integer` nulo, a conversão para `int` lança exceção.

```java executar
Integer valor = null;
try {
    int r = true ? valor : 0;
} catch (NullPointerException e) {
    System.out.println("NullPointerException");
}
```

```saida
NullPointerException
```

> [!COMPILADOR]
> Você é o `javac`. Este trecho compila?
>
> ```java nao-compila
> int estoque = 0;
> String situacao = estoque > 0 ? estoque : "esgotado";
> System.out.println(situacao);
> ```
>
> **Resposta:** Não compila, na linha 2. Os ramos são um `int` e uma `String`, e o tipo comum entre eles é uma referência genérica, não uma `String`. Para guardar numa `String`, os dois ramos precisam ser texto: `estoque > 0 ? "em estoque" : "esgotado"`, ou `"" + estoque` no primeiro ramo.

## Operadores bit a bit em inteiros

Com operandos inteiros, `&`, `|`, `^` e `~` operam bit a bit, como as [portas lógicas](/assistir/aprendiz-t1-e02), e os deslocamentos movem os bits, como no episódio de [complemento de dois](/assistir/aprendiz-t3-e02):

| Operador | Faz | Exemplo |
|---|---|---|
| `&` | E de cada bit | `0b1100 & 0b1010` = `0b1000` (8) |
| `\|` | OU de cada bit | `0b1100 \| 0b1010` = `0b1110` (14) |
| `^` | OU exclusivo de cada bit | `0b1100 ^ 0b1010` = `0b0110` (6) |
| `~` | inverte todos os bits | `~x` = −x − 1 |
| `<<` | desloca para a esquerda | `x << n` = x · 2ⁿ (enquanto não estoura) |
| `>>` | desloca para a direita, copiando o sinal | `-16 >> 2` = −4 |
| `>>>` | desloca para a direita, pondo zeros | `-16 >>> 28` = 15 |

![As operações E, OU e OU exclusivo entre 1100 e 1010, coluna por coluna, e o deslocamento de 1 três posições para a esquerda](/figuras/operacoes-bit-a-bit.svg "Cada coluna é uma porta lógica independente; deslocar para a esquerda multiplica por 2 a cada posição.")

```java executar
int a = 0b1100, b = 0b1010;
System.out.println(a & b); //> 1100 E 1010: só a coluna do 8 tem 1 nos dois.
System.out.println(a | b);
System.out.println(a ^ b); //> Onde os bits são diferentes: 0110.
System.out.println(~a); //> Inverte os 32 bits: dá -12 - 1.
System.out.println(1 << 4);
System.out.println(-16 >> 2);
System.out.println(-16 >>> 28);
```

```saida
8
14
6
-13
16
-4
15
```

Os operandos passam pela promoção numérica: `byte`, `short` e `char` viram `int` antes da operação, e `~b` com `b` do tipo `byte` é um `int`.

> [!MATEMATICA]
> Por que `~x` é sempre `-x - 1`? No complemento de dois, negar um número é inverter os bits e somar 1: `-x = ~x + 1`. Passando o 1 para o outro lado, `~x = -x - 1`. Com `x = 12`: `~12 = -12 - 1 = -13`, exatamente o que o programa imprimiu. E `~0`, todos os bits ligados, vale `-0 - 1 = -1`.

## O deslocamento tem limite

Num `int`, só os 5 bits de baixo da distância de deslocamento contam (num `long`, os 6 de baixo). Deslocar 32 posições é o mesmo que deslocar 0, e 33 é o mesmo que 1:

```java executar
System.out.println(1 << 32);
System.out.println(1 << 33);
System.out.println(1L << 32);
System.out.println(8 >> -1);
```

```saida
1
2
4294967296
0
```

`8 >> -1` usa os 5 bits de baixo de −1, que valem 31: o 8 é deslocado 31 posições para a direita e vira 0. A regra parece arbitrária, mas espelha o processador: no x86, a instrução de deslocamento de 32 bits também usa só os 5 bits de baixo da contagem.

> [!ERRO]
> Calcular 2³² com `1 << 32` e guardar num `long`, esperando 4.294.967.296. O `1` é `int`, o deslocamento acontece em `int`, e 32 vira 0: o resultado é 1. Para deslocar além de 31 posições, o valor da esquerda precisa ser `long`: `1L << 32`.

> [!IA]
> Pergunte a um assistente quanto vale `1 << 32` em Java e é comum ele responder 4.294.967.296, aplicando a matemática e não a regra dos 5 bits. A resposta certa, num `int`, é 1. Esse tipo de detalhe de linguagem é onde a IA mais erra: rode antes de acreditar.

## Flags: um conjunto num inteiro

Os operadores bit a bit brilham com **flags**, vários valores sim/não guardados num único número. É o [conjunto em bits](/assistir/aprendiz-t3-e01) da trilha Aprendiz, com os operadores compostos:

```java executar
int permissoes = 0;
permissoes |= 0b100;
permissoes |= 0b001;
permissoes &= ~0b001;
permissoes ^= 0b010;
System.out.println(Integer.toBinaryString(permissoes));
```

```saida
110
```

`|=` liga um bit, `&= ~` desliga, `^=` inverte, e `(x & mascara) != 0` testa.

> [!LAPIS]
> As permissões de um arquivo usam 4 para ler, 2 para escrever e 1 para executar. Começando com `int p = 0b111;`, todas ligadas, escreva a linha que tira só a permissão de escrever. Depois, qual é o valor de `p`?
>
> **Resposta:** `p &= ~2;`. O `~2` tem todos os bits ligados menos o de valor 2, e o `&` apaga só esse bit. `p` fica `0b101`, que vale **5**: ler e executar.

> [!ENGENHARIA]
> Flags em bits são compactas e rápidas, mas difíceis de ler: `p & 4` não diz nada a quem não conhece a convenção. Em código de negócio, prefira um `enum` com um `EnumSet`, da temporada de [coleções](/?t=pleno-t3). Por dentro, o `EnumSet` guarda as opções exatamente como bits num `long`, então você ganha a legibilidade sem perder o desempenho.

## Na IDE

- **Ternário e `if`, ida e volta.** Com o cursor no `?`, **Alt + Enter** oferece *Replace '?:' with 'if else'*. Num `if` que só escolhe um valor, a mesma tecla oferece o caminho contrário.
- **Ternários aninhados.** O IntelliJ pode marcar ternários dentro de ternários com o aviso *Nested conditional expression*, um convite a trocar a cadeia por um `switch`.
- **Deslocamento impossível.** `1 << 32` num `int` ganha o aviso *Shift operation by inappropriate constant*: a IDE conhece a regra dos 5 bits.

## Por baixo dos panos

O ternário compila para os mesmos saltos condicionais de um `if`: avalia a condição, pula para um ramo ou outro e deixa o valor escolhido na pilha. A diferença para o `if` está só na linguagem (expressão contra comando), e o tipo único do resultado é o motivo das regras de conversão: a pilha precisa saber se recebeu um `int`, um `double` ou uma referência.

Os operadores bit a bit são as operações mais baratas que existem: `iand`, `ior`, `ixor`, `ishl`, `ishr` e `iushr` viram, cada uma, uma única instrução do processador (`and`, `or`, `xor`, `shl`, `sar`, `shr` no x86), que roda em um ciclo. Compiladores trocam multiplicações e divisões por potências de 2 por deslocamentos quando o resultado é garantidamente o mesmo.

## Resumo para a prova

- `a ? b : c` é expressão; só um ramo é avaliado; associativo à direita
- O ternário não é comando: não pode ficar sozinho numa linha nem ter ramos `void`
- Ramos numéricos diferentes são promovidos: `true ? 1 : 2.0` imprime `1.0`
- `char` com constante `int` que cabe dá `char`; com variável `int`, dá `int`
- `Integer` nulo num ternário com ramo `int` lança `NullPointerException`
- `&`, `|`, `^`, `~` operam bit a bit com inteiros; `~x` = −x − 1
- `>>` mantém o sinal, `>>>` põe zeros; `x << n` multiplica por 2ⁿ
- Num `int`, só os 5 bits de baixo da distância contam: `1 << 32` é 1
